# 工具调用与记忆管理

## 一句话理解

工具调用使用严格 Schema、输入验证、权限令牌、超时与审计，副作用操作需幂等、确认与补偿事务；记忆分为会话、任务、长期知识与用户偏好，分别设置来源、过期、访问控制和删除策略——不要把未经验证的模型文本直接传给高权限工具。

## 1. 工具调用管理

### 1.1 为什么工具调用需要专门管理

Agent 的工具调用直接接触真实世界（API、数据库、文件系统、代码执行），风险远高于纯文本生成：

- **副作用**：工具调用可能修改数据、发送消息、执行代码
- **不可逆**：某些操作（删除、发送）无法撤销
- **权限滥用**：模型可能被诱导调用高权限工具
- **参数错误**：模型生成的参数可能不合法或危险
- **资源消耗**：工具调用消耗外部资源（API 配额、计算资源）

### 1.2 工具注册与 Schema

```python
# 工具注册示例
@tool_registry.register(
    name="send_email",
    version="v1.2.0",
    permissions=["email:send"],
    risk_level="high",
    requires_approval=True
)
def send_email(
    to: str,           # 收件人邮箱
    subject: str,      # 邮件主题
    body: str,         # 邮件正文
    attachments: list[str] = None  # 附件路径
) -> ToolResult:
    ...
```

每个工具注册时声明：

| 字段 | 说明 |
|:---|:---|
| name | 工具唯一标识 |
| version | 工具版本 |
| schema | 参数 JSON Schema |
| permissions | 所需权限列表 |
| risk_level | 风险等级 (low/medium/high) |
| requires_approval | 是否需要人工审批 |
| timeout | 超时时间 |
| idempotent | 是否幂等 |
| rate_limit | 调用频率限制 |

### 1.3 输入验证

模型生成的工具参数必须经过验证：

- **Schema 验证**：参数类型、必填项、枚举值
- **业务规则验证**：邮箱格式、URL 白名单、数值范围
- **安全验证**：SQL 注入、路径遍历、命令注入检测
- **内容审核**：参数中不包含有害内容

### 1.4 权限控制

```text
Agent 任务 → 权限策略 → 工具调用请求 → 权限检查 → 执行/拒绝
                ↓
          权限令牌 (短期有效, 最小权限)
```

- **最小权限原则**：工具只拥有完成任务所需的最小权限
- **权限令牌**：短期有效的令牌，任务结束自动失效
- **动态权限**：根据任务类型、用户角色动态授予
- **权限审计**：记录所有权限授予和拒绝

### 1.5 副作用管理

| 操作类型 | 示例 | 管理策略 |
|:---|:---|:---|
| 只读 | 查询数据库、搜索 | 无需特殊处理 |
| 可逆写 | 更新记录、创建文件 | 幂等 + 日志 |
| 不可逆写 | 删除、发送邮件 | 人工确认 + 补偿事务 |
| 高风险 | 执行代码、支付 | 沙箱 + 多重确认 |

### 1.6 幂等性

- **幂等键**：每个工具调用携带唯一 ID
- **去重**：接收方根据幂等键去重
- **结果缓存**：相同参数 + 幂等键返回缓存结果
- **重试安全**：幂等工具可安全重试

### 1.7 审计日志

每次工具调用记录：

| 字段 | 说明 |
|:---|:---|
| tool_name | 工具名称 |
| tool_version | 工具版本 |
| parameters | 调用参数（脱敏后） |
| result | 返回结果（脱敏后） |
| side_effects | 副作用记录 |
| caller | 调用者（Agent ID、任务 ID） |
| timestamp | 调用时间 |
| status | 成功/失败 |
| approval | 审批信息（如需） |

## 2. 记忆管理

### 2.1 记忆层次

```text
记忆类型
├── 会话记忆 (Session Memory)
│   ├── 当前对话的完整消息历史
│   ├── 生命周期: 单次会话
│   └── 存储: Redis / 内存
├── 任务记忆 (Task/Working Memory)
│   ├── 当前任务的中间状态、变量、计划
│   ├── 生命周期: 单次任务
│   └── 存储: 数据库 / Checkpoint
├── 长期知识 (Long-term Knowledge)
│   ├── 用户文档、知识库、历史交互摘要
│   ├── 生命周期: 持久
│   └── 存储: 向量数据库 / 知识图谱
└── 用户偏好 (User Preference)
    ├── 用户画像、偏好设置、历史反馈
    ├── 生命周期: 持久
    └── 存储: 数据库
```

### 2.2 会话记忆管理

- **消息历史**：完整的对话消息列表
- **上下文窗口**：超出模型上下文窗口时需截断或压缩
- **会话隔离**：不同会话间记忆隔离
- **过期策略**：会话结束后保留 N 天供续接

### 2.3 上下文压缩

长对话需要压缩以适应上下文窗口：

| 策略 | 说明 | 适用场景 |
|:---|:---|:---|
| 截断 | 只保留最近 N 条消息 | 简单对话 |
| 摘要 | 用 LLM 摘要历史对话 | 长对话 |
| 滑动窗口 | 固定窗口 + 摘要 | 平衡精度与成本 |
| 选择性保留 | 保留关键信息（决策、事实） | 任务型对话 |

```text
压缩前: [msg1, msg2, ..., msg50] (超长)
压缩后: [summary(msg1-40), msg41, ..., msg50]
```

### 2.4 长期知识管理

- **写入策略**：什么内容值得长期存储（用户偏好、事实性信息）
- **检索策略**：按相关性检索历史知识
- **冲突处理**：新旧知识冲突时以新为准或需确认
- **遗忘机制**：过期或低价值知识定期清理

### 2.5 记忆访问控制

| 记忆类型 | 访问控制 |
|:---|:---|
| 会话记忆 | 仅当前会话可访问 |
| 任务记忆 | 仅当前任务可访问 |
| 长期知识 | 按用户/团队权限过滤 |
| 用户偏好 | 仅对应用户可访问 |

### 2.6 记忆与隐私

- **敏感信息过滤**：记忆写入前过滤 PII
- **用户数据删除**：支持用户请求删除所有记忆
- **数据保留策略**：按类型设置保留期
- **加密存储**：敏感记忆加密存储

## 3. 安全边界

### 3.1 模型输出验证

> **核心原则：不要把未经验证的模型文本直接传给高权限工具。**

模型输出可能包含：

- **幻觉参数**：虚构的 URL、邮箱、ID
- **注入内容**：被 Prompt 注入诱导的恶意参数
- **格式错误**：不符合工具 Schema 的参数

验证流程：

```text
模型输出工具调用 → Schema 验证 → 业务规则验证 → 安全扫描
    → 权限检查 → (高风险: 人工确认) → 执行
```

### 3.2 工具调用限制

- **白名单**：Agent 只能调用注册的工具
- **参数约束**：限制参数值范围（如 URL 白名单）
- **频率限制**：单任务内工具调用次数上限
- **资源限制**：工具可消耗的资源上限

### 3.3 补偿事务

对于已执行但需要回滚的操作：

- **补偿操作**：执行反向操作（如已创建则删除）
- **状态记录**：记录已执行操作以便补偿
- **人工通知**：无法自动补偿时通知人工处理

## 4. 工具调用质量指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 参数正确率 | 工具参数符合业务规则的比例 | ≥ 95% |
| 不必要调用率 | 冗余或无效调用的比例 | ≤ 10% |
| 工具成功率 | 工具调用成功的比例 | ≥ 90% |
| 副作用事故率 | 导致意外副作用的调用比例 | ≤ 1% |
| 审批通过率 | 需审批操作中通过的比例 | ≥ 80% |

## 5. 常见问题

- **参数幻觉**：模型生成不存在的 ID 或 URL，需白名单验证
- **权限提升**：模型被诱导调用高权限工具，需权限策略
- **死循环调用**：Agent 反复调用同一工具，需步数限制
- **记忆膨胀**：长期记忆无限增长，需遗忘机制
- **上下文丢失**：压缩后关键信息丢失，需选择性保留
