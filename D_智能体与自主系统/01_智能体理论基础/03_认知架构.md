# 认知架构

## 一句话理解

认知架构为智能体提供了一张"功能蓝图"——感知如何输入、记忆如何存储、推理如何执行、行动如何控制、元认知如何监控——将智能体的认知能力分解为可设计的模块，保证各模块协同而非冲突。

## 概述

一个智能体需要完成多种认知功能：从环境中接收信息（感知）、记住当前状态（工作记忆）、从经验中检索知识（长期记忆）、推理和规划（审议）、执行动作（行动控制）、评估自身表现（元认知）。将这些功能塞进一个"端到端"的模型（如单个 LLM）虽然简单，但会导致可解释性差、调试困难、功能冲突的问题。

**认知架构**正是为这些功能提供系统和模块化设计——它不要求每层各用一个模型，而是要求**功能分工清晰、接口定义明确、信息流可跟踪**。本笔记是 [[00_智能体理论基础_综述|智能体理论基础]] 中"如何组织认知功能"的实践指南，BDI 框架（[[02_决策理论与BDI|决策理论与 BDI]]）回答了"如何做决策"，认知架构回答了"如何组织所有认知功能"。

## 发展历史

| 年代 | 里程碑 | 意义 |
|:---|:---|:---|
| 1957 | Newell & Simon 提出通用问题求解器（GPS） | 首个将问题解决作为认知过程的计算模型 |
| 1983 | Soar 架构（Newell） | 统一认知架构，问题空间+块学习，旨在覆盖所有认知行为 |
| 1993 | ACT-R 架构（Anderson） | 基于认知科学实验的认知架构，强调可验证性 |
| 1997 | 四资源模型（Three-layer 架构） | 将认知架构分为反应层、审议层和元管理层 |
| 2000s | 混合认知架构 | 结合符号推理和神经网络的混合设计 |
| 2010s | 深度强化学习作为"隐式认知架构" | 端到端学习范式挑战了模块化认知架构的假设 |
| 2022- | LLM Agent 认知架构 | 将 LLM 作为"审议层"，与记忆、工具、外部环境结合 |

## 核心概念

### 认知架构的核心功能模块

一个完整的认知架构通常包含以下模块：

| 模块 | 功能 | 输入 | 输出 |
|:---|:---|:---|:---|
| 感知（Perception） | 解释原始传感器输入，提取有意义的信息 | 原始观察 $o_t$ | 结构化感知结果 |
| 工作记忆（Working Memory） | 保存当前任务的状态信息 | 感知结果、历史状态 | 当前状态 $s_t$ |
| 长期记忆（Long-term Memory） | 存储知识和技能 | 检索请求 | 相关知识/技能 |
| 审议/推理（Deliberation） | 推理、规划、决策 | 当前状态 + 长期记忆 | 计划/动作选择 |
| 行动控制（Action Control） | 执行选定的动作 | 决策指令 | 实际动作 $a_t$ |
| 元认知（Metacognition） | 监控和评估自身认知过程 | 各模块状态 | 校准信号/异常检测 |

### 经典三层架构

大多数认知架构（包括 Soar、ACT-R 和现代 LLM Agent 架构）遵循三层设计：

```text
元管理层（Meta-level）
  ─ 监控与评估：任务进展、不确定性、错误检测
  ─ 资源分配：注意力、计算预算、时间管理
  ─ 学习控制：何时反思、何时更新知识

审议层（Deliberative Level）
  ─ 推理与规划：思维链、规划算法
  ─ 决策与选择：从候选方案中选择动作
  ─ 问题解决：符号推理、搜索

反应层（Reactive Level）
  ─ 快速响应：时间敏感的动作，不经过审议
  ─ 技能执行：已固化的熟练操作
  ─ 环境交互：感知与行动的基础接口
```

### 接口设计原则

每个模块之间的接口应记录以下信息，以支持可审计和可调试：

- **证据**：模块输出的依据是什么（如感知模块输出的"证据来源"）
- **状态假设**：模块的输入/输出假设了哪些未验证的条件
- **计划前置条件**：在审议层输出的计划中，每个步骤的前置条件
- **动作副作用**：行动控制模块执行的每个动作可能产生的副作用
- **失败归因**：元认知模块检测到异常时，记录的失败原因和归因路径

## 技术原理

### Soar 架构

Soar（State, Operator And Result）是 Laird 等人提出的统一认知架构，核心思想是：

- **问题空间**：所有认知活动都在问题空间中进行，每个问题空间包含一组状态和操作符
- **通用决策循环**：感知 → 提议操作符 → 评估操作符 → 选择操作符 → 应用操作符 → 评估结果
- **块学习（Chunking）**：当 Soar 在问题空间中遇到"僵局"（impasse）时，通过子目标解决问题，并将解决方案作为"块"存入长期记忆，供未来相似场景直接使用

Soar 的决策循环是所有认知架构中最完整的形式化，与 LLM Agent 的 ReAct 循环在结构上有深刻对应关系：感知 = Observe，提议操作符 = Thought，选择操作符 = Action，评估结果 = Feedback。

### ACT-R 架构

ACT-R（Adaptive Control of Thought—Rational）由 Anderson 提出，更强调认知科学实验的可验证性：

- **模块化**：视觉模块、手动模块、目标模块、陈述性记忆模块、程序性记忆模块等
- **缓冲机制**：每个模块通过有限容量的缓冲（buffer）与中央系统交互
- **理性分析**：模块的激活和选择基于贝叶斯理性分析——记忆检索的激活水平取决于使用频率、近因性和上下文相关度

ACT-R 在认知科学中被广泛用于建模人类行为实验，对 AI 记忆系统的设计（如 [[../05_记忆与持续学习/02_记忆架构与检索|记忆架构与检索]]）有直接指导意义。

### LLM Agent 的认知架构

LMA（Language Model Agent）架构是 LLM Agent 时代的认知架构设计范式，将 LLM 作为"审议层"的核心引擎：

```text
┌──────────────────────────────────────────────┐
│                  元认知层                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 反思能力  │  │ 置信度评估│  │ 错误检测  │  │
│  └──────────┘  └──────────┘  └──────────┘  │
├──────────────────────────────────────────────┤
│                  审议层（LLM）                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 推理/规划 │  │ 工具选择  │  │ 结构化输出│  │
│  └──────────┘  └──────────┘  └──────────┘  │
├──────────────────────────────────────────────┤
│                  记忆层                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 工作记忆  │  │ 长期记忆  │  │ 技能库    │  │
│  │(上下文窗口)│  │(向量数据库)│  │(程序记忆) │  │
│  └──────────┘  └──────────┘  └──────────┘  │
├──────────────────────────────────────────────┤
│                  感知与行动层                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 多模态感知│  │ 工具调用  │  │ 物理执行  │  │
│  └──────────┘  └──────────┘  └──────────┘  │
└──────────────────────────────────────────────┘
```

Sumers et al.（2023）的 *Cognitive Architectures for Language Agents* 是这一方向的重要综述，将 LLM Agent 映射到经典认知架构的各个模块。

## 关键方法与模型

| 架构 | 核心思想 | 特点 |
|:---|:---|:---|
| Soar | 问题空间 + 通用决策循环 + 块学习 | 最完整的认知架构理论 |
| ACT-R | 模块化 + 缓冲机制 + 贝叶斯激活 | 认知科学实验验证最充分的架构 |
| 三层架构 | 反应层-审议层-元管理层 | 简洁实用的功能分工模式 |
| LMA | LLM 作为审议层 + 外部记忆/工具 | LLM Agent 时代的认知架构范式 |

## 优势与局限

**优势**：认知架构将智能体的认知功能分解为可设计、可调试、可审计的模块，提升系统的可理解性和可控性；经典架构（Soar、ACT-R）提供了经过数十年验证的设计原则；三层架构的清晰分工为工程实现提供了参考蓝图。

**局限**：经典认知架构（Soar、ACT-R）的设计复杂度高，在大规模应用中难以维护；端到端学习方法（深度强化学习、LLM）在特定任务上可以达到更好的性能，但牺牲了架构的模块化和可解释性；LLM Agent 认知架构（LMA）仍在演化中，缺乏 Soar/ACT-R 那样的理论成熟度。

## 应用场景

- **复杂 Agent 系统设计**：需要多模块协同的 Agent 系统设计参考
- **可解释 AI 系统**：认知架构的模块化设计便于跟踪和审计决策过程
- **人机协作系统**：三层架构为"人在回路中"提供了自然的接口设计
- **认知科学计算建模**：ACT-R 等架构用于模拟和验证人类认知理论

## 前沿发展

- **可学习的认知架构**：认知架构的模块（如记忆管理策略、注意力分配）从固定设计变为可学习
- **LLM 作为认知架构的统一组件**：LLM 不再只是"审议层"，而是逐步承担记忆、感知、元认知等多层功能
- **认知架构的自动发现**：通过神经架构搜索或进化算法自动发现最优的认知功能分工

## 常见问题

**Q: 为什么不能用一个 LLM 完成所有认知功能？**
可以，但会导致"黑箱"问题：无法区分失败是感知错误、记忆检索错误还是推理错误。认知架构的模块化设计让每个功能可独立测试、调试和优化。在工程上，这就像"微服务架构" vs "单体应用"的权衡。

**Q: Soar 和 ACT-R 的主要区别是什么？**
Soar 追求"统一认知架构"——用一套机制（通用决策循环+块学习）覆盖所有认知行为；ACT-R 追求"认知科学可验证性"——每个模块的设计都基于人类行为实验数据。Soar 更适合 AI 工程，ACT-R 更适合认知科学建模。
