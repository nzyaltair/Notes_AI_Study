# 测试、诊断与开发工作流

## 一句话理解

DSH 的测试策略以真实组合和外部可观察结果为中心：单元测试守住契约，快照固定模型/协议/UI 表现，真实 API e2e 验证模型真正能驱动交付的能力。

## 测试层级

| 层级 | 主要验证对象 | 命令 |
|---|---|---|
| 单元测试 | 边界、错误路径、事件顺序、并发竞态、Fiber 清理 | `pnpm run test` |
| 覆盖率门禁 | 死代码与未触达代码（100% per file for `packages/*/*/src`） | `pnpm run test:coverage` |
| 快照 | 无密钥 transcript、持久化日志、协议和 UI 呈现 | `pnpm run test:snapshot` |
| 真实 API e2e | 真实模型、工具和外部世界的联通性 | `pnpm run test:e2e` |
| Web 浏览器快照 | Chromium 浏览器渲染与 UI 输出 | `pnpm run test:web` |
| 构建产物冒烟 | 已发布入口、模块解析与 Loader 组合 | `pnpm run test:e2e`（部分） |

## 快照策略

### ACP / headless 快照

- ACP 快照（`examples/acp-agent/tests/snapshots/`）启动真实自动化服务器、回放录制会话，对归一化 JSON-RPC 和重新持久化的日志执行 diff；
- headless 后端场景通过 JSONL 测试 driver 启动示例组装；
- 更新会话 transcript 时：`pnpm run test:snapshot:record`；仅刷新而回放仍有效时：`pnpm run test:snapshot:refresh`；
- 一个 ACP 场景（`text-turn`）固定完整的系统提示词与工具 schema 内容；其他 fixture 将其 token 化，修改只扰动一行。

### Web 浏览器快照

- CI 强制只读的 `DSH_SNAPSHOT=replay`，绝不写入预期输出；record/refresh 留在本地；
- `test:web` 会先构建以交付插件 CSS；
- 每处 diff 须评审。

### 何时需要快照测试

每项非平凡的模型可见、协议可见或人类可见变更，都必须在同一 PR 中通过可运行示例所属的快照套件添加或更新无密钥场景。包测试、e2e 断言、mock 与仅测试组合都不能取代组装后的 transcript。

## 关键测试规则

### 优先使用真实实现而非 mock

只 mock 开销高或不确定的边界（LLM 适配器、网络、时钟）；下游一切保持真实。桥接工具调用测试（`makeBridgeHarness({ withBash: true })`）接入 `dsh-bash-local` 与 `dsh-tool-bash` 后运行 `echo`——这比 mock 更能证明工具行为符合断言。

### 验证外部世界，而非自我报告

e2e 断言应重新运行命令或从外部重新读取文件；对 agent 自身输出做关键词探测会让作弊的 agent 通过。**断言未修改的文件逐字节一致**。

### 测试真实入口路径

- 产品可见的插件必须经 Loader/app 的真实配置加载测试；手工 `ctx.plugin(...)` 套件不足，它不覆盖交付路径；
- 对于没有 `inject` 的插件（bundle/组合插件），须添加显式 `expect('default' in mod).toBe(false)` + `unwrapExports` 往返断言；
- 「真实入口路径」指已发布的产物：包的 `bin` 运行构建后的 `lib/bin.js`，由普通 `node` 执行，而非 tsx（可暴露结算竞态、模块解析、被吞掉的加载失败）；
- 保持构建产物冒烟测试绿色（`packages/examples/*/tests/built-bin.e2e.ts`）。

### 测试子进程启动模式

- 已有构建产物的测试通道通过共享双模式启动器，从构建后的 `lib/` 运行示例；不要为这些子进程手写 `--import tsx`；
- 不加载 Cordis 的协议与操作系统 fixture 直接通过 Node 运行使用可擦除语法的 `.ts` 文件。

### 带密钥策略

作为 DeepSeek，不要吝惜真实 API 测试。冒烟测试（启动真实示例、发送一条提示词、检查外部世界）能捕获「单元测试全绿、产品却坏了」这类 mock 无法发现的问题。真实 API 套件通过密钥控制，缺少密钥时自动跳过，不阻塞无密钥贡献者。

## 日常诊断顺序

1. **配置转储**：`dsh --profile web --dump-config` 查看实际启动的配置树；
2. **Fiber 状态/依赖**：确认插件是否因 `inject` 不满足而挂起；
3. **会话事件**：从 `session/event` 流或持久化日志查看实际发生了什么；
4. **真实组合测试**：用 Loader/app 路径而非手工 `ctx.plugin()` 复现问题；
5. **构建入口测试**：用 `node` 而非 `tsx` 验证构建产物，排除 tsx 掩盖的问题。

## 开发环境搭建

### 前置条件

- Node.js 22.19+ 或 24+（CI 覆盖 22.19、24、26）；
- 启用了 Corepack 的 pnpm（仓库固定 `pnpm@11.7.0`；`corepack enable` 后 `pnpm install` 自动切换版本）；
- Git 2.26+（钩子设置启用 worktree 专属配置扩展）；
- 可选：`DEEPSEEK_API_KEY`，用于 Web/headless/ACP 演示及真实 API e2e 测试。

### 首次搭建

```sh
pnpm install     # 安装依赖，同时配置 Lefthook 钩子和双语配对合并驱动
pnpm run typecheck   # 验证搭建完成（含 Host + Client TypeScript 检查）
```

### TypeScript 项目布局

| 文件 | 角色 |
|---|---|
| `tsconfig.json` | solution 根：引用两个 aggregate；tsserver 发现入口 |
| `tsconfig.host.json` | Host aggregate：Host 包、示例、测试、脚本 |
| `tsconfig.client.json` | Client aggregate：`packages/client/*`、`apps/web` |
| `tsconfig.base.json` | 共享 compilerOptions 与 `paths` 映射（vitest 解析门面） |

**为何要分两个 aggregate**：Host 与 Client 在相同键下以不同服务对 `Context` 接口做声明合并；单一 program 同时看到两份合并会报冲突。因此：
- `tsconfig.base.json` 永不添加 `include` 或 `files`；
- 构建全仓 `ts.Program` 的脚本显式以 `tsconfig.host.json` 或 `tsconfig.client.json` 为种子；
- 新包只登记进一个 aggregate。

`api/remotes` 是唯一例外：需同时有 Host/Client tsconfig，且 `api-remotes` 通过 `hostPhase: true` 提前在 Host tsdown 中生成 Host 入口。

### 构建顺序

```sh
tsc -b tsconfig.host.json
tsdown --env.DSH_BUILD_FACE host      # 含 Typert 生成（Remote 约定）
tsc -b tsconfig.client.json
tsdown --env.DSH_BUILD_FACE client    # 消费生成的 Remote 约定
pnpm run build:web
```

完整构建：`pnpm run build`；仅 lib：`pnpm run build:lib`。

### Git 钩子

`lefthook.yml` 配置三类快速本地检查点：
- `pre-commit`：校验暂存的配对记录、运行 Oxlint、检查空白错误、运行 vendor manifest 守卫；
- `pre-merge-commit`：配对检查；
- `pre-push`：`pnpm run typecheck`（含 Typert 约定生成）。

### 常用命令

```sh
pnpm run typecheck        # TypeScript 完整检查
pnpm run build            # 完整构建
pnpm run test             # 单元测试
pnpm run test:coverage    # 覆盖率门禁
pnpm run hygiene          # publint + verify-node-next-types
pnpm run doc-sync         # 文档同步（含 type-equiv 验证）
pnpm run check:all        # 全面本地门禁集
```
