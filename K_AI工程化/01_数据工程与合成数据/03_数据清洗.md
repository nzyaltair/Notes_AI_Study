# 数据清洗

## 一句话理解

数据清洗把原始数据转换为结构一致、可训练、可审计的数据集——统一编码与 Schema、处理缺失与异常、脱敏隐私内容，清洗规则必须版本化并在样本级保留处理原因，避免"静默删除"造成数据分布不可解释。

## 1. 概述

原始数据通常包含噪声、错误、不一致和敏感信息。数据清洗是数据处理管线中工程量最大的环节之一，直接决定模型训练的质量上限。

清洗与过滤的区别：

| 维度 | 数据清洗 | 数据过滤 |
|:---|:---|:---|
| 目标 | 修复格式、一致性、完整性问题 | 决定样本是否保留 |
| 操作 | 修改字段、填补缺失、标准化 | 丢弃或采样 |
| 输出 | 修复后的数据 | 保留的子集 |

## 2. 常见处理

### 2.1 解析与规范化

将原始数据统一为结构化格式：

| 问题 | 处理方法 | 示例 |
|:---|:---|:---|
| 编码不一致 | 统一为 UTF-8 | GB2312 → UTF-8 |
| HTML 标签 | 解析提取正文 | `<p>文本</p>` → `文本` |
| 语言混乱 | 语言检测与标记 | 混合语言文档标注主语言 |
| 时间格式 | 统一时间表示 | ISO 8601 格式 |
| 单位不一致 | 统一单位系统 | 英制 → 公制 |
| Schema 不一致 | 统一字段名和类型 | 字段映射 |

**「内容」的定义本身就是设计决策**：常规做法删除页眉、页脚、导航栏、菜单，只提取正文；但某些场景下导航元素有助于模型理解网页整体布局，什么算内容、什么不算往往界限模糊。HTML→文本本质是**有损线性化**——HTML 是层级结构/渲染视觉，最终要变成 token 序列，必须在某处妥协：简单表格可用 Markdown 渲染，嵌套表格则显著变难。这类处理通常基于规则而非模型——因为要全量跑一遍互联网，速度比智能重要；DataComp-LM 的消融显示 trafilatura 与 resiliparse 的抽取质量优于 CommonCrawl 官方 WET 文本（未来方向是跑得飞快又更智能的基于模型的抽取器）。

### 2.2 完整性处理

| 问题类型 | 处理策略 | 示例 |
|:---|:---|:---|
| 空值 | 填充默认值 / 删除 / 标记 | 缺失字段填 `null` 或删除 |
| 损坏文件 | 修复 / 隔离 / 删除 | PDF 解析失败 → 隔离 |
| 截断记录 | 检测并修复或丢弃 | JSON 不完整 → 丢弃 |
| 无效链接 | 检测死链并标记 | URL 404 → 标记 |
| 多模态配对缺失 | 检查图文对、音视频对 | 图像无标注 → 标记 |

### 2.3 一致性校验

- **标签一致性**：标签值在允许范围内
- **字段范围**：数值在合理范围内
- **跨表主键**：关联表的主键一致
- **多模态对齐**：文本与图像/音频的时间戳对齐
- **逻辑一致性**：如结束时间 > 开始时间

### 2.4 异常处理

| 异常类型 | 检测方法 | 处理 |
|:---|:---|:---|
| 离群值 | 统计方法（3σ、IQR） | 截断 / 标记 / 保留 |
| 模板垃圾 | 模式匹配 | 删除 |
| 乱码 | 字符分布检测 | 删除 |
| 无意义文本 | 语言模型困惑度 | 删除 |
| 重复模板 | n-gram 分析 | 去重 |

### 2.5 隐私处理

- **PII 检测**：正则规则 + NER 模型识别个人信息
- **脱敏替换**：姓名 → `[NAME]`，手机 → `[PHONE]`
- **哈希化**：对 ID 类信息做不可逆哈希
- **删除**：完全删除敏感数据
- **聚合**：将精确值替换为区间（如年龄 → 年龄段）

## 3. LLM 预训练数据清洗

大模型预训练的数据清洗管线：

```text
原始网页 HTML
    ↓
解析提取正文 (trafilatura/boilerpipe)
    ↓
语言识别与过滤 (fastText)
    ↓
编码统一 (UTF-8)
    ↓
特殊字符清理 (控制字符、零宽字符)
    ↓
长度与质量检查 (最短长度、词频比)
    ↓
PII 检测与脱敏
    ↓
有害内容过滤
    ↓
清洗后数据集
```

### 3.1 关键清洗规则

| 规则 | 说明 | 典型阈值 |
|:---|:---|:---|
| 最短长度 | 文档太短无信息量 | < 50 词 → 丢弃 |
| 最长长度 | 文档太长可能异常 | > 100K 词 → 截断/拆分 |
| 词符比 | 单词与符号的比例 | 符号占比 > 30% → 检查 |
| 重复行比例 | 模板页面特征 | 重复行 > 30% → 丢弃 |
| 困惑度 | 语言模型评分 | 困惑度过高 → 低质量 |
| 字符分布 | 异常字符分布 | 非预期字符多 → 检查 |

### 3.2 PDF 数据的清洗

CommonCrawl 里除了 HTML 还有 PDF（有时光看 URL 后缀无法预判，下载前不知道是不是 PDF），HuggingFace 为此发布了 FinePDF 数据集，其经验：

- **获取问题**：CC 里的很多 PDF 因文件过大被截断，需要重新抓取
- **扫描件即图片**：部分 PDF 只是扫描图像，需要视觉语言模型 OCR——成本远高于纯文本处理
- **质量更高但清洗更难**：愿意做成 PDF 的内容通常经过精心整理，平均质量高于普通网页；但 HTML 中 `<h1>` 等标签提供的语义结构在 PDF 里丢失，需要的清洗反而更多
- **占比小但价值高**：PDF 在整个互联网中占比很小，可接受较高的单份处理成本

### 3.3 代码数据的清洗（The Stack v2 经验）

- **二进制文件剔除**：仓库中的二进制不适合训练
- **恶意软件清理**：GitHub 上存在恶意代码
- **机器人内容过滤**：大量 PR 由机器人产生
- **PR 线性化**：issue/PR 事件流不是线性序列，需决定上下文窗口（改动行前后几行？整个文件？），最终序列化为类 XML 结构（PR 元数据 + diff + 评论 + 审查状态）——让模型学习的是整个软件开发流程而不只是代码本身
- **低资源语言增强**：把低资源语言编译成 LLVM IR 中间表示，用高资源语言的（语言，IR）对照数据教模型学映射

## 4. 清洗规则版本化

### 4.1 为什么版本化

清洗规则变更会改变数据分布，影响模型训练结果。必须：

- **可追溯**：任意训练实验能追溯到使用的清洗规则版本
- **可复现**：相同规则版本 + 相同数据 = 相同清洗结果
- **可对比**：对比不同清洗规则的效果

### 4.2 版本记录

```json
{
  "cleaning_version": "v2.1.0",
  "rules": [
    {"rule_id": "min_length", "params": {"min_words": 50}},
    {"rule_id": "pii_redact", "params": {"types": ["name", "phone", "email"]}},
    {"rule_id": "lang_filter", "params": {"allowed": ["zh", "en"]}}
  ],
  "input_dataset": "raw_v1.0",
  "output_dataset": "cleaned_v2.1.0",
  "timestamp": "2024-01-15T10:00:00Z"
}
```

### 4.3 处理原因保留

在样本级记录处理原因：

- **保留**：通过所有清洗规则
- **修改**：哪个字段被修改、修改原因
- **删除**：被哪条规则删除

避免"静默删除"——不记录原因地删除数据会导致分布不可解释。

## 5. 质量保证

### 5.1 清洗质量指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 清洗通过率 | 通过所有规则的数据比例 | 60-80% |
| 误删率 | 被错误删除的高质量数据比例 | ≤ 5% |
| 残留噪声率 | 清洗后仍含噪声的比例 | ≤ 2% |
| PII 残留率 | 清洗后仍含 PII 的比例 | ≤ 0.01% |
| 规则冲突率 | 规则间互相矛盾的比例 | 0% |

### 5.2 人工抽检

- **随机抽样**：从清洗结果中随机抽样人工审核
- **边界抽样**：重点抽检在阈值边界的数据
- **金标准对比**：与人工标注的金标准对比

## 7. 常见问题

- **过度清洗**：清洗规则过严导致有用数据被删除
- **规则不一致**：不同批次使用不同清洗规则
- **静默删除**：删除数据未记录原因
- **PII 残留**：脱敏不彻底
- **性能瓶颈**：单机清洗无法处理大规模数据
