# 程序归纳、综合与通用问题求解

## 一句话理解

程序归纳从示例或轨迹归纳可执行规则，程序综合从规范、约束或自然语言构造程序；通用问题求解把它们串成"问题表述→生成→执行→验证→修订"的闭环。

## 核心概念

| 概念 | 定义 | 区别 |
|---|---|---|
| 程序归纳 | 从输入-输出示例或轨迹中推断程序 | 数据驱动、无显式规范 |
| 程序综合 | 从规范/约束/自然语言构造满足性质的程序 | 规范驱动、可验证 |
| 通用问题求解 | 面向任意可形式化问题的搜索-规划-执行框架 | 抽象于具体领域 |

## 闭环范式

```text
问题表述 → 候选生成/搜索 → 执行或模拟 → 验证 → 诊断与修订
```

- 搜索需要控制资源（深度/宽度/时间预算）。
- 验证需要独立于生成器的证据（测试、证明、模拟）。
- 开放环境中还要处理工具不确定性、目标歧义及价值约束。

## 关键方法

| 方法 | 核心机制 | 代表工作 |
|---|---|---|
| 穷举/演绎搜索 | 按语法或规范搜索程序空间 | SyGuS、Sketch |
| 神经引导搜索 | 神经网络打分候选程序 | DeepCoder、DreamCoder |
| 库学习 + 组合 | 从任务群中学习可复用函数库 | DreamCoder |
| LLM 生成 + 验证 | LLM 生成候选，测试/验证器筛选 | AlphaCode、CodeRL |
| 自我改进闭环 | 生成-执行-反思循环改进策略 | 各类 coding agent |

### DreamCoder 的代表性

DreamCoder 是程序综合研究的重要代表：交替执行"求解任务"与"压缩所学程序为库"，实现**程序库的自动发现与复用**——这与开放式智能的技能积累（见 [[../../07_开放式智能/03_自主技能获取与终身发现]]）在机制上同构。

## 优势与局限

- **优势**：程序是可执行、可验证的知识；组合性与可迁移性强。
- **局限**：程序空间巨大导致搜索成本高；规范/示例不足时解不唯一；LLM 生成程序的验证覆盖率有限。
