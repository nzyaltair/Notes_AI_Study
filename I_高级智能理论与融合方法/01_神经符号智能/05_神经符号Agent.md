# 神经符号 Agent

## 一句话理解

神经符号 Agent 把语言理解与感知交给神经模块，把任务分解、状态表示、规划搜索、工具执行和约束检查交给显式结构，用可验证的中间表示提升长程任务的可靠性。

## 架构组成

| 组件 | 神经部分 | 符号部分 |
|---|---|---|
| 感知 | 视觉/语言理解 | 结构化状态提取（实体、关系） |
| 规划 | 高层意图识别 | 规划器（PDDL/HTN/搜索） |
| 执行 | 生成工具调用 | 工具接口、执行器 |
| 记忆 | 语义检索 | 带来源与版本的事实库 |
| 验证 | 结果解释 | 约束检查、计划验证 |

## 关键设计

- **可读的状态与计划表示**：中间状态必须可审查，支持失败诊断。
- **受限工具接口**：工具调用有类型与权限边界，防止未预期行为。
- **计划前后的仿真与验证**：执行前用世界模型模拟，执行后验证结果。
- **失败诊断**：将失败归因于感知、规划、执行或环境，而非笼统报错。
- **长期记忆的来源管理**：记忆条目携带来源、时间与置信度，避免错误累积。

## 与 LLM Agent 的关系

神经符号 Agent 与 D 板块的 Agent 工程互补：这里关注表示与推理机制（如何保证正确性），D 板块关注系统实现与运行治理（如何可靠部署）。LLM Agent 面临的长程错误累积与幻觉问题，正是符号组件的验证与约束试图缓解的。

## 优势与局限

- **优势**：长程任务中可验证、可诊断、可审计；知识可显式更新。
- **局限**：符号状态提取本身会出错（感知噪声）；规划搜索开销大；复杂开放任务的符号化建模困难。

## 前沿发展

- **LLM 编排 + 符号验证**：LLM 负责灵活决策，符号层负责正确性把关。
- **可证明安全行动**：在执行前用形式化方法验证行动计划不违反安全约束。
- **神经符号技能库**：把已验证的技能/程序沉淀为可复用库，支持组合（对应开放式智能的技能获取）。
