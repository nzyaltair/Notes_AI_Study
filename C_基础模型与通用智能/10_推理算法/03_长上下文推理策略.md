# 长上下文推理策略

## 一句话理解

长上下文推理策略解决大模型如何在推理阶段高效处理超长序列（2K → 1M+ token）的问题，核心手段包括位置编码外推、KV-Cache 管理、注意力计算优化和分布式处理。

## 概述

LLM 推理时，长上下文带来三大挑战：KV-Cache 显存随序列长度线性增长、注意力计算 $O(n^2)$ 复杂度、推理延迟随序列长度增加。长上下文推理策略从推理优化角度解决这些问题，与模型架构层面的长上下文机制（位置编码设计、记忆机制）互补。

本笔记聚焦推理算法层面的策略，NV-Cache 机制的系统实现详见 [[../09_模型压缩与高效推理/07_KV-Cache机制|C-09 KV-Cache 机制]]，架构层面的位置编码设计详见 [[../02_语言基础模型/03_大语言模型核心架构/07_长上下文与记忆机制|大语言模型核心架构：长上下文与记忆机制]]。

## 核心概念

### 上下文长度的瓶颈

| 瓶颈 | 原因 | 影响 |
|------|------|------|
| KV-Cache 显存 | 随序列长度线性增长 | batch=1 时 128K 上下文可能占用数十 GB |
| 注意力计算 | $O(n^2)$ 复杂度 | Prefill 阶段计算量急剧增长 |
| 位置编码外推 | 训练时未见过的位置 | 长度泛化能力下降 |
| 注意力稀释 | 长序列中注意力分散 | "Lost in the Middle" 问题 |

### 两层优化

- **架构层**：位置编码外推、注意力模式设计、记忆机制
- **推理层**：KV-Cache 管理、注意力计算优化、分布式处理

## 技术原理

### 位置编码外推

RoPE 是大模型最常用的位置编码，但在训练长度外推时性能下降。外推方法通过修改 RoPE 频率实现长度扩展。

**位置插值（Position Interpolation, PI）**：
将超出训练长度的位置缩放到训练范围内：
$$\theta'_i = \theta_i / s, \quad s = L_{\text{target}} / L_{\text{train}}$$
- 简单有效，扩展 4-8x
- 需少量长序列微调
- 所有频率统一缩放，高频信息损失

**NTK-aware**：
调整 RoPE 基频 $\theta$，对高频和低频差异化处理：
$$\theta' = \theta \cdot s^{d/(d-2)}$$
- 高频部分保持不变，低频部分进行插值
- 扩展 8-32x，无需微调即可保持质量

**YaRN**：
分频段插值 + 温度缩放：
1. 将 RoPE 频率分为多个波段
2. 高频波段保持原始，低频波段插值，中间波段平滑过渡
3. 对注意力分数施加温度缩放补偿
- 扩展 16-64x，LLaMA-2 等模型的标准外推方法

**LongRoPE**：
通过进化搜索寻找每个频率维度的最优缩放因子，支持 128x+ 扩展（2M 上下文）。

### KV-Cache 管理

| 技术 | 原理 | 效果 |
|------|------|------|
| PagedAttention | 分页管理 KV-Cache | 减少碎片，吞吐提升 2-4x |
| KV-Cache 压缩 | 淘汰不重要的 KV | StreamingLLM 支持无限长度 |
| KV-Cache 量化 | FP16 → INT8/INT4 | 显存减少 50-75% |
| KV-Cache 卸载 | 溢出到 CPU 内存/SSD | 突破 GPU 显存限制 |
| MLA | 压缩到潜在向量 | DeepSeek-V2 减少 93.3% |

### 缓存驱逐策略

- **StreamingLLM**：保留初始 token（Attention Sink）+ 最近 token 的 KV
- **H2O**：基于注意力分数动态淘汰不重要的 KV
- **滑动窗口**：只保留最近 $W$ 个 token 的 KV
- **SnapKV**：在 Prefill 阶段预筛选重要 token

### 注意力计算优化

| 方法 | 复杂度 | 原理 |
|------|--------|------|
| FlashAttention | $O(n^2)$ IO 优化 | 分块计算，减少 HBM 读写 |
| Sliding Window | $O(n \cdot w)$ | 仅关注局部窗口 $w$ |
| GQA/MQA | 减少 KV 头 | 共享 K/V 头组 |
| Ring Attention | 分布式 $O(n^2/k)$ | 序列分片到 $k$ 个 GPU |

### Chunked Prefill

将长 prompt 分块预填充，避免单步 OOM：
- 将长 prompt 分为大小为 $C$ 的块
- 逐块 Prefill，增量更新 KV-Cache
- 允许 Prefill 与 Decode 交错调度

## 关键方法对比

| 方法 | 扩展倍数 | 需微调 | 特点 |
|------|---------|--------|------|
| 位置插值（PI）| 4-8x | 是 | 简单统一缩放 |
| NTK-aware | 8-32x | 否 | 高低频差异化 |
| YaRN | 16-64x | 少量 | 分频段+温度缩放 |
| LongRoPE | 128x+ | 少量 | 进化搜索最优 |

## 优势与局限

**优势**：
- 使模型能处理超长文档和多轮对话
- 位置外推方法可大幅扩展训练长度
- KV-Cache 管理有效控制显存增长

**局限**：
- "Lost in the Middle"：长序列中间信息容易被忽略
- 外推质量随长度增加而下降
- 缓存驱逐可能丢失关键上下文
- 长上下文推理成本随长度增长

## 应用场景

- **长文档分析**：学术论文、法律文档、技术报告的全文理解
- **多轮对话**：保持长对话历史的上下文一致性
- **代码理解**：大型代码库的全局分析
- **RAG 增强**：将更多检索结果纳入上下文
- **Agent 长期记忆**：Agent 任务中的长程上下文保持
