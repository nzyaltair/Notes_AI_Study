# 安全评测与安全工程综述

## 领域定义

安全工程将安全要求转化为可重复的设计、测试、发布和运营过程。安全评测（Security/Safety Evaluation）以可量化的方式估计系统的风险水平。二者共同构成"安全证据链"——而非简单地宣称安全。

## 为什么会出现

传统软件测试主要验证功能正确性；AI 系统的安全测试面临三个独特挑战：
1. **行为空间无法穷举**：自然语言输入空间无限，不能靠单元测试覆盖
2. **危害难以形式化**："有害输出"的定义随文化、场景、能力变化而变化
3. **攻击者会持续适应**：固定评测集会被绕过，需要动态和对抗性测试

## 发展历史

| 阶段 | 重点 | 代表工作 |
|---|---|---|
| 能力评测 (2020–) | 知识、推理基准 | MMLU、HellaSwag、BIG-bench |
| 安全内容过滤评测 (2021–) | 有害/无害分类 | ToxiGen、RealToxicityPrompts |
| 对齐/安全综合评测 (2022–) | 真实性、有帮助性、无害性 | TruthfulQA、Anthropic HHH |
| 标准化越狱评测 (2023–) | 攻击成功率、防御比较 | AdvBench、HarmBench (2024) |
| 危险能力评估 (2023–) | CBRN、网络、欺骗等高危能力 | Anthropic/OpenAI系统卡评测 |
| Agent 行动安全评测 (2024–) | 工具调用、权限遵守、轨迹安全 | AgentBench、AgentHarm、MACHIAVELLI |

## 核心工作流

```text
需求与风险 → 安全设计 → 离线评测/红队 → 发布门禁 → 线上监控 → 复盘与回归测试
```

目标不是宣称"绝对安全"，而是以可审计证据说明已知风险被识别、缓解、监测并有明确责任人。

## 当前发展状态

- **自动红队**（GCG、PAIR、AutoDAN）使攻击自动化，大幅提高评测效率
- **评判器校准问题**突出：LLM-as-Judge 的偏见和不一致性成为影响评测可信度的主要问题
- **动态基准**（如持续更新的私有测试集）成为防止测试集污染的主要手段
- **危险能力评估**（Dangerous Capability Evaluations）进入主要实验室的发布流程
- **Safety Case 方法论**从航空核工业引入 AI，开始形成行业实践
