# DSH 子系统参考地图

## 一句话理解

子系统页面是 DSH 的精确 API、事件和类型参考；本页按学习和设计问题聚合入口，帮助先定位职责，再回到当前版本官方文档核验细节。

## 如何使用

本页不复制生成式类型声明、完整工具 Schema 或配置默认值。遇到具体接口时，优先打开 `D:\_Projects\deepseek-harness\docs\subsystems\<主题>.zh.md`，并以当前源码生成内容为准。

## 子系统分组导航

### 内核运行时

| 子系统 | 核心职责 |
|---|---|
| `core` | Agent、Agent Loop、消息、`AgentHandle` 与通用类型模式；`ContentBlock`、`CallId`、品牌化 Id 等基础类型 |
| `scope` | `ScopeKey`/`ScopedLayers`/`Scoped<T>`：作用域化注册和分发载体；两层扁平结构（全局 + 精确作用域） |
| `invariants` | `ctx.invariants`（`InvariantRegistry`）：运行时关系约束的可配置注册与执行；每个包 `./invariant` 配套插件 |

### 会话、存储与可观察性

| 子系统 | 核心职责 |
|---|---|
| `session` | 仅追加 `SessionEvent` 日志；`deriveMessages()` surface 投影；`turn/step` 轮次结构；`Session.append()` |
| `persistence` | `ctx.sessionPersistence` seam；JSONL / SQLite 后端；flush 检查点协议；崩溃恢复 + 合成 `interrupted`；`SessionHeader` |
| `session-projection` | `ConversationNode` 和客户端 surface 树投影；分叉/恢复/压缩后的展示一致性 |
| `session-query` | `ctx.sessionQuery`（SQLite）：按内容、时间、标签跨会话检索 |
| `session-reference` | 跨会话引用解析；`@session/<id>` 链接 |
| `session-title` | `ctx.sessionTitle` seam；LLM 自动命名；`session/title` + `session/title-llm-request` 事件 |
| `spill` | `ctx.spillStore` seam；工具超大文本外溢存储；`SpillLocator`（不透明句柄）；`SpillRef.retrievalHint` |
| `storage` | `ctx.storage` seam；非会话键值数据（设置、凭据）；JSON / SQLite 后端 |
| `attachment` | 二进制附件存储；与事件日志分离 |
| `session-telemetry` | `ctx.sessionTelemetry` seam；OpenTelemetry 遥测 |
| `feedback` | `feedback/record` 事件；`/feedback` 命令记录人工备注 |

### 模型与上下文

| 子系统 | 核心职责 |
|---|---|
| `llm-streaming` | `StreamChunk`、`AssistantMessage`、`TokenUsage`；流式协议约定；`LlmAdapter.stream()` ↔ `LlmRuntime.stream()` 规范化 |
| `system-prompt` | `ctx.systemPrompt`；Section 注册与优先级合并；`agent/pre-step` waterfall 期间组装 |
| `token-meter` | `ctx.tokenMeter`（`TokenMeter`）；上下文 token 计量与预算管理；压缩触发信号 |
| `compaction` | `ctx.compaction` seam；压缩锁（`compaction/start` ~ `compaction/end`）；`compaction/summary`（shadow-price 协议）；`CompactionResult.shadowedRange` |

### 执行与可替换能力

| 子系统 | 核心职责 |
|---|---|
| `tools` | 工具定义（`ToolDefinition`）；执行流水线（`tools/pre-execute` → `tools/execute` → `tools/post-execute`）；`ToolResultMessage`；`CallId` 配对 |
| `filesystem` | `ctx.fs` seam；文件读写、搜索、编辑；`dsh-fs-local` / `dsh-fs-sandbox` / `dsh-fs-e2b` 后端 |
| `shell` | `ctx.shell` seam；Bash/PowerShell 命令执行；`dsh-bash-local` / `dsh-bash-sandbox` / `dsh-pwsh-local` 后端 |
| `subprocess` | `ctx.subprocess` seam；底层进程管理；`dsh-subprocess-local` / `dsh-subprocess-e2b` 后端 |
| `terminal` | `ctx.terminals`（终端）；交互式伪终端会话；`dsh-terminal-bash` |
| `code-runtime` | `ctx.codeRuntime` seam；代码执行 worker-thread 引擎（Code Mode）；`dsh-code-runtime-worker` |
| `web` | `ctx.web` seam；网页搜索 + fetch；`dsh-web-search-exa` / `dsh-web-search-perplexity` / `dsh-web-search-deepseek` / `dsh-web-fetch-http` |
| `lsp` | `ctx.lsp` seam；语言服务器协议；代码导航（goto def、references、hover）；`dsh-lsp-local` |
| `skills` | `ctx.skills` seam；分层 Markdown 技能发现（rank 100-600）；shadowing；`SkillInvocationPolicy` |
| `subagent` | `ctx.subagents` seam；一次性 / 可继续子代理；Activation 状态机；收件箱 FIFO；`subagent/descriptor` 事件 |
| `workflow` | `ctx.workflowEngine` seam；worker-thread 脚本引擎；`WorkflowMeta`；`WorkflowError.fatal` 失败纪律 |
| `jobs` | `ctx.jobs` seam（`JobRegistry`）；后台长时间任务；`JobStart`/`JobHooks`/`JobSnapshot`；`maxConcurrentJobsPerOwner` |

| 子系统 | 核心职责 |
|---|---|

| `permission-presets` | `ctx.permissionPresets`；预设组合批量切换权限；`permission/preset` 事件 |
| `sandbox` | `ctx.sandbox` seam；Landlock / e2b 沙箱隔离；`sandbox/mode` 事件 |
| `plan` | `ctx.planMode`；计划模式（软引导 + 待选步骤）；`plan/mode` 事件 |
| `user-questions` | `ctx.userQuestions` seam；`ask_user` 工具的人工回答方 |
| `commands` | `ctx.commands`；斜杠命令解析 / 分发 / 取消；`command/run` ~ `command/done` 事件对 |
| `goal` | `ctx.goals`；会话内单个持久目标；4 阶段（active/paused/blocked/complete）；`goal/change` 事件 |
| `schedule` | `ctx.schedule`；时间触发计划；UTC 归一化；at-least-once 投递；`schedule/change` 事件 |
| `settings` | `ctx.settings` seam；用户可写设置；`settings-file` 后端 |
| `credentials` | `ctx.credentials` seam；API Key 引用；`credentials-local` 后端 |
| `workspace` | 工作区边界；`$DSH_WORKSPACE` 路径；`context_files` 提示词注入 |
| `web-server` | DSH web 应用服务器；`dsh-web-app` Bundle |
| `client-modules` | 客户端动态模块加载；UI 扩展接入 |
| `extensions` | 扩展点（Conversation Node、工具、命令）注册约定 |
| `typert` | TypeScript 运行时类型收窄工具；`Branded`、`Tagged` 等基础模式 |

## 事件生产方/消费方矩阵

`docs/event-producer-consumer.zh.md` 以矩阵形式列出 DSH 所有 harness 自有事件的派发方、监听方和分发模式，这是选择扩展点的首要参考。关键事件摘要：

| 事件 | 模式 | 为什么重要 |
|---|---|---|
| `session/event` | emit | 约 20 个监听方；所有模型可见事实的唯一播出点 |
| `agent/pre-step` | waterfall | 约 12 个监听方；控制哪些消息进入步骤、注入提示词区段 |
| `tools/pre-execute` / `execute` / `post-execute` | waterfall | 完整工具执行策略链 |
| `llm/stream` | waterfall | LLM 流式输出的拦截与回放点 |
| `workflow/*` | emit | 工作流生命周期只读观察；监听器异常被隔离 |
| `subagent/start` / `subagent/end` | emit | 子 agent 启动/结束通知，以 parent carrier 作用域过滤 |

完整矩阵见：`D:\_Projects\deepseek-harness\docs\event-producer-consumer.zh.md`
