# 数据标注

## 一句话理解

数据标注把原始样本转化为监督、偏好、检索或评测信号——标注模式涵盖分类/抽取、生成式、偏好式与 AI 辅助，质量体系需定义标注指南、金标准、双标一致率与返工流程，不把低一致性简单平均而要回溯任务定义是否含糊。

## 1. 概述

数据标注是将原始数据转化为模型可学习的监督信号的过程。在 LLM 时代，标注的对象从传统分类标签扩展到指令回复、推理轨迹、偏好排序和工具调用轨迹。

标注的核心挑战：

- **质量一致性**：不同标注者对同一数据的判断可能不同
- **规模与成本**：大规模标注的成本和时间
- **任务定义**：标注指南是否清晰、无歧义
- **标注者能力**：专业领域需要专家标注

## 2. 标注模式

### 2.1 分类/抽取标注

传统 ML 最常见的标注类型：

| 标注类型 | 说明 | 示例 |
|:---|:---|:---|
| 文本分类 | 给文本打类别标签 | 情感分类、主题分类 |
| 命名实体 | 标注实体的边界和类型 | 人名、地名、组织名 |
| 关系抽取 | 标注实体间关系 | "A 是 B 的创始人" |
| 边界框 | 图像中目标的位置 | 物体检测 |
| 分割 | 像素级标注 | 语义分割 |

### 2.2 生成式标注

LLM 时代最重要的标注类型：

| 标注类型 | 说明 | 示例 |
|:---|:---|:---|
| 参考答案 | 给问题写标准答案 | 问答对 |
| 推理步骤 | 标注 CoT 推理过程 | 数学解题步骤 |
| 工具调用轨迹 | 标注工具调用序列 | Agent 执行轨迹 |
| 对话回复 | 多轮对话的回复 | 客服对话 |
| 代码生成 | 给需求写代码 | 代码补全 |

### 2.3 偏好式标注

用于 RLHF/DPO 训练：

| 标注类型 | 说明 | 示例 |
|:---|:---|:---|
| 成对比较 | 比较两个回复的优劣 | 回复 A vs 回复 B |
| 排序 | 多个回复排序 | 3 个回复按质量排序 |
| 拒答标注 | 标注应拒答的场景 | 有害问题标注拒答 |
| 安全标签 | 标注安全性维度 | 有害/安全/边界 |

### 2.4 AI 辅助标注

利用 AI 提升标注效率：

```text
原始数据 → AI 预标注 → 人工复核 → 争议仲裁 → 最终标注
```

| 模式 | 说明 | 效率提升 |
|:---|:---|:---|
| AI 预标注 | AI 先标注，人工修正 | 3-5 倍 |
| 主动学习 | AI 选择信息量大的样本 | 2-3 倍 |
| 弱监督 | 规则自动标注 | 10-100 倍 |
| 标注蒸馏 | 强模型标注弱模型数据 | 5-10 倍 |

## 3. 标注质量体系

### 3.1 标注指南

标注指南是标注质量的基石，应包含：

- **任务定义**：标注目标的清晰描述
- **标注规则**：具体的标注规则和边界
- **示例**：正例、反例、边界 case
- **常见错误**：已知易错点
- **决策树**：遇到不确定情况的处理流程

> **原则**：如果两个标注者对同一数据标注不一致，首先要回溯指南是否含糊，而非简单取平均。

### 3.2 金标准集 (Golden Set)

- **构建**：由专家标注的高质量样本集
- **用途**：评估标注者准确率
- **隐藏**：混入普通标注任务中，标注者不知哪些是金标准
- **更新**：定期审查和更新

### 3.3 一致性评估

| 指标 | 说明 | 计算 |
|:---|:---|:---|
| Cohen's Kappa | 两个标注者的一致性 | (Po-Pe)/(1-Pe) |
| Fleiss' Kappa | 多个标注者的一致性 | 扩展的 Kappa |
| 一致率 | 简单的一致比例 | 一致数/总数 |
| 双标一致率 | 两人独立标注的一致率 | 用于质量门控 |

**Cohen's Kappa 解读**：

| κ 值 | 一致性程度 |
|:---|:---|
| < 0.20 | 极差 |
| 0.21-0.40 | 一般 |
| 0.41-0.60 | 中等 |
| 0.61-0.80 | 良好 |
| 0.81-1.00 | 优秀 |

### 3.4 质量控制流程

```text
标注者培训 → 试标 → 金标准检查 → 正式标注
                ↓                      ↓
            通过 → 上岗          双标一致性检查
            不通过 → 再培训           ↓
                              一致性高 → 接受
                              一致性低 → 仲裁 + 返工
```

### 3.5 返工流程

- **自动检测**：低一致性自动触发返工
- **仲裁机制**：不一致样本由专家仲裁
- **反馈闭环**：返工原因反馈给标注者
- **淘汰机制**：多次返工的标注者淘汰

## 4. 标注元数据

每条标注记录应包含：

| 字段 | 说明 |
|:---|:---|
| annotator_id | 标注者 ID |
| task_version | 标注任务版本（指南版本） |
| model_assist_version | AI 辅助模型版本（如有） |
| confidence | 标注者自评置信度 |
| timestamp | 标注时间 |
| duration | 标注耗时 |
| review_status | 审核状态 |

## 5. 弱监督

用程序化规则替代人工标注：

### 5.1 Snorkel 框架

```text
标注函数 (Labeling Functions)
├── 规则1: 含"愤怒" → 负面
├── 规则2: 含"满意" → 正面
├── 规则3: 评分 > 4 → 正面
└── 规则4: 评分 < 2 → 负面
    ↓
模型去噪 → 融合多规则 → 最终标签
```

- **标注函数**：编写启发式规则作为标注函数
- **去噪模型**：学习标注函数的准确率和相关性
- **适用场景**：大规模、低精度要求的标注

### 5.2 远程监督

利用知识库自动标注：

- **方法**：用知识库中的事实匹配文本，自动生成标签
- **优点**：大规模、无需人工
- **局限**：噪声高、覆盖受限

## 6. 成本与效率

### 6.1 标注成本对比

| 标注模式 | 单条成本 | 质量 | 规模 |
|:---|:---|:---|:---|
| 专家标注 | $5-50 | 最高 | 小 |
| 众包标注 | $0.1-5 | 中 | 大 |
| AI 辅助 | $0.01-0.5 | 中高 | 大 |
| 弱监督 | $0.001-0.01 | 中低 | 极大 |
| 合成数据 | $0.001-0.01 | 中 | 极大 |

### 6.2 标注策略选择

```text
数据量需求 vs 质量需求:
├── 高质量 + 小规模 → 专家标注
├── 中质量 + 中规模 → AI 辅助 + 人工复核
├── 低质量 + 大规模 → 弱监督 / 合成数据
└── 高质量 + 大规模 → AI 预标注 + 专家复核（高成本）
```

## 8. 常见问题

- **指南模糊**：标注者对规则理解不同导致低一致性
- **标注者偏差**：个别标注者系统性偏向某类标签
- **疲劳效应**：长时间标注导致质量下降
- **领域知识不足**：非专家标注者无法处理专业领域
- **AI 辅助依赖**：过度依赖 AI 预标注，人工复核流于形式
