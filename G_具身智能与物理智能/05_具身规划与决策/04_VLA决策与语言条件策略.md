# VLA 决策与语言条件策略

## 一句话理解

VLA 将视觉、语言、本体状态和动作历史映射为动作 token 或连续动作，适合开放指令和多任务语义泛化；但语言理解不保证物理精度，部署必须走"提议 → 验证 → 执行 → 核验"闭环。

## 概述

语言条件策略（Language-Conditioned Policy）让机器人理解自然语言指令并执行对应动作。VLA（Vision-Language-Action）把这一思想推至基础模型规模：用大规模数据预训练统一表征，微调后实现开放指令的多任务泛化。VLA 是具身决策的前沿方向，但其精度、时延和安全边界决定了它必须与经典验证层协作。

## 发展历史

- **2018-2021**：语言条件模仿（LCBC）、SayCan（2022）把 LLM 与技能库结合——LLM 提供任务可行性排序。
- **2022**：RT-1 用 Transformer 统一视觉-语言-动作 token。
- **2023**：RT-2 将视觉语言模型微调为动作模型（Web 知识迁移）；PaLM-E 将多模态 LLM 与具身观测结合。
- **2024**：OpenVLA 开源 VLA 训练/微调基线；π（pi-zero）用流匹配生成连续动作；GR-1、HumanPlus 等人形 VLA 出现。
- **2025-**：VLA 与扩散策略、世界模型融合；大规模真机评测与跨本体 VLA 成为焦点。

## 核心概念

| 概念 | 定义 | 关键点 |
|---|---|---|
| 语言条件策略 | \(\pi(a\mid o, g)\) 指令条件化 | 指令落地 |
| 动作 token | 离散化动作序列 | RT 系列 |
| 连续动作生成 | 流匹配/扩散生成 | π 系列 |
| 视觉语言迁移 | VLM 知识迁移到动作 | RT-2 |
| 落地验证 | 语言→坐标→约束检查 | 精度保障 |
| 跨本体 VLA | 多平台共享策略 | 动作接口统一 |

## 技术原理

### 三条代表性路线

| 路线 | 核心思想 | 代表 | 特点 |
|---|---|---|---|
| 离散动作 token | 动作离散化为 token 与语言联合建模 | RT-1, RT-2 | 可复用 VLM 结构 |
| 开源微调基线 | 公开 VLA + 微调框架 | OpenVLA | 可复现、可扩展 |
| 生成式动作建模 | 流匹配/扩散生成连续动作 | π0, π0.5 | 高精度、多模态 |

### RT-2 的 Web 知识迁移

RT-2 从视觉语言模型（PaLI-X, PaLM-E）微调：输入图像+文本指令，输出动作 token。关键价值：VLM 预训练的语义知识（对象识别、常识）可迁移到动作预测。局限：语义泛化不等于可靠接触和精确几何。

### π（pi-zero）的流匹配

π0 用流匹配（Flow Matching）生成动作：把动作生成建模为从噪声到动作轨迹的连续变换，支持多模态动作分布，精度高于离散 token。π0.5 引入分块自回归，实现长时域动作生成。

### 落地闭环

VLA 的部署闭环：

```text
VLA 提议目标或短动作块
→ 运动学与约束验证（IK、碰撞、限幅）
→ 控制执行
→ 视觉/触觉核验
→ 失败则重规划
```

VLA 输出需要以短时域闭环执行，并经过运动学、控制和安全层验证。动作 token 不自带坐标语义，开放词汇不能替代碰撞/力限制。

## 关键方法与模型

| 模型 | 年份 | 核心贡献 | 边界 |
|---|---|---|---|
| SayCan | 2022 | LLM 技能选择 + 可供性 | 技能库依赖 |
| RT-1 | 2022 | 动作 token Transformer | 数据规模 |
| RT-2 | 2023 | Web 知识迁移 | 精度、安全 |
| PaLM-E | 2023 | 多模态 LLM 具身化 | 推理与控制的鸿沟 |
| OpenVLA | 2024 | 开源 VLA 基线 | 需任务数据适配 |
| π0 | 2024 | 流匹配连续动作 | 推理成本 |
| GR-1 | 2024 | 人形 VLA | 本体适配 |

## 优势与局限

| 方面 | 优势 | 局限 |
|---|---|---|
| 语义泛化 | 开放指令、常识 | 精度不足 |
| 多任务 | 共享表征 | 任务间冲突 |
| 数据利用 | 大规模预训练 | 数据标准统一难 |
| 可微调 | 参数高效适配 | 微调数据需求 |
| 端到端 | 免手工中间层 | 安全验证缺失 |

## 应用场景

- 家居任务：自然语言指令操作。
- 多任务操作：一套模型多技能。
- 人形操作：语言条件全身操作。
- 交互式任务：人类语言指令持续调整。

## 常见问题

- **把语言理解当物理能力**：理解指令 ≠ 精确执行。
- **忽略坐标语义**：动作 token 不自带坐标系。
- **跳过验证层**：开放词汇不能替代碰撞/力限制。
- **用演示视频评测**：需覆盖新物体、布局、指令组合、跨相机/本体、时延与安全。
