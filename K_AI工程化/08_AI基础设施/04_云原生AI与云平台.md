# 云原生 AI 与云平台

## 一句话理解

云原生 AI 用容器化、基础设施即代码、服务网格和声明式 API 构建可弹性伸缩的 AI 平台；云平台（AWS/GCP/Azure）降低了运维门槛，但需在成本、供应商锁定、数据合规和网络延迟之间权衡，混合云和多云策略正成为大规模 AI 部署的主流选择。

## 1. 云原生 AI 核心概念

### 1.1 云原生原则在 AI 中的映射

| 云原生原则 | AI 场景映射 | 实践 |
|:---|:---|:---|
| **容器化** | 训练/推理环境一致性 | Docker + CUDA 镜像 |
| **声明式 API** | 作业/服务声明 | K8s Job/Deployment + CRD |
| **不可变基础设施** | 环境可重建 | 镜像版本化 + IaC |
| **微服务** | 模型服务独立部署 | 每模型独立 K8s Service |
| **弹性伸缩** | 推理按需扩缩 | HPA + KEDA |
| **配置外部化** | 模型路径/参数配置 | ConfigMap + Secret |
| **可观测性** | 训练/推理监控 | Prometheus + Grafana |
| **GitOps** | 模型/配置版本管理 | ArgoCD + MLflow |

```yaml
  name: llm-training
spec:
  pytorchReplicaSpecs:
    Master:
      replicas: 1
      template:
        spec:
          containers:
          - name: pytorch
            image: nvcr.io/nvidia/pytorch:23.10-py3
            command: ["python", "train.py"]
            resources:
              limits:
                nvidia.com/gpu: 8

            - name: data
              mountPath: /data
            - name: checkpoint
              mountPath: /checkpoint
```

### 3.2 云平台选型决策

```text
云平台选型决策矩阵：

因素              权重    AWS    GCP    Azure    自建
─────────────────────────────────────────────────────
GPU 供应稳定性     高      ★★★    ★★★    ★★★     ★★★★
TPU 支持          中      ✗      ✓      ✗       ✗
成本（大规模）     高      ★★     ★★★    ★★      ★★★★
数据合规          高      ★★★    ★★★    ★★★     ★★★★★
网络性能          高      ★★★    ★★★    ★★★     ★★★★★
运维复杂度        高      ★★★★   ★★★★   ★★★★    ★★
供应商锁定风险     中      ★★     ★★     ★★      ★★★★★
弹性伸缩          高      ★★★★   ★★★★   ★★★★    ★★★
─────────────────────────────────────────────────────

决策建议：
├── 快速验证/原型 → 云平台托管服务
├── 大规模专有训练 → 自建集群 + 云 GPU 补充
├── 推理服务 → 云平台 + Spot Instance
├── 数据敏感 → 自建/混合云
└── TPU 生态 → GCP
```

### 3.3 成本模型

```text
云 GPU 成本对比（按需价格，美元/小时）：

GPU 型号       AWS      GCP      Azure     自建(摊销)
────────────────────────────────────────────────────
A100 80GB     $3.40    $3.67    $3.40     ~$1.50

L40S          $1.80    $2.00    $1.80     ~$0.80

成本优化策略：
├── Spot Instance（节省 60-70%）
│   ├── 适合：可中断训练/推理
│   ├── 风险：实例回收
│   └── 需配合弹性训练/checkpoint
│
├── 预留实例（节省 30-50%）
```

## 4. Serverless AI

### 4.1 Serverless 推理

```text
Serverless AI 推理特点：

优势：
├── 按请求付费（无空闲成本）
├── 自动伸缩到零
├── 无需管理基础设施
└── 快速部署

挑战：
├── 冷启动延迟（模型加载慢）
├── GPU 资源不连续
├── 请求超时限制
└── 成本可能高于持续负载

适用场景：
├── 低流量推理服务
├── 开发/测试环境
├── 突发流量场景
└── 多模型轮换服务

冷启动优化：
├── 模型权重预热（缓存到本地）
├── 镜像优化（分层 + 精简）
├── 预留并发（keep-alive）
├── 渐进式加载（先加载部分层）
└── 模型量化（减少加载量）
```

### 4.2 Serverless 训练

| 平台 | 特点 | 适用场景 |
|:---|:---|:---|
| **SageMaker Training Job** | 托管训练，按作业计费 | 中小规模训练 |
| **Vertex AI Training** | GCP 托管训练，TPU 支持 | TPU 训练 |
| **Azure ML Compute** | 按需计算集群 | 企业训练 |
| **Modal/Replicate** | Serverless GPU 函数 | 实验性训练 |
| **Lambda Labs** | 低成本 GPU 租用 | 长时间训练 |

## 5. 混合云与多云

### 5.1 混合云架构

```text
AI 混合云架构模式：

模式 1：训练在自建，推理在云
├── 自建集群：大规模训练（成本可控）
├── 云平台：推理服务（弹性伸缩）
└── 模型通过对象存储传输

模式 2：核心数据在私有云，计算在公有云
├── 私有云：数据存储/预处理
├── 公有云：GPU 计算（训练/推理）
└── 专线连接（Direct Connect / Cloud Interconnect）

模式 3：多云负载均衡
├── 跨云推理服务部署
├── 按地区/成本路由请求
├── 故障切换到备用云
└── 统一监控和管理

模式 4：云突发（Cloud Bursting）
├── 基线负载在自建集群
├── 高峰时溢出到云 GPU
├── 低谷时回收到自建
└── 需要统一的容器化和调度
```

### 5.2 多云管理挑战

| 挑战 | 说明 | 应对策略 |
|:---|:---|:---|
| **环境一致性** | 不同云的 GPU/CUDA 差异 | 统一容器镜像 |
| **数据迁移** | 跨云数据传输慢且贵 | 数据本地化 + 模型传输 |
| **网络延迟** | 跨云通信延迟高 | 避免跨云分布式训练 |
| **安全合规** | 不同云的安全模型 | 统一身份/密钥管理 |
| **成本追踪** | 跨云成本难以汇总 | 统一成本分析平台 |
| **监控统一** | 不同云的监控接口不同 | 统一可观测性平台 |
