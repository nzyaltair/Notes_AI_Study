# 插件开发与调试

## 一句话理解

DSH 插件是导出 `apply(ctx)` 的 TypeScript 模块；开发时通过局部 Patch 挂载，调试重点是依赖、Fiber 生命周期与卸载后的资源清理，而不是只看首次加载成功。

## 开发流程

1. 先确认新行为归属：Tool、服务、事件监听、会话事件还是客户端投影。
2. 以最小插件连接已有服务，声明 `name`、必要的 `inject` 和 `apply`。
3. 用局部 `cordis.yml` / patch 挂载至 Web 或 headless Profile。
4. 观察实际配置、Fiber 状态和会话事件，再补专项测试。

## 调试清单

- `inject` 是否与实际服务键一致？
- 配置 schema 是否拒绝了错误输入？
- 插件卸载后注册是否撤销，计时器和连接是否停止？
- 若改变模型上下文，是否已追加可重放的 SessionEvent？
- 若是策略钩子，是否选对 waterfall、guard 或仅观察事件？

## 常见插件形态

### 工具插件

在 `ctx.tools` 上注册。`defineTool` 提供类型化的 `execute` 参数；`ctx.tools.register()` 也直接接受原始 JSON Schema `ToolDefinition`（MCP 来源的工具就是如此到达的）。

### 钩子插件（策略门禁示例）

```ts
export const name = 'permission-gate'

export function apply(ctx: Context) {
  ctx.on('tools/pre-execute', async (exec, next): Promise<PreToolDecision> => {
    if (!(await isAllowed(exec))) {
      return { kind: 'deny', reason: 'Denied by policy.' }
    }
    return next()
  })
}
```

`tools/pre-execute` 是可重排的策略层；不变式需要单调最终拒绝时使用 `ctx.tools.guard()`。

### UI 插件

从 `session/event` 流渲染（`assistant/chunk` 是助手 token 流，加上 turn/step 边界与工具活动），通过 `agent.followup()` / `agent.steer()` 将输入驱动回去。向内建 Web Client 贡献业务行时，注册 `ConversationNodeDefinition` 与 keyed renderer。

### 外部协议驱动（协议桥接）

stdio 驱动创建/恢复 agent，将协议请求映射为 `followup()` 或 `cancel()`。底层提示词请求只返回持久入队回执，不保证结果与该 followup 直接对应；整个 agent 的状态需单独发布。通过 `AgentHandle.dispose()` 拆除 agent（stop + await exit 达到完全停稳）。

## API Gateway 与 Remote 方法

当 Host 侧的 Cordis 服务需要被浏览器 Client 调用时，使用 **Typert API Gateway**。

### 编程模型

业务服务用 `@Remote` 或 `@RemoteScope` 标注方法，使其对 Client 可见：

```ts
import { TypertRemoteService, Remote, RemoteScope } from '@deepseek-ai/dsh-typert-protocol'

export class GoalService extends TypertRemoteService {
  constructor(ctx: Context) {
    super(ctx, 'goals')
  }

  @Remote('create')
  createForClient(agent: Agent, request: CreateGoalRequest, signal: AbortSignal): CreateGoalResult {
    return this.create(agent, request)
  }

  @RemoteScope('agent', 'current')
  currentForClient(): CreateGoalResult {
    return { accepted: true }
  }
}
```

- `@Remote`：调用根 Host Context 中注册的服务；复杂 Host 对象通过 `TypertLookupMap` 声明与 wire identity 的关联（如 `agent` → `agentId`），Gateway 在调用前解析；
- `@RemoteScope(key)`：先解析 identity 为作用域 Context，再从该 Context 取服务调用方法；
- `signal: AbortSignal`：最后一个参数，记录在描述符中，不进入 `args`，Client 生成的方法接受最后一个可选 `AbortSignal`。

### Host/Client 双侧生成流水线

| 阶段 | 工具 | 产物 |
|---|---|---|
| Host lib | `tsc -b tsconfig.host.json` + `tsdown --env.DSH_BUILD_FACE host` | `lib/typert.host.js`、`lib/typert.host.d.ts` |
| Client lib | `tsc -b tsconfig.client.json` + `tsdown --env.DSH_BUILD_FACE client` | `lib/typert.remote-client.js`、`lib/typert.remote-client.d.ts` |

- 生成器（`dsh-typert-generator`）在 Host tsdown 阶段以 Host aggregate 为种子运行，Client tsdown 不再次启动 Typert；
- Client 应用只装配 `@deepseek-ai/dsh-api-remotes`，通过 `ctx.remote.$mount()` 挂载贡献；
- 直接调用：`ctx.remote.goals.create(agentId, { objective: '...' })`；作用域调用：`agentCtx.remote.goals.create({ objective: '...' })`。

### SRC 开发回退

Host 通过 `node --import tsx/esm` 从源码启动时不执行 Typert 编译插件。Gateway 从运行中函数解析简单参数名，构造较弱的临时描述符，不生成 Zod schema。SRC 只解决 Host 源码进程的分发，Client 不从运行中 Host 发现 decorator，Client Remote 类型始终来自最近一次生成的 `lib/typert.remote-client.*`。

修改 Remote 方法实现体（不改约定）无需重新生成；新增/删除 decorator、修改参数、返回值或 lookup 时须重新执行：

```sh
pnpm run build:lib
```

### Remote 的边界

Remote 只处理有单个请求与单个结果的一元方法调用。会话事件流、分页、增量 reduce、projection 不适合伪装成 Remote 方法——它们复用 Connection 但使用独立的数据协议和注册模型。
