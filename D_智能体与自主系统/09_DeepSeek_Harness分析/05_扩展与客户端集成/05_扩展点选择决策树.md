# 扩展点选择决策树

## 一句话理解

扩展 DSH 的第一步不是写代码，而是确定新行为属于模型动作、可替换后端、持久事实、UI 呈现还是运行策略，并接入其已有扩展点。

## 决策表

| 目标 | 首选机制 |
|---|---|
| 给模型一个新动作 | `ctx.tools.register()` |
| 更换底层执行环境 | Capability Seam 的 Provider |
| 新事实须跨刷新/恢复存在 | `SessionEventMap` + 投影 + 持久化 |
| 只改变聊天界面 | Conversation Node / 客户端投影 |
| 增加审批、超时、重试或指标 | `tools/*`、`agent/*` 或能力事件 |
| 人类触发但不进入模型上下文 | `ctx.commands` |
| 安装一套产品能力 | Package + Bundle + Profile |
| 给会话定制可见工具/提示词 | Agent scope 与 `agent.ctx` |
| Host 服务对 Client 开放 | `@Remote` / `@RemoteScope` + Typert API Gateway |

## 完整功能→机制映射表

以下映射来自 `docs/cookbook/extension-cookbook.zh.md`，覆盖主要产品功能的实现入口。

| 产品功能 | 插件机制 |
|---|---|
| **钩子系统**（用户级 + 项目级） | `agent/session-start`、`agent/pre-step`、`agent/request`、`tools/pre-execute`、`tools/post-execute`、`agent/turn-stopping` 上的监听器；waterfall 返回类型化决策；`dsh-hooks-claude-code`/`dsh-hooks-codex` 将钩子配置映射到这些扩展点 |
| **`/goal`** | `ctx.goals` 管理持久状态；`dsh-goal-round-driver` 通过公共 `Agent` 调度同会话 Round；独立的命令/工具提供人类/模型控制 |
| **`/loop`（强制续跑）** | 在 `turn/end` 会话事件上 `followup()` 下一次迭代 |
| **动态工作流** | `ctx.workflowEngine` + worker-thread 引擎 + `workflow` 工具；结构化进程内子任务通过作用域化提示词/工具注册、单调工具守卫、`concludeTurn()` 强制输出 |
| **消息排队 + steering** | 核心 `Agent.followup()` / `Agent.steer()` |
| **上下文压缩（自动 + 手动）** | `ctx.compaction` seam + `dsh-compaction-basic`；自动压力检查在 `agent/pre-step`，溢出恢复在 `agent/request-error`，手动调用方使用同一压缩服务 |
| **系统提示词可配置性** | `ctx.systemPrompt.section()`，支持排序与 scope 局部覆盖 |
| **`AGENTS.md`（根目录）** | 一个读取该文件的 section 提供方 |
| **`AGENTS.md`（子目录，按需触发）** | 从 watcher/工具结果监听器调用 `agent.inject()` |
| **内置工具** | `ctx.tools.register()`；schema 自动流入装配 |
| **ToolSearch / 渐进式披露** | 当可见集变化时替换作用域化的 `ctx.tools.restrict()` 注册；注册表保持展示/查找/执行三者对齐 |
| **工具截止时间 / 重试 / 指标** | `tools/execute` 包裹核心分发；包装层可替换 `exec.signal`、委托执行并检视规范化结果 |
| **最终工具结果审计/捕获** | `tools/result` 观察不可变的权威结果；结果变换用 `tools/post-execute` |
| **单调终端轮次策略** | 从成功的终端工具调用 `ToolExecution.concludeTurn()`；同一响应中后续工具调用仍可由 guard 阻止 |
| **子进程沙箱（landlock/sandbox-exec）** | 通过 `dsh-bash-sandbox` 使用 `ctx.sandbox` 后端；能力级别的拒绝用 `tools/pre-execute` |
| **权限系统 / AskUserQuestion** | `tools/pre-execute` 返回 `ask` 并通过 `ctx.approval` 应答；普通用户提问注册独立的面向模型 ask 工具 |
| **Plan mode** | `@deepseek-ai/dsh-plan-mode`：落日志的 `plan/mode` 状态、`plan:policy` 引导段、`/plan` 命令入口；强制约束留在沙箱/审批轴 |
| **subagent 委派** | `ctx.subagents` 提供方注册表（spawn/fork/acp/codex/claude-code/dsh-sdk）+ `dsh-tool-subagent` 向模型暴露已配置的提供方 |
| **MCP** | 每个服务器一个插件：发现工具 → `ctx.tools.register()` |
| **skill（技能）** | section + 工具注册；调用时通过 `inject()` 注入 skill 内容 |
| **记忆** | section 提供方 + 工具 |
| **定时任务（cron）** | 插件注册面向模型的调度工具；定时器触发 → 空闲时 `followup()` / 忙碌时 `inject()` 通知 |
| **UI（GUI / CLI 输出 JSONL）** | 监听 `session/event`（助手分片、边界、工具活动）；输入 → `followup()` |
| **Web Client Chat 业务节点** | 注册 `ConversationNodeDefinition` 与 `conversation.chat.node` keyed renderer |
| **遥测 / 可回放 trace** | `session/event` → JSONL；回放 = `sessions.create(id, { seed })` |
| **模型适配器** | 通过 `registerAdapter` 注册 `LlmAdapter` 子类 |
| **插件热重载** | 每个注册都是 `ctx.effect` → 随 HMR 直接生效 |

## 反模式

- 为临时策略修改 Agent Loop。
- 将持久领域事实只放在 React 状态或模块变量。
- 让 Tool 直接依赖某个具体 Provider，失去替换能力。
- 用文件名或插件加载顺序表达隐式依赖，而不声明 `inject`。
- 用 `system-prompt/assemble` 局部改写而不保留 Code Mode 和结构化输出协议的贡献（需要整体替换时必须保留活跃贡献）。
