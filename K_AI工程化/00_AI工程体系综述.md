# AI 工程体系综述：从研究模型到可信智能系统

## 一句话理解

AI Engineering 是把模型、数据、算力和软件系统组织为可交付、可观测、可迭代的智能产品的工程学科。它不止解决“模型能否运行”，还要保证系统在真实用户、真实负载与真实风险下持续创造价值。

## 1. 工程对象与边界

现代 AI 应用可抽象为：

```text
AI Application = Model + Data + Memory + Tools + Workflow + Evaluation + Operations
```

- **模型**：基础模型、专用模型、嵌入模型和路由模型。
- **数据**：训练、检索、反馈、评测和审计数据。
- **记忆与工具**：上下文、向量库、外部 API、执行环境。
- **工作流**：RAG、Agent、人工审核与业务编排。
- **评测与运维**：质量门禁、观测、成本、安全、可靠性治理。

本章节侧重上述能力的工程实现；模型原理、Agent 行为理论和安全价值判断分别由相应理论章节展开。

## 2. AI 系统生命周期

```mermaid
graph LR
  A[数据产生与治理] --> B[训练与实验]
  B --> C[离线评测与注册]
  C --> D[推理部署与应用编排]
  D --> E[在线观测与用户反馈]
  E --> F[错误分析与评测]
  F --> A
  F --> B
```

闭环中的每次变更都应可追溯：使用什么数据、代码和配置训练了哪个模型；该模型经历了哪些评测；由哪个服务版本向哪些用户提供能力；产生了哪些质量、成本和安全信号。

## 4. Research → Production

1. **研究验证**：定义任务、数据边界、基线及成功指标。
2. **实验与训练**：记录代码、数据、参数、环境、权重和评测结果。
3. **发布门禁**：通过能力、安全、鲁棒性、成本和兼容性检查后注册候选版本。
4. **部署运行**：经由网关、灰度、回滚和资源调度进入生产环境。
5. **持续改进**：把 trace、用户反馈、失败样本和漂移信号转化为评测集与训练数据。

## 5. 角色体系

| 角色 | 主要职责 |
|---|---|
| 数据工程师 | 数据管道、质量、治理与反馈闭环 |
| ML/训练工程师 | 分布式训练、实验、模型优化与注册 |
| 推理工程师 | Serving、性能、容量和硬件适配 |
| AI 应用工程师 | RAG、Agent、工具和业务工作流 |
| MLOps/LLMOps 工程师 | 发布、观测、网关、提示与追踪治理 |
| 平台/SRE 工程师 | 集群、资源、SLO、事件响应和恢复 |
| 评测与安全工程师 | 基准、红队、在线质量和风险门禁 |

## 6. 发展历史

| 时间 | 里程碑 | 意义 |
|:---|:---|:---|
| 2010s 中期 | Netflix/Uber 数据管道成熟 | 大规模 ML 数据工程实践形成 |
| 2015 | *Hidden Technical Debt in ML Systems* | 首次系统化描述 ML 工程债务 |
| 2017 | Argo Workflows / Kubeflow | Kubernetes 原生 ML 工作流 |
| 2018 | MLflow 发布 | 实验追踪与模型注册标准化 |
| 2019 | ZeRO (DeepSpeed) | 大模型训练工程的分水岭 |
| 2020 | GPT-3 API 发布 | LLM 进入工程化部署阶段 |
| 2021 | vLLM / PagedAttention | LLM 推理工程的革命性优化 |
| 2022 | ChatGPT 爆发 | LLMOps 需求激增，Prompt 管理成为独立实践 |
| 2023 | Agent 框架成熟 | AgentOps 成为独立工程方向 |
| 2023 | LLM Eval 体系化 | LLM Judge、Chatbot Arena 等评测范式建立 |
| 2024 | AI 基础设施专业化 | GPU 调度、通信库、编译器栈深度优化 |
| 2025 | AI 工程全栈成熟 | 从数据到部署的完整工程体系逐步规范化 |

## 7. 学习导航

按"供给—生产—交付—运营—优化"的顺序学习：数据工程 → 训练工程 → 推理工程 → 系统架构 → MLOps/LLMOps → 评测 → 基础设施与可靠性。
