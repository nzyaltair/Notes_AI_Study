# 模态编码器与 Token 化

## 一句话理解

多模态系统必须把连续、异步且长度不同的信号压缩成 token 或潜在状态；这一选择直接决定信息损失、上下文成本和对齐上限。

## Token 作为语义信息单元（CS336 视角）

Transformer 本质上是 token 处理器：输入一组 token，输出若干 token。将 token 概念扩展到多模态时的核心约束是——**token 必须代表某种语义信息单元**：

- 自然语言中 token 是子词，本身具有一定意义
- 单个像素单独来看没有意义，不能直接当作 token
- 因此非文本模态需要转化为**离散 token**（如 VQ-VAE 码字）或**连续 token**（如 patch 嵌入向量），后者可视为 token 的嵌入形式

| 模态 | 常见单元 | 关键取舍 |
|---|---|---|
| 文本 | 子词 token（BPE） | 词表覆盖与长度 |
| 图像 | patch/视觉 latent | 分辨率与小目标 |
| 图像（离散） | VQ-VAE 码字 | 信息损失 vs 可自回归生成 |
| 音频 | 频谱 patch/codec token | 韵律、音色和延迟 |
| 视频 | 时空 patch/压缩 latent | 帧率与长序列成本 |
| 动作 | 连续动作块/离散 token | 精度、坐标系和安全 |

过度压缩会让后续 LLM 无法读取关键证据；全部保留又造成注意力不可承受。设计需处理模态缺失、时间同步和配对噪声。

## ViT：图像 → patch 序列

**处理流程**：图像切分为固定大小 patch → 线性投影为向量（每个 patch 即一个 token）→ 加位置嵌入 → 输入标准 Transformer。

| 设计点 | 选择与证据 |
|---|---|
| patch 大小 | 原始 ViT 用 16×16；CLIP 用 14×14（ViT-L/14，约 24 层，RGB 三通道） |
| 位置嵌入 | 线性 1D 编码即可；CLIP 试过 1D vs 2D 位置嵌入，分类任务上**差异不显著**（更考虑空间结构的方法见 M-RoPE，[[04_视觉语言模型]]） |
| 序列表示 | 分类用序列首 token（CLS）；或全局平均池化；或注意力池化（查询向量对 K/V 做一轮注意力，比直接平均包含更多信息） |
| 分辨率预处理 | 网络图像长宽比随意 → 启发式处理：短边缩放至 224/336 后中心裁剪成方形（目标通常居中） |
| 分辨率调度 | CLIP 先用低分辨率训练再 upscale 到高分辨率（如 336×336）——纯为提速，高分辨率耗时 |

**动态尺寸问题**：神经网络偏好固定大小输入；高分辨率/任意长宽比图像的系统性解法（切块编码再拼接、动态分辨率）详见 [[04_视觉语言模型]] 中 LLaVA-OneVision 与 Qwen2-VL 的做法。

## VQ-VAE：图像 → 离散 token

源自 van den Oord et al. (2017)，是"让自回归 Transformer 生成图像"的经典路径（离散化 token 化的代表）：

1. 编码器把图像（块）映射为连续向量
2. 将向量**舍入到最近的码字**（codebook，如 8000 个码字）
3. 解码器从码字重建图像
4. 训练目标：最小化重建损失（量化步骤不可微，需附加技巧）

Chameleon 的配置：512×512 图像 → 1024 个 token，词表大小 8000。这样图像与文本可共用同一个自回归目标，详见 [[07_全模态与原生多模态模型]]。

**离散化的固有代价**：信息必然丢失——对极小的印刷文字做离散化后将无法再识别（OCR 失败）。这是离散 token 路线与连续编码器路线的分水岭。

## 模态间的熵不对称

同为 token，文本与图像的统计特性差异巨大（CS336，Chameleon 训练经验）：

- **文本**：预测下一 token 的熵较低——大部分词多少能猜到
- **图像**：token 熵非常高——几乎无法确定下一 token 会呈现什么

这一不对称是统一建模训练不稳定的根源之一（引发范数增长、损失尖峰），也解释了为什么"理解模态"与"生成模态"需要不同的编码/解码粒度（见 [[07_全模态与原生多模态模型]]）。
