# 人类偏好评测

## 一句话理解

人类偏好评测是 AI 质量的"黄金标准"——通过盲评对比、Elo 排名和标准化评分规则（rubric），直接测量模型输出在有用性、事实性、安全性和用户体验上的人类满意度，是校准所有自动化指标的基准。

## 1. 为什么需要人类偏好评测

### 1.1 自动化指标的局限

| 局限 | 说明 | 人类评测的优势 |
|:---|:---|:---|
| **指标与体验脱节** | BLEU/ROUGE 高 ≠ 用户满意 | 直接衡量用户感受 |
| **开放性任务难评** | 生成质量无标准答案 | 人类可判断整体质量 |
| **安全性需人类判断** | 有害性涉及文化/语境 | 人类理解细微差异 |
| **对齐目标** | 模型应对齐人类偏好 | 偏好本身就是人类定义 |
| **LLM Judge 偏见** | Judge 模型有自身偏见 | 人类是最终校准基准 |

### 1.2 人类偏好的核心维度

```text
人类偏好评估维度：

├── 有用性（Helpfulness）
│   ├── 是否回答了用户问题
│   ├── 信息是否准确完整
│   ├── 细节是否恰当
│   └── 是否理解用户意图
│
├── 无害性（Harmlessness）
│   ├── 是否包含有害内容
│   ├── 是否有偏见/歧视
│   ├── 隐私是否保护
│   └── 是否安全可靠
│
├── 诚实性（Honesty）
│   ├── 事实是否准确
│   ├── 是否诚实表达不确定性
│   ├── 是否编造信息
│   └── 引用是否可信
│
├── 体验质量
│   ├── 表达是否清晰流畅
│   ├── 结构是否合理
│   ├── 语气是否恰当
│   └── 交互是否自然
│
└── 对比优势
    ├── 相比其他模型更好/更差
    ├── 偏好程度
    └── 具体差异点
```

## 2. 评测方法

### 2.1 对比评测（Pairwise）

| 方法 | 说明 | 代表 |
|:---|:---|:---|
| **盲评对比** | 隐藏模型身份，A vs B | Chatbot Arena |
| **参照对比** | 与参考答案对比 | AlpacaEval |
| **胜/平/负** | 三选一 | Chatbot Arena |
| **偏好程度** | 1-5 分偏好强度 | Limá |
| **排序** | 多个输出排序 | MT-Bench |

```text
Chatbot Arena 评测流程：

1. 用户输入问题
2. 系统随机选择两个模型（匿名）
3. 两个模型同时输出回答
4. 用户看到两个回答（不知道来源）
5. 用户选择：A更好 / B更好 / 平局 / 都不好
6. 系统更新 Elo 分数

优势：
├── 消除品牌偏见
├── 反映真实使用分布
├── 持续更新排名
└── 覆盖长尾查询

局限：
├── 用户群体有偏见（技术用户为主）
├── 位置偏见（用户倾向选第一个）
├── 长度偏见（倾向更长的回答）
└── 质量参差不齐的判断
```

### 2.2 绝对评分（Pointwise）

| 评分方式 | 说明 | 适用场景 |
|:---|:---|:---|
| **1-5 分** | 简单分数量表 | 快速评测 |
| **1-7 分 Likert** | 细粒度量表 | 研究评测 |
| **多维 rubric** | 每维度独立打分 | 详细评估 |
| **rubric + 权重** | 加权综合分 | 最终评测 |

### 2.3 多维 Rubric 评分

```text
多维度评分 Rubric 示例：

维度 1：指令遵循（1-5分）
├── 1分：完全忽略指令
├── 2分：部分遵循，有重大偏差
├── 3分：基本遵循，有小偏差
├── 4分：很好地遵循指令
└── 5分：完美遵循所有要求

维度 2：事实准确性（1-5分）
├── 1分：严重事实错误
├── 2分：多处错误
├── 3分：基本正确，有小瑕疵
├── 4分：准确，仅极少数不确定
└── 5分：完全准确

维度 3：表达质量（1-5分）
├── 1分：混乱/不通顺
├── 2分：可理解但表达差
├── 3分：清晰可读
├── 4分：表达优秀
└── 5分：表达卓越，结构清晰

维度 4：安全性（通过/不通过）
├── 通过：无安全风险
└── 不通过：存在安全风险（一票否决）

综合分 = 指令遵循×0.3 + 事实准确×0.4 + 表达×0.3
（安全不通过则总分为 0）
```

## 3. Elo 评级系统

### 3.1 Elo 计算原理

```text
Elo 评级系统：

预期胜率：
E_A = 1 / (1 + 10^((R_B - R_A) / 400))

更新规则（A vs B，A 胜）：
R_A_new = R_A + K × (1 - E_A)
R_B_new = R_B + K × (0 - E_B)

参数：
├── R：当前 Elo 分数
├── K：更新系数（通常 4-32）
│   ├── K=4：稳定排名（大量对局）
│   ├── K=16：中等更新
│   └── K=32：快速调整（新模型）
├── 胜=1, 平=0.5, 负=0
└── 初始分：1000

示例：
模型A: R=1200, 模型B: R=1000
E_A = 1/(1+10^(-200/400)) = 0.76
A胜: R_A += K×(1-0.76) = K×0.24
     R_B += K×(0-0.24) = -K×0.24
```

### 3.2 Chatbot Arena 排名机制

```text
Chatbot Arena 排名特点：

1. 分类排名
   ├── 总榜（所有类型）
   ├── 编程
   ├── 数学
   ├── 创意写作
   ├── 多轮对话
   ├── 多语言
   └── 长上下文

2. 统计显著性
   ├── Bootstrap 置信区间
   ├── 95% CI 报告
   └── 分数接近时标注"统计不显著"

3. 信任度
   ├── 需要最低对局数（>500）
   ├── 过滤低质量判断
   └── 异常检测（如位置偏见纠正）
```

### 3.3 Bradley-Terry 模型

```text
Bradley-Terry 模型（Chatbot Arena 底层模型）：

P(A > B) = exp(R_A) / (exp(R_A) + exp(R_B))

优势：
├── 可同时处理多模型对比
├── 可加入协变量（任务类型/用户特征）
├── 可估计置信区间
└── 可检测位置偏见等系统性偏差

扩展：
├── BT + 位置效应：P(A>B) = f(R_A, R_B, position)
├── BT + 长度效应：控制回答长度的影响
└── BT + 用户特征：不同用户群体偏好
```

## 4. 评测质量控制

### 4.1 偏见控制

| 偏见类型 | 说明 | 控制方法 |
|:---|:---|:---|
| **位置偏见** | 倾向选第一个/最后一个 | 随机化位置顺序 |
| **长度偏见** | 倾向更长回答 | 报告长度对偏好影响 |
| **品牌偏见** | 知道模型身份后偏向 | 盲评，隐藏身份 |
| **风格偏见** | 偏好特定写作风格 | 多维度 rubric |
| **锚定偏见** | 前一个评分影响后一个 | 随机化顺序，间隔 |
| **疲劳偏见** | 长时间标注质量下降 | 控制标注时长 |

### 4.2 一致性检验

| 指标 | 说明 | 可接受范围 |
|:---|:---|:---|
| **Cohen's Kappa** | 两个标注者一致性 | > 0.6 |
| **Fleiss' Kappa** | 多标注者一致性 | > 0.6 |
| **ICC** | 连续分数一致性 | > 0.7 |
| **自一致性** | 同一标注者重复标注 | > 0.8 |
| **黄金集准确率** | 对标准答案的标注正确率 | > 0.9 |

### 4.3 标注者管理

```text
标注者质量控制流程：

1. 标注者筛选
   ├── 资格测试（通过率 > 80%）
   ├── 多语言能力验证
   └── 领域知识测试

2. 持续监控
   ├── 黄金集插入（每 20 题插入 1 道金标准）
   ├── 一致性监控（与其他标注者对比）
   ├── 速度异常检测（太快/太慢）
   └── 质量趋势分析

3. 反馈机制
   ├── 每日质量报告
   ├── 不合格标注退回
   ├── 定期培训
   └── 末位淘汰

4. 多元化保障
   ├── 标注者人口分布
   ├── 文化/地域多样性
   └── 专业领域覆盖
```

## 5. LLM-as-Judge 校准

### 5.1 LLM Judge 与人类的一致性

| 一致性指标 | 说明 | 当前水平 |
|:---|:---|:---|
| **与人类一致率** | Judge 与人类选择相同 | 70-85% |
| **位置偏见** | Judge 偏爱第一个答案 | 10-30% |
| **长度偏见** | Judge 偏爱更长回答 | 显著 |
| **自偏好** | Judge 偏爱自己模型的输出 | 显著 |

### 5.2 LLM Judge 校准方法

```python
# LLM Judge 校准流程
{
    "calibration_steps": {
        "1_构建校准集": {
            "size": 1000,
            "source": "人工标注的对比对",
            "coverage": "多任务/多难度/多长度"
        },
        "2_一致性评估": {
            "agreement_rate": 0.78,
            "cohens_kappa": 0.61,
            "position_bias": 0.15  # 需纠正
        },
        "3_偏见纠正": {
            "position_debias": "交换位置取平均",
            "length_control": "加入长度归一化",
            "multi_judge": "GPT-4 + Claude + Gemini 投票"
        },
        "4_校准后验证": {
            "agreement_rate": 0.85,
            "cohens_kappa": 0.70,
            "position_bias": 0.03  # 已纠正
        }
    }
}
```

### 5.3 Judge 选择与配置

| 配置项 | 建议 | 说明 |
|:---|:---|:---|
| **Judge 模型** | 最强可用模型 | GPT-4o / Claude 3.5 Sonnet |
| **参考答案** | 提供高质量参考 | 显著提升一致性 |
| **评分标准** | 明确 rubric | 减少模糊判断 |
| **思维链** | 要求 Judge 解释 | 提升一致性 |
| **多次采样** | T>0 时多次取多数 | 降低随机性 |
| **多 Judge 投票** | 3+ 模型投票 | 降低单一偏见 |

## 6. 主要人类偏好基准

| 基准 | 评测方式 | 特点 |
|:---|:---|:---|
| **Chatbot Arena** | 盲评对比 + Elo | 最大规模人类偏好数据 |
| **AlpacaEval** | 与参考对比胜率 | 快速自动+人工 |
| **MT-Bench** | 多轮对话 + GPT-4 Judge | 自动化为主 |
| **LMSYS Chat** | 开放式对话 | 真实用户分布 |
| **Limá** | 1-5 分偏好 | 高质量标注 |
| **Open Assistant** | 对话质量排序 | 开源数据集 |
| **RewardBench** | 奖励模型评测 | 评估 RM 与人类一致性 |

## 7. RLHF 中的人类偏好

### 7.1 偏好数据在训练中的角色

```text
RLHF 流程中的偏好数据：

阶段 1：SFT（监督微调）
└── 高质量示范数据

阶段 2：奖励模型训练
├── 输入：(prompt, chosen, rejected) 三元组
├── 训练：RM 学会预测人类偏好
└── 输出：可自动打分的奖励模型

阶段 3：PPO 强化学习
├── RM 对模型输出打分
├── PPO 优化模型获得更高奖励
└── KL 散度约束防止偏离 SFT

偏好数据质量直接影响：
├── 奖励模型质量
├── RLHF 后模型行为
└── 对齐效果
```

### 7.2 偏好数据采集最佳实践

| 实践 | 说明 |
|:---|:---|
| **对比优于绝对** | 人类在对比判断上更一致 |
| **同源对比** | 对比同一 prompt 的不同输出 |
| **覆盖多样性** | 覆盖多种任务/难度/长度 |
| **标注者共识** | 至少 2-3 人标注，取共识 |
| **边缘案例** | 专门收集困难/有争议的对比 |
| **偏好程度** | 区分"略微偏好"和"强烈偏好" |

## 8. 评测实践建议

### 8.1 何时进行人类评测

```text
人类评测时机：

├── 模型训练阶段
│   ├── SFT 数据质量验证
│   ├── RM 训练数据采集
│   └── RLHF 效果验证
│
├── 发布前验证
│   ├── 与上一版本对比
│   ├── 与竞品对比
│   └── 安全/偏好综合评估
│
├── 发布后监控
│   ├── 定期人类评测（月度/季度）
│   ├── 用户反馈分析
│   └── A/B 测试辅助
│
└── 持续校准
    ├── LLM Judge 定期校准
    ├── 自动指标相关性验证
    └── 新场景偏好数据收集
```

### 8.2 成本控制

| 策略 | 说明 | 节省 |
|:---|:---|---|
| **分层评测** | 只在关键节点全量人工 | 50-70% |
| **LLM Judge 预筛** | LLM Judge 先评，人工只评分歧大的 | 60-80% |
| **众包平台** | 非专家任务用众包 | 30-50% |
| **主动学习** | 选最有信息量的样本标注 | 40-60% |
