# 分布式训练与并行

## 一句话理解

将大模型训练任务切分到多张 GPU 上执行，通过数据并行、张量并行、流水线并行等策略在显存容量、通信开销和硬件拓扑之间取得平衡，实现可扩展的高吞吐训练。

## 概述

当模型参数从数十亿增长到数千亿甚至万亿时，单张 GPU 的显存（如 H100 80GB）远不足以容纳完整的模型参数、梯度和优化器状态。分布式训练通过将计算、存储和通信任务切分到多张设备上，使训练超大规模模型成为可能。

本笔记回答的核心问题：
- 有哪些并行策略？各自切分什么、代价是什么？
- 如何组合多种策略形成高效的训练系统？
- 拓扑结构（节点内 NVLink / 节点间 InfiniBand）如何影响策略选择？

| 时间 | 里程碑 | 意义 |

| 2023+ | 3D/4D 并行 + MoE EP | 千卡至万卡级训练标准 |

## 核心概念

### 计算与显存的矛盾

训练一个参数量为 $N$ 的模型，混合精度下大致需要：

| 组件 | 显存占用 |
|---|---|
| 模型参数（FP16） | $2N$ 字节 |
| 梯度（FP16） | $2N$ 字节 |
| 优化器状态（FP32 Adam） | $12N$ 字节 |
| 激活值 | 随 batch × seq_len 增长 |

以 175B 参数模型为例，仅参数+梯度+优化器状态就需约 $16 \times 175\text{B} = 2.8\text{TB}$ 显存，远超单卡容量。

### 通信基本操作

| 操作 | 说明 | 典型用途 |
|---|---|---|
| All-Reduce | 所有节点汇总并广播结果 | 数据并行梯度同步 |
| All-Gather | 收集各节点分片并广播完整数据 | ZeRO-3 前向参数收集 |
| Reduce-Scatter | 汇总后分片分发 | ZeRO-3 梯度切分 |
| All-to-All | 每对节点间点对点通信 | 专家并行 token 路由 |

**关键分解关系**：All-Reduce = Reduce-Scatter + All-Gather。这个分解是 ZeRO/FSDP 的核心——通过拆分 All-Reduce，可以在两个步骤之间插入参数分片逻辑，避免存储完整模型副本。

**基本原语**：Broadcast（广播）、Scatter（散射）、Gather（收集）、Reduce（规约）是更基础的操作，通常不直接出现在训练核心路径中，但它们是理解 All-Gather、Reduce-Scatter 等复合操作的基石。

### GPU 互联拓扑

| 层级 | 互联方式 | 特点 |
|---|---|---|
| 节点内 | NVLink + NVSwitch | GPU 间直连，支持 RDMA，~900 GB/s |
| 跨节点 | InfiniBand | 专用网络，支持 RDMA，~400 GB/s |
| 跨 Pod | Ethernet / RoCE | 通用网络，RoCE 可实现 RDMA |

- **RDMA**：GPU 直接读写另一 GPU 内存，无需 CPU 介入，是高效通信的关键
- **NVL72**：NVIDIA B200/B300 产品，72 个 GPU 共享同一 NVLink 域
- **NCCL**：NVIDIA 底层通信库，分析拓扑并自动选择最优通信路径

**拓扑与并行策略的匹配**：
- 张量并行（TP）：通信频繁，限在 NVLink 域内
- 流水线并行（PP）：点对点通信，可跨节点（InfiniBand）
- 数据并行（DP）：通信可重叠计算，适合最外层跨节点扩展

## 技术原理

### 数据并行（DP）

每个 GPU 持有完整模型副本，处理不同数据批次。前向后各 GPU 通过 All-Reduce 同步梯度。

- 优点：实现简单，扩展性好
- 代价：每张卡存储完整模型副本，显存浪费大
- 进化：ZeRO-DP 通过切分优化器状态/梯度/参数，消除冗余

### 张量并行（TP）

将单个层内的矩阵运算按行或列切分到多张 GPU 上。

- 列并行：$Y = XW$，将 $W$ 按列切分，各 GPU 计算部分输出后 All-Gather
- 行并行：$Y = XW$，将 $W$ 按行切分，输入也切分，各 GPU 计算后 All-Reduce
- 优点：支持单层超大参数
- 代价：层内高频 All-Reduce 通信，适合节点内高带宽环境（NVLink）

### 流水线并行（PP）

将模型按层切分到不同 GPU 上，输入数据以微批次流过各阶段。

- 关键问题：气泡（bubble）—— 前一阶段等待后一阶段完成时产生的空闲
- 经典调度：
  - GPipe：先所有前向再所有反向，bubble 大
  - 1F1B：交替执行前向和反向，减少激活显存和 bubble
  - Interleaved 1F1B：将每阶段进一步切分为多个虚拟阶段，进一步减少 bubble

气泡比例近似为 $\frac{P-1}{M}$，其中 $P$ 为流水线阶段数，$M$ 为微批次数。

**流水线并行的通信优势**：通信只涉及激活值（$B \times S \times H$），是点对点通信（层与层之间），而非全对全。数据量通常远小于传输整个参数矩阵，因此 PP 适合放在通信最慢的链路上（跨 Pod、跨数据中心）。

**零气泡流水线（Zero Bubble Pipeline）**：

传统流水线调度中气泡不可避免。零气泡方案的关键洞察是：反向传播中实际上包含**两种不同操作**：

| 操作 | 说明 | 时间敏感性 |
|------|------|-----------|
| **B（Backward-Input）** | 将偏导数沿计算图往回传 | **关键**：信号没传回去，下一阶段无法工作 |
| **W（Backward-Weight）** | 计算当前层权重的梯度 | **不关键**：权重的导数是叶节点，随时可算 |

零气泡策略：**尽快执行 B，将 W 延迟到计算空隙**。通过将 B 和 W 拆分为独立操作，在流水线空隙中插入 W 计算，几乎完全消除气泡。具体效果取决于 B 和 W 各自的工作负载比例。

### 序列/上下文并行（SP）

将 Transformer 注意力计算中的序列维度切分到多张 GPU 上，减少长上下文场景下每张卡的激活显存。代表方法：Ring Attention、Context Parallelism。

### 专家并行（EP）

针对 MoE 模型，将不同专家分配到不同 GPU 上。Token 通过 All-to-All 通信路由到对应专家所在的设备。本质类似于张量并行（都是拆分 MLP/FFN 组件），但有关键区别：

**EP vs TP 对比**（CS336 / Megatron-LM 并行指南）：

| 维度 | 张量并行（TP） | 专家并行（EP） |
|------|---------------|---------------|
| **拆分方式** | 将单个矩阵乘法按维度切分 | 将整个 FFN（专家）分配到不同设备 |
| **通信内容** | 密集且庞大的矩阵乘法激活值 | 稀疏的 token 路由激活值 |
| **GPU 利用率** | 矩阵切得太碎 → 维度变小 → 利用率下降 | token 精确路由到该去的专家，跳过不必要的计算 |
| **通信模式** | All-Gather / Reduce-Scatter | All-to-All（每次碰到 MoE 层都要路由 token） |
| **延迟敏感性** | 中等 | **高**：计算必须等 token 到达才能继续 |

- 关键挑战：负载均衡（避免部分专家过载）、All-to-All 通信开销
- **EP vs TP**：MoE 模型中几乎总是优先选 EP 而非 TP（Megatron-LM 官方建议），因为 EP 路由稀疏 token 激活值比 TP 切分密集矩阵更高效，GPU 利用率更高
- EP 是 DP 划分的子集，并行度受 DP 限制
- DeepSeek V3 使用 64 路 EP（跨 8 台机器），并自研 DeepEP 库优化 All-to-All 路由延迟
- EP 与其他策略的兼容性：FSDP、PP、TP 在 MoE 模型中仍然适用，标准做法是将 TP 替换为 EP

## 关键方法与模型

### ZeRO（Zero Redundancy Optimizer）

| 阶段 | 切分对象 | 显存节省 | 通信开销 |
|---|---|---|---|
| ZeRO-1 | 优化器状态 | ~4x | 与 DP 相同 |
| ZeRO-2 | 优化器状态 + 梯度 | ~8x | 与 DP 相同 |
| ZeRO-3 | 优化器状态 + 梯度 + 参数 | ~Nx | 额外 All-Gather |

ZeRO-Offload 进一步将状态移至 CPU 内存；ZeRO-Infinity 扩展至 NVMe。

### 3D 并行

将 DP × TP × PP 组合使用，典型配置：

- TP 限于节点内（NVLink 互连，8 卡一组）
- PP 跨节点（通信频率低，容忍较高延迟）
- DP 在最外层扩展（All-Reduce 通信量大但可重叠）

### FSDP（Fully Sharded Data Parallel）

PyTorch 原生实现的 ZeRO-3 等价方案，通过 `FullyShardedDataParallel` 模块包装模型，自动管理参数分片、收集和梯度同步。

## 并行策略选择准则

**CS336 简化决策流程**：
1. 模型放不进单 GPU → 用 TP 或 EP 切开（限制在 NVLink 域内）
2. 还放不下 → 用 PP 或 ZeRO-3/FSDP 塞进剩余层
3. 模型放得下后 → 剩余 GPU 全用 DP
4. batch size 太小 → 梯度累积

**核心准则**：能少用模型并行就少用，尽量把 DP 拉满；TP/EP 不出 NVLink 范围。

**Megatron-LM 的 MoE 并行指南**（同样适用于稠密模型，顺序相反）：
1. 优先用大部分 GPU 做 DP 分片
2. EP 和 TP 限制在 NVLink 域内
3. 跨节点用 PP

**临界批次大小与效率曲线**：

核心洞察：只要计算耗时 ≥ 通信耗时，通信开销就能被计算重叠隐藏。

```
效率
 ↑
100%─┐───────────────────────────
     │ ╱ ╱ ╱ ╱ ╱ ╱ ← 计算受限区
     │╱╱╱╱╱╱╱╱╱╱╱
     │ ← 临界批次大小
     │ ← 通信受限区
     │
     └────────────────────────→ batch size
```

- batch size 够大时，纯 FSDP 表现极好，瓶颈完全在计算
- batch size 减小 → 遇到通信瓶颈 → 叠加 TP/EP 将效率曲线外推
- 这就是"4D 并行"的含义：DP + TP + PP + SP（或 EP）同时使用

**激活重计算的反直觉收益**：重计算多做计算 → 省内存 → 更大 batch size → 更好的 GPU 利用率

## 实际训练案例

CS336 课程结合公开细节，分析了几个近期大规模训练案例的并行策略配置：

| 模型 | 参数量 | 架构 | 并行策略 | 备注 |
|------|--------|------|---------|------|
| **OLMo** (AI2) | 7B | 稠密 | 纯 FSDP | FSDP 扩展性出奇好，~7B 参数纯靠 FSDP 训练 |
| **DeepSeek V1** | — | 稠密 | DP + TP + PP | 经典 3D 并行组合 |
| **DeepSeek V3** | — | MoE | DP + **EP(64路)** + PP | 用 EP 替代 TP；8 台机器为一组构成 EP 域；沿用 PP 技巧保证利用率；自研 DeepEP 库 |
| **Qwen** | — | MoE | ZeRO-1 + EP + PP | EP 效率稍高于 TP 的替代方案 |
| **Llama 3 405B** | 405B | 稠密 | TP=8 + SP=1 + PP=16 + DP=1280 | 稀有地完整披露并行配置；长上下文扩展阶段拉高 SP、降低 DP |
| **Gemma 2** | — | 稠密 | FSDP + TP + SP | Google 用 FSDP 而非纯 TP |

**Llama 3 405B 细节**：
- 预训练主阶段：TP=8（NVLink 域）+ PP=16（跨节点）+ DP=1280（大规模数据并行）
- 长上下文扩展阶段：拉高上下文并行（SP），降低 DP——因为长上下文极度吃内存
- 训练过程中 GPU 故障了约 400 次，凸显大规模训练的容错挑战

**DeepSeek V3 细节**：
- 64 路 EP 是非常规的大规模专家并行，跨 8 台机器（每组 8 GPU × 8 = 64 设备）
- 沿用流水线并行中的调度技巧（如 1F1B）来保证 EP 不出现利用率低谷
- 自研 DeepEP 库，甚至挖掘未公开的 PTX 指令来优化 All-to-All 路由延迟

**关键启示**：
1. 小模型（~7B）纯 FSDP 足够，扩展性极好
2. 超大稠密模型用经典 3D 并行（TP + PP + DP），Llama 3 是最佳参考
3. MoE 模型将 TP 替换为 EP，其余策略不变
4. 长上下文训练需要 SP/CP，以 DP 缩减为代价
5. 大规模训练中 GPU 故障是常态，需要冗余和容错机制

## 优势与局限

### 优势

- 突破单卡显存上限，使训练超大规模模型成为可能
- 通过多卡并行缩短训练时间

### 局限

- 通信开销随 GPU 数量增长，扩展效率递减
- 跨节点网络带宽成为瓶颈
- 调试和容错复杂度高
- 并行策略选择需要丰富的经验

## 应用场景

- LLM 预训练（GPT、LLaMA 等）：3D 并行 + ZeRO
- MoE 模型训练：DP × TP × EP
- 长上下文微调：SP + TP
- 中等规模微调：FSDP / ZeRO-2

## 前沿发展

- **通信压缩**：梯度压缩（如 PowerSGD）减少 All-Reduce 数据量
- **重叠优化**：计算-通信重叠的自动化调度
- **弹性训练**：支持 GPU 动态加入/退出的弹性并行
- **万卡级训练**：网络拓扑感知调度与故障恢复
- **零气泡流水线**：分离 B/W 操作（输入梯度 vs 权重梯度）几乎完全消除气泡
- **专用 EP 库**：DeepEP（DeepSeek）、HybridEP（NVIDIA）针对 MoE All-to-All 路由优化
- **4D/5D 并行**：DP + TP + PP + SP + EP 全策略组合已成最大规模训练标配

## 常见问题

- **TP 和 PP 怎么选？**：TP 适合节点内（高带宽），PP 适合跨节点（容忍延迟）。
- **ZeRO-3 和 FSDP 一样吗？**：本质相同，FSDP 是 PyTorch 原生实现，ZeRO-3 是 DeepSpeed 实现。
- **DP 和 DDP 的区别？**：DP 是单进程多线程，有 GIL 瓶颈；DDP 是多进程，每卡一个进程，是标准做法。
