# 会话事件日志与模型历史

## 一句话理解

Session 是仅追加的事件流：模型历史由其中的 surface 事件投影，UI、恢复、fork 与遥测从同一日志派生，因此“模型可见即已记录”。

## 事件与投影

事件带有类型、单调 `seq`、时间和 JSON 可序列化数据。`user/message`、`assistant/message`、`tool/result` 是 surface 事件，可经 append 或 replace 参与 `deriveMessages()`；`turn/*`、`step/*`、`tool/call` 和 `assistant/chunk` 同样持久化，但不自动进入模型上下文。

## 设计约束

新增模型可见输入时，扩展 `SessionEventMap` 并实现日志到模型/界面的投影，不能只在请求前拼字符串。未知且未标记为可忽略的事件必须拒绝重建，避免静默丢失语义。

## 持久化事件分类体系

以下内容来自 `docs/persistence-catalog.zh.md`，是理解会话日志格式和实现投影的基础。

### 事件信封结构

每个事件信封（`SessionEvent<T>`）包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | `SessionEventType` | 事件键，判别联合的判别子 |
| `seq` | `number` | 单调递增序列号（会话内唯一） |
| `time` | `number` | Unix epoch 毫秒 |
| `data` | `SessionEventMap[T]` | 该类型对应的 payload |
| `ignorable?` | `true` | 存在时读取方可安全跳过未识别的类型；**缺失表示必须识别** |
| `surfaceOp?` | `SurfaceOp` | 仅 surface 事件携带；`append` 或 `{ op: 'replace', start, end }` |
| `sourceEventSeqs?` | `number[]` | 仅 surface 事件携带；该事件引用的早期事件 seq 列表 |

> `ignorable` 的语义：省略 = 必须；读取方遇到未识别的必须类型**应拒绝重建**，而非静默丢弃（丢弃可能改变剩余日志的解读）。写入方只在"纯信息型记录丢失后不影响重建"时才设置 `true`。

### Surface 事件 vs Log-only 事件

**Surface 事件**（`SurfaceEventType`）是产生 LLM 消息并参与有序 surface 列表的事件，只有三类：

| 类型 | 说明 |
|---|---|
| `user/message` | 用户角色消息（人类提示、`agent.inject()` 注入、目标续行） |
| `assistant/message` | 组装完成的 assistant 消息（包含 `usage` 时令 token 计量与输出同行） |
| `tool/result` | 工具调用结果（包含可选的 `error` 身份和 `meta` 展示载荷） |

这三类事件可携带 `surfaceOp` 和 `sourceEventSeqs`，`deriveMessages()` 从它们派生模型历史。

**Log-only 事件**是所有其他持久化事件：持久化且可回放，但不参与派生历史。包括但不限于：

| 分组 | 代表事件 |
|---|---|
| 轮次/步骤边界 | `turn/start`、`turn/end`、`step/start`、`step/end` |
| 流式原始数据 | `assistant/chunk`（raw stream chunk，令 token 级回放保真） |
| 工具调用 | `tool/call`（模型请求的调用；配对对应的 `tool/result`） |
| 代码子分发 | `tool/code-dispatch-start`、`tool/code-dispatch` |
| 审批 | `approval/asked`、`approval/decided`、`approval/policy` |
| 会话标题 | `session/title`、`session/title-llm-request` |
| 目标 | `goal/change` |
| 计划模式 | `plan/mode` |
| 沙箱 | `sandbox/mode` |
| 压缩 | `compaction/start`、`compaction/summary`、`compaction/prune`、`compaction/end` |
| 调度 | `schedule/change` |
| 待办事项 | `todo/write` |
| 工作流 | `tool-workflow/run-start`、`tool-workflow/agent-start/end`、`tool-workflow/run-end` |
| 钩子 | `hook/invoked`、`hook/result` |
| 会话生命周期 | `session/end-seed`（标记种子历史结束） |

### SurfaceOp 语义

| 值 | 含义 |
|---|---|
| `'append'` | 添加到 surface 末尾（正常路径） |
| `{ op: 'replace', start, end }` | 替换 surface 中 `start` 到 `end`（含两端）的节点；`sourceEventSeqs` 必须包含所有被替换节点的 seq。用于压缩摘要替换历史片段。 |

### 压缩（Compaction）协议

压缩时的 surface 替换遵循特定配对协议：
- `compaction/summary`（或 `compaction/prune`）紧接在 surface replace 事件**之前**，携带被替换范围的"shadow 定价"（`shadowedTokenCount`），消费方可据此减去被替换内容的 token 计量，而无需保留每节点定价；
- `compaction/start` 和 `compaction/end` 分别持有锁，两者之间不允许其他压缩；
- `session/end-seed` 标记恢复/fork 种子历史与当前生命周期的分界线。

### 格式版本

当前格式固定为 `SESSION_FORMAT_VERSION = 0`，是预发布格式，不暗示任何兼容性（包括向前兼容）。下游插件可以继续合并其他事件类型，这些类型设计上不属于本目录。
