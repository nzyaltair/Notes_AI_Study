# LLM 神经符号推理

## 一句话理解

LLM 负责理解自然语言与生成候选方案，符号组件负责计算、检索与验证——把"会说话"与"算得对"分开。

## 三类协作

1. **LLM → Symbolic**：将自然语言转成 SQL、代码、逻辑式或规划问题。
2. **Symbolic → LLM**：向模型提供检索证据、执行轨迹、证明状态和纠错反馈。
3. **LLM + Symbolic**：生成—执行—验证—修订闭环。

## 关键技术

- **程序辅助推理（PAL）**：LLM 生成 Python 程序，由解释器计算数值答案，避免算术幻觉。
- **工具调用（Toolformer 等）**：模型学习何时调用计算器、搜索、数据库等外部工具。
- **约束解码**：用类型系统或规则约束生成过程，保证输出结构合法。
- **验证器循环**：LLM 生成候选证明/解答，外部验证器检查，失败则反馈修订（对应 [[04_程序综合与形式化验证]]）。

## 典型任务

| 任务 | 神经部分 | 符号部分 |
|---|---|---|
| 数学题解 | 题目理解、程序生成 | 算术解释器、证明检查 |
| 表格问答 | 问题转 SQL | SQL 执行器 |
| 多跳问答 | 问题分解、证据排序 | 图谱/文档检索 |
| 形式证明 | 策略搜索、引理生成 | 证明检查器（Lean 等） |
| 规划 | 目标转 PDDL | 规划器搜索 |

## 实践原则

定义类型与权限；保留工具输入输出；将"执行成功"与"答案正确"分开评估；对解析失败、工具错误及证据冲突提供回退策略。

## 优势与局限

- **优势**：LLM 提供语义灵活性，符号层提供精确性；两者互补可显著降低幻觉与计算错误。
- **局限**：自然语言到形式语言的转换本身有歧义；工具调用失败模式复杂；验证成本高；LLM 仍可能在中间步骤出错并污染后续推理。

## 前沿发展

- **推理时验证**：把验证器作为生成器的打分器，引导搜索（对应 C 板块的推理时扩展）。
- **神经符号 Agent**：LLM 编排多工具、多验证步骤，见 [[05_神经符号Agent]]。
- **可证明的 LLM 推理**：在 Lean/Isabelle 等证明助手中验证 LLM 生成的数学推理链。
