# 模型失败与漂移处理

## 一句话理解

AI 系统的模型失败包括幻觉、格式错误、拒答失效、工具误用和异常成本，而漂移涵盖输入分布、数据质量、用户行为、检索知识和模型供应商版本变化——通过在线指标、抽样审查、统计检验和回归集发现问题，再以限流/回退、隔离影响、根因分析、修复评测和受控发布的流程进行处置。

## 1. 为什么 AI 模型会"悄悄失败"

传统软件系统的故障通常是**显式的**：服务崩溃、返回 500 错误、数据库连接超时。AI 模型的失败则往往是**隐性的**：

- **HTTP 200 但答案错误**：模型正常返回，但内容是幻觉
- **渐进退化**：模型质量逐周下降，不触发任何阈值告警
- **外部引发**：用户输入分布变化导致模型表现变差，但代码未改
- **供应商静默更新**：底层模型版本升级，行为发生微妙变化

因此，AI 可靠性工程必须建立**主动检测**机制，而非仅依赖错误率告警。

## 2. 模型失败模式分类

### 2.1 失败模式全景

| 失败类型 | 描述 | 根因 | 影响 |
|:---|:---|:---|:---|
| **幻觉** | 生成虚假事实或编造引用 | 训练数据不足、RAG 检索失败、温度过高 | 用户获得错误信息 |
| **格式错误** | 输出不符合 JSON/XML 等预期格式 | Prompt 不明确、模型能力不足 | 下游解析失败 |
| **拒答失效** | 应拒答的有害内容未拦截，或正常问题被误拒 | 安全过滤器误判 | 安全风险或用户体验差 |
| **工具误用** | Agent 调用错误工具或传入错误参数 | 推理错误、工具描述不清晰 | 任务失败或副作用 |
| **异常成本** | 单次请求消耗远超预期 token | 长上下文、无限循环、冗余生成 | 成本失控 |
| **上下文溢出** | 请求超出 context window | 对话过长或检索文档过多 | 请求失败或截断丢失信息 |
| **指令遵循退化** | 模型不再遵循系统 Prompt | 供应商更新或 Prompt 注入 | 行为不可预测 |
| **多语言退化** | 非英语语言质量明显下降 | 训练数据偏差 | 特定用户群体受影响 |

### 2.2 幻觉的深层原因

```text
幻觉根因分析：
  ├─ 训练数据层面
  │   ├─ 训练数据包含错误信息
  │   ├─ 长尾知识覆盖不足 → 模型"编造"填补空白
  │   └─ 知识截止日期后的事实变化
  ├─ 检索层面（RAG）
  │   ├─ 检索结果不相关 → 模型基于错误上下文生成
  │   ├─ 检索结果矛盾 → 模型选择错误信息
  │   └─ 检索为空 → 模型凭参数记忆生成
  ├─ 生成层面
  │   ├─ 温度过高 → 增加随机性
  │   ├─ 缺乏事实核查步骤 → 无验证机制
  │   └─ 过度自信的表达风格
  └─ 评估层面
      └─ 缺乏事实一致性评测 → 幻觉未被检测
```

### 2.3 Agent 工具调用失败模式

| 失败模式 | 示例 | 检测信号 |
|:---|:---|:---|
| 错误工具选择 | 查天气时调用了搜索工具 | 工具选择准确率下降 |
| 参数格式错误 | 传字符串给需要 int 的参数 | 参数验证失败率 |
| 参数值错误 | 日期格式错误或坐标越界 | 工具执行错误率 |
| 重复调用 | 循环调用同一工具 | 同一请求内重复调用次数 |
| 调用顺序错误 | 未登录就调用需要认证的接口 | 工具调用链异常 |
| 无限循环 | 不断重试失败的工具 | 步数超限 |

## 3. 漂移类型详解

### 3.1 漂移分类框架

```text
数据漂移（Data Drift）
  ├─ 输入漂移：用户输入的分布发生变化
  │   ├─ 词汇分布变化（新术语、新话题）
  │   ├─ 输入长度分布变化
  │   ├─ 语言分布变化（多语言比例变化）
  │   └─ 嵌入空间分布变化
  ├─ 输出漂移：模型输出的分布发生变化
  │   ├─ 输出长度变化
  │   ├─ 情感极性变化
  │   ├─ 拒答率变化
  │   └─ 格式合规率变化
  └─ 标签漂移：真实标签的分布变化
      └─ 用户反馈分布变化（点赞/点踩比例）

概念漂移（Concept Drift）
  └─ 同样输入的正确答案随时间变化
      ├─ 时效性知识（谁是现任 CEO）
      ├─ 政策法规变化
      ├─ 用户偏好变化
      └─ 业务规则更新
```

### 3.2 各类漂移的检测方法

| 漂移类型 | 检测方法 | 典型指标 | 告警阈值 |
|:---|:---|:---|:---|
| 输入长度漂移 | 统计输入 token 分布 | P50/P90/P99 token 数 | P99 偏移 > 20% |
| 词汇分布漂移 | 词频统计 + 新词检测 | 新词比例 | 日新词率 > 5% |
| 嵌入分布漂移 | 嵌入向量 + MMD/KS 检验 | MMD 距离 | p-value < 0.05 |
| 输出质量漂移 | 在线评测 + 用户反馈 | 评测得分、点赞率 | 得分下降 > 5% |
| 拒答率漂移 | 统计拒答比例 | 拒答率 | 偏移 > 3σ |
| 概念漂移 | 人工标注 + 对比基准 | 标注准确率 | 准确率下降 > 10% |
| 供应商版本漂移 | 固定测试集回归 | 回归集得分 | 得分变化 > 3% |

### 3.3 统计检验方法

#### KS 检验（Kolmogorov-Smirnov Test）

用于比较两个一维分布是否有显著差异。

```python
from scipy import stats

# 比较上周和本周的输入 token 长度分布
last_week_lengths = [120, 150, 130, ...]  # 上周样本
this_week_lengths = [180, 220, 190, ...]  # 本周样本

statistic, p_value = stats.ks_2samp(last_week_lengths, this_week_lengths)

if p_value < 0.05:
    print(f"检测到输入长度漂移！KS statistic={statistic:.4f}, p-value={p_value:.4f}")
```

**适用场景**：输入长度、输出长度、延迟等单变量分布。

#### MMD（Maximum Mean Discrepancy）

用于比较高维分布（如嵌入向量）的差异。

```python
import numpy as np
from sklearn.metrics.pairwise import rbf_kernel

def mmd(X, Y, gamma=1.0):
    """计算两组样本的 MMD 距离"""
    K_XX = rbf_kernel(X, X, gamma=gamma)
    K_YY = rbf_kernel(Y, Y, gamma=gamma)
    K_XY = rbf_kernel(X, Y, gamma=gamma)
    return K_XX.mean() + K_YY.mean() - 2 * K_XY.mean()

# 比较基准期和当前的嵌入分布
baseline_embeddings = np.array([...])  # 基准期嵌入（如 1000 条）
current_embeddings = np.array([...])   # 当前嵌入（如 1000 条）

mmd_score = mmd(baseline_embeddings, current_embeddings)
if mmd_score > threshold:
    print(f"检测到嵌入分布漂移！MMD={mmd_score:.6f}")
```

**适用场景**：输入嵌入分布、输出嵌入分布等高维数据。

#### PSI（Population Stability Index）

金融风控领域常用的漂移指标，适用于分桶后的分布比较。

```python
def calculate_psi(expected, actual, bins=10):
    """计算 PSI"""
    # 将预期分布分桶
    breakpoints = np.linspace(0, 100, bins + 1)
    expected_pct = np.percentile(expected, breakpoints)
    expected_bins = np.histogram(expected, bins=expected_pct)[0] / len(expected)
    actual_bins = np.histogram(actual, bins=expected_pct)[0] / len(actual)

    # 避免除零
    expected_bins = np.clip(expected_bins, 0.0001, None)
    actual_bins = np.clip(actual_bins, 0.0001, None)

    psi = np.sum((actual_bins - expected_bins) * np.log(actual_bins / expected_bins))
    return psi

# PSI 解读：
# < 0.1  → 无显著漂移
# 0.1-0.25 → 中等漂移，需关注
# > 0.25 → 显著漂移，需行动
```

### 3.4 供应商版本漂移检测

底层模型供应商（OpenAI、Anthropic 等）可能在不通知的情况下更新模型版本，导致行为变化。检测方法：

```text
策略：维护固定回归测试集，定期运行并对比基线

回归测试集设计：
  ├─ 100 条核心能力测试（事实问答、推理、代码生成）
  ├─ 50 条格式合规测试（JSON、XML、Markdown 输出）
  ├─ 30 条安全测试（有害内容拒答）
  ├─ 20 条多语言测试
  └─ 10 条长上下文测试

运行频率：每日 2 次（覆盖不同时段）
对比基线：首次部署时的测试结果

告警规则：
  ├─ 任一类别得分下降 > 3% → P3 告警
  ├─ 总体得分下降 > 5% → P2 告警
  └─ 安全类别得分下降 > 2% → P1 告警
```

### 4.2 在线评测系统

在线评测不应对所有请求执行（成本太高），而是采用**抽样 + 多层评测**策略：

```python
class OnlineEvaluationPipeline:
    """在线评测流水线"""

    def __init__(self):
        self.sampling_rate = 0.01  # 1% 采样率
        self.evaluation_layers = [
            self.rule_based_check,      # 规则检查（格式、长度）
            self.embedding_similarity,   # 嵌入相似度（语义一致性）
            self.llm_judge,             # LLM 评判（质量打分）
            self.fact_check,            # 事实核查（幻觉检测）
        ]

    async def evaluate(self, request, response):
        # 规则检查：快速、低成本
        rule_result = self.rule_based_check(response)
        if not rule_result.passed:
            return rule_result

        # 嵌入相似度：中成本
        sim_result = await self.embedding_similarity(request, response)
        if sim_result.score < 0.3:  # 低相似度可能幻觉
            return sim_result

        # LLM 评判：高成本，仅对 0.1% 请求执行
        if random.random() < 0.001:
            judge_result = await self.llm_judge(request, response)
            return judge_result

        return sim_result  # 默认返回中等置信度结果
```

## 6. 故障处置流程

### 6.1 发现到修复的全流程

```text
1. 发现
   ├─ 告警触发（指标异常）
   ├─ 用户反馈聚集（点踩率上升）
   └─ 定期评测发现（回归测试失败）
         ↓
2. 确认与分级
   ├─ 影响范围评估（多少用户/功能受影响）
   ├─ 严重程度定级（P0-P3）
   └─ 是否需要立即止损
         ↓
3. 临时止损
   ├─ 限流（降低 QPS 减少影响面）
   ├─ 回退（回滚到上一稳定版本）
   ├─ 降级（切换到小模型或缓存）
   └─ 功能关闭（禁用问题功能）
         ↓
4. 根因分析
   ├─ 变更排查（代码/Prompt/模型/数据）
   ├─ 日志分析（错误模式、时间线）
   ├─ A/B 对比（当前版本 vs 基线）
   └─ 用户案例深入分析
         ↓
5. 修复与验证
   ├─ 修复方案实施
   ├─ 回归测试集补充（防止复发）
   ├─ 预发布环境验证
   └─ 灰度发布验证
         ↓
6. 受控发布
   ├─ 灰度比例：1% → 5% → 25% → 100%
   ├─ 每阶段监控关键指标
   └─ 异常时自动回滚
```

### 6.2 回滚决策树

```text
检测到质量下降
    ↓
确认变更来源：
    ├─ 模型版本变更？
    │   ├─ 是 → 回滚模型版本 → 验证恢复
    │   └─ 否 ↓
    ├─ Prompt 变更？
    │   ├─ 是 → 回滚 Prompt → 验证恢复
    │   └─ 否 ↓
    ├─ 检索/工具变更？
    │   ├─ 是 → 回滚相关服务 → 验证恢复
    │   └─ 否 ↓
    ├─ 数据漂移？
    │   ├─ 是 → 评估是否需重新训练/微调
    │   │        → 临时调整 Prompt 或检索策略
    │   └─ 否 ↓
    └─ 供应商版本变化？
        ├─ 是 → 联系供应商确认
        │        → 评估是否切换模型版本
        └─ 否 → 深入根因分析
```

### 6.3 影响隔离策略

当检测到问题但尚未修复时，需隔离影响范围：

| 策略 | 实施方式 | 适用场景 |
|:---|:---|:---|
| **功能降级** | 关闭特定功能（如工具调用），保留基础对话 | 工具调用故障 |
| **用户分流** | 受影响用户走降级路径，其他用户正常 | 特定用户群体问题 |
| **地域隔离** | 问题地域走备用服务 | 区域性故障 |
| **模型分流** | 高风险请求走保守模型 | 安全相关问题 |
| **灰度暂停** | 停止扩大灰度比例 | 灰度中发现问题 |

## 8. 模型失败案例库

### 8.1 典型案例与处置

| 案例 | 症状 | 根因 | 处置 | 预防措施 |
|:---|:---|:---|:---|:---|

```text
工具误用      → 工具调用成功率 + 参数验证
异常成本      → 单请求 token 数监控 + 成本告警

多语言退化    → 多语言测试集 + 按语言分组的指标
```
