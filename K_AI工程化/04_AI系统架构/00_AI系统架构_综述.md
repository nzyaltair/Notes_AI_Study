# AI 系统架构综述

## 一句话理解

AI 系统架构负责把模型、数据、记忆、工具、工作流、评测和监控组合为可运行的智能产品：它不只是调用模型 API，而是定义组件边界、状态流转、失败回退和业务责任。

## 1. 领域定义

AI 系统架构关注：

- **组合**：如何将基础模型能力与检索、工具、记忆、用户接口组合为产品
- **编排**：多步骤、多模型、多工具的流程控制与状态管理
- **边界**：模型可信边界、权限边界、业务规则边界的工程设计
- **可靠性**：失败回退、降级策略、人工审批、安全约束

与推理工程（关注单次模型调用的性能）不同，AI 系统架构关注多次调用构成的完整任务链路。

## 2. 发展历史

| 时间 | 里程碑 | 意义 |
|:---|:---|:---|
| 2017-2020 | 单模型 API 模式 | 应用直接调用预测 API，无复杂编排 |
| 2020 | GPT-3 API 发布 | Prompt 工程成为第一代"AI 应用架构" |
| 2022 | LangChain 诞生 | Chain/Agent 抽象，LLM 应用编排框架兴起 |
| 2023.03 | ChatGPT Plugin / Function Calling | 工具调用成为 LLM 应用标准能力 |
| 2023.07 | LlamaIndex 成熟 | RAG 系统的数据连接层工具链 |
| 2023.10 | OpenAI Assistants API | 托管 Agent 状态和工具，降低应用开发门槛 |
| 2024 | Multi-Agent 框架成熟 | AutoGen、CrewAI 等多智能体编排框架 |
| 2024 | Agentic RAG | RAG 与 Agent 深度融合，动态检索与推理 |
| 2025 | MCP (Model Context Protocol) | 工具/数据接入标准化协议，跨生态互操作 |

## 3. 核心架构模式

### 3.1 AI 应用分层模型

```text
用户/业务接口层（API、UI、Webhook）
    ↓
编排与控制层（工作流、Agent、决策路由）
    ↓
模型网关层（路由、认证、限流、版本）
    ↓
能力层（LLM、嵌入模型、图像模型）
    ↓
数据与工具层（向量库、数据库、外部 API、代码执行）
    ↓
记忆与状态层（对话历史、任务状态、用户画像）
    ↓
观测与评测层（Trace、质量监控、安全过滤）
```

### 3.2 RAG 架构

检索增强生成（RAG）通过外部知识库为 LLM 提供上下文：

```text
文档摄取: 解析 → 切分 → 嵌入 → 索引（向量库）
查询链路: 用户问题 → 查询改写 → 混合检索 → 重排序 → 上下文构造 → LLM 生成 → 引用标注
```

设计重点：文档版本和权限过滤、Chunk 策略、混合检索（稠密+稀疏）、无答案拒答。

### 3.3 Agent 架构

```text
目标 → 规划/路由 → 工具调用 → 观察结果 → 状态更新 → 验证/交付
```

工程要点：显式状态机与停止条件、工具权限最小化、幂等与重试、执行沙箱、长任务持久化、人工审批节点。

### 3.4 多模型系统

多个模型协作完成任务：

- **级联路由**：按任务复杂度路由到小/大模型，平衡成本与质量
- **多模型投票**：多个模型输出取一致结果，提高可靠性
- **专家混合**：不同模型处理不同子任务（代码/数学/通用）
- **模型链**：一个模型输出作为下一个模型的输入

## 4. 架构设计原则

1. **先定义任务边界**：明确 AI 在系统中承担什么，不能做什么，人类在哪里介入
2. **控制面与执行面分离**：编排逻辑独立于模型调用，便于测试和替换
3. **模型输出必须验证**：结构校验、权限校验、业务规则，不直接作为高风险操作指令
4. **状态可持久化**：工具调用、任务进度、对话历史不应只存在内存中
5. **链路可追踪**：每次模型调用关联到 Trace，支持调试和质量监控
6. **降级有兜底**：模型不可用时有静态答案或人工接管路径

## 5. 检索系统与知识库

向量数据库是 RAG 系统的核心存储：

| 系统 | 特点 | 适用场景 |
|:---|:---|:---|
| Faiss | 高性能，内存为主，Meta 开源 | 批量离线检索 |
| Milvus | 分布式，支持过滤 | 大规模在线检索 |
| Qdrant | Rust 实现，高性能过滤 | 生产级 RAG |
| Weaviate | 混合检索内置 | 通用知识库 |
| pgvector | PostgreSQL 扩展 | 已有 PG 数据库集成 |
| Chroma | 轻量，开发友好 | 原型和小规模 |

混合检索（稠密向量 + 稀疏 BM25）通常优于纯向量检索，RRF 融合排序效果好。

## 8. 前沿发展

- **MCP（Model Context Protocol）**：Anthropic 提出的工具/数据接入标准化协议，推动跨生态互操作
- **Agentic RAG**：Agent 动态决定何时检索、检索什么，而非固定检索链路
- **Graph RAG**：基于知识图谱的检索，解决多跳推理问题（Microsoft GraphRAG）
- **长上下文 vs RAG**：128K+ 上下文模型使部分 RAG 场景可用长上下文替代，权衡取舍仍在研究
- **Multi-Agent Collaboration**：多智能体分工、通信、共识机制的工程实践
- **Stateful Agent 框架**：LangGraph、MemoryOS 等持久化 Agent 状态管理框架
- **AI Gateway**：统一模型网关，支持多厂商路由、成本控制、审计和安全过滤
