# 具身 Agent 架构

## 一句话理解

具身 Agent 是分层闭环系统：高层 Agent 负责语言理解与任务分解，状态与记忆层维护世界状态，规划层验证可行性，技能层执行，控制与安全层保证稳定与安全——每一层都须有明确接口、失败语义与权限。

## 概述

架构设计决定具身 Agent 的可靠性边界。纯端到端（一个模型从观测到电机）在长程、开放、高风险任务中缺乏记忆、验证与恢复能力；纯模块化又缺乏语义泛化。具身 Agent 架构研究如何在两者之间设计分层、可验证、可扩展的系统结构。

## 分层架构

```text
用户目标 / 任务规范
  ↓
高层 Agent：语言理解、任务分解、技能选择
  ↓
状态与记忆：对象地图、进度、经验、置信度
  ↓
规划/世界模型：可行性、后果、风险与替代方案
  ↓
技能/VLA：短动作块或局部目标
  ↓
控制与安全：IK、碰撞、限幅、急停
  ↓
真实环境 → 多模态观测 → 结果核验
```

## 各层职责与接口

| 层 | 输入 | 输出 | 失败语义 |
|---|---|---|---|
| 高层 Agent | 用户目标、世界状态 | 子任务序列、技能选择 | 无法分解→澄清 |
| 状态与记忆 | 多模态观测 | 对象地图、进度、置信度 | 状态过期→重新感知 |
| 规划/世界模型 | 子任务、状态 | 可行计划、风险估计 | 不可行→换方案 |
| 技能/VLA | 子目标 | 短动作块 | 失败→恢复 |
| 控制与安全 | 动作目标 | 电机命令 | 超限→拒绝/急停 |

## 设计原则

1. **接口明确**：每层输入、输出、失败语义、权限边界清晰。
2. **职责分离**：LLM 负责提出和解释，规划与状态估计负责验证，控制器负责稳定，安全层具有最终否决权。
3. **失败可定位**：错误归因到具体层（理解/感知/规划/执行/环境）。
4. **安全独立**：安全约束不依赖上层正确性。
5. **可扩展**：新技能、新记忆类型可插入而不重构整体。

## 架构范式对比

| 范式 | 优点 | 缺点 |
|---|---|---|
| 端到端 | 免手工接口、语义泛化 | 不可验证、无记忆 |
| 模块化分层 | 可验证、可调试 | 接口设计成本 |
| 混合 | 语义泛化 + 可验证 | 集成复杂度 |

## 关键架构组件

| 组件 | 功能 | 代表技术 |
|---|---|---|
| 高层推理 | 任务分解、意图理解 | LLM, VLM |
| 世界状态 | 对象、地图、进度 | 语义地图, 场景图 |
| 记忆 | 经验复用、长期知识 | 情景/语义记忆 |
| 规划器 | 可行性验证 | TAMP, 行为树 |
| 技能库 | 可复用动作单元 | VLA, 扩散策略 |
| 安全监督 | 约束与否决 | 限幅, 急停, CBF |

## 优势与局限

| 方面 | 优势 | 局限 |
|---|---|---|
| 可验证性 | 分层核验 | 接口成本 |
| 可扩展 | 模块替换 | 集成复杂度 |
| 可解释 | 决策可追溯 | 层间信息损失 |
| 鲁棒 | 恢复骨架 | 依赖各层质量 |

## 应用场景

- 家居服务：长程整理、清洁、做饭。
- 仓储物流：拣选-打包-上架。
- 巡检操作：检查 + 维护 + 报告。
- 人形机器人：全身操作 + 自主决策。

- **VLA 为中心的混合架构**：VLA 提供技能，Agent 层编排。
- **世界模型 Agent**：用世界模型验证候选计划。
- **可成长架构**：技能库与记忆持续扩展。
- **多 Agent 架构**：多机器人协作。

## 常见问题

- **把 LLM 当完整 Agent**：缺少验证、记忆与安全。
- **端到端神话**：长程任务必须有状态与恢复。
- **接口不完整**：缺少失败语义导致无法编排。
- **安全依赖模型**：安全必须独立于模型。
