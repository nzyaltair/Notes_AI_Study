# 环境接口

## 一句话理解

环境接口把世界转换为 Agent 可交互的契约，决定世界模型能学到什么、评测是否可复现；接口设计是环境智能的基础设施问题。

## 概述

任何学习系统都需要与环境交换信息：观测进来、动作出去、反馈返回。接口的完整性与语义清晰度直接决定世界模型可学习的信息与评测的可信度。

## 最小接口

```text
reset() → 初始观测
step(action) → 观测、奖励、终止、约束/诊断信息
```

## 接口契约要素

| 要素 | 含义 | 缺失的后果 |
|---|---|---|
| observation | 状态/观测定义 | 模型无法估计状态 |
| action | 动作语义与范围 | 行动条件预测错乱 |
| reward | 目标/代价信号 | 无法优化 |
| terminated/truncated | 任务结束 vs 被迫截断 | 价值估计偏差 |
| info/诊断 | 约束、风险、调试信息 | 无法校准与审计 |

真实系统还应补充：**时间戳、延迟、权限、风险、成本和状态版本**。

## 环境类型与接口风格

- **RL 标准接口**：OpenAI Gym / Gymnasium 风格，适合通用 RL。
- **物理引擎接口**：MuJoCo、Isaac 提供高速 step 与并行采样。
- **工具/API 环境**：还需定义参数模式、权限、幂等性、失败恢复和审计日志（LLM Agent 场景）。
- **仿真—现实统一**：接口应抽象出 sim/real 共用的语义层，便于 Sim2Real。

## 设计原则

1. **语义完整**：观测与动作的语义必须明确（单位、坐标系、时间粒度）。
2. **可复现**：版本、种子、初始分布固定，支持回归测试。
3. **信息充分**：把"什么是已知的、什么是未知的"编码进接口，而非静默丢弃。
4. **可注入**：支持扰动、故障与安全约束注入，用于评测与安全验证。

## 常见问题

- 接口把诊断信息丢弃，导致模型/评测无法解释失败。
- 动作语义漂移（延迟、截断、幂等性）未编码进接口。
- 训练与评测使用不同版本环境，造成结果不可比。
