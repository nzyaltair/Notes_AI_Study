# 安装启动与运行配置

## 一句话理解

DSH 的运行实例不是固定二进制配置，而是按优先级叠加 Bundle、Profile 和 Patch 后得到的 Cordis 插件树；用最小权限工作区启动，并用配置转储确认实际生效结果。

## 概述

官方 Web UI 流程从已启动的 `dsh` 服务开始：进程启动目录是默认文件系统位置，但 Web UI 仍需显式添加并选中工作区，未选中前不能输入任务。

## Profile、Bundle 与 Patch

- **Bundle**：可分发的一组 Cordis 插件配置和挂载代码。
- **Profile**：Harness home 中的具名运行组装，如 `web` 或 `headless`。
- **Patch**：按条目 id 替换配置或插入条目的 YAML 覆盖层；替换是整个 `config`，不是深度合并。

配置顺序为：Profile 声明的 Bundle（按声明顺序）→ Profile patch → home patch → 命令行 `--patch`。后者优先级最高。

```sh
dsh --profile web --dump-config
```

这条命令用于查看当前机器真实启动的树；不要根据示例猜测最终配置。

## 内置组装的职责

| 组装 | 作用 |
|---|---|
| `dsh-base` | 模型、工具、持久化、沙箱/审批、设置、凭据和遥测的基础层 |
| `dsh-web-app` | 增加浏览器应用和服务端接入 |
| `dsh-headless` | 增加一次性任务执行，不启动服务器 |

## 运行边界

- 先在可丢弃的 checkout、容器或最小权限目录中运行。
- Patch 可加载本地插件，也意味着它能改变安全策略；只使用可信代码。
- 修改配置后先检查 `--dump-config`，再做会修改文件或启动进程的任务。
