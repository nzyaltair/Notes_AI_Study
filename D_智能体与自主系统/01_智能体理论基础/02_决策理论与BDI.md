# 决策理论与 BDI

## 一句话理解

BDI（Belief-Desire-Intention）框架将智能体的决策过程分解为三个显式层次：信念（Belief，对世界的认知）、愿望（Desire，候选目标）和意图（Intention，已承诺要执行的计划）——意图的"承诺"机制是 BDI 区别于简单"感知-行动"循环的关键，它让 Agent 不会因每次新输入而随意改变计划。

## 概述

一个简单的"感知-行动"循环（如 ReAct）可以完成许多任务，但它有一个根本局限：**没有记忆和目标的一致性**。每次新观察都可能完全改变 Agent 的行为，导致 Agent 在长任务中"迷失方向"——刚刚还在做步骤 A，看到新信息后又转向步骤 B，最后什么也没完成。

BDI 框架解决了这个问题：Agent 维护一个"已承诺的意图"（当前正在执行的计划），除非遇到重大证据或失败，否则不会轻易改变。这使得 Agent 的行为具有**目标一致性**和**计划稳定性**，是长程任务和复杂决策的理论基础。本笔记是 [[00_智能体理论基础_综述|智能体理论基础]] 中"如何组织决策"的核心，与 [[01_Agent定义与理性|Agent 定义与理性]] 一起构成智能体理论的两大基石。

## 发展历史

| 年代 | 里程碑 | 意义 |
|:---|:---|:---|
| 1987 | Bratman 提出 BDI 的哲学基础 | 将信念、愿望、意图作为实践推理的核心概念，区分"正在考虑"和"已经承诺" |
| 1995 | Rao & Georgeff 形式化 BDI 逻辑 | 给出 BDI 的时间逻辑语义，使其可计算 |
| 1997 | PRS（Procedural Reasoning System） | 第一个基于 BDI 的 Agent 实现框架 |
| 1999 | JACK 商用 BDI 框架 | BDI 从学术走向工业 |
| 2000s | BDI 在机器人、游戏 AI 中应用 | 验证了 BDI 在复杂场景中的实用性 |
| 2022- | BDI 思想在 LLM Agent 中复兴 | 意图承诺、信念维护等概念以"任务队列""记忆流""状态跟踪"的形式重新出现 |

## 核心概念

### BDI 三要素

- **信念（Belief, B）**：Agent 对世界（包括自身和其他 Agent）的认知状态。信念不必是正确的，但必须是 Agent 当前认为真实的信息。信念随时间更新（通过感知和推理），更新方式在 [[../02_环境与世界模型/02_POMDP与状态估计|POMDP 与状态估计]] 中形式化
- **愿望（Desire, D）**：Agent 希望达到的未来状态，即候选目标。愿望可以是不一致的甚至冲突的——Agent 可能既想"快速完成任务"又想"保证质量"，两者都是愿望，但需要在决策时权衡
- **意图（Intention, I）**：Agent 已承诺要执行的计划。意图是 BDI 框架的核心创新——它是**从愿望中选出的、已承诺的、正在执行的**目标，具有稳定性。Agent 不会因为每个新观察而随意放弃意图

### BDI 决策循环

```text
感知环境 → 更新信念 → 生成愿望（候选目标）
  → 按效用与约束选择意图（承诺目标）
    → 细化意图为计划 → 执行计划
      → 执行中根据新观察监控计划进展
        → 计划成功 → 结束意图
        → 计划失败/新证据 → 重新考虑意图
```

### 意图的承诺策略

| 承诺策略 | 描述 | 适用场景 |
|:---|:---|:---|
| 盲从（Blind） | 一旦承诺，绝不放弃 | 需要绝对稳定性的任务 |
| 单步（Single-minded） | 除非目标已不可能实现，否则不放弃 | 大多数任务（默认策略） |
| 开放（Open-minded） | 任何时候只要有更好的选择就放弃当前意图 | 探索性、机会性任务 |

## 技术原理

### 从愿望到意图：选择机制

Agent 有多个愿望（候选目标），但一次只能执行少量意图（通常一个）。选择机制决定了：

1. **哪个愿望转化为意图**：基于效用评估、优先级、资源约束
2. **何时放弃意图**：计划失败、资源耗尽、风险上升、更有价值的替代出现
3. **如何处理冲突愿望**：愿望可能冲突（如"快速执行"和"安全执行"），需要权衡规则

### 计划与意图的关系

意图不是原子动作，而是需要细化为一组计划（Plan）的复合结构：

```text
意图: "完成项目调研"
  → 计划: ① 搜索资料 ② 阅读摘要 ③ 交叉验证 ④ 撰写报告
    → 子意图: "搜索资料" → 计划: ① 确定搜索关键词 ② 执行搜索 ③ 筛选结果
```

这种层次化的意图-计划结构是 [[03_认知架构|认知架构]] 中"审议模块"的核心设计模式。

### LLM Agent 中的 BDI 映射

BDI 的概念在 LLM Agent 中并非直接实现，而是以工程化的形式出现：

| BDI 概念 | LLM Agent 中的对应物 |
|:---|:---|
| 信念（Belief） | 记忆/状态库（存储环境信息和历史），见 [[../05_记忆与持续学习/01_Agent记忆|Agent 记忆]] |
| 愿望（Desire） | 任务队列中的候选子任务 |
| 意图（Intention） | 当前正在执行的计划/子任务 |
| 承诺（Commitment） | 计划执行中的"坚持"策略——不因每次新观察而随意改变 |
| 重新考虑 | 计划失败或新证据出现时的重规划机制 |

## 优势与局限

**优势**：意图承诺机制解决了"频繁切换目标"的问题，使 Agent 能坚持完成长程任务；BDI 将决策过程分解为可理解和可审计的步骤（信念→愿望→意图→计划），增强了可解释性；承诺策略提供了灵活性和稳定性之间的权衡空间。

**局限**：BDI 的精确形式化（时态逻辑）在开放世界中计算复杂且难以维护；BDI 的"信念"难以处理深度神经网络带来的不确定性；大多数 LLM Agent 不直接实现 BDI，而是使用更简单的 ReAct 循环——BDI 的价值更多是作为设计原则而非实现框架。

## 应用场景

- **长程任务 Agent**：需要坚持执行多步计划而不被中间信息干扰
- **可审计决策系统**：需要记录"为什么选择这个目标而不是另一个"的决策过程
- **多 Agent 协作**：Agent 之间需要明确各自的"承诺"以避免冲突

## 前沿发展

- **神经 BDI**：将 BDI 的结构化决策逻辑与神经网络的感知/推理能力结合
- **BDI 理论在 LLM Agent 中的简化实现**：用"任务队列"（意图栈）+ "记忆"（信念库）+ "策略"（愿望选择）的工程化组合替代完整 BDI 框架
- **意图承诺的强化学习**：学习何时应该坚持计划、何时应该重新考虑，而非使用固定策略

## 常见问题

**Q: BDI 和 ReAct 循环有什么区别？**
ReAct 是"思考-行动-观察"的简便循环，没有显式的"意图承诺"机制——每次新观察都可能改变 Agent 的下一步。BDI 增加了意图层，Agent 在承诺一个计划后不会轻易改变。ReAct 适合短任务，BDI 适合需要目标一致性的长任务。

**Q: BDI 在 LLM Agent 中还有价值吗？**
有。虽然 LLM Agent 通常不直接实现 BDI 框架，但 BDI 的设计原则（维护信念、选择目标、承诺意图）在工程上以"记忆系统""任务队列""状态跟踪"的形式存在。理解 BDI 有助于设计更稳定、更可解释的 LLM Agent。
