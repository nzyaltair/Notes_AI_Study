# 数据治理

## 一句话理解

数据治理规定数据在全生命周期内可被谁、以何种目的、在何种边界下使用——通过数据目录与所有者、授权与保留、分级保护与合规审查，在可审计边界内让数据可发现、可复用、可撤回。

## 1. 概述

数据治理不是"阻断数据使用"，而是"在可审计的边界内让数据可发现、可复用、可撤回"。它解决的是组织层面"谁可以用什么数据、做什么、怎么追责"的问题。

数据治理的核心目标：

- **可发现**：数据消费者能找到需要的数据
- **可复用**：避免重复采集和存储
- **可审计**：所有数据使用可追溯
- **可撤回**：用户可撤回数据使用授权
- **合规**：满足法律法规和行业标准

## 2. 核心机制

### 2.1 数据目录与所有者

建立组织级数据资产目录：

| 维度 | 内容 | 示例 |
|:---|:---|:---|
| 资产标识 | 数据集唯一 ID | `dataset_001` |
| 资产名称 | 人类可读名称 | "用户对话日志" |
| 用途 | 数据用途描述 | "模型训练与评测" |
| 敏感等级 | 数据敏感级别 | L1-L4 |
| 责任人 | 数据所有者 | 数据团队负责人 |
| 许可证 | 使用许可 | 内部/CC-BY/商业 |
| 生命周期 | 保留期限 | 90 天/1 年/永久 |
| 访问要求 | 访问审批流程 | 需负责人审批 |

### 2.2 授权与保留

| 机制 | 说明 | 示例 |
|:---|:---|:---|
| 许可管理 | 记录数据使用许可 | 开源 License/商业协议 |
| 用户同意 | 用户授权数据使用 | 隐私政策/同意书 |
| 访问审批 | 数据访问需审批 | 申请人→负责人→合规 |
| 删除请求 | 支持用户删除请求 | GDPR Right to be Forgotten |
| 保留期限 | 数据保留时间 | 日志 90 天，训练数据 1 年 |
| 过期处理 | 到期数据的处理 | 自动删除/匿名化 |

### 2.3 分级保护

按敏感等级实施差异化保护：

| 等级 | 说明 | 示例 | 保护措施 |
|:---|:---|:---|:---|
| L1 公开 | 可公开数据 | Wikipedia | 无特殊保护 |
| L2 内部 | 内部使用 | 内部文档 | 访问控制 |
| L3 机密 | 含敏感信息 | 用户数据 | 加密 + 审计 |
| L4 绝密 | 高度敏感 | PII/医疗数据 | 加密 + 隔离 + 审批 |

保护措施：

- **加密**：存储加密 + 传输加密
- **最小权限**：只授予完成任务所需的最小权限
- **脱敏**：对敏感字段脱敏后使用
- **隔离环境**：高敏感数据在隔离环境中处理
- **审计日志**：记录所有数据访问操作

### 2.4 合规审查

| 合规领域 | 说明 | 关键法规 |
|:---|:---|:---|
| 跨境传输 | 数据跨境传输限制 | GDPR, 数据安全法 |
| 版权 | 数据版权合规 | 著作权法, CC License |
| 个人信息 | 个人信息保护 | GDPR, PIPL |
| 行业监管 | 行业特定法规 | HIPAA(医疗), PCI-DSS(支付) |
| 供应商条款 | 第三方数据使用限制 | 数据采购协议 |

## 3. 数据生命周期管理

```text
创建/采集 → 分类分级 → 存储 → 使用/共享 → 归档 → 销毁
    ↓          ↓         ↓        ↓          ↓       ↓
  许可记录   敏感标记   加密    审计日志   压缩   不可逆删除
```

### 3.1 创建/采集阶段

- 记录数据来源和许可
- 执行 PII 检测
- 标注敏感等级

### 3.2 存储阶段

- 按敏感等级分区存储
- 加密存储
- 访问控制

### 3.3 使用/共享阶段

- 记录使用目的
- 审批流程
- 审计日志

### 3.4 归档/销毁阶段

- 到期自动归档或删除
- 删除需不可逆
- 保留删除证明

## 4. 隐私保护技术

### 4.1 匿名化 vs 假名化

| 方法 | 说明 | 可逆性 |
|:---|:---|:---|
| 匿名化 | 不可逆地去除标识信息 | 不可逆 |
| 假名化 | 用假名替换标识，保留映射 | 可逆（需密钥） |
| 聚合 | 将个体数据聚合为统计值 | 不可逆 |
| 差分隐私 | 在数据中注入噪声 | 不可逆 |

### 4.2 差分隐私

```text
差分隐私 = 在查询结果中注入校准噪声，使单个记录的存在不影响输出

ε-差分隐私: Pr[M(D)] ∈ S ≤ e^ε × Pr[M(D')] ∈ S

D 和 D' 只差一条记录
ε 越小 → 隐私保护越强 → 数据效用越低
```

### 4.3 联邦学习

- **方法**：数据不出本地，只共享模型梯度
- **适用**：多方协作训练，数据不互通
- **挑战**：梯度泄漏、通信开销

## 5. 数据合约 (Data Contract)

### 5.1 什么是数据合约

数据生产者与消费者之间的正式协议：

```yaml
data_contract:
  name: "user_interaction_log"
  version: "1.2.0"
  producer: "data_platform_team"
  consumers: ["ml_training_team", "analytics_team"]

  schema:
    - name: user_id
      type: string
      required: true
      pii: true
    - name: query
      type: string
      required: true
    - name: timestamp
      type: datetime
      required: true

  quality_sla:
    freshness: "max 1 hour delay"
    completeness: ">= 99.5%"
    accuracy: ">= 95%"

  retention: "90 days"
  refresh_frequency: "real-time"
```

### 5.2 合约管理

- **注册**：所有数据合约在中心注册
- **版本化**：合约变更需版本升级
- **审批**：破坏性变更需消费者同意
- **监控**：自动检查合约 SLA 是否满足

## 6. 审计与合规报告

### 6.1 审计日志

记录所有数据操作：

| 字段 | 说明 |
|:---|:---|
| timestamp | 操作时间 |
| actor | 操作者（用户/服务） |
| action | 操作类型（读/写/删除/导出） |
| resource | 数据资源 ID |
| purpose | 使用目的 |
| result | 操作结果 |
| ip_address | 操作来源 IP |

### 6.2 合规报告

| 报告类型 | 频率 | 内容 |
|:---|:---|:---|
| 数据使用报告 | 月度 | 各团队数据使用量与用途 |
| 访问审计报告 | 季度 | 异常访问检测 |
| 删除请求报告 | 月度 | 用户删除请求处理情况 |
| 合规检查报告 | 年度 | 全面合规审查 |

## 7. 常见问题

- **目录不完整**：数据资产未全部登记，存在"影子数据"
- **许可不清**：数据来源许可不明，存在法律风险
- **权限过宽**：为方便使用授予过大权限
- **审计缺失**：数据操作未记录，事后无法追溯
- **删除不彻底**：删除请求未完全执行，备份残留
