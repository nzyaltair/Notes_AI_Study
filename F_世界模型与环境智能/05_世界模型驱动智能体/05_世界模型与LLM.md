# 世界模型与 LLM

## 一句话理解

LLM 擅长语言知识、计划表述和工具调用，但文本续写并不保证对当前环境状态、执行副作用或物理约束有校准预测；世界模型可补足这一缺口，两者应协同而非互替。

## 概述

LLM 在大规模语料中学到了大量"世界通常如何运作"的常识，可作为**软世界模型**提供粗粒度预测与方案生成；但其预测缺乏对当前环境状态的锚定，可能产生"看似合理实则错误"的幻觉（如 reversal curse 显示 LLM 对训练中出现过的关系也不总能正确推理）。因此需要把语言计划落到可验证的环境状态与动作语义上。

## 协同模式

- **LLM 提议，世界模型验证**：LLM 生成目标、计划、代码或工具调用，世界模型模拟后果并筛选。
- **状态摘要供给 LLM**：世界模型把空间、网页、软件或机器人状态压缩为结构化摘要，供 LLM 查询与推理。
- **失败归因与数据采集**：LLM 将失败轨迹解释为规则/假设，指导采集新的验证数据并更新世界模型。
- **LLM 生成环境**：LLM 编写任务规则、奖励设计或场景脚本，扩展仿真环境（见 [[../../04_环境模拟与数字孪生/06_大规模环境生成|大规模环境生成]]）。

## 关键区分

| 维度 | LLM 软世界模型 | 可验证世界模型 |
|---|---|---|
| 状态锚定 | 弱（依赖上下文） | 强（显式状态估计） |
| 预测校准 | 弱（易幻觉） | 可校准、可检验 |
| 行动条件 | 文本层 | 状态/动作层 |
| 更新方式 | 提示/微调 | 交互数据持续更新 |

## 工程要点

关键是使语言计划可落到**明确状态、动作和可验证后置条件**，避免仅以语言自洽替代环境验证。工具/API 环境的副作用（幂等性、失败恢复、权限）必须由执行层审计，不能依赖 LLM 自述。
