# 多模态对齐与统一建模

## 一句话理解

多模态对齐使来自不同模态的相关内容在表示或生成过程中相互约束；统一建模则进一步用共享 token/潜变量或共享主干处理多类输入输出。

## 对齐的层次

| 层次 | 问题 | 常见方法 |
|---|---|---|
| 语义对齐 | 图像和文本是否表达相近概念？ | 对比学习、配对数据 |
| 细粒度对齐 | 词语对应哪个区域/时间片段？ | 跨注意力、区域/时间监督 |
| 生成对齐 | 输出是否满足另一模态条件？ | 条件似然、扩散、偏好反馈 |
| 交互对齐 | 多轮输入是否保持一致状态？ | 时序上下文、记忆与工具反馈 |

## CLIP：对比语言-图像预训练（2021）

> CS336 视角：CLIP 是现代 VLM 的许多基础的源头，值得深入拆解（P17）。

### 历史背景

GPT-3 之后语言领域已进入基础模型时代——只需抓取互联网文本，数据噪声很大，但只要训练足够大的模型就能从中提取意义。而当时的视觉领域仍依赖大规模人工标注数据集（ImageNet 上训练 ResNet，配合数据增强）。OpenAI 的问题是：**图像领域的等效方案是什么？** 答案是利用海量的"网络图像 + 文本描述"对。

### 目标函数：批内对比 = 2N 次 softmax 分类

设批内 $N$ 个图文对，图像编码为 $I_1,\dots,I_N$，文本编码为 $T_1,\dots,T_N$：

1. 嵌入归一化后计算 $N\times N$ 相似度矩阵（点积，带温度系数）
2. 对每行（图像 → 所有文本）与每列（文本 → 所有图像）分别做 softmax 交叉熵
3. 对角线元素为正样本，非对角线为负样本

CLIP 曾尝试的替代目标：从图像直接预测 caption（词袋形式）。结论是**精确建模 caption 的 token 序列对获取图像的粗粒度（分类级）表示并不关键**——对比排序目标反而更高效。

### 为什么用图文对而不是纯数据增强

纯对比自监督（同一图像的两个增强视图应有相似嵌入）只能捕捉**低级细节不变性**——数据增强无法把一只狗变成另一种狗；而配对文本提供**高阶语义信息**作为图像表示的监督信号。代价是过程噪声很大（配对错配、caption 提及其他物体），平均意义上有效，但需要大量数据过滤。

### 数据

- **WIT**（Web Image Text）：查询词驱动的网络搜索挖掘，约 4 亿图文对，未公开
- **OpenCLIP**：开源复现；构建 **LAION-5B**（50 亿带文本描述的图像）并公开
- **自举（bootstrapping）**：先用 CLIP 筛选数据，再训练 OpenCLIP——数据质量依赖模型自身

### 关键成果：零样本分类

CLIP 在 ImageNet 上实现零样本分类（图像嵌入与各标签文本嵌入比点积取最大），性能超越在 120 万张人工标注图像上训练的监督模型——后者依赖 Mechanical Turk 工人的大量清洗工时。注意其设计决策以图像分类为导向，粒度并不精细，但为后续 VLM 提供了稳健起点。

### 工程局限：损失与批量大小耦合

CLIP 需要极大的批量（约 32K）；softmax 在**整个批量**上归一化，样本间存在交互，缺乏可分解性——与语言模型训练（批内序列完全独立、最后聚合）形成对比。批量变小则损失函数本身退化。

## SigLIP：sigmoid 损失解耦批量（2023，Google）

SigLIP（Sigmoid Loss for Language Image Pre-training）将 $N\times N$ 多类分类简化为**独立二分类**：

- 相似度矩阵每个位置独立过 log-sigmoid；对角线标签为正，非对角线为负
- 不需要在批量内做 softmax 归一化 → **批量大小与损失解耦**

| 维度 | CLIP | SigLIP |
|---|---|---|
| 损失形式 | 批内 softmax 交叉熵（2N 次分类） | 逐元素 log-sigmoid 二分类 |
| 批量依赖 | 强（小批量损失退化） | 弱（小批量只是方差大、期望无偏） |
| 训练效率 | 256 卡 × 10 天 | 32 卡 × 5 天（单步 FLOPs 甚至慢 ~60%，优势在互联与可分解性） |
| 数据 | WIT 400M（未公开） | WebLI 约 10 亿图文对（含 OCR 文本、多语言、过滤） |

**并行化方式**：类似 DDP——每个设备持有一部分图文对，先各自计算局部损失，再通过多轮文本嵌入交换覆盖所有非对角线块。这本质上是把"样本间交互"从损失计算中移到通信中。更大批量并未带来实质帮助；SigLIP 2（2025）沿用相同架构做向后兼容的改进，成为 Qwen3-VL 等新一代 VLM 的默认视觉编码器。

## 统一建模的取舍

共享序列接口便于跨模态生成和模型复用，但不同模态的 token 密度、采样频率和噪声性质差异很大。实际系统常采用"专用编码器 + 连接器 + 共享主干"的折中方案，而非强行把所有信号离散成同一种 token。

统一离散 token 路线的极端尝试是 Chameleon（早期融合，详见 [[07_全模态与原生多模态模型]]）：文本与图像 token 熵特性差异大（文本下一 token 熵低、图像 token 熵极高），混合训练引发范数增长与不稳定，需要 QK-Norm 与 Z-loss 干预——"把图像称作 token 并不能改变图像的本质"。

## 失败模式

- 配对数据错配或网络文本偏差导致伪相关。
- 视觉/音频信息在压缩连接器中丢失。
- 语言主干以先验补全缺失感知，形成多模态幻觉。
- 模态缺失、时间不同步和对抗输入使离线基准失真。
