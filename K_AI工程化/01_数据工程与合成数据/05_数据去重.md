# 数据去重

## 一句话理解

去重降低训练重复、数据泄漏和记忆风险并减少无效算力消耗——从精确去重（内容哈希）到近似去重（MinHash/SimHash）再到语义去重（向量近邻），需在文档、段落和样本三种粒度执行，且必须在切分训练/验证集之前完成。

## 1. 概述

重复数据对模型训练有多重负面影响：

| 影响 | 说明 | 严重程度 |
|:---|:---|:---|
| 训练效率降低 | 重复数据浪费计算资源 | 中 |
| 模型记忆 | 模型死记硬背重复内容，降低泛化；若为版权内容则引发逐字复现风险 | 高 |
| 数据泄漏 | 测试集内容出现在训练集中，评测虚高 | 极高 |
| 分布偏差 | 重复的高频内容主导训练分布 | 高 |
| 评估失真 | 评测集被污染，无法反映真实能力 | 极高 |

**重复的典型来源**（网页规模数据中无处不在）：

- **镜像站**：爬虫不智能时同一内容被抓多份（完全重复）
- **Fork**：fork 一个仓库后修改通常只涉及少数文件，99% 内容未变
- **许可证/服务条款模板**：MIT 许可证文本在网络中精确重复千万次（仅许可文本相同，所在页面其余部分不同）
- **模板页换实体**：同一模板把“加拿大”替换成“美国”生成变体——用这些变体训练就是浪费 GPU
- **排版微差**：同一文章仅差一个逗号（LM1B 基准中发现）
- **极端案例**：C4 审计发现同一段防毒面具产品描述出现了 6.1 万次

研究表明，去重后训练效率可提升 20-40%，模型泛化能力显著提升。与去重相关的**去污染**（decontamination）甚至更重要：确保评测集不在训练集中（见 2.4 跨集合去重）。

## 2. 去重层次

### 2.1 精确去重

检测完全相同的文档或文件：

- **方法**：计算内容的哈希值（MD5/SHA-256），哈希相同则为重复
- **优点**：速度快、精确
- **局限**：只能检测完全相同的副本
- **适用**：文件级去重、数据库记录去重

```python
import hashlib
def exact_dedup(doc: str) -> str:
    return hashlib.md5(doc.encode()).hexdigest()
# 相同哈希 = 完全相同文档
```

**C4 的变体**：T5 对 CommonCrawl 做“三句跨度”的精确去重——找到含相同三句跨度的文档并移除该跨度。直接从文档中删三句话会破坏文本连贯性，但当年就是这么做的；工程实现上常用 map-reduce 风格分片以便并行化。

### 2.2 近似去重

检测表面略有不同但实质相同的文档：

| 方法 | 核心思想 | 复杂度 |
|:---|:---|:---|
| MinHash | 用随机哈希函数逼近 Jaccard 相似度 | O(n × k) |
| SimHash | 将文档压缩为指纹，海明距离判断相似 | O(n) |
| n-gram Jaccard | 直接计算 n-gram 集合的 Jaccard | O(n²) |
| LSH (Locality-Sensitive Hashing) | 将相似项映射到相同桶 | O(n) |

**LSH 分带（Banding）：把期望变成相变**

将 n 个 MinHash 哈希函数分成 b 个 band、每个 band 含 r 个哈希（如 12 个哈希 = 3 band × 4 哈希）。一个 band 内 r 个哈希全部相同才算该 band 匹配；任一 band 匹配即判定为候选重复对。对 Jaccard 相似度为 s 的文档对：

$$P[\text{碰撞}] = 1 - (1 - s^r)^b$$

- 单个 band 匹配概率 $s^r$ 随 r 指数衰减（低相似度几乎不可能全带匹配）
- b 个 band 至少一个匹配，把“至少一个”的概率锐化成 S 形曲线

**曲线形状即设计目标**：相似度低于阈值时匹配概率尽可能低、高于阈值时尽可能高，中间呈相变。例：b=10, r=10 时，s∈[0.7, 0.98] 对应碰撞概率 [0.25, 1]。两参数的调节方向：

| 调节 | 效果 |
|:---|:---|
| 增大 r（每带哈希数） | 阈值右移、曲线更陡——匹配更难（s=0.8 的碰撞概率可从 0.4 降到 0.008） |
| 增大 b（带数） | 阈值左移、匹配更容易 |

**阈值的解析近似**：相变临界点约在 $s^* \approx (1/b)^{1/r}$；调节 b、r 使 $s^*$ 等于目标阈值（如 0.9）。处于临界点时碰撞概率为 $1-(1-1/e) \approx 0.64$——随 b、r 增大，低于阈值处收敛到 0、高于阈值处收敛到 1。注意 b、r 过大带来存储与计算成本上升。

**MinHash 原理**：

```text
1. 将文档表示为 n-gram 集合
   doc1: {a, b, c, d}, doc2: {a, b, c, e}

2. 施加 k 个随机哈希函数
   h1: min(h1(a), h1(b), ...) → 签名第1位
   h2: min(h2(a), h2(b), ...) → 签名第2位
   ...

3. 对比签名
   签名相同位数 / k ≈ Jaccard 相似度

4. Jaccard 相似度
   J(A, B) = |A ∩ B| / |A ∪ B|
```

**为什么成立——排列视角的证明**：随机哈希函数在元素上诱导一个随机排列（如 4→3→1→5→2）；取 min 相当于看各自集合中排在首位的元素。两集合首位元素相同 ⟺ 排列选中的首行落在交集内，而首行均匀随机，因此：

$$P[\min h(A) = \min h(B)] = \frac{|A \cap B|}{|A \cup B|} = J(A, B)$$

这个性质刻意反直觉：一般哈希函数希望避免碰撞，而 MinHash 需要**以相似度为目标受控碰撞**——越相似的集合越容易撞到同一个值。100 个哈希函数的碰撞频率即为 Jaccard 的无偏估计（例：{1,2,3,4} vs {1,2,3,5} 的碰撞率收敛到 0.6）。

**但单个 MinHash 不够**：碰撞概率期望等于 Jaccard，但方差大、随机性强——碰撞发生并不意味着 Jaccard 超过阈值，反之亦然。要判定“J ≥ 0.99 才算重复”，需要把概率分布锐化成相变，这就引出 LSH 分带。

**SimHash 原理**：

```text
1. 对文档的每个特征（词/n-gram）计算哈希
2. 加权累加哈希值（词频为权重）
3. 生成指纹（正→1，负→0）
4. 海明距离 ≤ 3 → 近似重复
```

### 2.3 语义去重

检测表面不同但语义相同的样本：

- **方法**：用 Embedding 模型将文档向量化，计算近邻
- **工具**：FAISS、Milvus、Qdrant 等向量数据库
- **阈值**：余弦相似度 > 0.85-0.95（根据任务调整）
- **适用**：改写、翻译、释义检测

```text
文档1: "如何训练大语言模型"
文档2: "大模型的训练方法是什么"
→ 表面完全不同，语义高度相似
→ 语义去重可检测
```

### 2.4 跨集合去重

防止数据泄漏的关键步骤：

| 去重范围 | 目的 |
|:---|:---|
| 训练集内部 | 减少训练冗余 |
| 训练集 vs 验证集 | 防止评测虚高 |
| 训练集 vs 测试集 | 防止数据泄漏 |
| 训练集 vs 基准集 | 防止基准污染 |
| 训练集 vs 检索库 | 防止 RAG 系统作弊 |

## 3. 去重粒度

| 粒度 | 说明 | 适用场景 |
|:---|:---|:---|
| 文档级 | 整篇文档去重 | 预训练数据 |
| 段落级 | 段落/章节去重 | 长文档处理 |
| 样本级 | 单条训练样本去重 | SFT/评测数据 |
| 句子级 | 句子级去重 | 精细清洗 |

多粒度去重策略：先文档级粗筛，再段落级细筛。

## 4. 工程实践

### 4.1 去重流程

```text
全部文档
    ↓ 精确去重 (哈希)
    ↓ 近似去重 (MinHash + LSH)
    ↓ 语义去重 (Embedding + 近邻搜索)
    ↓ 跨集合去重 (与评测集对比)
    ↓ 去重后数据集
```

### 4.2 大规模去重优化

PB 级数据去重的工程挑战：

| 挑战 | 解决方案 |
|:---|:---|
| 内存不足 | 分片处理 + LSH 分桶 |
| 计算量大 | 分布式计算 (Spark/Ray) |
| 存储开销 | 布隆过滤器 (Bloom Filter) |
| 增量去重 | 维护已有指纹库，新数据查重 |

### 4.3 去重记录

去重后需记录：

- **保留代表**：每个重复簇中保留哪个文档
- **相似阈值**：使用的相似度阈值
- **簇大小**：每个重复簇的文档数量
- **删除比例**：去重删除的数据比例

### 4.4 特殊数据指纹

| 数据类型 | 指纹方法 | 说明 |
|:---|:---|:---|
| 代码 | AST + 标识符归一化 | 忽略变量名变化 |
| 表格 | 结构 + 值哈希 | 忽略格式差异 |
| 多模态 | 图像感知哈希 (pHash) | 忽略压缩/缩放 |
| 数学公式 | LaTeX 归一化 | 忽略空格/格式 |

## 5. 去重效果评估

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 去重率 | 删除数据占原始数据的比例 | 10-30% |
| 误删率 | 被错误删除的非重复数据 | ≤ 2% |
| 残留重复率 | 去重后仍存在的重复 | ≤ 1% |
| 训练效率提升 | 去重后训练速度提升 | 15-30% |
| 泛化改善 | 去重后模型泛化能力提升 | 显著 |

## 6. 常见问题

- **过度去重**：语义去重阈值过低导致不同主题数据被删
- **去重不足**：只做精确去重，遗漏近似重复
- **跨集污染**：未做跨集合去重导致评测虚高
- **增量去重遗漏**：新增数据未与历史数据比对
- **代码去重困难**：代码重构后表面变化大但逻辑相同
