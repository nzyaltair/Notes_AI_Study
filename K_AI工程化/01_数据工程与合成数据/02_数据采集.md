# 数据采集

## 一句话理解

数据采集是按任务、授权与代表性要求获取原始数据的过程，需明确目标分布、记录来源与许可、执行分层采样与隐私保护，并通过覆盖率、时效性、许可完整率等指标验收。

## 1. 概述

数据采集是数据工程的第一环，决定了后续所有处理的质量上限。AI 模型的能力受限于训练数据的覆盖面和质量，"Garbage In, Garbage Out"在 AI 时代依然成立。

采集的核心挑战：

- **代表性**：数据是否覆盖目标分布和长尾场景
- **合规性**：数据来源是否合法、是否有使用许可
- **时效性**：数据是否反映当前世界状态
- **隐私保护**：是否包含 PII 或敏感信息
- **规模与成本**：在有限预算下最大化数据价值

## 2. 数据来源

### 2.1 来源类型

| 来源类型 | 说明 | 示例 | 合规要点 |
|:---|:---|:---|:---|
| 公开语料 | 互联网公开数据 | CommonCrawl、Wikipedia、GitHub | 检查 License、robots.txt |
| 业务日志 | 产品运行产生的数据 | 用户点击、搜索、对话 | 用户同意、隐私政策 |
| 传感器数据 | 物理世界采集 | 摄像头、麦克风、GPS | 设备授权、数据最小化 |
| 合作数据 | 第三方数据采购 | 数据供应商、API | 数据使用协议、审计权 |
| 人工采集 | 定向收集/标注 | 标注平台、专家录入 | 标注协议、知识产权 |
| 合成数据 | AI/程序生成 | Self-Instruct、仿真 | 生成模型版本记录 |

### 2.2 LLM 预训练数据来源

| 数据类型 | 典型来源 | 占比（参考） |
|:---|:---|:---|
| 网页文本 | CommonCrawl | 40-60% |
| 代码 | GitHub、StackOverflow | 5-15% |
| 书籍 | Books3、Gutenberg | 5-10% |
| 学术论文 | arXiv、PubMed | 5-10% |
| 百科知识 | Wikipedia、Wikidata | 2-5% |
| 对话数据 | Reddit、论坛 | 5-10% |
| 专业领域 | 法律、医疗、金融 | 5-10% |

### 2.3 「互联网数据」的真实边界

「语言模型用整个互联网训练」是常见误解。互联网本质是一堆在线运行的服务器，预训练用的是爬虫快照，而**技术可爬且合法可用的部分远小于整个网络**：

| 限制层 | 类型 | 说明 |
|:---|:---|:---|
| 动态内容 | 技术 | App 型页面（如 Discord）需点按钮/填表单才产生内容，`curl` 无法抓取 |
| 深网 | 技术 | 不经超链接可达的内容，传统爬虫图遍历触及不到 |
| 围墙花园 | 技术+法律 | Facebook/X/LinkedIn/纽约时报等登录墙内容——平台自己可直接用，外人拿不到 |
| robots.txt | 约定 | 非法律强制但应遵守：列出禁抓爬虫名单（GPTBot、ClaudeBot、PerplexityBot 等）；**2023 年中起完全限制 AI 爬虫的网站比例骤增至约半数** |
| 反爬机制 | 技术 | Cloudflare 验证码、IP/国家封禁、频率限制 |
| 服务条款（ToS） | 法律 | 2016 年几乎无网站写条款；如今多数网站明确禁止内容用于 AI 训练 |
| 影子图书馆 | 法律 | LibGen、Anna's Archive 绕过付费墙分发受版权书籍/论文，法律上属盗版（虽曾长期流入训练数据，见 Books3） |

> Longpre 等《Consent in Crisis》系统审计了 CommonCrawl 域名的限制趋势：2023 年中之前 robots.txt 完全限制的比例长期稳定，之后骤升；服务条款限制同步趋严。结论：**合法可爬的互联网比技术可爬的互联网小得多**。

### 2.4 CommonCrawl：事实上的公共爬虫

大多数头部厂商自建爬虫以完全掌控数据；其余玩家依赖 CommonCrawl（2007 年起运营）：

- **规模**：每月爬取约 30-50 亿网页，累计宣称约 3000 亿页面；单次转储约数百 TB（不含图片）；作为参照，Google 搜索索引规模估计在 100PB 以上
- **格式**：WARC（原始 HTTP 响应，无损）与 WET（抽取的纯文本，有损）；用哪个工具做 HTML→文本抽取对下游质量影响显著——trafilatura、resiliparse 优于官方 WET 输出（DataComp-LM 消融，见 [[03_数据清洗]]）
- **爬取机制**：URL frontier 图遍历——从种子 URL 出发，下载页面、解析超链接入队、多机并行；需遵守 robots.txt、控制礼貌性速率、制定重访策略（常变页面多爬、静页面不重爬）
- **重复陷阱**：同一 URL 因浏览器状态显示不同内容，而多个 URL 又可能指向同一内容（镜像站），不加处理会引入大量重复（见 [[05_数据去重]]）

### 2.5 高质量垂直来源

网络分布不均匀——少数区域集中了高质量内容，值得单独获取：

| 来源 | 规模 | 获取方式 | 注意事项 |
|:---|:---|:---|:---|
| Wikipedia | 6700 万+ 多语言条目 | 官方定期数据转储（tar 包），官方不鼓励直接爬取 | 不收原创研究、有显著性门槛；**投毒风险**：在 dump 生成前抢注入编辑可进入快照（研究已证实可注入负面向量，现已修复）——高质量源也可能被攻击 |
| GitHub | 4.2 亿仓库（2800 万公开） | 仓库内容走 git 协议克隆（不要爬网页）；issue/PR/star 等元数据走 GH Archive 小时级事件流 | 宽松许可（MIT/Apache）可用于训练；fork/复制导致大量重复；Software Heritage 聚合 GitHub/GitLab/Bitbucket 仓库 |
| arXiv | 300 万+ 提交 | 批量下载，PDF + 可选 LaTeX 源文件 | 元数据为宽松许可、大量论文可选 CC 协议；「在 arXiv 上训练」实际指用 LaTeX 源而非 PDF |
| StackExchange | 海量问答 | 官方数据转储 | 问答格式天然接近监督信号（网上本就存在“用户提问”式数据）；投票数等元数据可用于过滤 |
| Gutenberg | 公版书（PG19 数据集） | 直接下载 | 版权已过期、属公共领域 |

### 2.6 预训练数据集演进史

| 年份 | 数据集 | 规模 | 关键做法 |
|:---|:---|:---|:---|
| 2018 | BERT（Books+Wiki） | ~3.3B 词 | 书籍语料源自 Smashwords 免费电子书抓取，因违反 ToS 被下架——**免费可得 ≠ 法律允许** |
| 2019 | GPT-2 WebText | 40GB / 800 万页 | Reddit karma ≥ 3 的帖子外链页面（好帖子指向好网站）；开源复现版 OpenWebText |
| 2019 | C4（T5） | ~177B token / 800GB | 启发式规则清洗 CommonCrawl；删除花括号意外过滤掉所有代码 |
| 2020 | GPT-3 | ~400B token | 线性质量分类器（WebText 正样本 vs 随机 CC 负样本）；Books1/Books2 至今成谜 |
| 2020 | The Pile | 825GB / 22 源 | 社区拼装：CC、PubMed、GitHub、arXiv、Enron 邮件、Books3、Gutenberg… |
| 2021 | MassiveText（Gopher） | ~2.1T token 池 | 英文限定 + 人工规则过滤（拒绝模型过滤以保持掌控）；论文数据处理章节写得最细 |
| 2023 | Llama 1 | 1.4T token | CCNet + 「被 Wikipedia 引用的页面」作为质量代理；最后一个详细披露数据处理的开源范本 |
| 2023 | RefinedWeb（Falcon） | 5T token（发布 600B） | 「只用网络数据就够」论；刻意避开模型过滤以避免引入偏差 |
| 2024 | FineWeb（HuggingFace） | 15T token | RefinedWeb 复刻+改进：全量 CC 转储、手工规则过滤、去重、PII 移除 |
| 2024 | Dolma（AI2） | 3T token | CC + Stack + C4 + Reddit(PushShift) + Semantic Scholar；语言识别 + 规则 + 毒性分类器 |
| 2024 | DCLM（DataComp-LM） | 240T 池 → 3.8T token | 标准化过滤实验平台；fastText 质量分类器（正样本 OpenHermes，负样本 RefinedWeb）一度是开源黄金标准 |
| 2024 | Nemotron（NVIDIA） | 6T token | 认为 DCLM 过于激进；LLM 按「教育价值」打分→训练 fastText；低质量改写+高质量合成任务 |
| 2024 | The Stack v1/v2 | 3TB → 67.5TB | 仅宽松许可代码；v2 加入 issue/PR 元数据，低资源语言编译成 LLVM IR 与源码对照学习 |
| 2025 | Common Pile | ~8TB | 验证「只用宽松授权数据能走多远」：可达早期 Llama 水平，但难以竞争更大 token 预算 |

> **两个教训**：① Books3（影子图书馆 Bibliotik 的 20 万本书）曾随 The Pile 广泛流通并被 Llama 1 使用，引发诉讼后全面下架——早期版权决策的影响会持续多年，这也是各家不再公开数据细节的原因；② 论文宣称的 token 数可能重复计多个 epoch，横向比较需看唯一 token 数。

## 3. 采集设计

### 3.1 目标分布定义

采集前必须明确：

- **目标任务**：数据用于什么任务（预训练、SFT、评测）
- **目标分布**：期望的语言、领域、难度、长度分布
- **覆盖维度**：语言、地域、领域、难度、时间
- **许可边界**：哪些 License 的数据可用

### 3.2 分层采样

不使用简单随机采样，而是按维度分层：

```text
分层采样示例:
├── 语言: 中文 30%, 英文 50%, 其他 20%
├── 领域: 技术 25%, 科学 20%, 文学 15%, 新闻 20%, 其他 20%
├── 难度: 简单 30%, 中等 50%, 困难 20%
└── 时间: 近1年 40%, 1-3年 35%, 3年以上 25%
```

分层采样的目标：

- **避免偏差**：防止高频来源（如营销页面）淹没高质量内容
- **长尾覆盖**：确保低频但重要的领域有足够样本
- **多样性**：避免数据分布过于集中

### 3.3 增量采集

对于持续运行的数据管线：

- **变更检测**：基于 URL、hash、修改时间检测新内容
- **增量拉取**：只采集变更部分，降低带宽和存储
- **版本快照**：定期全量快照作为基准

## 4. 元数据记录

每条采集的数据必须记录：

| 字段 | 说明 |
|:---|:---|
| source_url | 数据来源 URL |
| source_type | 来源类型（web/code/book/...） |
| timestamp | 采集时间 |
| content_hash | 内容哈希（用于去重） |
| license | 数据许可证 |
| language | 检测到的语言 |
| quality_score | 初始质量评分（如可计算） |
| pii_flag | 是否检测到 PII |
| crawl_metadata | 爬取元数据（HTTP 状态、大小等） |

## 5. 隐私与合规

### 5.1 PII 识别

在采集入口执行 PII 检测：

- **类型**：姓名、邮箱、手机号、身份证号、地址、银行卡号
- **处理**：脱敏替换、删除、标记隔离
- **工具**：正则规则 + NER 模型组合

### 5.2 敏感内容隔离

- **有害内容**：暴力、色情、仇恨言论的检测与隔离
- **版权内容**：识别可能的版权材料，标记并评估
- **受限内容**：行业限制（如医疗数据需脱敏）

### 5.3 可删除性设计

- **用户数据删除**：支持按用户 ID 删除所有关联数据
- **GDPR/CCPA 合规**：Right to be Forgotten
- **数据溯源**：从训练数据到模型的可追溯链

### 5.4 版权基础：什么受保护

- **保护对象**：固定于有形媒介的原创性表达；**想法不受保护**——快速排序算法本身不可版权化，但其实现代码可以
- **门槛极低**：作品固定即自动受保护、无需注册（起诉前登记仅约 65 美元）——网上几乎所有内容默认有版权
- **保护期**：约 75 年（美国现行制度为作者终身 + 70 年），过期进入公共领域
- **不受保护**：事实本身、无独创性编排的汇编（如电话簿）
- **不只防逐字复制**：角色、故事情节同样受保护——模型“复刻哈利·波特角色”也可能侵权；n-gram 逐字重叠检测不能覆盖全部侵权形态

### 5.5 两条合法使用路径

| 路径 | 机制 | 说明 |
|:---|:---|:---|
| 许可（License） | 合同法 | Creative Commons（2001 年起）在公共领域与版权间架桥——Wikipedia、可汗学院、OpenCourseWare；或商业授权（内容平台与模型厂商的数据协议） |
| 合理使用（Fair Use, §107） | 判例法四因素 | ① 使用目的与转换性（教育、转换性使用更有利）② 原作性质（事实性比虚构性更有利）③ 使用量（小部分比整部更有利）④ 市场影响（替代原作市场则不利）；四因素是倾向而非硬性规定 |

> **许可陷阱——许可洗白**：数据集层面的宽松许可不自动适用于其中单个作品。任何人都可以给版权作品贴 CC 标签；HuggingFace 上许多标着宽松许可的数据集，逐作品核查后并非如此。Common Pile 为此做了逐作品许可验证。

### 5.6 训练合法性的判例进展（截至 2026）

- **作者协会诉 Google（Google Books）**：展示版权书籍片段被认定合理使用，历经 11 年胜诉——为语言模型训练的类比论证提供先例
- **NYT 诉 OpenAI**：以“能诱导 ChatGPT 近逐字复现新闻报道”为证据，进行中
- **Anthropic 案（2025 里程碑判决）**：**买书并扫描自用 = 合理使用；下载盗版 = 不合理使用**——两者分开裁决；最终以约 15 亿美元和解，“先盗版再补买”不能免责
- **Meta 案**：训练本身被认定合理使用，但用 BitTorrent 下载 LibGen 盗版书的行为另案处理中
- **当前共识**：在合法获取副本上训练，目前“未被认定为不属于合理使用”；领域仍在快速演变，订阅式许可变更后新增内容不可继续使用

## 6. 验收指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 覆盖率 | 目标维度的覆盖比例 | ≥ 95% |
| 时效性 | 数据最新时间距今 | ≤ 30 天 |
| 重复率 | 采集数据中的重复比例 | ≤ 5% |
| 缺失率 | 关键字段缺失比例 | ≤ 2% |
| 许可完整率 | 有明确 License 的数据比例 | 100% |
| 采集失败率 | 采集任务失败比例 | ≤ 1% |
| PII 命中率 | 含 PII 的数据比例 | ≤ 0.1%（脱敏后） |

## 7. 常见问题

- **数据偏差**：过度依赖单一来源导致分布偏差
- **许可不清**：数据 License 不明导致法律风险
- **采集风暴**：高频采集对目标站点造成压力
- **数据腐败**：传输/存储过程中数据损坏
- **冷启动**：新领域数据从零采集，周期长
- **重复陷阱**：镜像站、URL 别名导致同一内容多份副本（见 [[05_数据去重]]）
- **快照投毒**：数据转储前被注入恶意编辑（Wikipedia 案例）
