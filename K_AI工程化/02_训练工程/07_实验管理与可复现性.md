# 实验管理与可复现性

## 一句话理解

实验管理通过系统化记录每次训练的完整上下文（代码、数据、环境、参数、结果），确保任何实验结果可追溯、可复现、可比较。

## 概述

机器学习实验的本质是受控实验——要得出"方案 A 优于方案 B"的结论，必须控制所有变量。如果实验没有完整记录，就无法排除"差异来自随机种子或数据版本不同"等混淆因素。

本笔记回答的核心问题：
- 一次实验必须记录哪些信息？
- 什么是"可复现"？可复现到什么程度？
- 如何设计实验管理流程以支持团队协作？

## 核心概念

### 实验记录的最少信息

一次实验必须记录以下完整上下文：

| 类别 | 记录内容 |
|---|---|
| 任务定义 | 目标、数据集、评测协议 |
| 代码版本 | commit hash、diff、分支 |
| 运行环境 | 容器镜像、Python 版本、库版本 |
| 数据版本 | 数据 manifest（文件名 + hash）、数据版本号 |
| 随机性 | 随机种子（Python、NumPy、PyTorch、CUDA） |
| 硬件拓扑 | GPU 数量、型号、并行配置 |
| 超参数 | 所有配置参数 |
| 训练指标 | loss 曲线、学习率、梯度范数等 |
| 评测结果 | Benchmark 分数、人工评测 |
| 工件 | 模型权重、日志、输出样本 |
| 失败信息 | 错误类型、异常日志、失败原因 |

### 可复现的层次

| 层次 | 定义 | 难度 |
|---|---|---|
| 位级复现 | 完全相同的权重和 loss 曲线 | 极难（需控制所有非确定性） |
| 统计复现 | 相同分布的结果（均值和方差在容差内） | 可行 |
| 结论复现 | 相同的结论（A 优于 B 的判断不变） | 标准 |

## 技术原理

### 非确定性来源

| 来源 | 说明 | 可控性 |
|---|---|---|
| 随机种子 | Python/NumPy/PyTorch RNG | 可固定 |
| CUDA 非确定性 | atomicAdd 顺序不确定 | 部分可控（`torch.use_deterministic_algorithms`） |
| cuDNN 算法选择 | 自动选择最快算法 | 可固定为确定性算法（但变慢） |
| 分布式通信 | All-Reduce 浮点累加顺序不确定 | 不可完全控制 |
| 数据加载顺序 | 多 worker 异步加载 | 可固定（但影响性能） |

### 统计容差

分布式训练下位级复现通常不可行，应定义统计容差：

- 重复运行 $k$ 次（如 3-5 次）
- 计算关键指标的均值 $\mu$ 和标准差 $\sigma$
- 定义接受区间：$[\mu - 2\sigma, \mu + 2\sigma]$
- 复现结果落入区间即视为可复现

### 实验追踪系统

实验追踪系统应支持：

| 功能 | 说明 |
|---|---|
| 自动记录 | 最小化手动记录，自动捕获代码版本、环境、参数 |
| 实验对比 | 多次实验的指标曲线叠加比较 |
| 工件管理 | 模型权重、日志等工件与实验记录关联 |
| 搜索与过滤 | 按参数、指标、标签搜索历史实验 |
| 协作与共享 | 团队成员可查看和复用实验 |
| 血缘追踪 | 从数据 → 代码 → 实验 → 模型 → 部署的完整链路 |

### 配置管理最佳实践

使用结构化配置文件（如 YAML/Hydra）管理实验配置：

- 所有超参数在配置文件中定义，不在代码中硬编码
- 配置文件纳入版本控制
- 每次实验自动保存当时使用的配置文件
- 支持配置继承和覆盖（base config + override）

## 优势与局限

### 优势

- 避免"我不知道这个结果怎么来的"
- 支持团队协作和知识积累
- 便于发现和纠正错误

### 局限

- 完整记录增加开发开销
- 工具链集成需要前期投入
- 位级复现在实践中通常不可行

## 应用场景

- 预训练实验：记录完整的训练配置和数据版本
- 消融实验：系统化对比不同设计选择的影响
- 微调实验：记录基础模型版本 + 微调数据 + 超参数
- 评测实验：记录评测协议、数据集版本和结果

## 常见问题

- **可复现为什么不等于位级一致？**：CUDA 的 atomicAdd、cuDNN 算法选择、分布式 All-Reduce 的浮点累加顺序都存在非确定性。即使固定所有随机种子，也无法保证位级一致。
- **用文件名做版本管理为什么不行？**：`model_v2_final_final_really_final.pt` 无法回答"它用了什么数据""和 v1 有什么区别"等问题。实验追踪系统提供结构化元数据和搜索能力。
- **实验追踪和 Git 有什么关系？**：Git 管理代码，实验追踪管理训练运行（代码 + 数据 + 环境 + 参数 + 结果的完整快照）。实验追踪记录会引用 Git commit hash。
