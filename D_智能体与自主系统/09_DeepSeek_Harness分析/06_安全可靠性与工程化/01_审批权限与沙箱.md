# 审批、权限与沙箱

## 一句话理解

审批决定一次工具调用是否获得用户授权，权限预设组织策略选择，沙箱约束进程与文件效果；三者相互配合，但不能把其中任一层当作其他层的替代品。

---

## 分层防护模型

```
工具调用请求
  │
  ▼
[1] tools/pre-execute waterfall
    ├── allow → 单调 guard 层
    ├── deny  → 直接拒绝
    └── ask   → ctx.approval.request()
                  ├── ApprovalPolicy: 'never' → 直接 rejected（不触达应答者）
                  └── ApprovalPolicy: 'ask' → approval/request waterfall 应答者链
                        ├── allowed-once → 单调 guard 层
                        └── rejected / cancelled / unavailable → 拒绝
  │
  ▼
[2] 单调 guard（ctx.tools.guard()）
    不可被后续插件放宽的最终拒绝策略
  │
  ▼
[3] ctx.sandbox（进程启动时）
    约束 argv 和文件效果；失败时默认关闭
  │
  ▼
[4] 文件系统自身（fs/write-intent、fs/edit-intent waterfall）
    读后编辑、写意图和路径策略
```

---

## 审批 seam：ctx.approval

### 会话级 ApprovalPolicy

`ApprovalPolicy` 决定在交互式应答者运行之前发生什么：

| 策略 | 行为 |
|---|---|
| `'ask'`（默认） | 委托给组合的应答者链；无应答者时默认 `unavailable` |
| `'never'` | 确定性地返回 `rejected`，不分发任何应答者（CI/无人值守模式） |

**生效机制**：会话日志中最后一条 `approval/policy` 事件决定生效值，回退到服务配置；`setApprovalPolicy(session, policy)` 是唯一的写入路径，确保回放能重建覆盖值。

### ApprovalOutcome（闭合结果集）

| 值 | 含义 |
|---|---|
| `'allowed-once'` | 仅授权所询问的那一个操作（单次授权） |
| `'rejected'` | 明确拒绝 |
| `'cancelled'` | 请求被撤回（signal 触发） |
| `'unavailable'` | 应答者缺失/不负责/抛异常/不合规；**调用方失败关闭**（fail closed） |

> `never` 策略在 waterfall 分发**之前**强制执行，即使以 `prepend` 注册的应答者也无法绕过。

### ApprovalRequest 字段

| 字段 | 说明 |
|---|---|
| `agent` | 请求方 agent（路由和审计的锚点） |
| `toolName` | 所审批的工具名（展示与审计用） |
| `callId?` | 精确工具调用 id（让 UI 将提示附到已流式展示的调用上，不重复渲染参数） |
| `reason?` | 人类可读的审批原因 |
| `signal?` | 撤回信号（`abort` → 立即结算为 `cancelled`，丢弃晚到的应答） |

### 分发与审计事件

执行顺序：
1. 追加 `approval/asked`（log-only，含 `ApprovalRequestId`、`toolName`、`callId?`、`reason?`）；
2. 运行 `approval/request` waterfall，第一个应答者占唯一决策槽位；
3. 追加 `approval/decided`（log-only，含相同 `id` + `ApprovalOutcome`）；
4. 以结果完成，调用方执行对应逻辑。

**审计事件仅写入日志**，不进入模型 transcript；模型可见的行为是调用方派生的工具结果与当前运行时上下文快照。

### 委托（Delegation）语义

父子代理之间可通过 `approval/policy { source: 'delegation' }` 事件将策略注入子会话；`source: 'delegation'` 标记区分注入的覆盖与运行时切换。

---

## 权限预设：ctx.permissionPresets

`permission/preset` 事件（log-only）记录所选 preset；`effectivePermissionPreset` 读取会话日志中最后一条该事件，在 Bundle 匹配时保留选择。

权限预设是批量切换策略的快捷方式，实际策略仍通过各自的 seam（`approval/policy`、`sandbox/mode` 等）控制。

---

## 沙箱：ctx.sandbox / ctx.sandboxPolicy

`ctx.sandbox`（seam）控制**进程隔离**（Landlock、e2b 等机制）；`ctx.sandboxPolicy`（core）控制**按会话沙箱模式**。

### SandboxMode 事件

`sandbox/mode { mode, source? }` — log-only：
- `source?: 'delegation'`：子代理委托注入的覆盖；
- 最后一条生效；无事件则回退到服务配置。

### 失败策略

沙箱不可用时**默认关闭**（fail closed），而非静默放行；`RunnerFailureRule` 将 Landlock 致命诊断映射为退出码 125，明确区分致命证据与信息性通知（参见故障复盘 0004）。

---

## 实践规则

- **缺少可响应审批方时默认拒绝**，不能把"没人回答"解释为允许（`unavailable` → fail closed）；
- 将能力授权限定到 session、workspace 与具体操作，不以"模型可信"替代隔离；
- Python 最小组合的 `danger-full-access` 仅适合临时 checkout 或容器；
- 审批审计应写入会话事实（`approval/asked`/`approval/decided`），方便恢复和追责；
- 三层（审批、单调 guard、沙箱）互补，不互相替代；未声明的安全属性不是隐性提供的。
