# 训练成本与容量规划

## 一句话理解

将模型规模、数据量、序列长度和并行策略转化为 GPU 时、存储、网络和预算需求，在训练前估算总成本并在训练中追踪资源效率。

## 概述

大模型训练是计算密集型任务，一次 175B 参数模型预训练的成本可达数百万美元。容量规划的目标是在训练前估算资源需求，在训练中追踪资源利用率，并通过调度优化提高资源效率。

本笔记回答的核心问题：
- 如何估算训练所需的总 GPU 时和成本？
- 哪些因素影响训练效率？
- 如何通过调度和资源管理降低成本？

## 核心概念

### 计算量估算

训练所需总计算量可通过 Scaling Laws 估算：

$$C \approx 6 \times N \times D$$

其中 $N$ 为模型参数量，$D$ 为训练 token 数，$C$ 为总 FLOP。

| 模型规模 | 数据量 | 估算 FLOP | H100 GPU 时（50% MFU） |
|---|---|---|---|
| 7B | 1.4T tokens | $5.9 \times 10^{22}$ | ~6,500 |
| 70B | 1.4T tokens | $5.9 \times 10^{23}$ | ~65,000 |
| 175B | 3.0T tokens | $3.2 \times 10^{24}$ | ~350,000 |

### 成本构成

| 成本类别 | 说明 | 占比 |
|---|---|---|
| GPU 计算 | 训练 GPU 时 | 60-70% |
| 存储 | 数据存储 + 检查点存储 | 5-10% |
| 网络 | 跨节点通信带宽 | 5-10% |
| 人力 | 研究和工程团队 | 10-15% |
| 其他 | 电力、冷却、设施 | 5-10% |

### 关键效率指标

| 指标 | 定义 | 目标 |
|---|---|---|
| MFU | Model FLOPs Utilization | >40% |
| 有效 tokens/s | 每秒处理的有效 token 数 | 依赖模型规模 |
| GPU 利用率 | GPU 计算单元活跃比例 | >80% |
| 闲置比例 | 空闲 GPU 时 / 总 GPU 时 | <15% |
| 单有效 token 成本 | 总成本 / 有效 token 数 | 越低越好 |

## 技术原理

### 容量规划流程

#### 1. 计算量估算

根据模型参数量 $N$ 和训练数据量 $D$ 估算总 FLOP：

$$C = 6ND$$

考虑 MFU 后的实际 GPU 时：

$$\text{GPU 时} = \frac{C}{\text{GPU FLOPS} \times \text{MFU} \times 3600}$$

#### 2. 显存估算

确保模型 + 优化器状态 + 激活值适配到可用 GPU 显存。需考虑并行策略：

- ZeRO-3：$\frac{16N}{D_{\text{gpu}}}$
- TP + PP：按拓扑分配

#### 3. 数据 I/O 带宽

训练数据读取带宽需匹配 GPU 消费速度：

$$\text{所需带宽} = \frac{\text{tokens/s} \times \text{bytes/token}}{\text{压缩比}}$$

#### 4. 检查点存储

检查点总空间：

$$\text{检查点空间} = \text{单次检查点大小} \times \text{保留数量} \times \text{冗余系数}$$

#### 5. 失败重跑预算

根据 MTBF 估算故障概率，预留重跑预算：

$$\text{预期浪费} = \frac{\text{训练时长}}{\text{MTBF}} \times \text{检查点间隔} \times \text{GPU 时成本}$$

#### 6. 排队时间

共享集群中需考虑作业排队等待时间，取决于集群调度策略和优先级。

### 成本优化策略

| 策略 | 节省方式 | 代价 |
|---|---|---|
| Spot/抢占式实例 | 2-5 倍成本节省 | 可能中断，需容错 |
| 弹性调度 | 利用空闲资源 | 实现复杂 |
| 批量调度 | 合并小作业 | 延迟增加 |
| 模型压缩先训练 | 小模型迁移超参数 | 需验证迁移有效性 |
| 混合精度 + 优化 | 减少 GPU 时 | 数值风险 |
| 数据本地化 | 减少网络读取 | 存储冗余 |

## 关键方法与模型

### Chinchilla 最优计算分配

Hoffmann et al. (2022) 发现多数大模型训练存在"参数过剩、数据不足"的问题。对于给定计算预算 $C$，最优分配为：

$$N_{\text{opt}} \propto C^{0.5}, \quad D_{\text{opt}} \propto C^{0.5}$$

即模型和数据应等比例增长。Chinchilla 70B 用 1.4T tokens 训练，性能超过 175B 的 GPT-3（0.3T tokens）。

### LLaMA 的成本效率策略

LLaMA 系列通过以下策略降低训练成本：

- 使用更多数据（1.0-1.4T tokens）训练较小模型
- 高效的 Tokenizer（SentencePiece）减少 token 数
- 优化的训练框架（FlashAttention、高效并行）

## 优势与局限

### 有效的实践

- Scaling Laws 提供了可靠的计算量预估
- MFU 作为效率指标便于跨实验比较
- 容量规划使预算管理成为可能

### 局限

- 估算依赖经验参数（MFU、MTBF），偏差可能较大
- GPU 供应周期长，容量规划需提前数月
- 网络和存储的隐性成本容易被低估

## 常见问题

- **MFU 多少算正常？**：大模型训练 MFU 通常在 35-55%。低于 30% 说明有优化空间。
- **Spot 实例能用于大模型训练吗？**：可以，但需要完善的检查点和恢复机制。Spot 中断频率高于训练 MTBF 时收益有限。
- **如何估算 MFU？**：可以先在小规模（如 8 卡）上测试，然后按并行策略的扩展效率推算大规模 MFU。通常大规模效率低于小规模。
