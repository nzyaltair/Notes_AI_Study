# 层次规划与规划—RL 结合

## 一句话理解

长程任务不可能在原子动作层做全状态搜索——层次规划将任务分解为"高层选子目标、低层执行技能"的多级结构；规划与 RL 结合则让 LLM 的结构化推理能力与 RL 的试错学习能力互补，形成"规划验证结构、RL 学习执行"的协同模式。

## 概述

无论是经典规划（[[01_STRIPS_PDDL与HTN|STRIPS/PDDL]]）还是 LLM 规划（[[03_LLM规划与长程任务|CoT/ReAct]]），在原子动作层处理长程任务都面临同样的困境：搜索空间过大、步骤间依赖复杂、环境动态变化。**层次规划**（Hierarchical Planning）通过引入抽象层级解决这个问题：高层规划关注"宏观目标"（如"完成调研报告"），低层规划关注"具体执行"（如"点击搜索按钮"）。

与此同时，**规划与 RL 的结合**（Planning-RL Integration）试图融合两种范式的优势：规划提供结构化验证和可解释性，RL 提供不确定性下的自适应能力和经验学习。[[00_规划与推理_综述|规划与推理]] 提到"RL 处理反馈下的策略改进"，本笔记正是对这一结合范式——尤其是层次规划与 RL 结合——的详细展开。

## 发展历史

| 时间 | 里程碑 | 意义 |
|:---|:---|:---|
| 1999 | Options 框架（Sutton et al.） | 将多步策略封装为可调用的"技能"，层次 RL 的奠基 |
| 2003 | MAXQ 分层 RL（Dietterich） | 基于值函数分解的层次 RL 框架 |
| 2004 | 分层规划理论（Erol et al.） | HTN 规划的完整形式化 |
| 2017 | Hindsight Experience Replay（Andrychowicz et al.） | 让 RL 从失败中学习，目标条件 RL 的突破 |
| 2017 | HRL 结合深度 RL | 深度层次强化学习在复杂任务中展示效果 |
| 2020 | Skill-based RL | 学习可复用的技能库，作为规划的基本单元 |
| 2022- | LLM 作为高层规划器 + RL 作为低层执行器 | 分层规划与 RL 结合的新范式 |

## 核心概念

### 层次规划的三层抽象

| 层级 | 时间尺度 | 规划粒度 | 代表方法 |
|:---|:---|:---|:---|
| 战略层 | 小时/天级 | 子目标序列 | HTN、PDDL 规划 |
| 战术层 | 分/秒级 | 技能序列 | Options、Skill-based RL |
| 执行层 | 毫秒/秒级 | 原子动作 | MPC、RL 策略 |

### Options 框架

Options（Sutton et al., 1999）是层次 RL 的核心概念：一个 Option 是一个"带内部策略的宏动作"，包含三要素：

- **策略** $\pi(o \mid s)$：在 Option 内部如何选择动作
- **终止条件** $\beta(s)$：Option 何时结束
- **初始集** $I(s)$：Option 可以从哪些状态开始

```text
高层策略选择 Option → Option 内部策略执行多步动作
  → Option 终止（达到子目标或超时）→ 高层策略选择下一个 Option
```

Options 的直观含义："将"搜索"封装为一个可复用的技能——高层只要说"搜索"，不用关心具体怎么敲键盘、点搜索按钮。

### 规划与 RL 的互补关系

| 维度 | 规划（Planning） | 强化学习（RL） |
|:---|:---|:---|
| 环境模型 | 需要（显式或隐式） | 不需要（model-free）或需要（model-based） |
| 决策方式 | 前瞻搜索 | 记忆-策略映射 |
| 可验证性 | 高（可证明最优） | 低（无保证） |
| 不确定性处理 | 弱（需要在模型中显式建模） | 强（通过试错学习） |
| 样本效率 | 高（不需要交互） | 低（需要大量交互） |
| 泛化能力 | 对相同结构的问题强 | 对相似状态空间强 |

## 技术原理

### 层次规划的核心机制

**高层规划**：在抽象动作空间（子目标、技能、Options）中生成计划。抽象动作的"效果"定义在高层状态空间，不涉及低层执行细节。

**低层执行**：接收到高层指定的子目标或技能后，低层策略（可以是 RL 策略、规则或 LLM Agent）将子目标细化为具体的原子动作序列。

**层级间通信**：高层向低层传递"目标"，低层向高层返回"完成/失败/异常"信号。通信频率和信息的粒度影响整体效率。

### 规划与 RL 结合的三种模式

**模式一：规划生成数据，RL 学习策略**

使用规划器生成训练数据，用 RL 从数据中学习策略。特点是：规划器提供高质量的训练数据，RL 学到的策略在推理时不需要规划器。

**模式二：RL 提供执行器，规划提供验证**

RL 学到的策略作为"动作原语"，规划器负责在原语空间中选择和组合。特点是：规划器确保整体结构正确，RL 执行器确保具体动作适应环境。

**模式三：规划与 RL 交替迭代**

规划器生成计划 → 执行计划 → 收集反馈 → 更新 RL 策略 → 更新规划器。特点是：两者在持续交互中共同改进。

### 层次规划在 LLM Agent 中的实现

LLM Agent 中的层次规划表现为：

```text
高层：LLM 生成"宏观计划"（5-10 个里程碑）
  → 中层：每个里程碑由 LLM 或规则引擎分解为"技能序列"
    → 低层：每个技能由 RL 策略、规则或工具调用执行
      → 执行结果反馈回中层/高层，触发重规划
```

这种分层让 LLM 的有限上下文窗口专注在宏观层面，低层执行利用可复用的技能库（[[../05_记忆与持续学习/03_记忆巩固与经验学习|技能库]]），避免在每一步都需要 LLM 调用。

## 关键方法与模型

| 方法 | 层次结构 | 规划方式 | 学习方式 |
|:---|:---|:---|:---|
| Options | 高-低两层 | 高层选择 Option | 低层 Option 内部策略可学习 |
| MAXQ | 多层 | 值函数分解 | 各层值函数独立学习 |
| HRL (HIRO) | 高-低两层 | 高层选子目标 | 高层和低层策略独立更新 |
| SNN-HRL | 多层 | 高层选子目标 | 子目标对策略的约束 |
| Feudal Networks | 多层 | 高层下指令，低层执行 | 信息烟囱结构 |
| Plan-Skill | 高-低两层 | 规划器选技能 | 技能库可学习 |

## 优势与局限

**层次规划的优势**：将长程任务分解为可管理的子问题，降低搜索复杂度；抽象层级让高层规划不受低层细节影响，增强鲁棒性；技能/Options 可复用，在新任务中不需要从零开始学习。

**规划-RL 结合的优势**：规划的结构化验证弥补 RL 的不可解释性；RL 的试错学习弥补规划的不确定性处理不足；两者结合可以在样本效率和泛化能力之间取得更好的平衡。

**局限**：层次规划的设计依赖人工定义层级和抽象边界；层级间通信的信息丢失可能导致"高层目标与低层执行脱节"；规划-RL 结合增加了系统复杂度，调试和工程化困难。

## 应用场景

- **机器人操控**：高层规划"抓取杯子"，低层 RL 学习具体的抓取策略
- **游戏 AI**：高层规划"占领资源点"，低层 RL 学习具体的战斗和移动
- **Web Agent**：高层规划"完成预订流程"，低层执行具体的点击和输入操作
- **自动驾驶**：高层规划"从 A 到 B 的路径"，低层控制"方向盘和油门"

## 前沿发展

- **LLM 作为高层规划器 + RL 作为低层执行器**：LLM 理解任务并生成宏观计划，RL 策略执行具体技能
- **自动技能发现**：从经验数据中自动发现和抽象可复用的技能，减少人工定义
- **端到端可学习的层次规划**：层次结构本身成为可学习的参数，而非人工设计
- **多层级间的互信息优化**：设计层级间通信的信息量，使高层能精确指导低层又不约束过紧

## 常见问题

**Q: 层次规划中的"技能"和"Option"有什么区别？**
技能是更通用的概念，指任何可复用的行为单元；Option 是技能的形式化数学定义。在工程中，技能通常指"带输入输出接口的模块化行为"，Option 通常指"带内部策略和终止条件的马尔可夫选项"。两者在大部分情况下可互换使用。

**Q: 为什么层次规划在 LLM Agent 中特别重要？**
LLM 的上下文窗口有限，无法在单次推理中处理长程任务的所有细节。层次规划让 LLM 只关注高层决策，低层执行使用可复用的技能库或规则引擎，大幅降低对上下文的依赖。
