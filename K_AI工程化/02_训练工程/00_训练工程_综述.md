# 训练工程综述

## 一句话理解

训练工程是把算法和数据转化为高质量可部署模型的工程学科，核心任务是以可接受的时间、成本和稳定性，在数百至数万张 GPU 上完成大规模模型训练，并保证结果可复现、可追踪。

## 1. 领域定义

训练工程（Training Engineering）涵盖大模型训练全流程的工程实践：

- **分布式并行**：将计算、参数和数据切分到多设备协同运行
- **内存与通信优化**：在显存约束下最大化计算效率
- **训练稳定性**：保证长时间训练不发散、可恢复
- **实验管理**：版本化代码、数据、参数、结果，支持可复现
- **训练成本**：量化资源消耗，支持容量规划和工程权衡

训练工程在 AI 系统生命周期中处于数据工程下游、推理工程上游，是模型能力的直接生产环节。

| 时间 | 里程碑 | 意义 |

## 3. 核心挑战

### 3.1 四大工程瓶颈

| 维度 | 瓶颈 | 工程应对 |
|:---|:---|:---|
| **计算** | GPU 利用率低（通信等待、气泡） | 通信计算重叠、流水线调度优化 |
| **显存** | 参数 + 梯度 + 优化器状态超出单卡 | ZeRO、激活重计算、混合精度 |
| **通信** | AllReduce/AllGather 成为瓶颈 | 层级化通信、节点内 NVLink + 节点间 IB |
| **稳定性** | Loss Spike、节点故障、数值溢出 | 梯度裁剪、检查点、弹性容错 |

### 3.2 LLM 训练全流程

```text
数据准备（清洗/去重/配比）
    ↓
预训练（大规模语料，自监督）
    ↓
监督微调 SFT（指令遵循数据）
    ↓
偏好对齐（RLHF/DPO/PPO）
    ↓
评估与注册（离线基准 + 安全检查）
    ↓
部署（推理引擎 + 服务化）
```

## 4. 主要技术分支

### 4.1 分布式并行

| 策略 | 切分对象 | 适用规模 | 主要代价 |
|:---|:---|:---|:---|
| 数据并行 DP | 样本 | 所有规模 | 梯度同步通信 |
| 张量并行 TP | 层内矩阵 | 单节点大模型 | 高频 AllReduce |
| 流水线并行 PP | 模型层 | 超大规模 | Bubble、调度复杂 |
| 序列并行 SP | Token 维度 | 长上下文 | 注意力通信 |
| 专家并行 EP | MoE 专家 | MoE 模型 | All-to-all 通信 |

实践中大规模训练通常组合为 **3D 并行（DP × TP × PP）**，并根据集群拓扑（节点内 NVLink、节点间 InfiniBand）优化分配。

### 4.2 内存优化

- **ZeRO**：阶段 1/2/3 分别切分优化器状态、梯度和参数，Offload 可将部分状态移至 CPU/NVMe
- **激活重计算**：反向传播时重新计算激活值而非存储，以 30% 额外计算换取约 7 倍激活显存节省
- **混合精度**：FP32 主权重 + BF16/FP16 计算，既保持数值稳定又利用 Tensor Core 加速
- **FlashAttention**：分块注意力计算，将注意力层显存从 O(n²) 降至 O(n)

### 4.3 训练框架

| 框架 | 核心能力 | 主要场景 |
|:---|:---|:---|
| PyTorch FSDP | 参数分片，原生集成 | 通用分布式训练 |
| DeepSpeed | ZeRO、Offload、MoE | 大模型微调与预训练 |
| Megatron-LM | TP/PP/EP 高性能 Transformer | 超大规模预训练 |
| ColossalAI | 多种并行与内存优化 | 灵活实验 |

### 4.4 实验管理与可复现性

记录代码版本、容器环境、数据 manifest、随机种子、硬件拓扑、参数、指标和工件。使用 MLflow、W&B 等追踪系统。可复现不等于位级一致，分布式环境下需定义统计容差。

### 4.5 微调与对齐工程

- **SFT**：指令微调数据构造与配比，LoRA/QLoRA 高效微调
- **RLHF**：奖励模型训练 + PPO 策略优化，工程复杂度高
- **DPO**：直接偏好优化，无需奖励模型，工程相对简化
- **持续预训练**：在已有权重基础上继续训练新领域数据

## 5. 训练成本结构

训练成本 = GPU 时数 × 单位成本，决定因素：

- **模型规模**：参数量决定每步 FLOP，可用 Chinchilla 定律估计最优规模
- **数据量**：Token 数量决定步数（Chinchilla: 最优 token ≈ 20× 参数量）
- **MFU**（Model FLOP Utilization）：实际计算效率，大规模训练通常 40~60%
- **集群利用率**：节点故障、维护停机等导致的有效时间损失

容量规划公式（近似）：训练时间 = (6 × N × D) / (节点数 × 单卡算力 × MFU)，其中 N=参数量，D=Token数。

## 7. 前沿发展

- **FP8 训练**：H100 Transformer Engine 支持 FP8 前向 + FP16 梯度，进一步提升吞吐
- **长上下文训练**：Ring Attention、DeepSpeed Ulysses 实现 1M token 级训练
- **MoE 训练**：Mixtral、DeepSeek-MoE 等稀疏激活架构的规模化训练
- **持续学习**：在线数据增量训练，保留旧知识同时吸收新知识（灾难性遗忘问题）
- **多模态预训练**：图文音视频统一预训练的数据管线与架构工程
- **Disaggregated Training**：Prefill/Decode 分离思想延伸至训练（异构计算分离）
- **合成数据训练**：全合成数据集（含推理轨迹）推动 reasoning 模型训练
