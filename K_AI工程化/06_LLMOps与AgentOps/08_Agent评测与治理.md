# Agent 评测与治理

## 一句话理解

Agent 评测同时检查最终结果和执行过程——任务成功、工具参数正确性、步数、成本、恢复能力、权限违规和安全边界；治理措施包括策略门、沙箱、人工审批、Trace 审计、红队用例和事故复盘，开放环境任务必须设置最大预算、最大步数与明确停止条件。

## 1. Agent 评测的特殊性

Agent 评测不同于传统 ML 评测，也不同于 LLM 评测：

| 维度 | ML 评测 | LLM 评测 | Agent 评测 |
|:---|:---|:---|:---|
| 评测对象 | 模型输出 | 生成文本 | 执行轨迹 + 最终结果 |
| 过程关注 | 否 | 部分 | 是（路径影响安全性） |
| 多步推理 | 否 | 部分 | 是（多步工具调用） |
| 副作用 | 无 | 无 | 有（工具调用改变外部状态） |
| 成本维度 | 推理延迟 | Token | Token + 工具调用 + 时间 |
| 安全边界 | 模型输出 | 内容安全 | 工具权限 + 内容安全 |

核心原则：**不只看"做对了什么"，还要看"怎么做的"和"有没有做不该做的"**。

## 2. 评测维度

### 2.1 结果评测

| 指标 | 说明 | 评测方法 |
|:---|:---|:---|
| 任务成功率 | 最终是否完成用户任务 | 执行器验证 / 人工 |
| 答案质量 | 最终输出的质量 | LLM Judge / 人工 |
| 完整性 | 是否完成所有子任务 | 检查清单 |
| 准确性 | 结果信息是否准确 | 知识库校验 |

### 2.2 过程评测

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 步数效率 | 完成任务所用步数 vs 最优步数 | ≤ 最优 × 1.5 |
| 工具调用质量 | 参数正确性、必要性 | 参数正确率 ≥ 95% |
| 路径合理性 | 执行路径是否合理 | 人工评估 |
| 恢复能力 | 遇到错误后能否恢复 | 恢复成功率 ≥ 80% |
| 无效操作率 | 冗余/无效步骤比例 | ≤ 10% |

### 2.3 成本评测

| 指标 | 说明 |
|:---|:---|
| 总 Token 消耗 | 任务总输入 + 输出 Token |
| 工具调用次数 | 任务中工具调用总次数 |
| 执行时间 | 任务从开始到完成的总时间 |
| 资源消耗 | CPU、内存、API 调用次数 |
| 单位成本 | 每成功任务的平均成本 |

### 2.4 安全评测

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 权限违规率 | 调用未授权工具/参数的比例 | 0% |
| 越界操作率 | 执行超出任务范围操作的比例 | 0% |
| 数据泄漏率 | 输出中包含敏感信息的比例 | 0% |
| 越狱成功率 | 对抗测试中 Agent 被攻破的比例 | ≤ 1% |
| 审批绕过率 | 需审批操作被绕过的比例 | 0% |

## 3. 轨迹评测

### 3.1 轨迹数据结构

```text
Trajectory:
├── Step 1: LLM → 决定搜索
├── Step 2: Tool: search("query") → results
├── Step 3: LLM → 决定读取文件
├── Step 4: Tool: read_file("path") → content
├── Step 5: LLM → 生成答案
└── Result: "任务完成"
```

### 3.2 轨迹评分方法

| 方法 | 说明 | 适用场景 |
|:---|:---|:---|
| 最短路径对比 | 与最优轨迹对比步数 | 已知最优解的任务 |
| LLM Judge | 用强模型评估轨迹合理性 | 开放式任务 |
| 人工评估 | 专家审查轨迹 | 高风险场景 |
| 规则检查 | 检查是否违反约束 | 安全相关 |
| 回放验证 | 重放轨迹验证可复现性 | 调试 |

### 3.3 轨迹数据集

从生产 Agent Trace 中提取：

- **成功轨迹**：高效完成任务的轨迹，用于微调
- **失败轨迹**：任务失败的轨迹，用于改进
- **边界轨迹**：触发安全机制的轨迹，用于红队测试

## 4. Agent 治理

### 4.1 策略门 (Policy Gate)

在 Agent 执行关键节点设置策略检查：

```text
Agent 执行 → 策略门 → 检查通过 → 继续
              ↓
         检查失败 → 阻断 + 通知
```

策略门类型：

| 策略门 | 检查内容 | 触发条件 |
|:---|:---|:---|
| 工具调用前 | 权限、参数合法性 | 每次工具调用 |
| 高风险操作前 | 人工审批 | risk_level=high |
| 成本阈值 | Token/费用是否超限 | 每步检查 |
| 步数限制 | 是否超过最大步数 | 每步检查 |
| 内容输出前 | 安全过滤 | 最终输出 |

### 4.2 沙箱隔离

- **代码执行**：在容器沙箱中执行，限制网络和文件访问
- **工具执行**：工具在受限环境中运行，权限最小化
- **数据隔离**：Agent 只能访问授权的数据

### 4.3 人工审批

```text
高风险操作 → 暂停 Agent → 通知审批人
    ↓
审批人审查:
    ├── 参数是否合理
    ├── 操作是否必要
    └── 风险是否可控
    ↓
批准 → 继续执行
拒绝 → 终止 / 跳过 / 替代方案
超时 → 默认策略（拒绝/降级）
```

### 4.4 Trace 审计

所有 Agent 执行记录完整 Trace，用于：

- **事后审计**：追溯 Agent 行为
- **合规报告**：满足监管要求
- **事故调查**：分析故障原因
- **改进依据**：发现系统性问题

### 4.5 红队测试

定期对 Agent 进行对抗性测试：

- **Prompt 注入**：通过输入诱导 Agent 执行未授权操作
- **权限提升**：尝试调用高权限工具
- **数据泄漏**：尝试获取未授权数据
- **拒绝服务**：尝试消耗过多资源
- **社会工程**：模拟用户诱导 Agent

## 5. 开放环境治理

对于在开放环境中运行的 Agent（如浏览网页、操作软件）：

### 5.1 预算限制

| 预算类型 | 说明 |
|:---|:---|
| Token 预算 | 单任务最大 Token 消耗 |
| 步数预算 | 单任务最大执行步数 |
| 时间预算 | 单任务最大运行时间 |
| 工具调用预算 | 单任务最大工具调用次数 |
| 费用预算 | 单任务最大费用 |

### 5.2 停止条件

- **显式完成**：Agent 声明任务完成
- **预算耗尽**：任一预算达到上限
- **用户取消**：用户主动终止
- **安全触发**：安全策略门阻断
- **连续失败**：连续 N 步失败

### 5.3 紧急停止

```text
紧急停止信号 → 立即中断当前操作 → 保存状态 → 清理资源 → 通知运维
```

- **硬停止**：立即终止，不等待当前步骤完成
- **软停止**：完成当前步骤后停止
- **全局开关**：一键停止所有运行中 Agent

## 6. 事故复盘

### 6.1 事故分级

| 级别 | 说明 | 响应 |
|:---|:---|:---|
| P0 | 数据丢失/泄漏/安全 breach | 立即停止 + 高管通报 |
| P1 | Agent 执行未授权高风险操作 | 停止相关 Agent + 调查 |
| P2 | Agent 任务失败率突增 | 排查 + 降级 |
| P3 | 单个任务异常 | 记录 + 分析 |

### 6.2 复盘流程

```text
事故发生 → 紧急处置 → 收集 Trace → 根因分析
    → 改进措施 → 更新策略/评测集 → 验证 → 复盘文档
```

## 7. 评测集设计

### 7.1 任务分级

| 级别 | 说明 | 评测要求 |
|:---|:---|:---|
| L1 | 单步工具调用 | 参数正确性 |
| L2 | 多步顺序任务 | 路径正确性 + 结果 |
| L3 | 多步分支任务 | 决策正确性 + 恢复能力 |
| L4 | 开放环境任务 | 全维度 + 安全 |

### 7.2 评测环境

| 环境 | 说明 | 用途 |
|:---|:---|:---|
| 模拟环境 | Mock 工具，无真实副作用 | 快速评测 |
| 沙箱环境 | 真实工具但受限 | 集成测试 |
| 生产镜像 | 生产数据副本 | 发布前验证 |
| 生产环境 | 真实流量 | 在线监控 |

## 8. 常见问题

- **只评结果不评过程**：Agent 可能通过危险路径完成任务
- **评测集过简单**：真实场景的复杂度未覆盖
- **安全边界过松**：为追求任务成功率放宽安全限制
- **无红队测试**：只测正常流程，不测对抗场景
- **事故无复盘**：问题重复发生，无系统性改进
