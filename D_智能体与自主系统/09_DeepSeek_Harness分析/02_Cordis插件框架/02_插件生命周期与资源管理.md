# 插件生命周期与资源管理

## 一句话理解

Fiber 将插件的依赖、运行状态和资源所有权绑定在一起：依赖满足时加载，依赖消失时自动卸载，所有注册与 effect 清理随之撤销。

## 状态与依赖

典型状态为 `PENDING → LOADING → ACTIVE`，加载异常进入 `FAILED`，卸载经过 `UNLOADING → DISPOSED`。插件用 `inject` 声明所需服务；Cordis 只在依赖可用时执行 `apply`，提供方消失则会撤销依赖方，恢复时再加载。

## 资源管理规则

- `ctx.on()`、工具/适配器注册等由 Fiber 自动追踪。
- `ctx.effect(() => cleanup)` 管理连接、计时器、子进程等外部资源。
- 清理按注册逆序发起；多个异步清理可能并发，因此存在顺序依赖的释放步骤应放在同一个 cleanup 中。
- `ctx.plugin()` 创建子 Fiber；父插件卸载会递归卸载子插件。

## 实践判断

热重载安全的标准不是“新插件能加载”，而是 dispose 后旧注册、定时器和监听器确实消失。为每个注册表提供卸载后断言的测试，避免 HMR 重复注册。
