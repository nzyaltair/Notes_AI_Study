# 交互式模拟器

## 一句话理解

交互式模拟器要求生成环境对动作持续响应、状态跨回合保存，而不是播放预先生成的视频；它是生成式世界模型从"预测"走向"可训练环境"的关键形态。

## 概述

交互式生成把用户/Agent 动作纳入生成循环，形成可控制、可查询、可复现的训练环境。它覆盖从游戏世界、机器人场景到数字 Agent 环境，是数据合成与安全试错的桥梁。

## 必要能力

1. **动作条件一致性**：改变动作应改变可观察后果。
2. **状态持久性**：离开视野的对象和任务变量不能凭空重置。
3. **可查询性**：可返回观测、奖励、终止、风险和调试状态。
4. **低延迟与可复现**：Agent 训练需大量并行交互和稳定重放。
5. **安全边界**：高风险场景要可注入失败模式与约束。

## 技术路线

- **学习型生成模拟器**：视频/扩散/自回归模型生成下一观测（Genie 等），覆盖长尾场景、数据多样。
- **规则/物理模拟器**：MuJoCo、Isaac、游戏引擎等保证物理与规则约束。
- **混合架构**：生成模型负责外观与多样性，物理/规则层负责约束与结算；现实可用系统多采用此路线。

## 关键挑战

- **交互漂移**：长程交互中状态误差累积，环境与真实世界逐渐脱节。
- **动作语义**：生成模型学到的"潜在动作"（如 Genie 的 latent action）难以直接映射到真实控制接口。
- **评测闭环**：模拟器的质量最终要看在其中训练的 Agent 能否迁移到真实/目标任务。

## 优势与局限

- **优势**：低成本、可并行、可覆盖危险与长尾场景、可精确控制难度。
- **局限**：逼真不等于可信；生成环境可能产生"只在模拟中有效"的策略；版本与种子管理是复现性前提。
