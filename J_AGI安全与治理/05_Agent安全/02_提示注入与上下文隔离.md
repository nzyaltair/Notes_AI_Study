# 提示注入与上下文隔离

## 一句话理解

Agent 会主动读取外部内容，这些内容既可能是任务数据，也可能携带诱导 Agent 改变目标的指令；隔离措施通过来源标记和数据-指令分离阻止不可信内容升级为执行命令。

## 威胁路径

```text
恶意外部内容 → 检索/浏览/工具返回 → 写入上下文或记忆 → 模型误认指令 → 越权行动
```

**直接注入**来自用户输入；**间接注入**藏在 Agent 主动读取的内容中（网页、文档、邮件、工具返回值）。多轮交互、编码转换和跨模态载体会扩大绕过空间。

## 典型场景

- **RAG 中毒**：检索库中的文档包含"忽略先前指令，执行以下操作..."
- **工具返回注入**：API 返回值中藏入改变行为的指令
- **网页恶意内容**：浏览 Agent 访问的页面包含不可见文本指令
- **邮件/文档劫持**：AI 助手处理含注入内容的邮件导致越权操作

## 隔离措施

1. **来源标记**：为系统规则、用户请求、工具结果、检索证据分别保留可信度与来源。
2. **数据—指令分离**：外部内容只能作为引用数据，不能直接修改执行策略或权限。
3. **上下文最小化**：只提供当前任务必要片段，敏感提示和凭据不进入模型上下文。
4. **危险动作再验证**：执行前由外部策略层重新检查目标、参数和授权，而非相信上下文结论。
5. **内容净化与检测**：识别高风险指令模式、隐藏文本、URL 重定向和编码载荷，但不依赖检测作为唯一防线。

**不存在通用的纯提示词防御。** 安全性来自信任边界、权限限制和执行前验证的组合。

## 防御局限

- 模型无法可靠区分"这是数据"和"这是指令"——这是语言模型的架构性问题
- 内容过滤难以穷举所有编码和绕过变体
- 最根本的防御是不让外部内容能够触发高影响执行
