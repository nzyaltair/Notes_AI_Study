# 程序综合与形式化验证

## 一句话理解

程序综合从规范、示例或自然语言生成程序；形式化验证用类型检查、模型检查、定理证明或测试确认性质——两者构成"生成候选—执行检查—反馈修订"的可验证计算范式。

## 核心技术

### 程序综合

| 方法 | 核心思想 | 代表工具 |
|---|---|---|
| 归纳综合 | 从输入-输出示例中搜索程序 | FlashFill、Synthesis |
| 基于约束 | 用 SMT 求解器编码程序搜索空间 | Sketch、CVC4/SYGUS |
| 神经引导 | 神经网络打分候选程序 | DeepCoder、Codex-based |
| LLM 生成 | 从自然语言生成代码 | AlphaCode、Codex |

### 形式化验证

| 方法 | 验证什么 | 代表工具 |
|---|---|---|
| 类型检查 | 静态类型正确性 | Haskell、Rust、Lean |
| 模型检查 | 有限状态系统的时序性质 | SPIN、NuSMV |
| 定理证明 | 数学性质的交互式证明 | Coq、Isabelle、Lean |
| 运行时验证 | 执行轨迹满足监控性质 | 断言、fuzzing |

## 生成-验证闭环

```text
规范/示例 → 候选程序生成 → 执行或模拟 → 性质检查 → 失败诊断 → 修订生成
```

搜索需要控制资源，验证需要独立于生成器的证据。LLM 时代，程序综合通常用 LLM 生成候选，测试或验证器筛选，形成"LLM 生成 + 符号验证"的神经符号协作（见 [[03_LLM神经符号推理]]）。

## 不能忽略的边界

验证只对明确形式化的性质成立；规范遗漏、环境假设错误与工具链漏洞仍会导致错误。因此需保存规范、证明对象和执行上下文，并结合测试与人工审查。**验证的正确性不等于系统的安全性**——它还取决于规范是否覆盖了真实需求。

## 优势与局限

- **优势**：程序是可执行、可测试、可审计的知识载体；验证可提供保证级别远超统计方法。
- **局限**：规范编写成本高；搜索空间爆炸；LLM 生成程序的长尾错误难以穷尽验证；形式化证明需要大量专家时间。

## 前沿发展

- **LLM + 证明助手**：用 LLM 生成 Lean/Isabelle 证明，自动检查其正确性。
- **神经验证**：用神经网络逼近或加速模型检查。
- **程序修复**：从验证失败信息自动修复程序（如 AlphaRepair）。
