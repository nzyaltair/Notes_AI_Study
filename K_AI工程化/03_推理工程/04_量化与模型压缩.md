# 量化与模型压缩

## 一句话理解

量化（Quantization）用低比特表示权重、激活或 KV Cache，减少显存占用和访存带宽；模型压缩还包括蒸馏、剪枝与低秩分解，共同目标是让大模型在有限硬件上高效推理。

## 1. 概述

LLM 推理的核心瓶颈是**访存带宽**而非算力：每生成一个 token 需要读取全部模型权重，而 FP16 的 70B 模型权重达 140 GB，单次读取就需要 ~70ms（A100 带宽 2 TB/s）。

量化与压缩解决的核心问题：

- **显存占用**：INT4 量化使 70B 模型从 140 GB 降至 35 GB，可在单卡 A100 上运行
- **访存带宽**：读取量减少 4 倍，直接降低 TPOT
- **部署成本**：更小的模型适配更便宜的硬件（消费级 GPU、NPU）
- **计算效率**：低精度运算利用 Tensor Core 的更高吞吐（INT8 算力 = 2× FP16）

量化的核心矛盾是**精度损失**：比特越低、速度越快，但模型质量下降。评估必须在真实任务上全面测量，而非仅看 PPL。

## 3. 核心概念

### 3.1 量化的基本原理

将浮点数映射到低精度整数：

$$x_{quant} = \text{round}\left(\frac{x}{s}\right) + z$$

- $s$：缩放因子（scale），$s = \frac{x_{max} - x_{min}}{2^b - 1}$
- $z$：零点（zero point），使 0 能精确表示
- $b$：目标比特数

**反量化**（推理时）：
$$x_{dequant} = s \times (x_{quant} - z)$$

### 3.2 量化粒度

| 粒度 | 描述 | 参数量 | 精度 | 速度 |
|:---|:---|:---|:---|:---|
| Per-Tensor | 整个张量一个 scale | 1 | 最差 | 最快 |
| Per-Channel | 每个输出通道一个 scale | $C_{out}$ | 好 | 快 |
| Per-Group | 每 $g$ 个元素一个 scale（如 $g=128$） | $C_{out} \times \frac{C_{in}}{g}$ | 最好 | 略慢 |
| Per-Token | 激活值按 token 粒度 | $B \times S$ | 好 | 快 |

**LLM 量化通常使用 Per-Group（权重）+ Per-Token（激活）**，兼顾精度和速度。

### 3.3 权重量化 vs 激活量化 vs KV Cache 量化

| 量化对象 | 缩写 | 效果 | 挑战 |
|:---|:---|:---|:---|
| 仅权重 (Weight-Only) | W4A16 / W8A16 | 减少显存和权重读取带宽 | 解量化开销 |
| 权重+激活 (Weight-Activation) | W8A8 / W4A4 | 减少显存 + 加速计算 | 激活值异常值 |
| KV Cache | KV8 / KV4 | 减少KV Cache显存 | Key通道间方差大 |

**Weight-Only 量化**（如 GPTQ, AWQ）：
- 推理时权重以 INT4 存储，计算前反量化为 FP16
- 减少显存占用和权重读取带宽
- 不利用 INT8 Tensor Core 的计算加速
- 适合访存瓶颈的 Decode 阶段

**Weight-Activation 量化**（如 SmoothQuant, W8A8）：
- 权重和激活都是低精度
- 利用 Tensor Core 的 INT8/FP8 计算加速
- 适合计算密集的 Prefill 阶段
- 激活值异常值（outliers）是主要挑战

### 3.4 异常值问题

LLM 的激活值存在极少数但极大的异常值（outliers），可达正常值的 100 倍以上：

```
正常激活值分布:
  [0.1, -0.3, 0.5, 0.2, -70.0, 0.4, 0.1, 65.0, -0.2, 0.3, ...]
                          ↑              ↑
                       异常值          异常值
```

如果使用 Per-Tensor 量化，异常值会导致 scale 过大，正常值的量化精度严重损失。这是 LLM 量化区别于 CNN 的核心难点。

## 4. 技术原理

### 4.1 GPTQ

GPTQ 基于**二阶信息（Hessian）**逐层量化权重，最小化量化误差：

**核心思想**：
1. 逐列量化权重矩阵 $W$
2. 量化第 $i$ 列后，更新剩余列以补偿量化误差
3. 使用 Hessian 矩阵 $H = X^T X$（$X$ 为校准数据）指导更新

**算法**：
```
输入: 权重 W (n×m), 校准数据 X, Hessian H = X^T X
for i = 0 to m-1:
    # 1. 量化第 i 列
    w_q[i] = quantize(W[:, i])

    # 2. 计算量化误差
    error = W[:, i] - w_q[i]

    # 3. 用 Hessian 逆更新剩余列
    W[:, i+1:] -= error * H[i, i]⁻¹ * H[i, i+1:]
```

**特点**：
- 4-bit 量化后精度损失通常 < 1 PPL
- 校准集小（128-1024 样本）
- 量化时间约 1-4 小时（70B 模型）
- Weight-Only 方案，不加速 Prefill 计算

### 4.2 AWQ (Activation-Aware Weight Quantization)

AWQ 的核心发现：**并非所有权重同等重要**，与激活值幅度大的通道对应的权重更为关键。

**核心思想**：
1. 识别"显著通道"（对应激活值大的通道）
2. 对显著通道施加缩放因子 $s$，保护其精度
3. 非显著通道正常量化

```
原始: W × X → 低比特量化 W → 精度损失

AWQ: (W × s) × (X / s)
      ↑ 对显著通道缩放     ↑ 激活值反向缩放
      → 量化时保护显著权重  → 数学上等价于原始计算
```

**优势**：
- 不需要反向传播，纯 PTQ
- 4-bit 精度优于 GPTQ（在部分任务上）
- 支持搜索最优缩放因子
- 实现简单，推理开销小

### 4.3 SmoothQuant

SmoothQuant 解决 W8A8 场景下激活值异常值的问题：

**核心思想**：将激活值的异常值"平滑"迁移到权重上：

$$Y = (X \cdot s) \times \left(\frac{W}{s}\right)$$

- $s$：平滑因子，$s_j = \frac{\max(|X_j|)^\alpha}{\max(|W_j|)^{1-\alpha}}$
- $\alpha$：迁移强度（通常 0.5）
- 激活值除以 $s$ → 异常值缩小
- 权重乘以 $s$ → 略微增大但不影响量化（权重本就平滑）

```
量化前:
  X = [0.1, -0.3, 0.5, -70.0, 0.4]  ← 激活值有异常值
  W = [1.2, 0.8, -0.5, 0.3, -0.9]   ← 权重平滑

平滑后 (α=0.5):
  X' = [0.1, -0.3, 0.5, -7.0, 0.4]  ← 异常值缩小 10×
  W' = [12, 8, -5, 3, -9]           ← 权重增大但仍可量化
```

**优势**：
- W8A8 无精度损失
- 利用 INT8 Tensor Core 加速计算
- 适合计算密集的 Prefill 场景

### 4.4 LLM.int8()

LLM.int8() 采用**混合精度分解**：

```
对于每个 token 的激活:
  if 激活值存在异常值 (> 阈值):
      异常值通道: FP16 计算 (少数通道)
      正常通道: INT8 计算 (多数通道)
      Y = Y_int8 + Y_fp16
  else:
      全部 INT8 计算
```

- 约 0.1% 的通道需要 FP16，99.9% 可用 INT8
- 无精度损失，但计算效率不如纯 INT8（分支开销）
- 适合 7B-13B 模型的 INT8 推理

### 4.5 FP8 量化

H100 原生支持 FP8（E4M3 和 E5M2），相比 INT8 优势明显：

| 特性 | INT8 | FP8 (E4M3) | FP8 (E5M2) |
|:---|:---|:---|:---|
| 动态范围 | [-128, 127] | [-448, 448] | [-57344, 57344] |
| 异常值处理 | 需 SmoothQuant | 自然兼容 | 自然兼容 |
| 计算加速 | Tensor Core | Transformer Engine | Transformer Engine |
| 精度 | 好 | 更好 | 好（大动态范围） |

**FP8 推理流程**：
```
权重: FP16 → E4M3 (一次性转换)
激活: FP16 → E4M3 (每步动态转换)
计算: FP8 × FP8 → FP32 → FP16 (硬件自动处理)
```

- 无需校准集（动态量化）
- 精度损失极小
- 但需要 H100+ 硬件支持

### 4.6 其他压缩技术

#### 知识蒸馏（Knowledge Distillation）

```
Teacher 模型 (大) → 软标签 / 隐藏状态 → Student 模型 (小)
```

- **黑盒蒸馏**：仅用 Teacher 的输出
- **白盒蒸馏**：利用 Teacher 的中间层表示
- **序列级蒸馏**：用 Teacher 生成数据训练 Student

#### 剪枝（Pruning）

| 类型 | 描述 | 稀疏率 | 加速 |
|:---|:---|:---|:---|
| 非结构化剪枝 | 逐个权重置零 | 高（90%+） | 需稀疏硬件 |
| 结构化剪枝 | 移除整行/列/头 | 中（30-50%） | 通用加速 |
| 半结构化剪枝 | N:M 稀疏（如 2:4） | 中 | NVIDIA 支持 |

LLM 剪枝面临挑战：大模型对结构化剪枝敏感，精度下降明显。

#### 低秩分解（Low-Rank Decomposition）

将大权重矩阵分解为两个小矩阵的乘积：

$$W_{m \times n} \approx A_{m \times r} \times B_{r \times n}, \quad r \ll \min(m, n)$$

- 参数量从 $mn$ 减少到 $r(m+n)$
- 与 LoRA 思路类似但方向相反（LoRA 是适配，分解是压缩）

## 6. 评估方法

量化评估必须全面覆盖，不能只看 PPL：

| 评估维度 | 指标 | 重要性 |
|:---|:---|:---|
| 语言建模 | PPL / Loss 变化 | 基础但不够 |
| 下游任务 | MMLU, HellaSwag, GSM8K 等 | 核心能力 |
| 长上下文 | 长文档 QA / 摘要 | 量化误差累积 |
| 代码生成 | HumanEval / MBPP | 格式敏感 |
| 工具调用 | Function Calling 准确率 | 格式严格 |
| 安全性 | 拒答率 / 异常输出 | 量化可能破坏对齐 |
| 公平性 | 不同群体表现差异 | 量化可能放大偏差 |
| 推理速度 | TTFT / TPOT / 吞吐 | 部署关键 |

**评估注意事项**：
- 不同硬件和 kernel 对同一量化格式的实际性能差异很大
- 应在目标硬件上用真实输入输出分布测试
- 量化对不同模型结构的敏感度不同（GQA vs MHA, FFN 大小等）

## 7. 优势与局限

### 7.1 优势

- **显存节省**：INT4 量化使显存减少 4 倍，70B 模型可单卡运行
- **带宽节省**：权重读取量减少，直接降低 Decode 延迟
- **计算加速**：INT8/FP8 利用 Tensor Core 更高算力
- **部署民主化**：消费级 GPU 也能运行大模型
- **无损选项**：FP8、SmoothQuant 等可实现近乎零精度损失

### 7.2 局限与挑战

- **精度损失**：4-bit 以下量化在复杂推理任务上质量明显下降
- **异常值敏感性**：LLM 激活值异常值使量化比 CNN 困难得多
- **硬件依赖**：FP8/FP4 需要特定 GPU 型号，INT8 kernel 跨平台不一致
- **校准集偏差**：PTQ 校准集与实际分布不匹配时精度下降
- **长上下文退化**：量化误差在长序列下累积
- **量化-微调冲突**：量化后 LoRA 微调可能不收敛

## 8. 应用场景

| 场景 | 推荐方案 | 原因 |
|:---|:---|:---|
| 生产低延迟推理 | FP8 (H100) | 无损 + 2× 加速 |
| 消费级 GPU 部署 | AWQ 4-bit | 精度好，显存小 |
| 本地/CPU 推理 | GGUF Q4_K_M | llama.cpp 优化 |
| 高吞吐批处理 | SmoothQuant W8A8 | 利用 INT8 计算 |
| 长上下文服务 | KV Cache INT8 + 权重 FP8 | 减少总显存 |
| 极致压缩 | GPTQ 3-bit + 蒸馏 | 最低显存占用 |
| 端侧 NPU | INT4 | NPU 算力最优精度 |

## 10. 前沿发展

- **1-bit LLM (BitNet)**：权重和激活均为三值（-1, 0, 1），训练时量化，推理无需反量化
- **FP4 推理**：B200 原生 FP4 支持，4 倍于 FP8 的推理速度
- **自适应量化**：不同层/任务使用不同比特数，自动搜索最优配置
- **量化感知 LoRA (QLoRA)**：4-bit 基础模型 + LoRA 微调，16GB 显存微调 70B
- **KV Cache 压缩**：结合量化和蒸发（eviction），支持百万级上下文
- **旋转量化**：通过 Hadamard 变换旋转权重，消除异常值后量化
- **硬件-量化协同设计**：芯片设计中考虑量化需求，如稀疏 INT4 计算
