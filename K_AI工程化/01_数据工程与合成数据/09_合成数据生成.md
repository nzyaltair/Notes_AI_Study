# 合成数据生成

## 一句话理解

合成数据生成通过程序或 AI 模型创建训练与评测数据——当真实高质量数据稀缺或成本高昂时，合成数据是突破数据瓶颈的关键手段，也是大模型持续 Scaling 的重要燃料。

## 概述

随着互联网高质量文本数据趋于耗尽（预计 2024-2026 年间网络文本数据接近被完全消耗），合成数据成为 LLM 训练的核心数据来源。合成数据不仅用于扩充数据量，更用于：

- 生成特定格式的指令数据（SFT）
- 构造推理轨迹数据（CoT、工具调用）
- 制造对齐训练数据（偏好对、拒答样本）
- 生成难以从真实世界获取的数据（机器人仿真、安全红队）
- 构造评测数据集

| 时间 | 里程碑 | 意义 |

## 核心概念

### 合成数据类型

| 类型 | 生成方式 | 主要用途 |
|:---|:---|:---|
| 指令-回复对 | LLM 自动生成 | SFT 训练 |
| 偏好数据 | LLM 生成 + 排序 | RLHF/DPO 训练 |
| 推理轨迹 | 搜索/LLM 生成 CoT | 推理能力训练 |
| 智能体轨迹 | 环境交互（工具调用、PR 修复） | 代码/工具 Agent 训练 |
| 对话数据 | 多轮 LLM 对话模拟 | 对话模型训练 |
| 代码数据 | 程序自动生成 + 验证 | 代码模型训练 |
| 仿真数据 | 3D 引擎 / 物理引擎 | 机器人/自动驾驶 |
| 对抗数据 | 红队生成 | 安全对齐训练 |

### 质量 vs 多样性 权衡

高质量数据（类教科书）与大规模数据的权衡：
- **Phi 系列经验**：精选的高质量合成数据（1B token 教科书级）可训练出远超其他 1.3B 模型的效果
- **多样性需求**：过于相似的合成数据导致模型覆盖分布过窄
- **实践建议**：质量过滤 > 规模扩张，先确保 Seed Data 高质量

## 技术原理

### Self-Instruct

Wang et al. (2023) 提出的自举式指令数据生成方法：

```text
1. 人工准备少量种子指令（175 个高质量任务）
2. 用 LLM（GPT-3）生成新任务（指令 + 输入 + 输出）
3. 质量过滤：
   - ROUGE-L < 0.7（去相似）
   - 关键词过滤（低质量模式）
   - 长度过滤
4. 通过筛选的任务加入任务池，循环生成
```

**局限**：生成数据质量受限于种子模型能力；存在偏见放大和格式单一化风险。

### Evol-Instruct

WizardLM 提出，通过"进化"操作复杂化已有指令：

- **深化（Deepen）**：增加推理步骤，使任务需要更深入思考
- **拓宽（Broaden）**：扩展任务到新领域
- **增加约束**：添加格式、长度、风格约束
- **更具体化**：将抽象指令具体化为特定场景

### 推理轨迹合成

构造 Chain-of-Thought 和工具调用数据：

1. **正向生成**：用强模型（GPT-4/o1）生成推理过程
2. **拒绝采样**：生成多个答案，只保留正确的（Rejection Sampling）
3. **MCTS 搜索**：蒙特卡洛树搜索探索解题路径（DeepSeek-R1 方法）
4. **过程监督**：标注每个推理步骤的正确性（PRM 数据）

### 仿真数据生成

用于具身智能和机器人训练：

- **物理引擎**：Isaac Sim、Mujoco、PyBullet 生成机器人轨迹
- **渲染引擎**：Unity、Unreal 生成视觉场景数据
- **随机化**：Domain Randomization 提升 Sim2Real 迁移能力

### 智能体轨迹合成（后训练数据主战场）

后训练数据的通用配方：**定义一组环境 × 一组任务/提示 × 从教师（强模型或人）收集回复**。开源社区的后训练数据几乎全部为合成生成（人工慢且贵，前沿机构用人机混合）；关键认知：**教师模型 ≠ 最强模型**——更强的模型不一定是更好的老师。

**OpenThoughts（2025）**——数学/科学/代码推理数据：

```text
来源: StackExchange、NuminaMath 等人工来源 + 部分合成（编程/数学/化学）
生成: 对每个问题采样 16 组回复，合计 120 万实例（问题数 = 120万/16）
发现:
├── 只用少数优质来源 > 把所有来源都拿来用
├── 每题多采样（16 组）显著有效
├── QwQ-32B 教学效果优于 DeepSeek-R1（更强 ≠ 更会教）
└── 简单的答案过滤效果有限
```

**代码智能体数据三部曲**——从「能生成代码」到「能做软件开发」：

| 项目 | 环境 | 任务 | 规模 | 关键创新 |
|:---|:---|:---|:---|:---|
| SWE-smith | 真实 GitHub 仓库（智能体先装依赖使其可运行） | 智能体自动生成（如故意引入 bug）后验证 | 5 万样本 | 合成任务 + 验证器闭环 |
| SWE-zero | 真实 GitHub PR | 真实任务 | 30 万轨迹 | 发现模型无需代码执行反馈也有 ~70 分（允许执行 ~80）——对代码内部语义有真实理解，免去每仓配 docker 镜像；从大编码模型蒸馏+过滤 |
| SWE-bench-Rebench | Rebench 任务 | 混合 | 1200 万轨迹 | 把无环境执行反馈的思路规模化 |

**环境是代码智能体数据的真正难点**：与数学题不同，SWE 任务有重型依赖，多数 GitHub 仓库无法直接运行，回退到历史 commit 状态时装一堆过时依赖更是噩梦；三部曲的演进正是「环境执行反馈」与「纯模型推理」的成本权衡。

**合成度的谱系**：完全合成（环境+任务都合成，如 SWE-smith）↔ 半合成（真实环境+合成任务，或合成环境+真实任务，如 SWE-zero）；回复一律来自强教师模型，且需兼具教学能力。

## 关键方法与模型

### 数据质量评估与过滤

| 方法 | 描述 | 工具 |
|:---|:---|:---|
| IFD (Instruction Following Difficulty) | 用 SFT 模型的困惑度评估指令难度 | 无标准工具 |
| DEITA | 基于复杂性和质量的选择框架 | 开源 |
| QuRating | 评测数据对预训练的价值 | 开源 |
| LLM Judge | 用强模型评估数据质量 | GPT-4 等 |
| n-gram 去重 | MinHash 相似度 | datasketch |
| Reward Model 过滤 | 用 RM 分数过滤低质量回复 | 各类 RM |

### 合成数据与真实数据混合

最佳实践：

1. 用高质量真实数据构建评测集，不用于训练
2. 合成数据先过滤（多样性 + 质量），再混合
3. 保持一定比例的真实数据防止分布坍缩
4. 按数据类型分别管理质量预算

## 优势与局限

### 优势

- **可控性**：可精确控制数据格式、难度、领域分布
- **可扩展**：无上限地生成，突破真实数据稀缺瓶颈
- **隐私安全**：不包含真实用户数据，合规性好
- **稀有场景覆盖**：可生成真实世界中罕见的边缘案例
- **成本可控**：大规模生成比人工标注便宜数量级

### 局限与风险

- **模型坍缩（Model Collapse）**：用合成数据递归训练导致模型退化，尾部分布消失
- **偏见放大**：生成模型的偏见被放大并编码进训练数据
- **多样性不足**：合成数据趋向常见模式，长尾分布欠缺
- **质量上限**：合成数据质量受限于生成模型能力
- **领域特定困难**：医疗、法律等专业领域的合成数据准确性难以保证

**模型坍缩机制**（Shumailov 等, 2024）：

```text
真实数据 → 训练 Model_1
Model_1 生成合成数据 → 训练 Model_2
Model_2 生成合成数据 → 训练 Model_3（分布收窄）
...
Model_n：极端退化，只能生成均值附近的输出
```

防御措施：始终混合真实数据；合成数据做多样性过滤；监控生成分布变化。

## 应用场景

| 场景 | 合成方法 | 数据规模 |
|:---|:---|:---|
| SFT 指令数据 | Self-Instruct / Evol-Instruct | 10K-1M 条 |
| RLHF 偏好数据 | LLM 生成 + 排序/AI 反馈 | 10K-100K 对 |
| 数学推理 | 程序验证 + 拒绝采样 | 100K-10M 条 |
| 代码数据 | 程序生成 + 执行验证 | 1M-100M 条 |
| 代码智能体轨迹 | 真实仓库 + 自动任务 + 教师蒸馏 | 50K-12M 轨迹 |
| 机器人训练 | 仿真引擎 | 1M-1B 轨迹 |
| 安全红队 | 对抗生成 | 10K-100K 条 |
| 评测数据集 | 多样化生成 + 人工审核 | 1K-10K 条 |

## 前沿发展

- **验证驱动的合成**：只保留可程序验证（代码执行、数学验证）的数据，保证正确性
- **AI 反馈训练（RLAIF）**：用 AI 代替人类提供偏好反馈，大幅降低 RLHF 成本
- **合成预训练数据**：不仅是 SFT 数据，预训练数据也开始引入合成生成（Nemotron：低质量网页用 LLM 改写成维基风格、高质量文档用 LLM 生成问答/摘要任务）
- **智能体轨迹规模化**：代码 Agent 轨迹从万级增长到千万级（Rebench 1200 万），环境搭建与执行反馈的成本权衡成为核心设计变量
- **模型坍缩的理论研究**：研究数据分布保护策略（真实数据锚定、多样性正则化）
- **多模态合成数据**：图文对、视频-字幕对的合成生成技术
