# 模型网关与成本治理

## 一句话理解

模型网关统一认证、路由、限流、重试、缓存与审计，把直接调用模型 API 转化为受治理的平台能力；成本治理以预算、配额与降级路径防止 Token 开销失控。

## 1. 为什么需要模型网关

直接在业务代码中调用 LLM API 存在多重问题：

- **供应商锁定**：切换模型供应商需修改所有调用点
- **成本失控**：无统一计量，无法追踪 Token 消耗
- **安全风险**：API Key 散落，缺乏统一认证
- **可靠性差**：无限流、重试、熔断，故障扩散
- **审计缺失**：无法追溯谁在何时调用了什么模型

模型网关作为所有 LLM 调用的统一入口，解决以上问题。

## 2. 网关架构

```text
客户端 (业务服务/Agent)
        ↓
    模型网关
    ├── 认证与授权 (Auth)
    ├── 路由决策 (Router)
    ├── 限流与配额 (Rate Limiter)
    ├── 语义缓存 (Cache)
    ├── 重试与熔断 (Resilience)
    ├── 内容策略 (Content Policy)
    ├── 审计与计量 (Audit & Metering)
    └── 供应商抽象 (Provider Abstraction)
        ↓
    LLM Provider (OpenAI / Anthropic / 本地模型)
```

## 3. 核心能力

### 3.1 认证与授权

- **API Key 管理**：统一存储，业务侧使用内部 Token
- **租户隔离**：按团队/项目/用户隔离配额和审计
- **RBAC**：不同角色可调用不同模型（如仅高级团队可用 GPT-4）

### 3.2 路由决策

按任务类型、成本预算、延迟要求路由到不同模型：

| 路由策略 | 说明 | 示例 |
|:---|:---|:---|
| 任务类型路由 | 按请求类型选择模型 | 简单问答 → 小模型；推理任务 → 大模型 |
| 成本路由 | 按预算选择模型 | 低预算 → Haiku；高预算 → Sonnet |
| 延迟路由 | 按延迟要求选择模型 | 实时 → 本地模型；非实时 → API |
| 故障转移 | 主模型故障时切换 | OpenAI 故障 → Azure OpenAI |
| 负载均衡 | 多实例间分流 | 多个 vLLM 实例轮询 |

### 3.3 限流与配额

- **并发限制**：防止突发流量打满下游
- **TPM 限制**：每分钟 Token 数限制
- **RPM 限制**：每分钟请求数限制
- **租户配额**：按团队/项目分配月度 Token 预算
- **用户配额**：按用户设置日/小时调用上限

### 3.4 语义缓存

对相同或语义相似的查询返回缓存结果：

- **精确匹配**：相同 Prompt + 参数 → 直接返回
- **语义匹配**：Embedding 相似度高于阈值 → 返回缓存
- **TTL 策略**：按内容时效性设置缓存过期时间
- **缓存隔离**：按租户、用户隔离缓存

> **注意**：语义缓存需谨慎，相似问题可能有微妙差异导致答案不同。

### 3.5 重试与熔断

- **重试策略**：指数退避，最多 N 次
- **超时控制**：请求级超时 + 流式读取超时
- **熔断**：错误率超阈值时暂停调用该供应商
- **降级**：主模型不可用时降级到备用模型

### 3.6 内容策略

- **输入过滤**：PII 检测、注入攻击防护
- **输出过滤**：有害内容检测、敏感信息脱敏
- **内容审计**：记录输入输出摘要（脱敏后）

## 4. 成本治理

### 4.1 成本归因

每条请求记录：

| 维度 | 字段 |
|:---|:---|
| 模型信息 | model_id, provider |
| Token 计量 | input_tokens, output_tokens, cached_tokens |
| 成本 | cost_usd |
| 租户 | team, project, user_id |
| 时间 | timestamp |
| 缓存 | cache_hit (bool) |
| 错误 | error_code (如有) |

### 4.2 预算管理

```text
组织预算
├── 团队 A 预算: $10,000/月
│   ├── 项目 1: $6,000
│   └── 项目 2: $4,000
└── 团队 B 预算: $5,000/月
```

- **预算告警**：用量达 80% / 90% / 100% 时通知
- **硬限制**：超出预算时拒绝请求或降级到便宜模型
- **滚动预算**：按日/周/月追踪

### 4.3 成本优化策略

| 策略 | 节省幅度 | 实现方式 |
|:---|:---|:---|
| 模型降级 | 50-80% | 简单任务用小模型 |
| 语义缓存 | 20-40% | 相似查询命中缓存 |
| Prompt 压缩 | 10-30% | 精简系统指令和上下文 |
| 批量请求 | 10-20% | 使用 Batch API（延迟换成本） |
| 本地模型 | 60-90% | 高频任务用本地部署模型 |

### 4.4 成本看板

- **实时看板**：当前小时/天 Token 消耗与成本
- **趋势分析**：按天/周/月成本趋势
- **TOP 消费者**：最贵的租户/模型/Prompt
- **异常检测**：成本突增告警

## 5. 供应商抽象

```python
# 统一接口，底层适配不同供应商
class LLMGateway:
    def chat(self, messages, model, **kwargs):
        provider = self.router.select(model, **kwargs)
        return provider.chat(messages, model, **kwargs)
```

- **统一 API**：OpenAI 兼容格式作为标准
- **供应商适配**：OpenAI、Anthropic、Azure、本地模型
- **能力声明**：每个模型声明支持的能力（function calling、vision 等）

## 6. 常见问题

- **缓存中毒**：错误缓存被反复返回，需缓存失效机制
- **路由偏差**：路由策略导致某些模型过载
- **Key 泄漏**：API Key 出现在日志中，需密钥管理
- **计费误差**：Token 计数与供应商不一致，需对账
- **降级风暴**：主模型故障时所有流量涌入备用模型
