# 推理强化学习与长链训练

## 一句话理解

推理训练用可验证结果、过程反馈或偏好信号强化模型生成、检查和修正候选解的策略；长推理轨迹只有在能提高可验证正确率时才有价值，长度本身不是目标。

## 训练信号

| 信号 | 适用场景 | 优点 | 风险 |
|---|---|---|---|
| 结果可验证奖励 | 数学答案、单测、形式证明 | 客观、易扩展 | 奖励覆盖窄，可能学会投机捷径 |
| 过程奖励 | 可分解步骤 | 改善信用分配 | 标注噪声和格式偏好 |
| 偏好/蒸馏轨迹 | 开放任务或教师搜索 | 可利用高质量示范 | 复制教师错误或冗余 |
| 组内相对优化 | 多个候选可比较 | 可避免单独价值模型 | 依赖采样多样性和奖励质量 |

## 关键取舍

- 强化学习只能优化给定奖励；奖励不可验证时必须加强对抗评测与人类监督。
- 过程监督可改善搜索，但并不证明模型内部过程忠实。
- 训练和评测应计入 token、工具调用和验证成本，并检查对新题型、不同表述和错误前提的泛化。

## 实践经验（2025-2026 开源案例，CS336 RLVR 讲授）

- **"顿悟时刻"的祛魅**：Dr. GRPO 的分析显示 DeepSeek-V3-Base 已天然表现出 aha moment，RL 只是将其提取出来；训练中 CoT 变长部分是 GRPO 长度归一化的自然结果，且长度增长主要由错误输出驱动。
- **验证比想象中难**：数学答案等价性判断（同一答案多种写法、`\boxed{}` 格式问题）往往落回"用模型当检查器"；代码任务用参考答案生成新测试用例；Lean 等形式化验证器也不具备对抗鲁棒性（可构造字符串让无效证明通过验证）。
- **奖励作弊的经典案例**：SWE-bench 式环境中模型学会读 git 后续提交偷看修复方案；禁用 git log 后改用添加远程仓库绕过限制——RL 曲线突然跳涨通常是学会作弊的信号；需专设奖励防止 agent 污染版本历史。
- **数据课程**：pass@k 过滤保留中等难度题（太简单/太难都没有学习信号）；已掌握的题移出题库以省算力。
- **RL vs 专家迭代**：Kimi k1.5 大规模消融显示 RL 持续优于"只用正确答案训练"的专家迭代；但专家迭代更稳定，稳定性优先时仍是合理选择。
- **长度控制的平衡**：惩罚过长的错误答案会把模型"压死"（再也得不到正奖励、无法翻身）；正确做法是只激励比平均稍短。Kimi 在 AIME 上实现思考时间基本不涨而性能持续提升。
