# 模型编辑与行为控制

## 一句话理解

模型编辑在不完全重训的情况下修改知识、偏好或行为；行为控制则通过训练、推理、执行和运营四个层次共同约束模型行动——编辑是补救工具，执行层是安全关键约束的可靠保障。

## 模型编辑

模型编辑（如 ROME、MEMIT）通过干预特定权重或激活定位并修改错误事实、偏好或后门。它是补救工具，不是通用控制机制。

### 评估维度

1. **可靠性**：目标行为是否按预期改变。
2. **泛化**：同义表达、相关任务和多轮情境是否一致改变。
3. **局部性**：无关能力是否被破坏。
4. **持久性**：后续微调、上下文变化是否使修改消失。
5. **安全性**：是否产生新绕过路径或泄露信息。

### 主要方法

| 方法 | 机制 | 特点 |
|---|---|---|
| ROME | 定位事实到单个 MLP 层，直接修改权重 | 精确但难批量扩展 |
| MEMIT | 批量编辑，分布到多层 | 支持大规模编辑 |
| 激活转向（Steering Vectors） | 在推理时向激活空间添加方向向量 | 灵活但效果不持久 |
| 指令微调（Fine-tuning） | 用少量样本重新对齐 | 简单有效但可能过拟合 |

## 行为控制分层

```text
训练层：偏好优化、对抗训练、模型编辑
推理层：约束解码、验证器、输出审查
执行层：策略引擎、权限、审批、状态机
运营层：监控、回滚、事故响应
```

越靠近执行层，约束越可确定和可审计。对金额、权限、物理动作等硬边界，应使用确定性策略、签名和状态机验证；概率模型适合提出方案、解释上下文和生成候选，而不应单独授权不可逆操作。

## 推理时约束技术

- **约束解码**：在生成过程中直接屏蔽禁止 token 或路径
- **输出分类器**：独立的安全分类器对输出进行后处理审查
- **验证器（Verifier）**：对 Agent 的行动计划进行形式化或语义验证
