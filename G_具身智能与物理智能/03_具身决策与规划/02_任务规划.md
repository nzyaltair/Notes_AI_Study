# 具身 Agent 与任务规划

## 一句话理解

具身 Agent 不只是"能动的 LLM"：它必须在不确定物理世界中分解任务、选择技能、监控执行、处理失败，并始终维持安全边界。高层智能来自结构化规划与恢复逻辑，而不是单纯增大模型参数。

## 1. 从语言 Agent 到具身 Agent

| 维度 | 纯语言 Agent | 具身 Agent |
|---|---|---|
| 输出 | 文本/工具调用 | 物理动作/技能参数 |
| 反馈 | API 返回值 | 多模态感知、接触力、位姿误差 |
| 失败模式 | 逻辑错误、幻觉 | 碰撞、滑移、卡住、无法到达 |
| 恢复策略 | 重试/换工具 | 重新感知/重新规划/安全撤退 |
| 时延约束 | 秒级可接受 | 毫秒级控制、秒级重规划 |
| 安全性 | 信息风险 | 物理伤害风险 |

语言 Agent 的"工具调用"在具身场景变为"技能调用"，但技能有前置条件、后置条件、执行时延、失败概率和安全约束——这些在纯软件 Agent 中通常不存在。

## 2. 任务分解与规划

### LLM 做任务分解

LLM 可将"准备早餐"分解为"去厨房→打开冰箱→取出牛奶→倒牛奶→取出麦片→倒入碗中"。但 LLM 容易忽略：

- **物理约束**：冰箱门是否可开？手臂能否到达？牛奶是否在视野中？
- **时序依赖**：必须先开门才能取物，必须先抓稳才能移动。
- **资源状态**：冰箱可能已开、牛奶可能不在原位、碗可能已被占用。

因此 LLM 的任务分解应被视为**候选计划**，而非可执行方案；必须由规划器和执行器验证和修正。

### Task and Motion Planning（TAMP）

TAMP 在符号任务规划与连续运动可行性之间迭代：

1. 任务规划器生成符号动作序列（如 `open(fridge) → pickup(milk) → pour(milk, bowl)`）。
2. 运动规划器验证每个动作的连续可行性（IK 可达、无碰撞、抓取稳定）。
3. 若某个动作不可行，将失败信息反馈给任务规划器，重新选择策略。

TAMP 是语言模型接入物理世界的标准桥梁，但它计算量大、需要显式建模，且对感知不确定性敏感。在实践中常与学习策略结合：TAMP 处理高层可行性，学习策略处理感知和接触。

## 3. 行为树与执行监控

行为树（Behavior Tree）是具身执行的标准编排形式：

```
Sequence [准备早餐]
  ├── Condition: 冰箱关闭？
  │     └── Action: 打开冰箱
  ├── Selector [取牛奶]
  │     ├── Sequence [直接取]
  │     │     ├── Condition: 牛奶可达？
  │     │     └── Action: 抓取牛奶
  │     └── Sequence [调整后取]
  │           ├── Action: 移动到另一侧
  │           └── Action: 抓取牛奶
  ├── Action: 倒牛奶
  └── Action: 放回牛奶
```

- **Sequence**：子节点顺序执行，任一失败则整体失败。
- **Selector**：子节点按优先级尝试，第一个成功即返回。
- **Condition**：检查前置条件，不执行动作。
- **Decorator**：重试、超时、次数限制等修饰。

行为树的价值不是"手工编码所有情况"，而是为学习策略提供**结构化的恢复骨架**：策略可以自由决定如何抓取，但必须在抓取失败时进入恢复分支。

## 4. 技能库与技能学习

| 维度 | 说明 |
|---|---|
| 技能定义 | 名称、前置条件、后置条件、参数空间、失败模式 |
| 技能实现 | 规划、IL、RL、VLA 或混合策略 |
| 技能接口 | 输入（目标/对象/参数）→ 输出（成功/失败/部分完成） |
| 技能组合 | 行为树、状态机或 LLM 编排 |
| 技能学习 | 从演示学习新技能、从失败中改进、技能泛化到新对象 |

技能库应被视为可扩展、可替换的模块集合。高层 Agent 不需要知道"抓取"技能的内部实现，但需要知道它的前置条件（对象可达、已检测）、后置条件（对象在手中）、失败模式（滑移、碰撞）和恢复路径。

## 5. 记忆、状态与上下文

具身 Agent 需要维护多种记忆：

| 记忆类型 | 内容 | 更新频率 | 用途 |
|---|---|---|---|
| 工作记忆 | 当前任务、子目标、感知状态 | 每步更新 | 实时决策 |
| 语义地图 | 对象位置、属性、关系 | 秒到分钟 | 空间查询 |
| 情景记忆 | 过往交互结果 | 每次任务后 | 经验复用和失败避免 |
| 语义知识 | 常识、工具用法、操作顺序 | 静态或缓慢更新 | 任务分解和常识推理 |

一个常见失败模式是：Agent 忘记已经做过的事（重复开冰箱）、忽略环境变化（物体被移走后仍操作原位置）、或在不安全状态下继续执行。记忆管理必须与感知更新和失败检测协同。

## 6. LLM/VLM 在具身 Agent 中的角色

| 角色 | 适合 | 不适合 |
|---|---|---|
| 任务分解与推理 | 开放指令理解、常识推理、子任务排序 | 毫秒级实时控制 |
| 语义感知 | 开放词汇识别、属性判断、空间关系 | 精确几何和位姿 |
| 技能选择 | 根据上下文选择技能和参数 | 验证连续可行性 |
| 失败解释 | 分析失败原因、提出替代方案 | 直接执行物理恢复动作 |
| 交互与沟通 | 与用户确认意图、解释行为、求助 | 替代安全监督 |

核心原则：LLM/VLM 提议，规划器验证，控制器执行，安全层裁决。四者不可互相替代。
