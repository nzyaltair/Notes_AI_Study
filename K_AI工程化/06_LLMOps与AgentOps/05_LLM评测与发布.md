# LLM 评测与发布

## 一句话理解

LLM 发布不能只验证 API 成功率，需覆盖事实性、指令遵循、格式、安全、检索质量与成本的多维评测，采用影子流量、灰度与在线实验验证真实任务质量，评测集需版本化并隔离训练数据。

## 1. 为什么 LLM 发布需要特殊门禁

传统 ML 模型发布验证的是 API 成功率和数值指标（AUC/F1）。LLM 发布面临的挑战完全不同：

- **非确定性输出**：无法用单元测试覆盖所有输出
- **多维质量**：不只是"对错"，还有格式、风格、安全、忠实度
- **Prompt 变更影响**：Prompt 修改等同模型变更，需同等评测
- **模型升级风险**：同一模型的新版本可能行为变化
- **成本影响**：输出 Token 长度变化直接影响成本

核心原则：**不优化单一分数，而是多维评测 + 渐进发布**。

## 2. 评测维度

### 2.1 能力评测

| 维度 | 说明 | 评测方法 |
|:---|:---|:---|
| 事实性 | 输出信息是否准确 | 人工标注 + 知识库校验 |
| 指令遵循 | 是否按指令格式、约束输出 | 规则匹配 + LLM Judge |
| 推理能力 | 多步推理是否正确 | 执行器验证 + 人工 |
| 格式合规 | JSON/Markdown 等格式是否正确 | 解析器验证 |
| 语言质量 | 流畅度、连贯性、语气 | LLM Judge + 人工 |

### 2.2 安全评测

| 维度 | 说明 | 评测方法 |
|:---|:---|:---|
| 拒答能力 | 应拒答的场景是否正确拒绝 | 红队用例集 |
| 越狱防护 | 越狱攻击是否被防御 | 对抗性测试集 |
| 有害内容 | 是否生成有害、歧视性内容 | 安全分类器 |
| 偏见检测 | 输出是否存在系统性偏见 | 公平性评测集 |
| PII 泄漏 | 是否泄漏训练数据中的隐私 | PII 检测器 |

### 2.3 场景评测

- **业务任务成功率**：核心业务场景的端到端成功率
- **用户满意度**：人工评分或用户反馈
- **多轮对话质量**：上下文理解、话题切换、记忆保持

### 2.4 成本评测

| 指标 | 说明 |
|:---|:---|
| 平均输入 Token | 单次请求平均输入长度 |
| 平均输出 Token | 单次请求平均输出长度 |
| 成本分布 | P50/P90/P99 单次请求成本 |
| 成本异常率 | 超出预期成本的请求比例 |

## 3. 评分方法

### 3.1 方法对比

| 方法 | 优点 | 局限 | 适用场景 |
|:---|:---|:---|:---|
| 规则匹配 | 快速、确定性强 | 无法评估语义 | 格式检查、关键词 |
| LLM Judge | 可评估开放式输出 | Judge 有偏差 | 语义质量、推理 |
| 人工评分 | 最可靠 | 成本高、速度慢 | 高风险最终验收 |
| 执行器 | 客观验证 | 需可执行环境 | 代码生成、工具调用 |
| 嵌入相似度 | 快速、可量化 | 只反映语义距离 | 相似度匹配 |

### 3.2 LLM Judge 最佳实践

- **使用强模型评弱模型**：如 GPT-4 评 GPT-3.5
- **评分标准明确**：提供评分 rubric 和示例
- **多 Judge 投票**：多个 Judge 模型评分取平均
- **校准 Judge**：用人工标注校准 Judge 的准确性
- **关注 Judge 偏差**：位置偏差（偏好第一个答案）、长度偏差

### 3.3 评分组合

```text
最终评分 = w1 × 规则分 + w2 × Judge分 + w3 × 人工分 + w4 × 执行器分
```

权重根据场景调整，高风险场景人工分权重更高。

## 4. 评测集管理

### 4.1 评测集设计原则

- **覆盖性**：覆盖核心场景、边界 case、对抗 case
- **隔离性**：评测集不能用于训练或 few-shot
- **版本化**：评测集本身版本化管理
- **动态更新**：从生产 Trace 中持续补充新 case
- **分层结构**：核心集（必过）+ 扩展集（参考）+ 对抗集（安全）

### 4.2 评测集分类

| 类型 | 规模 | 用途 | 频率 |
|:---|:---|:---|:---|
| 冒烟集 | 20-50 条 | 快速验证基本功能 | 每次 PR |
| 核心集 | 200-500 条 | 覆盖核心场景 | 每次发布 |
| 扩展集 | 1000+ 条 | 全面质量评估 | 版本发布 |
| 对抗集 | 100-300 条 | 安全与边界 | 安全相关变更 |
| 回归集 | 动态 | 历史失败 case | 每次发布 |

## 5. 发布流程

### 5.1 发布门禁

```text
变更请求 → 离线评测 → 门禁检查 → 影子流量 → 灰度发布 → 全量发布
              ↓            ↓           ↓          ↓
          评分计算     自动/人工     离线对比    在线监控
              ↓            ↓           ↓          ↓
          评分 < 基线    阻断        质量不达标   异常回滚
```

### 5.2 门禁规则

| 规则 | 阈值 | 动作 |
|:---|:---|:---|
| 核心集评分 | ≥ 基线 - 2% | 否则阻断 |
| 安全集评分 | ≥ 95% | 否则阻断 |
| 格式合规率 | ≥ 99% | 否则阻断 |
| 成本变化 | ≤ +10% | 否则需审批 |
| 回归集 | 0 回归 | 否则阻断 |

### 5.3 影子流量

新版本接收真实流量副本，不返回结果给用户：

- **目的**：在真实流量分布下验证质量
- **指标**：LLM Judge 分数、成本分布、延迟
- **对比**：与当前线上版本对比

### 5.4 灰度发布

| 阶段 | 流量比例 | 监控重点 | 持续时间 |
|:---|:---|:---|:---|
| Canary | 1-5% | 错误率、延迟、成本 | 2-4 小时 |
| Early | 10-25% | 用户反馈、质量分 | 12-24 小时 |
| Mid | 50% | 全维度监控 | 24-48 小时 |
| Full | 100% | 持续监控 | - |

### 5.5 回滚机制

- **自动回滚**：质量指标低于阈值时自动切回
- **手动回滚**：一键回滚到任意版本
- **回滚速度**：Prompt/配置变更秒级回滚；模型变更需预切换

## 6. 在线实验

### 6.1 A/B 测试

- **流量分桶**：按用户 ID 哈希分桶
- **对照设计**：控制组（当前版本）vs 实验组（新版本）
- **统计显著性**：需足够样本量才能得出结论
- **关键指标**：用户满意度、任务成功率、成本

### 6.2 交错测试 (Interleaving)

将两个模型的输出交替展示给用户：

- **优势**：比 A/B 测试所需样本量更少
- **适用**：排序、推荐类场景
- **局限**：不适用于多轮对话

## 7. 常见反模式

- **只看 API 成功率**：忽略输出质量
- **优化单一分数**：为评测分高而过度优化，损害真实质量
- **评测集泄漏**：评测数据用于训练，分数虚高
- **无灰度直接全量**：变更风险未控制
- **无回滚能力**：发现问题后无法快速恢复
