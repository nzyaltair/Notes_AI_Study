# MoE 路由与规模化

稀疏混合专家（MoE）以路由器为每个 token 选择少量专家，在近似固定激活计算下扩大总参数容量。关键问题包括路由粒度、专家专业化、容量上限、负载均衡损失、通信与训练稳定性。

- **Sparse MoE / Switch Transformer**：以 Top-k 或 Top-1 路由稀疏激活专家。
- **负载均衡**：避免少数专家过载、其余专家闲置；但过强均衡也可能限制专业化。Switch Transformer 均衡损失 $N\sum f_i P_i$ 对 $P_i$ 求导恰为 token 比例 $f_i$，本质是梯度空间的比例惩罚；OLMoE 消融显示完全去掉均衡损失后几乎所有 token 涌向 2 个专家、训练损失显著恶化。DeepSeek-V3 进一步用「每专家偏置 + 在线调整」实现无辅助损失均衡。
- **规模化证据**：保持激活参数不变、仅增加专家数量，损失持续下降（Switch Transformer）；同等验证损失下 MoE 训练约比稠密快 2 倍（OLMoE）。MoE 降低激活 FLOPs，不自动降低参数存储、通信和服务复杂度。
- **路由设计空间**：token 选择（事实标准，最稳）> 专家选择（Llama 4 曾试）；哈希路由仅作论文基线；RL/线性指派可行但不划算。专家分工停留在表面模式（标点/语言字符），并非语义专家。
- **现代实现**：细粒度专家、共享专家（DeepSeekMoE 首创，Qwen3/GLM/Kimi 沿用）与改进路由体现容量、稳定性、成本之间的折中。
- **系统维度**：专家并行是数据/模型并行之外的第三维度（all-to-all 路由激活值）；路由专家可先降维投影再通信以节省开销；历史教训——早期框架静默丢弃溢出 token，现代 dropless 架构（Megablocks 等）已解决。
- **训练/微调坑**：router softmax 用 FP32 + z-loss 稳定；微调 experts 严重过拟合，常见做法是只微调 attention/非 MoE 层；Upcycling（稠密→MoE 回收，MiniCPM/Qwen1.5-MoE 案例）现已让位于从头 MoE 训练。
