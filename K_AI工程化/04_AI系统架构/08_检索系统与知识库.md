# 检索系统与知识库

## 一句话理解

检索系统从大规模文档集合中快速找到相关信息，是 RAG 和知识密集型 AI 系统的核心基础设施。

## 核心概念

### 检索范式

| 范式 | 原理 | 优势 | 局限 |
|------|------|------|------|
| 稀疏检索（BM25）| 词袋 + TF-IDF 加权 | 简单、高效、可解释 | 无法处理语义匹配 |
| 稠密检索（Dense Retrieval）| 双编码器 + 向量相似度 | 语义匹配能力强 | 需要 GPU 推理 |
| 混合检索 | 稀疏 + 稠密融合 | 兼顾精确匹配和语义 | 系统复杂度高 |
| 学习排序（LTR）| 用 ML 模型对候选排序 | 可融合多种特征 | 需要训练数据 |

### 检索流程

```
查询 → 查询理解 → 检索 → 重排序 → 融合 → 生成
```

- **查询理解**：查询改写、扩展、消歧
- **检索**：从索引中获取 top-K 候选
- **重排序**：用更精确的模型对候选重新排序
- **融合**：多路检索结果融合

### 向量索引

| 索引方法 | 原理 | 优势 | 局限 |
|---------|------|------|------|
| Flat（暴力搜索）| 全量计算 | 100% 准确 | 海量数据不可行 |
| IVF（倒排文件）| 聚类 + 近邻搜索 | 速度快，内存友好 | 精度损失 |
| HNSW（分层导航图）| 多层图结构 | 速度快，精度高 | 内存占用较大 |
| PQ（乘积量化）| 向量压缩 | 内存占用极低 | 精度损失 |

### 知识库构建

- **知识抽取**：从文档中提取实体、关系、事件
- **知识融合**：合并多源知识，消除冲突
- **知识更新**：增量更新，保持时效性
- **知识图谱**：用图结构组织知识，支持推理

## 应用场景

- **RAG 检索增强**：为 LLM 提供外部知识
- **企业搜索**：内部文档、知识库检索
- **问答系统**：基于知识库的自动问答
