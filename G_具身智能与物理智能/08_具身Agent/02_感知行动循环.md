# 感知—行动循环

## 一句话理解

具身 Agent 的基本循环为：观测 → 状态估计 → 选择目标/技能 → 预测与验证 → 执行短动作 → 核验 → 更新或恢复。物理环境的延迟、遮挡、接触和外部变化意味着不能长时间开环执行。

## 概述

感知-行动循环（Perception-Action Loop）是具身智能区别于静态 AI 的核心机制：智能体不只在动作后等待反馈，而是把感知、预测、行动、核验组织成持续的闭环。闭环的长度、频率和内容决定了系统的鲁棒性——开环越久，误差与环境变化越容易累积为失败。

## 发展历史

- **1948**：Wiener 控制论提出反馈闭环思想。
- **1980s**：Brooks 的 Subsumption 架构强调行为分层与实时反应，反对串行流水线。
- **2000s**：视觉伺服（Visual Servoing）将感知-行动闭环形式化（IBVS, PBVS）。
- **2020s**：VLA 时代重提"短时域闭环"——LLM/VLA 低频提议，感知-执行-核验高频闭环。

## 核心概念

| 概念 | 定义 | 意义 |
|---|---|---|
| 闭环 | 行动结果反馈到下一决策 | 鲁棒性的来源 |
| 开环 | 无反馈的序列执行 | 误差累积 |
| 核验 | 执行后确认结果 | 失败检测 |
| 重规划 | 失败后重新选择方案 | 恢复机制 |
| 观测-动作时延 | 感知到执行的延迟 | 时延破坏闭环 |
| 滚动时域 | 短块执行 + 重新观测 | 标准部署模式 |

## 技术原理

### 基本循环

```text
观测 → 状态估计 → 目标/技能选择 → 预测与验证
→ 执行短动作 → 核验 → 状态更新 → 下一轮
                  ↓ 失败
              归因与恢复（重感知/重规划/求助）
```

### 闭环设计维度

| 维度 | 短闭环 | 长闭环 |
|---|---|---|
| 时域 | 1-5 秒 | 分钟级 |
| 频率 | 高频核验 | 低频检查 |
| 适用 | 接触、抓取、避障 | 任务级监控 |
| 风险 | 延迟与计算成本 | 误差累积 |

### 触发重规划的信号

低置信度、状态过期、预测误差大、碰撞风险或技能超时应触发重新感知、重规划、降级或人工接管：

| 信号 | 检测 | 应对 |
|---|---|---|
| 低置信度 | 感知置信度 | 重新观察 |
| 状态过期 | 时间戳 | 更新地图 |
| 预测误差大 | 预期-观测比对 | 重规划 |
| 碰撞风险 | 碰撞检测 | 撤退/重规划 |
| 技能超时 | 进度监控 | 换方案/求助 |

### 开环 vs 闭环执行

- **开环执行**：一次性生成长动作序列（早期 BC）。优点：简单；缺点：复合误差、无法应对环境变化。
- **短时域闭环**：执行短动作块（1-2 秒）后重新观测。优点：鲁棒；缺点：时延与计算开销。
- **分层闭环**：高层低频（任务级），低层高频（伺服级）。标准工程方案。

## 关键方法与模型

| 方法 | 核心思想 | 适用 |
|---|---|---|
| 视觉伺服 (IBVS/PBVS) | 图像特征/位姿反馈 | 接近与抓取 |
| 滚动时域执行 | 短块 + 重观测 | VLA/扩散策略 |
| 行为树循环 | 结构化检查-执行 | 长程任务 |
| Inner Monologue | 语言反馈核验 | 语言任务 |
| 执行监控 | 预期-观测比对 | 通用 |

## 优势与局限

| 方面 | 优势 | 局限 |
|---|---|---|
| 鲁棒性 | 抵抗误差与变化 | 时延开销 |
| 可恢复 | 失败可检测 | 检测器本身会错 |
| 分层性 | 多时标协作 | 接口复杂 |

## 应用场景

- 抓取：接近-接触-核验闭环。
- 导航：避障-重定位闭环。
- 长程任务：子任务级核验。
- VLA 部署：短时域闭环执行。

- **语言核验循环**：用 VLM 核验任务是否完成。

## 常见问题

- **长时间开环执行**：误差与环境变化累积。
- **只测最终成功率**：应报告闭环成功率、观测-动作时延、失败检测和恢复率。
- **核验不充分**：动作执行后必须确认结果。
