# 语言落地与规划 Agent

## 一句话理解

语言模型可将"准备早餐"提议为子任务，但必须将名词、关系和动词落地到对象状态、技能接口和物理约束——`open(fridge)` 只有在检测到把手、可达、碰撞可避、技能可用且安全条件满足时才是可执行动作。

## 概述

语言落地（Language Grounding）解决"自然语言指令如何变成可验证的物理动作"。LLM 擅长任务分解与常识推理，但语言是符号的、物理世界是连续的——"红色杯子"必须映射到具体 3D 对象，"放在左边"必须解析参考系并验证可达。规划 Agent 研究语言理解、对象检索、技能选择与物理验证的完整链路。

## 发展历史

- **2018-2020**：语言条件模仿（LCBC）、视觉语言导航（VLN）将语言与感知结合。
- **2022**：SayCan 用 LLM 技能排序 + 可供性选择；Inner Monologue 用语言反馈闭环；Code as Policies 用 LLM 生成规划代码。
- **2023-2025**：LLM + 语义地图 + TAMP 的混合架构成熟；VLA 直接语言-动作映射；HomeRobot 等长程语言任务基准。

## 核心概念

| 概念 | 定义 | 关键点 |
|---|---|---|
| 语言落地 | 符号到物理的映射 | 指代消歧、参考系 |
| 指代解析 | 确定指令指的对象 | "那个红色的" |
| 任务分解 | 指令拆为子任务 | LLM 常识 + 验证 |
| 技能选择 | 为子任务选技能 | 前置条件检查 |
| 物理验证 | 可行性验证 | IK、碰撞、可达 |
| 澄清机制 | 指代不清时提问 | 不猜不执行 |

## 技术原理

### 语言解析 → 物理落地链路

```text
语言指令 → 指代解析（哪个对象）
→ 对象/关系查询（3D 语义地图）
→ 技能候选生成（可用技能）
→ TAMP/世界模型验证（可达、碰撞、后果）
→ 执行与核验
→ 指代不清/风险高/缺技能 → 澄清、拒绝或求助
```

### 任务分解的陷阱

LLM 任务分解容易忽略：

- **物理约束**：冰箱门是否可开、手臂能否到达。
- **时序依赖**：必须先开门才能取物。
- **资源状态**：冰箱可能已开、物体可能被移动。

因此 LLM 的任务分解应被视为**候选计划**，必须由规划器和执行器验证和修正。

### 技能选择与落地

`open(fridge)` 可执行的条件：

```text
检测到冰箱（感知）
→ 检测把手与开合轴（几何）
→ 可达且无碰撞（IK/碰撞）
→ open 技能可用（技能库）
→ 安全条件满足（力/速度限制）
→ 执行
```

### 澄清与拒绝

对指代不清、风险高或缺少技能的指令，Agent 应：

- **澄清**：询问用户意图（"哪个杯子？"）。
- **拒绝**：安全风险高的指令拒绝执行。
- **求助**：能力不足时请求人类协助。

## 关键方法与模型

| 方法 | 核心思想 | 适用 |
|---|---|---|
| SayCan | LLM 技能排序 + 可供性 | 技能选择 |
| Inner Monologue | 语言反馈闭环 | 长程任务 |
| Code as Policies | LLM 生成规划代码 | 结构化任务 |
| VLM 指代 | 视觉-语言指代 | 对象解析 |
| 语义地图查询 | 语言检索对象 | 定位 |
| TAMP 验证 | 可行性检查 | 执行前验证 |

## 优势与局限

| 方面 | 优势 | 局限 |
|---|---|---|
| 语义泛化 | 开放指令 | 幻觉 |
| 常识推理 | 任务分解 | 忽略物理约束 |
| 可组合 | 新任务分解 | 验证成本 |
| 交互澄清 | 减少歧义 | 依赖用户在场 |

## 应用场景

- 家居任务：自然语言指令执行。
- 服务机器人：用户对话驱动的任务。
- 人形操作：语言条件全身操作。
- 仓储：指令驱动的拣选。

## 常见问题

- **把 LLM 分解当可执行计划**：必须物理验证。
- **忽略参考系**："左边"没有参考系无意义。
- **不澄清直接猜**：指代不清应询问。
- **跳过安全检查**：高风险指令必须拒绝。
