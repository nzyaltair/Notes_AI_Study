# 数据配比

## 一句话理解

数据配比决定多个数据源在训练中各占多少份额——从「凭感觉手调」到「按比例/均匀采样」，核心约束是**每数据源 epoch 会计**（高质量源先被训完多轮而过拟合）；最具理论依据的做法是用小规模代理实验拟合「配比 → 损失」的回归模型再优化放大（DoReMi/RegMix 系）。

## 1. 概述

清洗、过滤、去重之后得到的是一组规模更小的高质量文档池——但它们来自不同来源（网页、代码、论文、数学、百科），**如何分配权重**直接影响模型能力方向。The Pile 时代就为 22 个子集分别设定权重，本质是一种资源分配问题。

配比之所以难：不同源之间不可直接比较（一段代码和一篇论文谁更"高质量"？），且每个源的数据量有限（小源分配过多权重会被反复训练）。

## 2. 混合策略谱系

| 策略 | 做法 | 问题 |
|:---|:---|:---|
| 凭感觉手调（vibes） | 依据直觉微调权重，实践中最常见 | 无可复现性，与第一性原理相反 |
| 均匀采样 | 每采一个 chunk 均匀随机选源 | 忽略质量与规模差异 |
| 按比例采样 | 按各源 token 数占比采样 | 合理但会被"体量巨大而低质"的源吃掉预算 |
| 质量加权 | 高质量源更高权重 | 小规模高质量源容易超epoch（见第 3 节） |
| 回归式配比 | 小模型实验拟合配比→损失，优化后放大 | 目前最有理论依据（见第 5 节） |

**工程实现（批次层面）**：训练时逐元素采样决定其来自哪个混合分量，再用该分量的序列填满整个 batch——一般每个序列源自同一分量，混合策略在 batch 层面生效；为降低梯度方差，一个 batch 内最好包含多个混合成分。

## 3. 核心约束：Epoch 会计

配比设计中最容易翻车、也是实际大模型训练项目中真实翻过车的一点：**只看数据集定义分布，忽略了每个数据点实际被训练的次数**。

```text
示例：低质量源 10T token + 高质量源 10B token，训练预算 1T token
均匀采样（各 50%）:
├── 低质量源: 只接触 500B / 10T = 5% 的数据（0.05 epoch）
└── 高质量源: 500B / 10B = 50 epoch ← 每个数据点重复训练 50 次

后果: 运气好是浪费算力，运气不好就是过拟合
```

要点：

- **训练 N 个 token ≠ N 个唯一 token**：论文宣称的 token 数常包含多轮 epoch 重复计数（跑两个 epoch 数字就翻倍）
- **必须监控每个数据源实际运行的 epoch 数**：不全程监控，很容易在不知不觉中跑满 50 个 epoch
- **质量与规模往往反相关**：高质量源通常更小，只按质量分配权重必然导致超 epoch

## 4. Epoch 控制方法

| 方法 | 原理 | 出处 |
|:---|:---|:---|
| UniMax | 均匀采样各源，但为每源设定 epoch 上限（如 20）；约束为「分配概率 × 训练 token 数 ≤ 上限」，有简单流程在约束下求混合比例 | 多语言训练场景（低资源语言数据稀缺问题） |
| 模拟 epoch（simulated epochs） | 让小规模实验呈现大规模实验的数据稀缺状态：全量混合下采样到 1% 再训练，避免"小模型跑完 epoch、大模型又跑一遍"的失配 | 与 Scaling Laws 的 μP 参数化同一思想——让超参可迁移 |
| 截断轮次 | 直接截断高权重小源的 epoch | 简单粗暴 |

> **为什么小模型实验必须模拟数据稀缺**：若小模型用 10B、大模型用 1T，直接下采样 1% 会让小模型在维基百科等小源上被迫跑几十个 epoch 而过拟合、损失死锁——得到的"最优配比"在大规模上并不成立。模拟 epoch 让小规模实验复现大规模高容量阶段的数据稀缺，配比结论才可迁移。

## 5. 回归式配比：用代理实验优化混合

**DoReMi / RegMix / Data Mixing Laws** 一族方法的核心流程，与 Scaling Laws「先低成本探路再放大」同构：

```text
1. 缩小规模：固定一个小的代理模型（数千万~数亿参数）
2. 采样配比：用 Dirichlet 分布（或指数分布）采样 K 组不同的混合权重
3. 训练代理：每组配比训练一个小模型，记录目标指标
   （下游评测分数或困惑度均可，由目标决定）
4. 拟合回归：以混合权重为输入、损失为输出训练回归模型
   （对数线性模型通常已很有效；提升决策树亦可）
5. 优化求解：对回归函数做优化，找最优混合比例
6. 放大训练：用最优配比训练真正的大模型
```

**设计选择**：

- **采样分布**：Dirichlet / 指数分布，覆盖配比单纯形
- **回归方法**：对数线性、提升决策树
- **目标指标**：困惑度 or 下游评测——见下方风险

**三个风险**：

1. **对下游评测过拟合**：预训练目标是通用能力。若评测集混入大量代码类基准，回归会学出"把权重全给代码"的解——最终模型写诗一塌糊涂。按比例/均匀混合反而免疫此问题（不依赖下游评测）。
2. **外推到分布边缘**：回归在采样覆盖范围内可靠，但优化过程本质是逼近极端情形——那里数据可能覆盖不足。
3. **小→大迁移假设**：最优配比与规模相关的效应确实存在（训练 token 越多，低质量数据越可接受，最优解不同）；在开源社区常用规模下该假设不明显错误，但不能盲目外推到任意规模。

> **教训**：优化任何目标都要小心——很容易把目标本身优化错（ optimizing the wrong thing ）。

## 6. 退火阶段（Annealing）的数据配比

预训练末尾的低学习率阶段（退火/衰减阶段）是配比设计的主战场：

- **指令数据前移**：把 instruction tuning 数据与高质量数据混入退火阶段已是通行做法——既扩展指令数据规模，又更侧重高质量数据；预训练、指令微调、高质量数据的界限日益模糊（"base model 已名不副实"——多数基座预训练时就混入了 UltraChat 类对话数据）
- **为什么最高质量数据放退火阶段**：退火阶段最接近部署分布、学习率最低——是全训练最重要的部分；不把全预训练都做成高质量的原因是 token 不够（全用维基百科很快耗尽）
- **典型案例——MiniCPM 两阶段**：第一阶段标准互联网数据配比；第二阶段（退火）切换为 Stack Exchange、UltraChat 等高质量对话数据，下调通用数据占比
- **退火阶段是消融实验主场**：中期训练比完整预训练短得多，每种候选配比可跑约 10 次消融——据此评估各数据源质量，结论反哺预训练阶段该加什么数据；预训练配比的决策通常就是在衰减阶段跑批量消融后确定的
- **现实流程证据**：Meta 因书籍数据被起诉的法庭文件披露了研究人员通过消融实验估算书籍语料价值、再据此定配比的真实流程
- **方法本质是试错**：配比虽有 DoReMi/RegMix 等算法（见第 5 节），实践中主要靠试错与直觉——对某领域做消融、把影响最大的排序、再大致决定放什么

## 7. 领域 × 质量二维网格

现代做法（如 Nemotron、Web Organizer 一系）不只按"数据源"混合，而是把 CommonCrawl 内部按主题聚类（如 Web Organizer 的主题归类）+ 质量过滤，构建**领域 × 质量的二维网格**——每个格子都是一个可独立调权的混合素材，再叠加外部数据源（代码、论文、数学语料等）。

## 8. 常见问题

- **配比只看质量**：忽略数据量，小源超 epoch 过拟合
- **epoch 失控**：未监控每源 epoch 数，隐性多轮训练
- **代理实验失配**：小模型用全量数据、大模型重复跑，结论不可迁移（应模拟 epoch）
- **回归目标过拟合**：下游基准主导回归目标，配比偏向单一领域
- **token 数口径不一**：多 epoch 重复计数导致不同论文的"token 数"不可比
- **配比消融只在预训练做**：应优先在退火阶段做（成本低一个量级），结论反哺预训练配比
