# AI 评测体系综述：如何判断"是否更智能"

## 一句话理解

AI 评测体系是衡量 AI 系统能力、安全性和对齐程度的标准化框架——没有可靠的评测，就无法判断模型是否更智能、是否安全、是否更接近 AGI，评测是 AGI 进步的"度量衡"。

## 1. 领域定义

AI 评测是对 AI 系统进行全面、系统、可重复的评估。核心问题：

- **能力评测**：模型能做什么？做到什么程度？
- **安全评测**：模型会做什么不该做的？
- **对齐评测**：模型的行为是否符合人类意图？
- **效率评测**：模型的资源消耗如何？

### 评测的挑战

| 挑战 | 描述 | 原因 |
|------|------|------|
| Goodhart 定律 | 优化评测 ≠ 提升能力 | 评测成为目标就失去意义 |
| 数据污染 | 测试数据出现在训练中 | 互联网数据难以隔离 |
| 评测过时 | 评测跟不上能力发展 | 新能力不断涌现 |
| 生态碎片 | 评测框架不统一 | 缺乏标准化 |
| 通用性 | 通用能力难以评测 | AGI 评测没有"标准答案" |

## 2. 核心评测维度

### 2.1 能力评测

| 评测类型 | 代表 | 评测内容 |
|----------|------|----------|
| 语言理解 | MMLU, HellaSwag | 知识与推理 |
| 数学推理 | GSM8K, MATH | 数学能力 |
| 代码生成 | HumanEval, MBPP | 编程能力 |
| 常识推理 | ARC, WinoGrande | 常识理解 |
| 长文本 | Needle-in-Haystack, LongBench | 长上下文能力 |
| 多语言 | MGSM, XWinograd | 多语言能力 |
| 多模态 | MMMU, MathVista | 视觉理解 |

### 2.2 推理评测

| 评测类型 | 代表 | 特点 |
|----------|------|------|
| 数学推理 | AIME, OlympiadBench | 高难度数学 |
| 逻辑推理 | LogiQA, ProofNet | 形式推理 |
| 科学推理 | SciBench, GPQA | 科研推理 |
| 代码推理 | LiveCodeBench, SWE-bench | 实际工程 |

### 2.3 Agent 评测

| 评测类型 | 代表 | 评测内容 |
|----------|------|----------|
| Web Agent | WebArena, WebVoyager | 网页操作 |
| Coding Agent | SWE-bench, HumanEval | 代码开发 |
| Tool Use | API-Bank, ToolBench | 工具调用 |
| 游戏 Agent | CRADLE, Voyager | 游戏交互 |
| 开放世界 | OSWorld | 操作系统操作 |

### 2.4 安全评测

| 评测类型 | 代表 | 评测内容 |
|----------|------|----------|
| 对抗攻击 | AdvBench, HarmBench | 对抗鲁棒性 |
| 有害输出 | ToxiGen, RealToxicityPrompts | 毒性生成 |
| 隐私泄露 | PrivacyBench | 隐私保护 |
| 幻觉评测 | TruthfulQA, HaluEval | 事实性 |
| 偏见评测 | BBQ, WinoBias | 社会偏见 |

### 2.5 对齐评测

| 维度 | 方法 | 说明 |
|------|------|------|
| 有用性 | 人类偏好评估 | 输出是否有用 |
| 无害性 | 红队测试 | 是否产生有害输出 |
| 诚实性 | 事实性评测 | 输出是否诚实 |
| 可控性 | 指令遵循评测 | 是否遵循指令 |

## 3. 评测方法论

### 3.1 自动评测 vs 人类评测

| 方法 | 优势 | 劣势 |
|------|------|------|
| 自动评测 | 快速、可重复、大规模 | 可能与人类判断不一致 |
| LLM-as-Judge | 低成本、有推理 | 偏差、位置效应 |
| 人类评测 | 金标准 | 昂贵、不可重复 |
| 混合评测 | 兼顾成本和质量 | 复杂度高 |

### 3.2 动态评测

- 防止数据污染：动态生成新测试题
- 适应性评测：根据模型能力调整难度
- 持续评测：持续跟踪模型更新

## 4. 发展历史

1. 2018：GLUE/SuperGLUE 标准化 NLU 评测
2. 2021：MMLU 成为 LLM 标准评测
3. 2022：BigBench 大规模评测套件
4. 2023：SWE-bench 等真实任务评测
5. 2024：Agent 评测框架 (WebArena, OSWorld)
6. 2025-26：动态评测、LLM-as-Judge 成为主流

## 5. 与 AGI 的关系

- **进步的度量衡**：没有评测就无法判断 AGI 进展
- **安全的守门人**：评测是安全部署的必要条件
- **能力的边界**：评测揭示模型的能力边界
- **对齐的验证**：评测验证模型是否对齐人类意图

## 6. 学习路径

1. 理解主流评测基准 (MMLU, GSM8K)
2. 学习评测方法论（自动 vs 人类 vs LLM-as-Judge）
3. 研究数据污染问题
4. 了解 Agent 评测框架
5. 探索动态评测和持续评测

## 7. 未来趋势

- 动态自适应评测
- Agent 综合评测
- 安全评测标准化
- 多模态统一评测
- AGI 里程碑评测
