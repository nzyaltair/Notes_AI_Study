# 视觉语言模型

## 一句话理解

视觉语言模型（VLM）把图像或区域特征接入语言模型，使文本生成可受视觉证据约束；回答流畅不等于模型可靠地看见了图像内容。

图文预训练学习视觉—语言语义对应，多模态指令训练让模型按任务格式使用视觉 token。评测需区分识别、OCR、空间关系、跨图比较和幻觉，并采用图像扰动避免语言先验取巧。

## 架构模板

现代 VLM 共享同一架构骨架（CS336 总结）：**视觉编码器 + 连接器/投影器 + 语言模型**。视觉编码器把图像映射为向量序列（"图像 token 化"），投影到语言模型的嵌入空间后与文本 token 拼接送入标准 Transformer。好处是可直接复用预训练语言模型，而非从零训练。注意：这类模型**只理解、不生成图像**——多模态内容只存在于输入端，输出始终是文本。

## LLaVA 系列

### LLaVA（2023）

| 组件 | 选择 |
|---|---|
| 视觉编码器 | CLIP ViT-L/14（表现最好的 CLIP 版本） |
| 语言模型 | Vicuna——首个在共享 GPT 对话数据上微调的 LLaMA 模型 |
| 投影器 | 线性投影 $W$ |
| 数据 | MS-COCO（众包标题 + 边界框）→ 喂给 GPT-4 合成对话/问答/详细描述/复杂推理，共 15.8 万样本 |

意义：GPT-4 已能视觉推理但闭源；LLaVA 让开源社区第一次看到 VLM 的内部运作机制。两阶段训练（对齐 → 指令微调）详见 [[03_跨模态对齐与连接器]]。即便提示词不清晰（没直接问"哪里出了问题"），模型也能给出合理解释。

### LLaVA-1.5（2023）

核心改动：线性投影 → **两层 MLP** 投影器。整体架构不变。

### LLaVA-OneVision（2024）

支持**单图、多图、视频**（视频 = 连续帧采样，本质仍是图像）：

| 组件 | 选择 |
|---|---|
| 视觉编码器 | SigLIP（替换 CLIP） |
| 语言模型 | Qwen2（当时最强开源 LM） |
| 投影器 | 两层 MLP |
| 上下文 | 最多 32 帧；token 过多时用插值下采样 |

**任意分辨率（AnyRes）策略**——解决视觉编码器搞不定高分辨率的问题（一份文档裁成 336×336 就没法读了；OCR 需要保留细粒度信息，否则 J 看起来像 I）：

1. 图像下采样生成一条全局路径（整图的粗编码）
2. 同时切成若干 336×336 块，分别编码
3. 拼接所有块向量；数量过多时插值减少
4. 自适应资源分配：**单图 = 更高分辨率；多图 = 基础分辨率（图多了只能粗略浏览）；视频 = 更低分辨率/每帧更少 token**（视频数据量巨大，需节省计算，且要防止视频淹没文本）

**数据理念**：既要高质量也要数量；大多为特定任务定制（VQA、表格问答）——属于后训练性质，目标是让模型对齐人类意图。坦率承认是在**蒸馏 GPT-4**（没有标注预算时的现实选择）。

**跨模态迁移**（论文最有趣的发现）：

- 训练时只用"单图 OCR"和"多图关系推理"两类数据，测试时模型能处理"一张图中既有表格又有图表 + 多张截图间关系推理"的组合场景（如驱动 GUI Agent）
- **视觉提示（visual prompting）**：在图中画一个圆圈标记需要操作的区域——圆圈是图像的一部分
- 启示：乍看像针对每个任务下手（监督学习式），但任务足够多时模型似乎能实现某种迁移

## Qwen-VL 系列

### 演进总览

| 版本 | 视觉编码器 | 关键创新 |
|---|---|---|
| Qwen-VL (2023) | OpenCLIP ViT | 交叉注意力 + 2D 位置嵌入压缩到固定 256 token；`<img>`/`<box>`/`<ref>` 特殊 token；支持中文、边界框输出、OCR |
| Qwen2-VL (2024) | OpenCLIP ViT（微调） | **朴素动态分辨率**：224×224 块经 ViT 编码，2×2 patch 合并压缩 token 数；**M-RoPE** 多模态旋转位置编码（高度、宽度、时间三维） |
| Qwen2.5-VL | — | 迭代改进 |
| Qwen3-VL (2025) | SigLIP 2 | 长上下文 256K、交错 M-RoPE、显式时间戳、深度融合 adapter |

Qwen-VL 系列的边界框能力值得注意：模型**不生成图像**，只输出边界框坐标（特殊 token 形式）——定位任务被转化为文本生成。

### M-RoPE 与其修正（Qwen2-VL → Qwen3-VL）

RoPE 的核心性质：向量内积只依赖相对距离。一维中距离即 token 间隔数；推广到三维 $(h, w, t)$（高度、宽度、时间），每个图像块/帧位置由三元组表示。

**Qwen3-VL 发现的缺陷**：RoPE 各维度对应不同频率，若整块维度顺序分配（时间 → 宽度 → 高度），**时间维度可能全是低频而高度维度全是高频**。修正：将维度**交错排列**，使每个轴都同时接触低频与高频信息。

**显式视频时间戳**：把时间戳直接作为 token（如 `0s`）插入序列——此前时间信息隐含在帧的位置差异中；显式化后模型可直接引用（"两秒后发生了什么"），显著增强时间感知。

**防视频主导**：视频样本 token 数远多于单图样本；若所有 token 一视同仁，视频样本会主导训练。Qwen3-VL 大致按**序列长度的平方根做归一化**，压制超长样本的影响；另一种做法是直接调低模态权重（数据配比问题，与纯文本 LM 训练同理）。

### Qwen3-VL 的其他要点

- 语言底座：Qwen3 系列（dense + MoE）——LM 底座质量对最终 VLM 帮助很大
- 长上下文重点投入：最高 256K，对长视频尤为关键（多模态的关键问题之一就是如何处理长上下文）
- 训练：预训练 4 阶段 + 后训练 3 阶段；上下文渐进 8K → 32K → 256K；后训练用长 CoT 数据做 SFT + 蒸馏 + RL
- 这是一篇侧重**系统实现**的论文：架构图基本不变，变化在数据、规模与训练课程——从 Qwen 到 Qwen3 整体框架不变，主要是规模扩展与长上下文处理
- 结果：与 Gemini、GPT-5、o4.1 等闭源模型对比仍有竞争力

## 视觉塔为何可以很小

视觉编码器参数量通常不到 10 亿（LLaVA 视觉塔约 72M vs 7B LM）：它执行的是**局部操作**，只理解一个个小 patch；缺乏世界知识，无法对 patch 做高层推理。VLM 的核心能力仍源于语言模型，视觉塔只负责把像素翻译成语义向量。
