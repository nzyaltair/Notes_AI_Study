# AI 评测体系综述

## 一句话理解

评测是模型与系统发布的质量门禁：覆盖离线能力、集成行为、在线效果、安全和成本。完整评测链路为：基准回归 → 场景/对抗测试 → 预发布验证 → 灰度与 A/B → 持续监控。

## 1. 领域定义

AI 评测体系解决：

- **能力度量**：量化模型在标准任务上的性能，用于横向比较和版本回归
- **质量门禁**：发布前验证系统满足能力、安全、成本要求
- **在线验证**：灰度、A/B 测试验证真实业务效果
- **持续监控**：检测模型漂移、输出质量下降、用户体验变化

评测贯穿 AI 系统生命周期，是训练工程（发布前验证）、LLMOps（持续监控）和 AI 可靠性工程（质量保障）的交叉点。

## 2. 发展历史

| 时间 | 里程碑 | 意义 |
|:---|:---|:---|
| 2010s | ImageNet、GLUE、SQuAD | 单一任务标准化基准，推动 NLP/CV 发展 |
| 2021 | BIG-bench | 超大规模多任务评测，覆盖 200+ 任务 |
| 2021 | HELM | 整体性 LLM 评测，多维度归一化评分 |
| 2022 | MMLU | 大学水平知识测试，成为能力评测事实标准 |
| 2023 | MT-Bench / Chatbot Arena | 人类偏好评测，弥补自动化评测局限 |
| 2023 | LLM-as-Judge | 用强模型替代人工评分，扩大评测覆盖 |
| 2023 | GAIA | AGI 任务测试基准，测试现实任务完成能力 |
| 2023 | HumanEval / MBPP / SWE-Bench | 代码能力评测体系成熟 |
| 2024 | MMMU / MathVista | 多模态评测基准成熟 |
| 2024 | AgentBench | 系统性 Agent 评测框架 |
| 2024 | 污染检测 | 评测集泄露检测成为发布必要环节 |

## 3. 评测层次

### 3.1 完整评测链路

```text
离线能力评测（基准 + 回归集）
    ↓
集成测试（场景、对抗、压力、安全）
    ↓
预发布验证（影子流量 + 人工抽查）
    ↓
灰度发布（小流量 + A/B）
    ↓
在线持续监控（质量、成本、安全）
    ↓
用户反馈收集 → 回到离线评测
```

### 3.2 评测维度矩阵

| 维度 | 内容 | 代表基准 |
|:---|:---|:---|
| **知识与推理** | 事实问答、常识、逻辑 | MMLU、HellaSwag |
| **数学** | 算术、代数、竞赛题 | GSM8K、MATH |
| **代码** | 代码生成、调试、理解 | HumanEval、SWE-Bench |
| **长上下文** | 长文档理解、多跳检索 | SCROLLS、LongBench |
| **指令遵循** | 复杂指令、格式约束 | IFEval、MT-Bench |
| **安全** | 越狱抵抗、有害内容、偏见 | HarmBench、BBQ |
| **多模态** | 图文理解、视觉问答 | MMMU、MathVista |
| **Agent** | 工具使用、多步任务 | AgentBench、GAIA |
| **人类偏好** | 对话质量、有用性、无害性 | Chatbot Arena、AlpacaEval |

## 4. 核心评测方法

### 4.1 自动化评测

- **规则评测**：精确匹配、正则、执行测试（代码）——客观且可复现
- **模型评测（LLM-as-Judge）**：用强模型评估生成质量，需校验一致性和偏见
- **人类评测**：黄金标准，成本高，用于校准自动化评测

### 4.2 对比评测 vs 绝对评测

- **对比（Pairwise）**：模型 A vs 模型 B，更易获得一致人类判断（如 Chatbot Arena）
- **绝对打分**：在固定标尺上打分，需仔细设计标尺避免偏差

### 4.3 多模态评测

图像、视频、音频输出的评测需专门指标：
- 图像相似性（SSIM、LPIPS）
- 感知质量（FID、Inception Score）
- 多模态一致性（CLIP Score）

### 4.4 Agent 评测

评测 Agent 行为而非单次输出：
- **任务成功率**：端到端任务完成率
- **轨迹效率**：完成任务的步数和 Token 消耗
- **工具使用正确性**：参数准确率、不必要调用率
- **安全性**：越界操作率、权限滥用检测

## 5. 评测质量保障

### 5.1 评测集管理

- 版本化评测集，记录来源、构造方法和标注协议
- **隔离训练数据**：评测集不能泄漏到训练中（污染检测）
- 定期刷新基准，防止"死记硬背"型过拟合
- 维护内部私有评测集，补充公开基准的盲点

### 5.2 统计严谨性

- 报告置信区间，不只报告点估计
- 区分统计显著差异和业务显著差异
- 对多数据集报告平均指标时注意权重问题
- 消融实验区分改进来源

### 5.3 评测指标选择

好的评测指标必须：
1. 与业务目标正相关（不只优化单一分数）
2. 稳定可复现（相同配置重复结果一致）
3. 对真实改进灵敏（能区分有意义的差异）
4. 对作弊不敏感（不能通过 Prompt 套分）

## 6. 人类偏好评测

Chatbot Arena（LMSYS）使用 Elo 评级系统对 LLM 排名：

- 用户在不知模型身份的情况下对比两个模型输出
- 选出偏好的一方，更新双方 Elo 分数
- 优势：消除标准化基准的局限，反映真实使用体验
- 局限：成本高、慢、受用户群偏见影响

LLM Judge 评测格式（GPT-4 作为评判）：提供参考答案或评分标准，让模型输出 1-10 分和理由。主要偏见：位置偏见（更偏爱第一个答案）、风格偏见（更偏爱详细输出）。

## 7. 在线评测与 A/B 测试

离线评测不能替代在线验证：

- **影子流量**：新版本接收生产流量但不返回给用户，对比结果
- **灰度发布**：5% → 20% → 100% 逐步放量
- **A/B 测试**：统计显著性检验确认真实改进
- **业务指标**：任务完成率、用户满意度、转化率

在线和离线结果不一致时，在线结果优先。

## 10. 前沿发展

- **Dynamic Benchmarks**：动态生成评测题目，防止数据污染和记忆作弊
- **Capability Elicitation vs True Capability**：区分提示技巧带来的表现提升与真实能力提升
- **多智能体系统评测**：评测 Multi-Agent 协作任务的新方法论
- **对齐评测**：超越安全过滤，评测模型是否真正符合人类价值观
- **可信度评测**：校准（Calibration）、幻觉检测、不确定性量化
- **视频生成评测**：运动一致性、物理合理性等视频质量评测
