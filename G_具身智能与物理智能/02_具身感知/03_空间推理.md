# 空间推理

## 一句话理解

空间推理把几何、语义和本体能力联系起来，回答"目标在何处、如何到达、动作后是否仍安全"——它解决的是语言与几何之间的翻译问题，而非单纯的空间计算。

## 概述

空间推理是连接"语言描述的意图"与"几何可验证的行动"的桥梁。机器人收到"把红色杯子放在盘子左边"这类指令时，需要解析"左边"的参考系、定位杯子和盘子、检查可达性与碰撞，最终生成可执行动作。空间推理失败是语言智能落地为物理行动的主要障碍之一。

## 核心概念

| 概念 | 定义 | 难点 |
|---|---|---|
| 空间关系 | 左右、前后、上下、里外、支撑 | 参考系依赖（观察者/物体/环境） |
| 拓扑关系 | 连通、相邻、包含 | 语义与几何的映射 |
| 可达性 | 机器人能否到达某位姿 | 受本体自由度、关节限位约束 |
| 可见性 | 目标是否在视野内 | 遮挡、视角、光照 |
| 语义定位 | 把语言指代映射到坐标 | 指代消歧、开放词汇 |
| 代价地图 | 导航空间的可通行性 | 动态障碍、机器人尺寸 |

## 技术原理

### 参考系与空间关系

空间关系高度依赖参考系，这是空间推理的第一个陷阱：

- **观察者中心**（"我左边"）：依赖相机/机器人朝向。
- **物体中心**（"杯子左边"）：依赖物体坐标系（有正面/无正面之分）。
- **环境中心**（"房间东侧"）：依赖全局地图坐标。

语言表达"左边"时，必须显式声明参考系才能转换为坐标约束。神经方法（场景图网络、关系 Transformer）学习从语言与几何联合推断关系，但必须验证输出与坐标约束的一致性。

### 从语言到坐标约束

实用系统的标准流程：

```text
语言指令 → 指代解析（哪个对象）→ 关系解析（相对哪里）
→ 对象检索（3D 语义地图）→ 坐标约束生成 → IK/碰撞/运动规划验证
```

语义查询与几何验证解耦：LLM/VLM 负责语义层（"红色杯子""盘子左边"），几何层用 3D 位姿、可达性分析和碰撞检测验证可行性。不能把 VQA 准确率当作空间推理能力。

### 可达性与导航空间

- **操作可达性**：机械臂 IK 求解 + 碰撞检查验证末端能否到达抓取位姿。
- **导航可达性**：代价地图（栅格）标注可通行区域，考虑机器人尺寸（膨胀）、动态障碍和狭窄通道。
- **全身可达性**：人形机器人需要考虑移动 + 操作联合的可达空间。

关键区别：语言中的"左边"依赖参考系；视觉中的近邻不代表机械臂可达；地图中的空闲不代表机器人本体可通过。

### 场景图与关系推理

3D 场景图以节点（对象、房间）和边（关系）表达场景结构，支持：

- 关系查询："杯子在哪个柜子上"。
- 子图检索："厨房里所有台面上的物体"。
- 增量更新：物体被移动后更新边。

## 关键方法与模型

| 方法 | 核心思想 | 适用 |
|---|---|---|
| 代价地图 + A*/D\* | 栅格导航规划 | 移动导航 |
| 3D Scene Graph | 场景图表示与查询 | 长程任务 |
| Relation Transformer | 图注意力关系推理 | 视觉关系检测 |
| LLM 空间提示 | 语言指导空间推理 | 语义定位 |
| 可微空间推理 | 关系约束嵌入损失 | 联合优化 |
| 拓扑地图 | 节点-边拓扑导航 | 大范围导航 |

## 优势与局限

| 方法 | 优势 | 局限 |
|---|---|---|
| 几何验证 | 可证明、精确 | 依赖精确感知 |
| 语义检索 | 开放词汇、泛化 | 坐标精度不足 |
| 场景图 | 结构化、可增量 | 依赖数据关联稳定性 |
| LLM 推理 | 常识、组合性 | 幻觉、缺乏精确几何 |

## 应用场景

- 导航："去厨房""绕过桌子到冰箱前"。
- 操作："把碗放在锅的右边"。
- 装配："将螺丝插入孔中"。
- 长程任务："整理房间：把散落的书放回书架"。

## 前沿发展

- **LLM 空间推理**：用 LLM 做空间常识推理，但输出需几何验证。
- **开放词汇空间查询**：SAM + 3D 特征场支持任意语言空间检索。
- **可微场景图优化**：把场景图嵌入可微计算图。
- **动态空间推理**：对象被移动后的场景图增量更新。

## 常见问题

- **把 VQA 准确率当空间推理能力**：关系检测准确 ≠ 动作可行。
- **忽略参考系**："左边"没有参考系就没有意义。
- **混淆可达与空闲**：地图空闲 ≠ 机器人可达（尺寸、关节限位）。
- **静态假设**：家居场景物体常被移动，空间推理必须支持更新。
