# 认知架构综述：组织感知、记忆、推理、行动与学习

## 一句话理解

认知架构不是某个模型，而是一组关于智能系统应有哪些持久功能、它们如何通信、如何受资源约束和如何学习的整体假设。它为 AGI 提供从“单模型能力”走向“可持续系统”的组织蓝图。

## 为什么需要认知架构

单一模型可以完成感知、生成或局部推理，却不自动拥有跨任务的状态管理、长期记忆、目标保持、错误恢复和在线学习。认知架构关注这些功能如何形成闭环：

```text
感知 → 状态估计 / 注意 → 工作空间 ↔ 记忆
                         ↓
                  推理 / 规划 / 决策
                         ↓
                     行动与反馈
                         ↓
                 学习与元认知调控
```

## 经典路线

| 路线 | 代表 | 核心主张 | 对 AGI 的启发 |
|---|---|---|---|
| 符号认知架构 | SOAR、ACT-R | 显式规则、模块化记忆和问题求解 | 可解释控制、任务状态和规则学习 |
| 混合架构 | CLARION 等 | 显式与隐式知识协作 | 神经表征与符号约束互补 |
| 全局工作空间 | GWT、LIDA | 被选中的信息向多个专门模块广播 | 共享状态、全局调度、跨模块协同 |
| 现代 Agent 架构 | LLM + 工具/记忆/规划 | 基础模型作为通用表征与语言接口 | 运行时、外部记忆、验证与恢复闭环 |

## 设计维度

1. **功能分解**：哪些能力应由感知、记忆、规划、执行、学习和监控承担？
2. **状态与通信**：共享工作空间、消息总线、黑板系统还是端到端隐状态？
3. **表征组合**：文本、向量、符号、程序和环境状态如何互操作？
4. **控制与门控**：何时检索、思考、调用工具、行动或停止？
5. **学习与更新**：经验写入何处，何时巩固到策略或参数中？
6. **评测**：模块是否真正提高了长程任务、泛化、可解释性、能耗或可靠性？

## 与当前 AI 的关系

LLM 并不天然等于认知架构。LLM 可以充当语言理解、通用表征或启发式规划器；架构层还需明确环境状态、可验证记忆、工具接口、权限、终止条件与失败恢复。参见 [[../../D_智能体与自主系统/00_智能体与自主系统_综述|D 智能体与自主系统]]。
