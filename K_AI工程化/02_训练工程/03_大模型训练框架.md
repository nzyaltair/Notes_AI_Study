# 大模型训练框架

## 一句话理解

训练框架封装并行策略、混合精度、检查点管理和集群调度，为大模型训练提供可复用的工程基础设施。

## 概述

训练框架是连接算法研究员和硬件集群的中间层。它将分布式训练中的并行策略、显存优化、容错恢复等复杂工程问题封装为可配置 API，使研究者能聚焦于模型结构和训练策略本身。

本笔记回答的核心问题：
- 主流训练框架各自擅长什么场景？
- 选型应考虑哪些维度？
- 框架的边界在哪里——它不解决什么问题？

## 发展历史

| 时间 | 框架节点 | 意义 |
|---|---|---|
| 2014 | TensorFlow DistBelief → v1 | 分布式训练框架化 |
| 2016 | PyTorch + torch.distributed | 灵活的分布式训练 API |
| 2018 | Horovod（Uber） | 简化多 GPU All-Reduce |
| 2019 | Megatron-LM（NVIDIA） | TP + PP 高性能训练 |
| 2020 | DeepSpeed（Microsoft） | ZeRO 系列显存优化 |
| 2021 | FSDP（PyTorch 原生） | ZeRO-3 等价的官方实现 |
| 2022 | ColossalAI | 统一多种并行抽象 |
| 2023+ | Megatron-DeepSpeed 融合 | 大规模训练工程标准化 |

## 核心概念

### 框架 vs 平台

训练框架解决的是**单作业的并行与优化**问题。它不解决：

- 多作业排队与调度（需要 K8s/Slurm）
- 数据管理与版本控制（需要 DVC/MLflow）
- 监控与告警（需要 Prometheus/Grafana）
- 权限与成本控制（需要平台层）

### 框架的核心职责

| 职责 | 说明 |
|---|---|
| 并行策略管理 | 配置和组合 TP/PP/DP/EP |
| 显存优化 | ZeRO、激活重计算、Offload |
| 混合精度 | 自动管理精度转换和 loss scaling |
| 检查点管理 | 分布式保存与恢复 |
| 通信优化 | All-Reduce/All-Gather 的拓扑感知调度 |
| 数据加载 | 分布式数据分片与预取 |

## 关键方法与模型

### PyTorch Distributed / FSDP

PyTorch 原生分布式训练生态，包括 `torch.distributed`、`DDP`、`FSDP` 和 `torch.distributed.pipeline`。

- DDP：标准数据并行，每卡持有完整模型
- FSDP：参数分片数据并行，等价于 ZeRO-3
- 优点：原生集成、社区支持好、调试友好
- 局限：TP/PP 需配合 Megatron 或自行实现
- 适用：中小规模训练、微调、研究实验

### DeepSpeed

Microsoft 开源，核心贡献是 ZeRO 系列显存优化。

- ZeRO-1/2/3：渐进式显存切分
- ZeRO-Offload：CPU 卸载
- ZeRO-Infinity：NVMe 卸载
- DeepSpeed-MII：推理服务
- 优点：显存优化能力最强，配置灵活
- 局限：TP/PP 支持不如 Megatron
- 适用：资源受限环境下的大模型训练、微调

### Megatron-LM

NVIDIA 开源，核心贡献是高性能 TP/PP 实现。

- TP：层内矩阵切分，针对 NVLink 优化
- PP：1F1B 和 Interleaved 1F1B 调度
- EP：MoE 专家并行
- 序列并行：长上下文优化
- 优点：大规模预训练性能最优
- 局限：工程复杂度高，需 NVIDIA 硬件生态
- 适用：千卡以上大规模预训练

### ColossalAI

国产开源框架（HPC-AI Tech），核心是一体化并行抽象。

- 支持多种并行策略统一配置
- Gemini：自适应显存管理
- 优点：API 友好，对非 NVIDIA 硬件支持较好
- 局限：社区规模和生态不如前两者
- 适用：多种规模实验、非 NVIDIA 硬件

### 选型对比

| 维度 | FSDP | DeepSpeed | Megatron-LM |
|---|---|---|---|
| 并行策略 | DP + 参数分片 | DP + ZeRO + Offload | TP + PP + DP + EP + SP |
| 大规模预训练 | 中 | 中 | 最优 |
| 微调场景 | 优 | 最优 | 不推荐 |
| 调试难度 | 低 | 中 | 高 |
| 硬件要求 | 通用 GPU | 通用 GPU | 推荐 NVIDIA + NVLink |

## 优势与局限

### 优势

- 降低分布式训练工程门槛
- 封装硬件底层细节
- 促进训练方案复用

### 局限

- 框架之间不互通：DeepSpeed 和 Megatron 的检查点格式、并行配置不兼容
- 框架版本更新快，API 稳定性差
- 框架不解决集群运维、调度和成本治理问题

## 应用场景

- LLM 预训练：Megatron-LM（或 Megatron-DeepSpeed 融合方案）
- 参数高效微调：FSDP + LoRA 或 DeepSpeed ZeRO-2
- 全参数微调：DeepSpeed ZeRO-3 或 FSDP
- 研究实验：FSDP（简单、灵活）

## 前沿发展

- **统一并行抽象**：像 Alpa 那样自动搜索和配置并行策略
- **编译器集成**：框架与编译器栈（如 XLA、TorchInductor）深度集成
- **异构硬件支持**：对 AMD ROCm、Intel Gaudi 等非 NVIDIA 硬件的支持
- **弹性训练**：支持 GPU 动态加入/退出的框架级支持

## 常见问题

- **FSDP 能替代 DeepSpeed 吗？**：在 ZeRO-3 级别基本可以。但 DeepSpeed 的 Offload（CPU/NVMe）能力 FSDP 暂不完全等价。
- **Megatron 只能用于 NVIDIA GPU 吗？**：Megatron-LM 的 TP 实现依赖 NCCL，理论上可在支持 NCCL 的平台上运行，但性能优化针对 NVIDIA 硬件。
- **为什么不用框架自带的检查点格式？**：框架格式通常与并行拓扑绑定，换拓扑需转换格式。建议保存为统一格式（如 Safetensors）便于跨框架使用。
