# 动作表示与分词

## 一句话理解

动作表示决定策略“能输出什么”和“如何被学习”：连续控制量适合精确执行，离散 token 便于复用序列模型，动作块和概率生成则用来表示时序相关和多种可行解。

## 核心设计问题

给定连续动作 \(a_t\in\mathbb{R}^d\)，模型可直接预测 \(a_t\)，也可经量化器 \(q\) 变为 token \(z_t=q(a_t)\)。量化使序列建模更容易，但引入不可避免的重建误差 \(\lVert a_t-\hat a_t\rVert\)。

| 表示 | 适用条件 | 主要代价 |
|---|---|---|
| 关节/末端连续向量 | 坐标系稳定、要求精确控制 | 尺度归一化和多峰动作困难 |
| 离散动作 token | 可共享词表、动作集合有限 | 量化误差和词表设计 |
| 动作 chunk | 低层控制重复、需降低决策频率 | 开环执行误差累积 |
| 轨迹分布 | 示范有多种可行路径 | 采样和实时性成本 |

## 设计原则

1. 明确坐标系、单位、夹爪语义、频率和观测—动作时延。
2. 让训练数据与部署硬件的动作空间可转换；否则跨本体迁移没有明确含义。
3. 使用 chunk 时保留重规划和安全中断接口。
4. 以任务成功率、轨迹平滑性、延迟和安全事件共同评估，而非只比较动作 MSE。
