# 监控、评测与安全治理

## 一句话理解

Agent 系统的质量保障不能只看最终回答是否正确：可观测性记录 Agent 如何决策和行动，评测证明其在目标场景中的真实表现，安全治理限制其失败时可能造成的影响范围。

## 概述

传统软件的正确性可以通过单元测试穷举验证；Agent 的行为是非确定性的、多步骤的，同一输入在不同次运行中可能产生不同的执行路径。这使得"监控（发生了什么）+ 评测（做得好不好）+ 治理（能造成多大影响）"三者必须协同工作，构成 [[../00_Agent工程系统_综述|Agent 工程系统]]走向生产落地的最后一道关卡。三者关系：监控提供治理与评测所需的原始数据，评测衡量系统能力边界，治理则在监控发现风险信号时提供硬性约束。

## 发展历史

早期 LLM 应用监控直接沿用 Web 服务的 APM（Application Performance Monitoring）思路，只记录延迟和错误率，无法回答"模型为什么给出这个答案"。2023 年前后，LangSmith、Langfuse 等专为 LLM 设计的可观测性工具兴起，引入了针对提示、检索证据、工具调用链的结构化 Trace 记录。评测方面，早期依赖人工标注，成本高、速度慢；2023 年后 LLM-as-Judge（用强模型评估弱模型输出）成为主流方案，尽管存在自我偏好等已知偏差。安全治理则受 Prompt Injection、越权工具调用等真实事故推动，从"事后补救"发展为"设计阶段内置护栏"，形成了 OWASP LLM Top 10 等行业规范，详见 [[../07_LLM应用安全|LLM应用安全]]。

## 核心概念

- **Trace（追踪）**：记录 Agent 一次完整执行过程的结构化日志，串联从输入到输出的所有中间步骤
- **LLM-as-Judge**：使用另一个（通常更强的）LLM 对模型输出进行打分或比较，替代或辅助人工评估
- **红队测试（Red Teaming）**：主动模拟攻击者行为（提示注入、越权尝试）以发现系统安全漏洞
- **护栏（Guardrails）**：在输入/输出层设置的规则或模型化过滤器，拦截不安全或不合规的内容
- **人工接管（Human-in-the-loop）**：在高风险决策点强制或允许人工介入，中断自动执行流程

## 技术原理

### Trace 应记录的关键字段

一个完整 Trace 应关联：任务目标、模型/提示版本、状态变化、检索证据、生成的计划、工具输入输出、权限判定结果、每步延迟、Token 消耗与费用、最终结果与成功判定。这些字段共同支持故障复盘——当 Agent 给出错误答案时，能够定位是检索证据不足、规划错误、工具调用失败还是模型幻觉导致。

### 核心监控指标

| 指标 | 含义 |
|:---|:---|
| 任务成功率 | 端到端完成预定目标的比例 |
| 平均步骤数 | 完成任务所需的 Agent Loop 迭代次数，反映效率 |
| 工具失败率 | 工具调用出错或返回无效结果的比例 |
| 恢复率 | 失败后通过重试/重规划成功完成任务的比例 |
| 风险拦截率 | 护栏成功拦截的高风险动作占比 |
| 人工接管率 | 需要人工介入完成的任务占比 |
| 延迟与成本 | 端到端响应时间与 Token 费用 |

### 评测的分层体系

生产级 Agent 评测需要从局部到端到端逐层验证，单一层次的通过不代表系统整体可靠：

1. **单元测试层**：单个工具调用的正确性、结构化输出的 Schema 合规性
2. **场景回放层**：在录制的历史场景或模拟环境中重放任务，验证行为一致性
3. **端到端层**：长程任务的完整成功率、故障恢复能力、资源消耗是否在预算内
4. **红队安全层**：针对提示注入、越权操作、数据泄露、危险副作用的主动攻击测试
5. **生产监控层**：上线后的持续在线监控与人工抽检，捕捉长尾场景

### 治理的核心手段

最小权限原则（Agent 仅拥有完成任务所需的最小工具与数据访问范围）、执行沙箱隔离、高风险操作的审批阈值、Token/费用预算上限、完整审计日志、敏感数据访问隔离、紧急停止开关（Kill Switch）。任何标榜"自主"的能力都不应绕过这些控制点。

## 优势与局限

**优势**：将不可控的"黑盒 Agent"转化为可观测、可度量、可约束的工程系统，是 Agent 从演示走向生产的必要条件。

**局限**：LLM-as-Judge 存在自我偏好和评分不稳定问题；端到端评测成本高，难以覆盖所有长尾场景；治理措施（如严格权限控制）可能牺牲部分自主性和响应速度，需要在安全与体验间权衡。

## 应用场景

- 企业级客服 Agent 上线前的红队安全测试与灰度发布
- 编程 Agent 的端到端任务成功率追踪与失败原因归因
- 金融、医疗等高风险领域 Agent 的强制人工审批流程

## 前沿发展

- **自动化红队**：使用 LLM 自动生成攻击性提示进行大规模安全测试，替代人工红队的部分工作
- **多维度 LLM-as-Judge**：结合多个评委模型投票或使用专门训练的评判模型，降低单一模型评分偏差
- **实时护栏模型化**：从规则匹配走向轻量级分类模型实时拦截，兼顾准确率与延迟

## 常见问题

**Q: LLM-as-Judge 可靠吗？**
有一定可靠性但存在系统性偏差，例如模型倾向于给更长的回答打高分（长度偏差），或偏好与自己风格相似的输出（自我偏好）。生产系统通常需要人工抽检校准评委模型的评分标准。

**Q: 监控和评测的区别是什么？**
监控是持续、被动地记录线上真实流量的行为数据；评测是主动、有计划地用标准化任务集测试系统能力，通常在发布前或定期回归时进行。
