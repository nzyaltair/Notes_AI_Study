# 长程任务与恢复

## 一句话理解

长程任务的难点不只是规划长度，而是环境在执行中变化。可靠系统需维护子任务进度、对象状态、技能前置条件、超时和失败类型，并系统化地检测、诊断和恢复失败。

## 概述

长程任务（Long-Horizon Tasks）指需要几十到几百步操作、跨越多个场景、持续数分钟到数小时的任务（"整理房间""准备早餐"）。其难点不在于单步动作，而在于：环境在执行中变化、状态信息过期、失败累积、进度难以追踪。长程任务与恢复研究如何让系统在真实环境中可靠地"坚持到底"。

## 发展历史

- **1990s-2000s**：分层任务网络（HTN）、状态机用于长程任务编排；执行监控（Execution Monitoring）概念出现。
- **2010s**：行为树（Behavior Trees）在游戏和机器人中流行，成为结构化编排标准。
- **2020s**：LLM 做任务分解后，长程任务成为热门（ALFRED 基准、HomeRobot）；失败诊断与自主恢复成为独立研究问题。

## 核心概念

| 概念 | 定义 | 关键点 |
|---|---|---|
| 子任务进度 | 当前处于哪一子任务 | 防重复执行 |
| 前置/后置条件 | 技能可执行的先决条件 | 验证而非假设 |
| 执行监控 | 实时检查执行是否符合预期 | 早发现早恢复 |
| 失败分类 | 感知/规划/控制/环境失败 | 正确归因 |
| 恢复策略 | 重试、换方案、求助、中止 | 按失败类型选择 |
| 安全撤离 | 无法完成时的安全退出 | 最后防线 |

## 技术原理

### 行为树编排

行为树以 Sequence、Selector、Condition 和 Decorator 显式组织检查、重试、回退与安全撤离：

```text
Sequence [整理桌面]
  ├── Condition: 桌面有目标物？
  ├── Selector [取杯子]
  │     ├── Sequence [直接取]
  │     │     ├── Condition: 杯子可达且可见？
  │     │     ├── Action: 抓取杯子
  │     │     └── Condition: 抓取成功？
  │     └── Sequence [调整后取]
  │           ├── Action: 移动视角重新感知
  │           ├── Action: 调整站位
  │           └── Action: 抓取杯子
  ├── Action: 移动至放置区
  └── Action: 放置
```

- **Sequence**：顺序执行，任一失败则整体失败。
- **Selector**：按优先级尝试，第一个成功即返回。
- **Condition**：检查条件，不执行动作。
- **Decorator**：重试、超时、次数限制等修饰。

行为树的价值不是手工编码所有情况，而是为学习策略提供**结构化的恢复骨架**。

### 失败检测与分类

失败检测是恢复的前提：

| 失败类型 | 表现 | 检测方法 |
|---|---|---|
| 感知失败 | 对象位姿错误 | 置信度低、重新观察 |
| 规划失败 | IK 无解、碰撞 | 规划器返回无解 |
| 执行失败 | 滑移、卡住、碰撞 | 力/触觉异常、进度停滞 |
| 环境变化 | 对象被移走 | 状态一致性检查 |

检测手段：预期-观测一致性、力/触觉事件、进度超时、任务后核验。

### 恢复策略分级

```text
轻量恢复：重新观察 → 换抓取姿态 → 调整站位
中级恢复：重新规划子任务序列 → 换技能
高级恢复：请求人类协助 → 安全中止 → 报告失败
```

LLM 可提出替代计划，但连续可行性仍须由状态估计、TAMP 和安全层验证。

### 状态维护

可靠系统需维护：

- **子任务进度**：已完成/进行中/待执行。
- **对象状态**：物体位置、姿态、属性更新。
- **技能前置条件**：执行前验证而非假设。
- **超时与重试计数**：防止无限重试。

## 关键方法与模型

| 方法 | 核心思想 | 适用 |
|---|---|---|
| 行为树 | 结构化检查-执行-恢复 | 工程部署 |
| 分层任务网络 (HTN) | 任务分解为方法 | 符号规划 |
| 执行监控 | 预期-观测比对 | 通用 |
| LLM 重规划 | 失败后生成替代计划 | 开放任务 |
| 视觉状态机 | 视觉检查驱动状态转移 | 家居任务 |
| 求助策略 | 低置信时请求人类 | 长程保障 |

## 优势与局限

| 方法 | 优势 | 局限 |
|---|---|---|
| 行为树 | 显式、可调试 | 手工编写成本 |
| 监控 | 早发现失败 | 检测器本身会错 |
| LLM 重规划 | 灵活、常识 | 幻觉、不可验证 |
| 求助 | 突破能力边界 | 依赖人类在场 |

## 应用场景

- 家居任务：整理、清洁、做饭。
- 仓储：拣选-打包-上架长流程。
- 实验室/医疗：多步骤流程执行。
- 搜索与救援：长时间自主任务。

## 前沿发展

- **自主失败归因**：从日志自动诊断失败原因。
- **LLM 恢复规划**：失败上下文 → LLM 提议恢复。
- **长程记忆**：跨任务经验复用的情景记忆。
- **长程基准**：ALFRED、HomeRobot 等标准化评测。
- **恢复技能学习**：从失败数据学习恢复策略。

## 常见问题

- **把长任务当单策略**：单一低层策略难承担记忆与恢复。
- **忽略环境变化**：对象被移动后仍按旧地图执行。
- **无限重试**：必须有重试上限和求助机制。
- **只测成功率**：应记录恢复次数、失败检测延迟和恢复后成功率。
