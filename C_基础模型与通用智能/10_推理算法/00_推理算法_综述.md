# 推理算法综述

## 领域定义

推理算法关注**大模型在推理阶段的生成策略与效率算法**：如何从模型输出的概率分布中选择 token（解码与采样）、如何以更少的串行步骤达到相同生成质量（投机解码/多token预测）、如何在不牺牲质量的前提下扩展上下文长度（长上下文推理策略）、以及如何在推理时动态分配计算资源（推理时扩展/测试时计算）。

本域的核心问题是：**给定一个已训练好的模型，推理阶段还能做什么来提升质量、效率或可控性？**

它与以下方向边界清晰：
- **C-08 推理与思考**：关注模型本身的"思考能力"（CoT、搜索式推理、验证器），本域关注"如何高效地生成"
- **C-09 模型压缩与高效推理**：关注模型本身的压缩（蒸馏、量化、剪枝）和系统级推理优化（KV-Cache、并行调度），本域关注生成策略与算法
- **K-03 推理工程**：关注推理服务的工程化（Serving、框架选型、部署运维），本域关注算法原理

## 核心问题

1. 如何从概率分布中选择 token 以平衡质量、多样性与可控性？
2. 如何在不损失质量的前提下突破逐 token 串行生成瓶颈？
3. 如何高效处理超长序列（2K → 1M+ token）？
4. 如何在推理时动态分配计算资源以最大化质量-成本比？
5. 如何组合多种策略（解码 + 加速 + 长上下文 + 推理时扩展）以应对实际部署约束？

## 不包含什么

- **模型训练/微调**：本域不涉及训练阶段的优化（如蒸馏训练、量化训练），这些属于 C-09
- **模型架构设计**：注意力机制、位置编码等架构层面的设计属于 C-02 语言基础模型
- **推理服务部署**：Serving 框架、集群运维、容量规划属于 K-03 推理工程
- **推理能力提升**：本域不讨论如何训练模型变得更聪明（属于 C-08 推理与思考），而是讨论如何让已有的推理过程更高效

## 常见误解

1. **"解码策略选择不重要，模型好就行"**：实际上，解码策略对生成质量影响巨大，T=0.7 和 T=0.1 的生成结果可能天差地别
2. **"投机解码会降低质量"**：标准投机解码通过拒绝采样保证输出分布与原始解码完全一致，无损
3. **"长上下文只是工程问题"**：位置编码外推涉及算法创新，不仅仅是工程优化
4. **"推理时扩展 = 无限计算"**：推理时扩展的核心是预算分配，而非无限投入

## 当前争议与开放问题

1. **推理时扩展 vs 训练时扩展**：两者在效果和成本上的最优权衡尚不明确
2. **投机解码的通用性**：在不同任务和模型上，加速比差异很大，缺乏通用理论
3. **长上下文的质量上限**：当前 1M+ 上下文的使用率仍很低，"Lost in the Middle" 问题未解决
4. **解码可解释性**：如何理解和预测不同解码策略的输出行为？
