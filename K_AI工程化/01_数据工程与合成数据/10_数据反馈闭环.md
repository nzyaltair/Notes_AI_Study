# 数据反馈闭环

## 一句话理解

数据反馈闭环把线上使用转化为可验证的数据改进——从用户行为和 Trace 中提取失败信号，经隐私检查、失败聚类、标注验证后形成新增评测集与训练集，用对照实验确认改进未伤害其他能力，而非直接把用户日志投入再训练。

## 1. 概述

模型上线后，真实用户交互中蕴含了大量有价值的数据改进信号。但直接把用户日志投入再训练是危险的——存在隐私风险、分布偏差和质量不可控等问题。

数据反馈闭环的核心原则：

- **先评测再训练**：先建立评测集验证改进效果
- **脱敏去重**：反馈数据需隐私处理和去重
- **对照验证**：用对照实验确认改进没有副作用
- **闭环迭代**：持续从生产中学习并改进

## 2. 反馈闭环流程

```text
用户行为/Trace
    ↓
隐私与同意检查
    ↓
失败聚类与分析
    ↓
人工或自动标注
    ↓
新增评测集与训练集
    ↓
离线验证
    ↓
灰度发布
    ↓
在线度量
    ↓
(回到顶部，持续迭代)
```

## 3. 信号来源

### 3.1 显式反馈

| 信号 | 说明 | 价值 |
|:---|:---|:---|
| 用户评分 | 点赞/点踩、1-5 星 | 直接质量信号 |
| 人工反馈 | 文字反馈、投诉 | 详细问题描述 |
| 人工接管 | 用户要求转人工 | 任务失败信号 |
| 拒绝使用 | 用户放弃使用 | 体验问题 |

### 3.2 隐式反馈

| 信号 | 说明 | 推断 |
|:---|:---|:---|
| 任务失败 | Agent 任务执行失败 | 能力不足 |
| 工具错误 | 工具调用参数错误 | 指令理解错误 |
| 搜索无结果 | 检索结果为空 | 知识缺失 |
| 纠错对话 | 用户纠正模型输出 | 幻觉/错误 |
| 重复提问 | 用户反复问同一问题 | 未理解需求 |
| 延迟/成本异常 | 响应时间或成本异常 | 性能问题 |
| 安全拦截 | 安全策略触发 | 安全边界 |

### 3.3 Trace 分析

从 LLM Trace 中提取质量信号：

- **LLM Judge 分数**：用强模型评估输出质量
- **检索质量**：检索结果的相关性
- **工具调用质量**：参数正确性
- **上下文利用率**：检索内容是否被引用

## 4. 失败聚类

### 4.1 聚类方法

```text
所有失败案例
    ↓
Embedding 向量化
    ↓
聚类分析 (HDBSCAN / K-Means)
    ↓
聚类主题标注
    ↓
按优先级排序
```

### 4.2 聚类维度

| 维度 | 示例聚类 | 优先级 |
|:---|:---|:---|
| 错误类型 | 事实错误/格式错误/幻觉/拒答 | 高（事实错误） |
| 领域 | 技术/法律/医疗/金融 | 按业务优先级 |
| 难度 | 简单/中等/困难 | 中（困难案例） |
| 频率 | 高频失败 vs 低频失败 | 高（高频失败） |
| 影响 | 用户体验影响程度 | 按影响排序 |

### 4.3 优先级排序

```text
优先级 = 频率 × 影响 × 可修复性

高频 + 高影响 + 可修复 → P0（立即处理）
高频 + 低影响 → P1（版本规划）
低频 + 高影响 → P2（关注但不紧急）
低频 + 低影响 → P3（暂不处理）
```

## 5. 数据加工

### 5.1 隐私处理

- **PII 脱敏**：用户个人信息替换为占位符
- **同意检查**：确认用户已同意数据用于改进
- **数据最小化**：只保留改进所需的最少数据
- **去标识化**：去除可关联到用户的信息

### 5.2 去重与过滤

- **去重**：去除重复的失败案例
- **质量过滤**：过滤低质量反馈（如无意义的评分）
- **分布检查**：确保反馈数据分布合理

### 5.3 标注与验证

```text
失败案例 → 人工/自动标注
    ↓
标注内容:
├── 正确答案（应输出什么）
├── 错误原因（为什么错了）
├── 改进方向（如何修复）
└── 评测用例（如何验证修复）
```

## 6. 评测集与训练集构建

### 6.1 评测集扩充

从失败案例中构建评测用例：

- **回归测试集**：确保已修复的问题不再出现
- **边界测试集**：覆盖边界场景
- **对抗测试集**：安全相关失败案例

### 6.2 训练集构建

从失败案例中构建训练数据：

- **正确答案**：人工标注的正确回复
- **偏好对**：正确回复 vs 错误回复（用于 DPO）
- **指令数据**：从失败案例中提取的指令-回复对

### 6.3 数据隔离

- **评测集不用于训练**：防止数据泄漏
- **训练集不用于评测**：防止过拟合评测
- **版本化管理**：记录数据来源和加工过程

## 7. 离线验证

### 7.1 验证流程

```text
新增训练数据 → 训练模型 → 固定评测集测试
                            ↓
                      对比基线模型:
                      ├── 目标能力提升？
                      ├── 其他能力下降？
                      └── 安全边界保持？
```

### 7.2 对照实验

- **A/B 对比**：基线模型 vs 改进模型
- **多维度评测**：不只看目标能力，检查所有能力
- **公平性检查**：确认改进未损害特定群体
- **安全回归**：确认安全能力未下降

## 8. 灰度发布与在线度量

### 8.1 灰度发布

改进模型经离线验证后，渐进上线：

```text
1% 灰度 → 5% → 25% → 50% → 100%
```

### 8.2 在线度量

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 失败率下降 | 同类失败案例减少 | ≥ 30% |
| 用户满意度 | 评分提升 | 显著提升 |
| 任务成功率 | 端到端成功率 | ≥ 基线 |
| 安全指标 | 安全触发率 | ≤ 基线 |
| 成本指标 | 单次请求成本 | ≤ 基线 + 10% |

## 9. 数据飞轮

```text
模型上线 → 收集反馈 → 改进数据 → 训练更好模型 → 上线
    ↑                                                    |
    └────────────────────────────────────────────────────┘
                        持续迭代
```

数据飞轮的核心：

- **正向循环**：更多用户 → 更多反馈 → 更好数据 → 更好模型 → 更多用户
- **质量门槛**：每轮迭代需通过质量验证
- **防止退化**：监控模型是否在某些维度退化
- **迭代节奏**：平衡迭代速度和质量保障

## 10. 常见问题

- **直接再训练**：把用户日志直接投入训练，无隐私处理
- **无评测先训练**：未验证改进效果就上线
- **副作用未检查**：改进了目标能力但损害了其他能力
- **反馈偏差**：只有不满意用户给反馈，导致数据偏差
- **闭环断裂**：收集了反馈但未用于改进
