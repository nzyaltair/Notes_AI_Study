# 全模态与原生多模态模型

## 一句话理解

全模态表示模型覆盖多种输入输出；原生多模态进一步主张在统一训练和内部表示中建模模态交互，两者不能混为一谈。

统一 token/latent 可支持端到端跨模态生成，但会遇到模态配比失衡、目标干扰、tokenizer 不一致与评测碎片化。模块化系统更易替换与审计，应按时延、可控性和证据需求选择。

## 北极星目标：任意模态到任意模态

语言模型已实现"任意文本到任意文本"的转换（代码、诗歌、甚至 DNA 序列）。全模态（omni）模型的目标是：**接收任意模态组合的输入，输出任意模态组合的结果**（如图像+视频提问、文本生成图像、音频转图像）。当前主流前沿模型几乎都具备多模态能力，但构建路径分叉明显。

## Chameleon：早期融合统一离散 token（Meta，2024）

> CS336 视角：与"视觉编码器 + 连接器 + LM"的组合式路线相对，Chameleon 代表另一种极端——一切皆离散 token。

### 核心思想

把所有内容（文本 + 图像）都映射为离散 token，用**同一个自回归语言模型**处理：

- **优雅之处**：同一机制分析与生成图像；文本与图像真正处于同一空间，可交替生成（"我无聊了，给我看点鸟的照片" → 输出文本、图像、文本、图像交错）
- 图像经 VQ-VAE 离散化：512×512 → 1024 token，词表 8000（详见 [[02_模态编码器与Token化]]）
- 需要训练**新的统一分词器**（文本 BPE + 图像码字合并）
- 训练即标准语言模型训练：**无需适配器、无需视觉编码器**；两阶段（大规模无监督 → 高质量数据），与纯 LM 训练惯例一致

### 训练不稳定性：熵不对称的代价

尽管文本与图像在同一 token 空间，**两者的表现差异显著**——文本下一 token 熵低（大部分词可猜到），图像 token 熵极高（根本无法确定下一个 token 是什么）。混合训练引发一系列范数问题：参数不断增大、损失不稳定。

**缓解手段**：QK-Norm 与 Z-loss 正则化（控制范数增长）——多模态训练的稳定性经验后来反哺纯语言模型架构（见 [[../../B_连接主义与深度学习/08_Transformer与注意力机制/07_Transformer工程实践|Transformer 工程实践]]）。

### 缺点与教训

- **性能不理想**：同等条件下不如组合式 VLM
- **离散化必然丢失信息**：极小的印刷文字离散化后无法识别（OCR 失败）
- **多模态配比难调**：比 Qwen 系列的权重调整问题更显著
- 历史注脚：VQ-VAE 曾广泛用于图像生成（transformer 只能生成离散数据）；扩散模型兴起后该路线已不如从前流行

**另一条生成路径**：VLM 挂载扩散头生成图像（组合式而非统一式）。

## 前沿模型现状（CS336 观察）

- Gemini、GPT 等发布时被宣传为**原生多模态**、能处理所有模态——事实如此，但架构细节未公开
- 合理推测：可能使用**连续编码器**（保留信息不丢失）+ **扩散模型**负责生成
- 多模态最大的难点始终是**如何处理非文本模态**

## 理解与生成的不对称

一个有趣的观察：**理解模态与生成模态之间存在对称关系，且具体情况各不相同——不存在一种通用的编码器**：

| 任务 | 需要的粒度 | 合适工具 |
|---|---|---|
| 分类/语义理解 | 高层语义即可，向量可以很小 | CLIP 式对比编码器（5 年后仍是捕捉图像语义的首选） |
| OCR/图像生成 | 非常精细的细节（高低频信息） | 扩散模型——能对高低频分别微调 |

## 模态间的权衡

- 视频的信息密度通常**低于**文本——不应让视频 token 淹没文本
- 实操上：调低视频模态权重，或按序列长度平方根归一化（Qwen3-VL 做法）
- 当前最佳实践的共识：**连续编码器**负责理解（CLIP 类思路仍广泛使用）+ **扩散模型**负责生成
