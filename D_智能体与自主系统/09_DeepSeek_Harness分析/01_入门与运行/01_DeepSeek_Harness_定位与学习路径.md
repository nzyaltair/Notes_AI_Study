# DeepSeek Harness 定位与学习路径

## 一句话理解

DSH 是把 Agent 的推理、执行和状态管理拆为可组合插件的运行平台；入门目标不是记住所有包，而是先掌握“模型—Agent—工具—日志—工作区”的闭环。

## 概述

一次交互由客户端把消息送入 Agent，Agent Loop 组装提示词和工具 Schema，LLM 决定回答或工具调用，工具结果记录回会话，后续请求再从日志派生上下文。DSH 的价值在于这条闭环可替换、可持久化且受策略控制。

## 最小心智模型

| 对象 | 职责 | 初学者首先关心的问题 |
|---|---|---|
| LLM | 产生流式响应和工具调用 | 模型、凭据、输入模态是否配置正确？ |
| Agent | 接收输入、维护 inbox、驱动 turn | 当前会话是否正在运行或被取消？ |
| Tool | 对模型开放的动作 | 参数、权限、结果如何受控？ |
| Session | 追加事件日志 | 刷新后是否能回放并重建历史？ |
| Workspace | Agent 操作的项目位置 | 是否选中了可安全修改的目录？ |

## 常见误区

- 把 DSH 当成固定功能的聊天产品：它实际是由 Profile、Bundle、Patch 组合出的插件树。
- 把 UI 输出视为权威状态：可恢复事实来自会话事件日志。
- 在未隔离的工作区授予 Agent 写文件和 Shell 权限：能力可用不意味着适合直接开放。
