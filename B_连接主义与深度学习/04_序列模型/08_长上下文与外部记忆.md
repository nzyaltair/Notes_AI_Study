# 长上下文与外部记忆

## 一句话理解

长上下文建模需要同时解决位置外推（模型能否处理训练时未见过的更长长度）、计算与内存成本（注意力的二次复杂度、KV Cache 的显存占用）、信息检索（模型能否在长文本中定位关键信息）和有效利用（模型是否真的"用到"了长上下文，而非只是"能装下"）四类问题。稀疏/线性注意力、SSM、分块记忆和外部检索是互补而非互斥的方案。

## 核心问题分解

| 问题 | 现象 | 代表方案 |
|---|---|---|
| 位置外推 | 训练 4K，推理需要 128K+ | RoPE 插值/外推、ALiBi、NTK-aware scaling |
| 计算成本 | 注意力 $\mathcal{O}(T^2)$ | 稀疏注意力、线性注意力、滑动窗口注意力 |
| 内存成本 | KV Cache 随序列线性增长 | KV Cache 压缩、量化、MQA/GQA、PagedAttention |
| 长程依赖建模 | RNN/短窗口注意力遗忘早期信息 | SSM（见 [[07_状态空间模型SSM]]）、检索增强 |
| 有效利用（Lost in the Middle） | 模型倾向于关注开头结尾，忽略中间内容 | 位置插值校正、长上下文专项微调、检索定位 |

## 与 RAG／外部记忆的关系

长上下文（把所有信息塞进 Prompt）与检索增强生成 RAG（按需从外部库检索）是解决"模型需要用到超出即时上下文信息"这一问题的两种互补路线，而非替代关系：长上下文降低了工程复杂度但成本随长度增长，RAG 成本低但依赖检索质量。混合方案（长上下文 + 检索定位相关片段）是当前的工程实践主流。
