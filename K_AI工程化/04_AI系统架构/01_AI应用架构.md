# AI 应用架构

## 一句话理解

AI 原生应用由模型服务、上下文管理、业务工作流、工具层、评测与观测组成，架构设计的核心是先定义任务边界和人机责任分配，再选择模型和编排策略——模型输出必须经过结构校验和业务规则验证，不能直接作为高风险操作指令。

## 1. 概述

传统应用架构以确定性逻辑为核心，AI 原生应用架构以**概率性模型推理**为核心组件。这带来了根本性的架构变化：

- **确定性 → 概率性**：模型输出不确定，需要验证和兜底
- **无状态 → 有状态**：对话历史、任务上下文需要管理
- **同步 → 异步**：长生成任务需要流式和异步处理
- **固定逻辑 → 动态编排**：Agent 根据中间结果决定下一步

AI 应用架构解决的核心问题：

- **组件边界**：模型、检索、工具、记忆、业务逻辑的职责划分
- **可靠性**：模型失败时的降级、重试、兜底策略
- **可观测性**：每次模型调用的 Trace、质量监控、成本追踪
- **安全约束**：模型输出的权限校验、内容过滤、人工审批

## 3. 核心概念

### 3.1 AI 应用分层模型

```text
┌──────────────────────────────────────┐
│  用户/业务接口层                       │  ← API、UI、Webhook、流式响应
├──────────────────────────────────────┤
│  编排与控制层                          │  ← 工作流引擎、Agent、决策路由
│  (Orchestration)                     │
├──────────────────────────────────────┤
│  模型网关层                            │  ← 路由、认证、限流、版本、成本
│  (AI Gateway)                        │
├──────────────────────────────────────┤
│  能力层                               │  ← LLM、嵌入模型、VLM、音频模型
│  (Model Serving)                     │
├──────────────────────────────────────┤
│  数据与工具层                          │  ← 向量库、数据库、外部 API、代码执行
├──────────────────────────────────────┤
│  记忆与状态层                          │  ← 对话历史、任务状态、用户画像
├──────────────────────────────────────┤
│  观测与评测层                          │  ← Trace、质量监控、安全过滤、成本审计
└──────────────────────────────────────┘
```

### 3.2 服务拆分建议

| 服务 | 职责 | 部署特点 |
|:---|:---|:---|
| API 网关 | 请求入口、鉴权、限流 | 无状态，水平扩展 |
| 编排服务 | 工作流执行、Agent 编排 | 有状态（任务级），需持久化 |
| 模型网关 | 模型路由、负载均衡、成本控制 | 无状态，代理层 |
| 模型推理 | LLM/嵌入模型推理 | GPU 密集，独立扩缩容 |
| 工具执行 | 代码执行、API 调用 | 沙箱隔离，独立扩缩容 |
| 检索服务 | 向量检索、知识库查询 | 内存/IO 密集 |
| 记忆服务 | 对话历史、上下文管理 | 有状态，低延迟 |
| 审计观测 | Trace、日志、质量监控 | 异步，写密集 |

### 3.3 人机协作模式

| 模式 | 描述 | 适用场景 |
|:---|:---|:---|
| **Human-in-the-loop** | 关键决策需人工审批后执行 | 高风险操作（支付、删除） |
| **Human-on-the-loop** | AI 自主执行，人工监控可干预 | 中等风险（内容生成、客服） |
| **Human-out-of-the-loop** | AI 完全自主，无人工干预 | 低风险（推荐、摘要） |
| **Copilot** | AI 辅助人类，人类主导决策 | 代码编写、文档撰写 |
| **Delegation** | 人类委派任务，AI 自主完成 | 数据分析、调研 |

```text
                         └────────────────┘
```

### 4.2 输出验证管线

模型输出在到达用户或执行操作前，必须经过多层验证：

```python
# 输出验证管线示例
def validate_output(model_output, context):
    # 1. 结构校验
    if not validate_schema(model_output, expected_schema):
        return retry_or_fallback("结构不合规")

    # 2. 权限校验
    if not check_permissions(model_output.action, context.user):
        return reject_or_escalate("权限不足")

    # 3. 业务规则
    if not check_business_rules(model_output, context):
        return retry_with_feedback("违反业务规则")

    # 4. 内容安全
    if not content_safety_filter(model_output):
        return filter_or_replace("内容不安全")

    # 5. 高风险操作 → 人工审批
    if is_high_risk(model_output.action):
        return send_to_human_review(model_output)

    return model_output
```

### 4.3 上下文管理

| 策略 | 描述 | 适用场景 |
|:---|:---|:---|
| 完整历史 | 保留所有对话轮次 | 短对话 |
| 滑动窗口 | 保留最近 N 轮 | 中等长度对话 |
| 摘要压缩 | 旧对话摘要 + 近期完整 | 长对话 |
| 检索式记忆 | 按相关性检索历史 | 超长对话/跨会话 |
| 结构化状态 | 维护任务状态机 | Agent 工作流 |

### 4.4 流式响应

```text
传统请求-响应:
  Client ──请求──▶ Server ──[模型完整生成]──▶ Client
  ←─────────── 用户等待 N 秒 ──────────▶

流式响应 (SSE/WebSocket):
  Client ──请求──▶ Server
  Client ◀─token1── Server
  Client ◀─token2── Server
  Client ◀─token3── Server
  ...
  Client ◀─[done]── Server
  ←─ 用户即时看到输出 ─→
```

## 5. 架构设计原则

1. **先定义任务边界**：明确 AI 承担什么、不能做什么、人类在哪里介入
2. **控制面与执行面分离**：编排逻辑独立于模型调用，便于测试和替换
3. **模型输出必须验证**：结构校验、权限校验、业务规则，不直接作为高风险操作指令
4. **状态可持久化**：工具调用、任务进度、对话历史不应只存在内存中
5. **链路可追踪**：每次模型调用关联到 Trace，支持调试和质量监控
6. **降级有兜底**：模型不可用时有静态答案或人工接管路径
7. **成本可观测**：每次调用的 token 数、模型选择、成本可追踪和审计

## 6. 优势与局限

### 6.1 优势

- **智能增强**：将模型能力嵌入业务流程，实现智能自动化
- **灵活编排**：模型、工具、检索按需组合，适应多变需求
- **渐进增强**：模型升级时架构不变，收益直接传导
- **人机协同**：人类聚焦高价值决策，AI 处理重复工作

### 6.2 局限与挑战

- **不确定性**：模型输出不可预测，需要全面的验证和兜底
- **延迟波动**：模型推理延迟远大于传统 API，影响用户体验
- **成本可控性**：Token 计费模式下，成本随使用量线性增长
- **安全风险**：Prompt 注入、数据泄露、幻觉输出需要多层防护
- **可测试性**：概率性输出难以编写确定性测试

## 7. 应用场景

| 场景 | 架构模式 | 关键设计 |
|:---|:---|:---|
| 智能客服 | RAG + Agent + 人工兜底 | 意图路由、知识检索、人工转接 |
| 代码助手 | Copilot 模式 | 上下文感知、流式补全、安全沙箱 |
| 文档分析 | 多模型流水线 | OCR → 理解 → 摘要 → 结构化输出 |
| 数据分析 | Agent + 工具调用 | 自然语言 → SQL/代码 → 执行 → 可视化 |
| 内容审核 | 多模型投票 | 多模型独立判断 → 仲裁 → 人工复核 |
