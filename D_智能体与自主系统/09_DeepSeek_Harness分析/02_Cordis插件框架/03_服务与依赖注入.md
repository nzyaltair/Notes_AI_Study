# 服务与依赖注入

## 一句话理解

服务是在 `ctx` 上公开的运行时能力；`inject` 将插件加载时机绑定到服务可用性，避免在未准备好的依赖上进行隐式或脆弱的调用。

## 服务契约

服务通常由 `Service` 子类或当前 Fiber 提供的值实现，消费者通过 `ctx.<key>` 使用。接口定义应描述稳定能力和失败语义；提供方则负责本地、远程或沙箱等具体机制。

```ts
export const inject = ['tools']
export function apply(ctx: Context) {
  ctx.tools.register(/* ... */)
}
```

## `inject` 与 `ctx.get`

- `inject`：声明硬依赖；服务缺失时插件不活跃，适合正确性依赖。
- `ctx.get(name)`：按需读取可能不存在的服务，适合可选集成；调用方必须处理 `undefined`。

不要仅靠“启动顺序”假设服务已存在。服务替换或动态卸载会使隐式依赖变成运行时故障。
