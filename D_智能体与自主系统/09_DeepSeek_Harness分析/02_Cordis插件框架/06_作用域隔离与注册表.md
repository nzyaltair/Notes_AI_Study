# 作用域隔离与注册表

## 一句话理解

DSH 的 scope 让同一注册表能为不同 Agent 提供不同的工具、提示词或限制；它是**扁平的两层可见性边界**（全局 vs 精确 scope），不是父子 Agent 的继承树，父子关系仅以 lineage 数据表达。

## 核心规则

一个活跃 Agent 自身可作为 scope key，`agent.ctx` 上的注册只对该 Agent 可见并随其生命周期撤销。无 scope 的注册全局可见；同名局部注册可遮蔽全局注册。`tools.restrict()` 对全局工具集取交集过滤，随后再合并局部工具，因此展示、查找与执行保持一致。

## 两层扁平结构

Scope 只有两层，采用扁平设计：

| 层 | 说明 |
|---|---|
| **全局层（Global）** | 无 scope 的注册，所有 agent 均可见 |
| **精确作用域层（Scoped）** | 绑定到某个 `ScopeKey` 的注册，只在该 key 对应的 agent 内可见 |

带作用域的注册**不会向下继承给 subagent**；子树行为通过 lineage 数据表达，从不通过 scope 结构。

## 身份标识与分发载体

### ScopeKey

`ScopeKey` 是不透明的对象身份标识，按对象同一性（引用相等）比较：

```ts
type ScopeKey = object
```

已交付的 agent loop 使用活跃的 `Agent` 对象作为自身的 key，但该原语从不检视该对象。

### Scoped&lt;T&gt; — 路由载体

`Scoped<T>` 是编译期品牌标记，标注在 `scopeTarget(base, key)` 返回的不透明路由接收器上。作用域过滤的事件声明要求以此载体作为 `this` 类型，而真正的事件主体仍作为显式参数传入：

```ts
// 事件分发时以 Scoped<Agent> 作为 thisArg（scope carrier）
ctx.emit(scopeTarget(ctx.agents, agent), 'agent/turn-start', ...)
```

- **scope carrier**：其过滤器放行**无标签监听器** + **主体自身的监听器**；
- *无主体*的 carrier（没有 key）只放行无标签监听器。

### Scoped dispatch 规则

| 事件类型 | 分发方式 |
|---|---|
| 关于某个 agent 活动的事件 | 以该 agent 的 carrier 进行过滤分发 |
| 关于注册表本身的事件（"一个工具被添加了"） | 不过滤（注册表主体事件） |

## 拥有所有权的注册上下文（Scope）

`Scope` 将带标签的注册上下文与两个拆卸接口配对：

```ts
interface Scope {
  ctx: Context         // scope 拥有的注册上下文
  rawDispose: () => Promise<void> | void  // Cordis 的精确 disposer（用于有序复合 effect）
  dispose(): Promise<void>                // 公共完全停稳边界（竞态调用方安全）
}
```

## 带作用域的注册表层（ScopedLayers）

`ScopeLayer` 表示一个注册表在某一层级的完整贡献；`ScopedLayers<L>` 管理全局层与惰性按需创建的精确作用域层：

- **全局层**：立即创建；
- **精确作用域层**：惰性创建（读取不创建）；
- **`peek(undefined)`**：无作用域覆盖层时返回 `undefined`；
- **`merge()`**：按插入顺序依次物化全局具名条目，再合并带作用域的遮蔽项；
- 只有带作用域 layer 完全为空时才回收它，不会丢弃兄弟 table。

## 注册表条目类型

### NamedEntries&lt;V&gt;

按插入顺序的查找和动态迭代，重复项错误由调用方处理。

- 同一轮非空 table 生命周期内，迭代器可以**观察后续变化**；
- table 被清空后，现有迭代器不再观察后续插入。

### AnonymousEntries&lt;V&gt;

每次 append 分配唯一标识，值相等的条目仍彼此独立（适用于无名钩子/限制/监听器）。

## 遮蔽（Shadowing）语义

最具体者胜出：一个带作用域的工具/片段/变量仅在该 scope 内替换同名的全局对应项。这是按 agent 定制 persona 和工具变体的机制：

```
全局：tool "bash" → 标准实现
scope A：tool "bash" → 沙箱实现（遮蔽全局）
scope B：不声明 "bash" → 继续使用全局
```

## Restriction（工具限制）

`tools.restrict()` 为单个 scope 过滤全局工具集合：

- 多个 restriction 取**交集**组合；
- scope-local 注册在过滤之后合并；
- 被过滤掉的全局工具：不出现在提示词 + 拒绝执行 + 与不存在的工具无法区分。

## Setup Window（创建时隙）

`CreateAgentOptions.setup` 是创建者组装 agent 作用域环境的唯一正确时机：
- 此时 scope 和 agent 对象已存在，但 agent/会话**尚未发布**；
- `agent/session-start` 尚未触发，首次提示词尚未组装；
- setup 只做注册，**从不驱动 agent**。

任何工具/提示词/限制的 scope-local 注册必须在 setup window 内完成；setup 之外注册属于全局可见。

## Lineage（血统数据）

父子关系以数据形式携带，**不影响可见性**，**不通过 scope 结构表达**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `parentSession` | `SessionId` | fork/resume 的源会话 |
| `delegationDepth` | `number` | 持久化；0=顶层，子代理 = 父 depth+1 |
| `subagentDepth` | `number` | 运行时；恢复后重置，防止无限递归预算重建 |

`delegationDepth` 持久化，让递归预算在重启和恢复后存活；`subagentDepth` 仅运行时，恢复后重置为 0，避免预算在恢复时凭空恢复。

## 何时使用

为单个会话准备 persona、工具集或模型策略时，在创建 Agent 的 setup window 中注册；不要以子代理层级假设可见性继承。
