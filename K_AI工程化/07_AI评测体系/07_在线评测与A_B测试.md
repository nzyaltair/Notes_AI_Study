# 在线评测与 A/B 测试

## 一句话理解

在线评测是 AI 系统的"真实考场"——通过影子流量、灰度发布和 A/B 测试，在真实用户和真实负载下验证离线评测无法覆盖的任务完成率、用户满意度、延迟成本和安全事件，当离线与在线结果矛盾时，在线结果优先。

## 1. 为什么离线评测不够

### 1.1 离线 vs 在线评测差异

| 维度 | 离线评测 | 在线评测 |
|:---|:---|:---|
| **数据分布** | 固定测试集 | 真实用户查询分布 |
| **查询类型** | 预定义覆盖 | 长尾/意外/对抗查询 |
| **用户行为** | 无交互 | 多轮/中途退出/追问 |
| **环境** | 隔离沙箱 | 生产环境（含故障） |
| **指标** | 准确率/F1 | 满意度/留存/成本 |
| **延迟** | 无限制 | 实时约束 |
| **成本** | 无限制 | 每次调用有成本 |
| **规模** | 有限样本 | 全量流量 |

### 1.2 离线-在线不一致的常见原因

```text
离线高、在线低的常见原因：

├── 分布偏移
│   ├── 离线测试集不代表真实分布
│   ├── 用户查询更口语化/模糊
│   └── 长尾查询离线未覆盖
│
├── 交互差异
│   ├── 离线是单轮，在线是多轮
│   ├── 用户会追问/修正
│   └── 用户会给出上下文
│
├── 延迟敏感性
│   ├── 离线不关心延迟
│   ├── 在线用户对延迟敏感
│   └── 高延迟导致用户放弃
│
├── 成本约束
│   ├── 离线可调用大模型多次
│   ├── 在线有每次调用成本限制
│   └── 成本压力导致降级
│
└── 安全/合规
    ├── 离线未覆盖的边缘案例
    ├── 生产环境合规要求
    └── 用户隐私保护
```

## 2. 在线评测层次

### 2.1 评测阶段

```text
在线评测三阶段：

阶段 1：影子流量（Shadow Traffic）
├── 新版本接收生产流量（不返回给用户）
├── 对比新旧版本输出差异
├── 验证无崩溃/异常
└── 成本：2× 推理成本

阶段 2：灰度发布（Canary Release）
├── 小流量（1-5%）真实服务用户
├── 密切监控护栏指标
├── 逐步放量 5% → 20% → 50% → 100%
└── 异常时自动回滚

阶段 3：A/B 测试
├── 对照组 vs 实验组
├── 统计显著性检验
├── 多指标综合评估
└── 决策：全量/迭代/放弃
```

### 2.2 指标体系

| 指标类型 | 指标 | 说明 |
|:---|:---|:---|
| **北极星指标** | 任务完成率 | 核心业务价值 |
| **主要指标** | 用户满意度 | 评分/点赞/留存 |
| **护栏指标** | 安全事件率 | 不能恶化 |
| **护栏指标** | 延迟 P95/P99 | 不能恶化 |
| **护栏指标** | 错误率 | 不能恶化 |
| **护栏指标** | 成本/查询 | 在预算内 |
| **辅助指标** | 人工接管率 | 需人工干预比例 |
| **辅助指标** | 多轮交互深度 | 平均轮次 |
| **辅助指标** | 用户重试率 | 重新提问比例 |

## 3. A/B 测试设计

### 3.1 实验设计要素

```text
A/B 测试设计清单：

├── 假设
│   ├── 原假设 H0：新版本与旧版本无差异
│   ├── 备择假设 H1：新版本优于旧版本
│   └── 方向性：单尾/双尾检验
│
├── 指标
│   ├── 主要指标（1个）：用于决策
│   ├── 护栏指标（3-5个）：安全阈值
│   └── 辅助指标：诊断用
│
├── 样本量
│   ├── 最小可检测效应（MDE）
│   ├── 显著性水平 α（通常 0.05）
│   ├── 检验功效 1-β（通常 0.80）
│   └── 计算公式：n = f(α, β, MDE, σ)
│
├── 分流单位
│   ├── 用户级（推荐）：同一用户始终在同一组
│   ├── 会话级：每次会话随机分配
│   └── 请求级：每次请求随机
│
├── 实验时长
│   ├── 最短周期：覆盖完整周期（如 1-2 周）
│   ├── 样本量达标：确保统计功效
│   └── 新奇效应：排除初期波动
│
└── 停止规则
    ├── 达到样本量 + 统计显著 → 停止
    ├── 护栏指标恶化 → 立即停止
    └── 最大实验时长 → 评估
```

### 3.2 样本量计算

```python
# A/B 测试样本量计算示例
import math

def sample_size(mde, baseline_rate, alpha=0.05, power=0.80):
    """
    mde: 最小可检测效应（绝对值）
    baseline_rate: 基线指标值
    alpha: 显著性水平
    power: 检验功效
    """
    z_alpha = 1.96   # 双尾 α=0.05
    z_beta = 0.84    # power=0.80

    p1 = baseline_rate
    p2 = baseline_rate + mde
    p_avg = (p1 + p2) / 2

    n = ((z_alpha * math.sqrt(2 * p_avg * (1 - p_avg)) +
          z_beta * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) / mde) ** 2

    return math.ceil(n)

# 示例：任务完成率从 80% 提升到 82%（MDE=2%）
# 每组需要约 7,848 个样本
sample_size(mde=0.02, baseline_rate=0.80)
# → 7848
```

### 3.3 分流策略

| 策略 | 说明 | 适用场景 |
|:---|:---|:---|
| **哈希分流** | hash(user_id) % 100 < 50 → A | 标准 A/B |
| **分层分流** | 先分用户群再分实验 | 多实验并行 |
| **互斥分流** | 不同实验用不同流量 | 避免干扰 |
| **正交分流** | 独立维度分流 | 多因子实验 |
| **SWITCH** | 同一用户轮流体验 A/B | 减少用户间差异 |

### 3.4 统计检验

```text
常用统计检验方法：

├── 比率类指标（转化率/成功率）
│   ├── 卡方检验
│   ├── Z 检验（大样本）
│   └── Fisher 精确检验（小样本）
│
├── 连续类指标（延迟/评分）
│   ├── t 检验（正态分布）
│   ├── Mann-Whitney U 检验（非参数）
│   └── Bootstrap 置信区间
│
├── 序数类指标（排序/偏好）
│   └── Wilcoxon 符号秩检验
│
└── 多重比较校正
    ├── Bonferroni 校正
    ├── Benjamini-Hochberg (FDR)
    └── 预注册假设减少校正需求
```

## 4. 影子流量

### 4.1 影子流量架构

```text
影子流量架构：

用户请求 → 负载均衡器 ──→ 生产模型（返回用户）
                    │
                    └──→ 影子模型（结果仅记录对比）
                            │
                            ▼
                      对比分析服务
                      ├── 输出差异率
                      ├── 质量对比
                      ├── 延迟对比
                      └── 成本对比

注意事项：
├── 影子模型不影响用户响应延迟
├── 影子模型需异步执行
├── 影子流量成本 = 额外推理成本
├── 需处理影子模型超时/失败
└── 对比结果需存储和分析
```

### 4.2 影子流量分析

| 分析维度 | 指标 | 说明 |
|:---|:---|:---|
| **输出一致性** | 完全相同率 / 语义相似度 | 新旧版本差异程度 |
| **质量提升** | LLM Judge 对比胜率 | 新版本是否更好 |
| **延迟变化** | P50/P95/P99 对比 | 性能变化 |
| **错误变化** | 新增错误 / 消除错误 | 错误模式变化 |
| **成本变化** | token/调用成本对比 | 经济影响 |
| **安全变化** | 有害输出率对比 | 安全影响 |

## 5. 灰度发布

### 5.1 灰度策略

```text
灰度发布策略：

策略 1：按流量比例
├── 1% → 5% → 10% → 25% → 50% → 100%
├── 每阶段观察 24-48 小时
└── 护栏指标恶化时自动回滚

策略 2：按用户分群
├── 内部用户 → 白名单用户 → 小流量 → 全量
├── 优先暴露给容忍度高的用户
└── 逐步扩大用户群体

策略 3：按功能模块
├── 先灰度低风险功能
├── 再灰度核心功能
└── 最后灰度高风险功能

自动回滚触发条件：
├── 错误率 > 基线 × 1.5
├── 延迟 P95 > 基线 × 1.3
├── 安全事件 > 0（严重）
├── 用户满意度下降 > 5%
├── 人工接管率上升 > 10%
└── 成本超预算 20%
```

## 6. 在线持续监控

### 6.1 监控指标体系

```text
在线持续监控分层：

层 1：系统健康（实时）
├── QPS / 并发数
├── 延迟 P50/P95/P99
├── 错误率 / 超时率
├── GPU 利用率
└── 服务可用性

层 2：模型质量（准实时，分钟级）
├── 输出质量采样评分（LLM Judge）
├── 安全过滤触发率
├── 拒答率
├── 幻觉率采样
└── 引用准确率

层 3：用户体验（小时级）
├── 用户满意度趋势
├── 任务完成率
├── 多轮交互深度
├── 用户重试率
└── 留存率

层 4：业务影响（日级）
├── 转化率
├── 人工工单量
├── 用户投诉量
├── 成本趋势
└── ROI
```

### 6.2 漂移检测

| 漂移类型 | 检测方法 | 响应 |
|:---|:---|:---|
| **输入分布漂移** | query embedding 分布对比 | 更新评测集 |
| **输出质量漂移** | LLM Judge 质量趋势 | 排查原因 |
| **用户行为漂移** | 满意度/留存趋势 | 调整模型 |
| **概念漂移** | 知识时效性检查 | 更新知识库 |
| **对抗模式漂移** | 攻击模式变化 | 更新安全策略 |

│
├── 分析报告
│   ├── 统计检验结果

│   ├── 指标趋势图

### 7.2 常见陷阱

| 陷阱 | 说明 | 应对 |
|:---|:---|:---|
| **新奇效应** | 初期效果后期消失 | 观察足够长时间 |
| **星期效应** | 周末 vs 工作日差异 | 覆盖完整周期 |
| **幸存者偏差** | 只分析完成用户 | 分析中途退出 |
| **辛普森悖论** | 整体与分组结论矛盾 | 做分群分析 |
| **提前停止** | 未达样本量就停止 | 预注册停止规则 |
| **多重检验** | 多指标增加假阳性 | Bonferroni 校正 |
| **交互效应** | 并行实验相互影响 | 互斥分流设计 |
| **选择偏差** | 分流不均匀 | 检查分流均衡性 |

## 8. 决策框架

### 8.1 实验结果决策矩阵

```text
决策矩阵：

                    主要指标
              提升    无差异    下降
           ┌────────┬────────┬────────┐
    良好   │ 全量上线│ 继续   │ 放弃   │
护  │      │        │ 观察   │       │
栏  ├──────┼────────┼────────┼────────┤
指  │ 恶化  │ 权衡   │ 放弃   │ 放弃   │
标  │      │ (需优化)│       │       │
    │      ├────────┼────────┼────────┤
    │ 严重  │ 放弃   │ 放弃   │ 放弃   │
    │ 恶化  │        │        │       │
           └────────┴────────┴────────┘

权衡场景处理：
├── 主要指标提升但成本增加 → 计算 ROI
├── 主要指标提升但延迟增加 → 评估用户容忍度
├── 主要指标提升但部分用户变差 → 分群发布
└── 主要指标无差异但成本降低 → 可全量
```
