# 机器人系统工程：从硬件契约到实时安全

## 一句话理解

可靠机器人是硬件、驱动、状态估计、规划、控制和安全监督的协同系统，而不是把一个策略模型直接接到电机。系统工程的任务是让每一层有明确接口、可验证约束和独立安全底线。

## 概述

机器人系统工程解决"如何让物理系统可靠运行"的问题。学习型策略可以生成动作，但动作到达硬件前要经过坐标系对齐、IK、碰撞检查、速度限幅和力矩限制；硬件返回的传感数据要经过时间同步、标定、滤波和健康检查。没有这套工程契约，策略在仿真中再好也无法在真机上复现。

## 发展历史

- **1980s-1990s**：各厂商封闭系统，接口不统一；实时控制依赖专用硬件。
- **2000s**：ROS（2007）成为开源标准，提供节点、话题、服务模型；但 ROS 1 非实时。
- **2010s**：ROS 2（2017）引入 DDS，支持实时 QoS、多机和工业部署；MoveIt 成为操作标准栈。
- **2020s**：NVIDIA Isaac 平台统一仿真、感知和控制；学习策略开始与 ROS 2 集成；安全标准（ISO 10218, ISO/TS 15066）更新。

## 核心概念

| 概念 | 定义 | 意义 |
|---|---|---|
| 硬实时 | 错过截止时间即为失败 | 控制环、安全监督 |
| 软实时 | 偶尔超时可接受 | 感知、规划 |
| 时钟同步 | 分布式节点共享时间基准 | 多传感器融合、动作对齐 |
| 坐标树 | \(\text{tf2}\) 维护坐标系变换 | 所有数据都要带 frame ID |
| 安全纵深 | 多层独立安全机制 | 不依赖单点故障 |
| 看门狗 | 超时自动安全停止 | 防止软件挂起导致失控 |

## 分层架构

```text
运行层  ｜ 日志、回放、版本、权限、人工接管、事故复盘
智能层  ｜ 感知、世界模型、任务规划、VLA/技能策略
状态层  ｜ 时钟同步、坐标树、标定、滤波、传感健康
实时层  ｜ 驱动、控制环、看门狗、力矩/速度约束
硬件层  ｜ 执行器、编码器、相机、力/触觉、急停、限位
```

关键原则：**安全约束在最底层独立实现**，不依赖上层软件。急停、硬件限位和功率限制是独立电路或固件级机制。

## 技术原理

### ROS 2 与实时性

ROS 2 基于 DDS（Data Distribution Service），提供：

- **QoS（Quality of Service）**：可靠性、持久性、历史深度和截止时间策略，可按数据类型选择。
- **节点与组件**：支持生命周期管理和进程内通信。
- **实时支持**：通过 RTOS 或 Preempt-RT 内核实现硬实时控制。
- **\(\text{tf2}\)**：维护坐标系树，所有传感和动作数据都携带 frame ID 和时间戳。

典型 QoS 选择：

| 数据类型 | QoS 策略 | 原因 |
|---|---|---|
| 控制命令 | Reliable + Keep Last 1 | 丢失命令不可接受，但只需最新值 |
| 图像流 | Best Effort + Keep Last 1 | 允许丢帧，只保留最新 |
| 诊断 | Reliable + Keep All | 不丢诊断信息 |
| 状态估计 | Reliable + Keep Last 1 | 确保状态一致 |

模型推理通常非硬实时，应与伺服控制隔离：策略以低频（10-30 Hz）输出目标，控制器以高频率（500 Hz-1 kHz）跟踪。

### 时钟同步

分布式系统中，多传感器数据必须共享时间基准：

- **NTP/PTP**：网络时间协议 / 精确时间协议，PTP 可达亚微秒级。
- **硬件触发**：相机外触发或编码器同步。
- **时间戳来源**：传感器数据应在采集时刻打时间戳，而非接收时刻。

时间未对齐会导致：多传感器融合错位、动作-观测因果倒置、数据集训练数据不一致。

### 端到端时延

```text
采集 → 同步 → 推理 → 通信 → 规划 → 执行
```

每段都贡献时延和抖动。时延及抖动必须进入仿真和验收指标；一条"正确但过期"的动作仍可能危险。

### 安全设计

安全纵深设计原则：

1. **硬件层**：急停按钮、机械限位、功率限制（独立于软件）。
2. **固件层**：速度/力矩限制、看门狗超时。
3. **控制层**：碰撞检查、工作空间约束、速度限幅。
4. **策略层**：置信度阈值、低置信降级、拒绝危险目标。
5. **运行层**：权限管理、审计日志、人工接管。

每层独立可验证，不依赖上层正确。**任何策略输出都必须可被裁剪或拒绝。**

## 关键方法与模型

| 方法/工具 | 核心功能 | 角色 |
|---|---|---|
| ROS 2 | 模块通信与编排 | 系统中间件 |
| MoveIt 2 | 运动规划、IK、碰撞 | 操作栈 |
| \(\text{tf2}\) | 坐标树管理 | 状态层 |
| DDS QoS | 通信质量保证 | 实时性 |
| Isaac Sim/Lab | 仿真与验证 | 开发与测试 |
| 看门狗 | 超时安全停止 | 安全层 |
| 功率/力矩限制 | 硬件级安全 | 硬件层 |

## 优势与局限

| 方面 | 优势 | 局限 |
|---|---|---|
| ROS 2 | 开源、社区大、模块化 | 非 RTOS 下非硬实时 |
| MoveIt 2 | 功能全面、成熟 | 高自由度规划慢 |
| 安全纵深 | 多层冗余、可验证 | 增加系统复杂度 |
| 仿真验证 | 可批量测试 | sim-to-real 差距 |

## 应用场景

- 工业机器人：结构化环境、固定流程。
- 协作机器人：人机共享空间、力控安全。
- 移动操作：导航 + 操作、多传感器融合。
- 人形机器人：全身控制、多接触、安全共处。
- 学习策略部署：策略输出 → IK → 碰撞 → 限幅 → 控制器。
