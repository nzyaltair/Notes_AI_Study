# 搜索与 MCTS

## 一句话理解

搜索是在状态空间或动作空间中寻找从初始状态到目标状态路径的通用方法；MCTS 通过"选择-扩展-模拟-回传"四步迭代，在大分支空间中智能分配搜索预算，是 AlphaGo/MuZero 等超人类 AI 的核心引擎。

## 概述

规划的核心是"找到一条从当前状态到目标状态的动作路径"——这本质上是一个搜索问题。从经典的 A* 搜索到现代 MCTS，搜索算法一直是规划系统的核心引擎。[[00_规划与推理_综述|规划与推理]] 中提到的"搜索比较候选路径"正是本笔记的主题。在 LLM Agent 时代，搜索的概念以更灵活的形式出现：ToT（Tree of Thoughts）在"思维空间"中搜索，MCTS 在"动作空间"中搜索，A* 在"状态空间"中搜索——三种搜索在不同抽象层级上服务于同一目标：找到最优的决策路径。

## 发展历史

| 年代 | 里程碑 | 意义 |
|:---|:---|:---|
| 1968 | A* 搜索（Hart et al.） | 带启发式的最优搜索算法，完备且最优 |
| 1977 | IDA*（Korf） | 迭代加深 A*，减少内存占用 |
| 2006 | UCT（Kocsis & Szepesvári） | 将 UCB 策略引入 MCTS，解决探索-利用平衡 |
| 2012 | 带启发式的 MCTS | 用深度学习的估值函数替代随机模拟 |
| 2016 | AlphaGo（Silver et al.） | MCTS + 深度策略/值网络，达到超人类水平 |
| 2020 | MuZero（Schrittwieser et al.） | 无需已知规则，隐式模型 + MCTS |
| 2023 | ToT（Yao et al.） | 将树搜索的思想引入 LLM 推理 |
| 2024 | MCTS 在 LLM 推理中复兴 | 多种工作用 MCTS 改进 LLM 的推理能力 |

## 核心概念

### 搜索的基本要素

- **状态空间** $\mathcal{S}$：所有可能状态的集合
- **初始状态** $s_0$：搜索开始的起点
- **目标测试** $G(s)$：判断当前状态是否为目标状态
- **动作生成** $A(s)$：从状态 $s$ 可执行的动作集合
- **转移模型** $T(s, a)$：执行动作 $a$ 后到达的新状态
- **路径成本** $c(s, a, s')$：从 $s$ 通过 $a$ 到达 $s'$ 的成本

### 搜索的分类

| 维度 | 分类 | 代表算法 |
|:---|:---|:---|
| 信息完备性 | 完全信息 vs. 不完全信息 | A* vs. 博弈搜索 |
| 确定性 | 确定性 vs. 随机性 | A* vs. MCTS |
| 最优性 | 最优 vs. 可接受 | A* vs. 贪婪搜索 |
| 搜索方向 | 前向 vs. 后向 vs. 双向 | 前向搜索 vs. 回归搜索 |
| 记忆 | 树搜索 vs. 图搜索 | 标准 DFS vs. 带 closed set 的搜索 |

## 技术原理

### A* 搜索：最优搜索的经典

A* 按 $f(n) = g(n) + h(n)$ 扩展节点，其中 $g(n)$ 是从起点到节点 $n$ 的实际路径成本，$h(n)$ 是从 $n$ 到目标的启发式估计成本。**当 $h(n)$ 是可容许的（admissible，不低估实际成本）时，A* 保证找到最优解**。

A* 在 LLM Agent 规划中的局限：状态空间可能没有良好的启发式函数，且 LLM 生成的状态转移可能不可靠。

### MCTS：蒙特卡洛树搜索

MCTS（Monte Carlo Tree Search）是搜索 + 采样的结合，通过四步迭代在大分支空间中高效分配搜索预算：

```text
① 选择（Selection）：从根节点开始，使用 UCB1 公式选择子节点，直到叶节点
② 扩展（Expansion）：如果叶节点不是终止状态，添加一个或多个子节点
③ 模拟（Simulation）：从新节点开始，使用默认策略（如随机动作）模拟到终止状态
④ 回传（Backpropagation）：将模拟结果沿路径回传，更新节点的访问次数和累计值
```

**UCB1 公式**：$UCB1 = \frac{w_i}{n_i} + c \sqrt{\frac{\ln N}{n_i}}$，其中 $w_i$ 是节点 $i$ 的累计奖励，$n_i$ 是节点 $i$ 的访问次数，$N$ 是父节点的总访问次数，$c$ 是探索常数。第一项鼓励利用，第二项鼓励探索。

### MCTS 在 LLM 推理中的应用

ToT（Tree of Thoughts）将 MCTS 的思想引入 LLM 推理：

- **思维节点**：LLM 生成的一段推理文本或候选答案
- **扩展（value-based）**：LLM 评估当前思维节点的质量，决定是否继续扩展
- **模拟（rollout）**：LLM 从当前思维节点继续推理，直到生成完整答案
- **回传**：生成的答案质量沿路径回传，更新节点估值

## 关键方法与模型

| 方法 | 核心思想 | 特点 |
|:---|:---|:---|
| A* | $f(n) = g(n) + h(n)$ | 可容许启发式时最优 |
| IDA* | 迭代加深 + 阈值 | 内存友好 |
| UCT/MCTS | 选择-扩展-模拟-回传 | 大分支空间高效 |
| AlphaGo Zero | MCTS + 策略-值网络 | 无需人类知识，超人类水平 |
| MuZero | 隐式模型 + MCTS | 无需已知规则 |
| ToT | 思维树搜索 | LLM 推理中的树搜索 |

## 优势与局限

**搜索的优势**：通用性——任何可以用状态空间表示的问题都可以搜索；最优性保证——A* 在可容许启发式下保证最优解；MCTS 在大分支空间中高效——不需要全状态空间搜索。

**搜索的局限**：状态空间爆炸——实际问题的状态空间通常太大，无法穷举；启发式依赖——A* 的效率完全取决于启发式质量；MCTS 的模拟策略——随机模拟在稀疏奖励场景中可能无效；LLM Agent 中的搜索成本——每次搜索需要多次 LLM 调用，成本高。

## 应用场景

- **游戏 AI**：AlphaGo、MuZero 在棋类游戏中的应用
- **路径规划**：A* 及其变体在机器人导航中的广泛应用
- **LLM 推理增强**：ToT/MCTS 用于改进 LLM 的多步推理质量
- **规划验证**：用搜索验证 LLM 生成的计划是否可行

- **MCTS + LLM 推理**：用 MCTS 增强 LLM 的多步推理和规划能力

## 常见问题

**Q: A* 和 MCTS 有什么本质区别？**
A* 是确定性搜索，依赖启发式 $h(n)$ 的准确性来保证最优性；MCTS 是基于随机采样的搜索，通过多次模拟来逼近最优解。A* 适合状态空间可穷举、启发式易得的问题；MCTS 适合分支巨大、无法穷举、需要搜索预算分配的问题。

**Q: MCTS 在 LLM 推理中效果如何？**
MCTS 在需要多步推理的复杂任务（如数学证明、规划）中效果显著，可以显著提升 LLM 的推理深度和正确率。但每次 MCTS 搜索需要多次 LLM 调用，计算成本是瓶颈。
