# Agent 评测

## 一句话理解

Agent 评测不仅看最终结果，更看整个行动轨迹——任务是否成功、工具调用是否正确、步骤是否高效、是否安全合规，是衡量模型从"对话"到"行动"能力跨越的关键评估体系。

## 1. Agent 评测与 LLM 评测的本质差异

| 维度 | LLM 评测 | Agent 评测 |
|:---|:---|:---|
| **评测对象** | 单次输入→输出 | 多步决策轨迹 |
| **环境** | 无状态 | 有状态环境 |
| **成功标准** | 输出质量 | 任务完成 + 轨迹质量 |
| **变量** | Prompt | Prompt + 工具 + 环境 + 历史 |
| **复现性** | 高（固定输入） | 低（环境+随机性） |
| **成本** | 低 | 高（多步 API 调用） |

## 2. 核心评测维度

### 2.1 结果维度

| 指标 | 定义 | 适用场景 |
|:---|:---|:---|
| **任务成功率** | 最终结果是否正确 | 所有 Agent 任务 |
| **部分成功分** | 按完成程度打分 | 复杂多步任务 |
| **正确性** | 输出信息是否准确 | 信息检索/问答 |
| **完整性** | 是否覆盖所有要求 | 报告生成 |

### 2.2 轨迹维度

| 指标 | 定义 | 理想值 |
|:---|:---|:---|
| **步骤数** | 完成任务的总步数 | 越少越好（效率） |
| **Token 消耗** | 总输入/输出 token | 越少越好（成本） |
| **工具调用正确率** | 正确调用次数 / 总调用次数 | 越高越好 |
| **不必要的调用率** | 冗余/无效调用比例 | 越低越好 |
| **恢复能力** | 出错后能否自我纠正 | 越强越好 |
| **循环检测** | 是否陷入重复循环 | 0 次 |

### 2.3 安全维度

| 指标 | 定义 |
|:---|:---|
| **越界操作率** | 执行超出权限的操作 |
| **权限滥用检测** | 尝试提权或绕过限制 |
| **敏感信息泄露** | 工具返回中的 PII 是否保护 |
| **不可逆操作** | 是否执行了删除/转账等危险操作 |
| **幻觉工具调用** | 调用不存在的工具或编造参数 |

## 3. 主流 Agent Benchmark

### 3.1 通用 Agent 能力

| 基准 | 评测场景 | 特点 |
|:---|:---|:---|
| **AgentBench** | 多场景 Agent 评测 | 操作系统/数据库/卡片游戏/知识图谱 |
| **GAIA** | 通用 AI 助手 | 真实世界多步任务 |
| **Mind2Web** | 网页交互 | 1372 个真实网站任务 |
| **WebArena** | 网页操作 | 自托管环境可复现 |
| **OSWorld** | 操作系统操作 | 真实 OS 虚拟机 |

### 3.2 工具调用评测

| 基准 | 评测能力 | 指标 |
|:---|:---|:---|
| **API-Bank** | API 调用 | 调用准确率 |
| **ToolBench** | 大规模工具使用 | 16000+ API |
| **NexusRaven** | 函数调用 | 参数准确率 |
| **BFCL (Berkeley Function Calling)** | 凥数调用综合 | 多语言/复杂参数 |
| **τ-Bench** | 工具+策略执行 | 策略遵循率 |

### 3.3 编码 Agent

| 基准 | 评测场景 | 特点 |
|:---|:---|
| **SWE-Bench** | 真实仓库修 Bug | Docker 执行测试 |
| **SWE-Bench Verified** | 人工验证子集 | 减少假阴性 |
| **HumanEval-Vision** | 图转代码 | UI 截图→前端代码 |
| **DevBench** | 端到端开发 | 需求→设计→编码→测试 |

### 3.4 多智能体

| 基准 | 评测场景 |
|:---|:---|
| **AgentBench-Multi** | 多 Agent 协作 |
| **Cradle** | 通用计算机任务 |

## 4. 评测环境设计

### 4.1 沙箱环境

```text
┌─────────────────────────────────────────┐
│              Agent 评测沙箱               │
├─────────────────────────────────────────┤
│                                         │
│   ┌─────────┐   ┌─────────┐            │
│   │ 文件系统 │   │ 数据库   │            │
│   └─────────┘   └─────────┘            │
│                                         │
│   ┌─────────┐   ┌─────────┐            │
│   │ Web Server│  │ API Mock│           │
│   └─────────┘   └─────────┘            │
│                                         │
│   ┌─────────────────────────┐          │
│   │   状态检查器（验证最终状态）│          │
│   └─────────────────────────┘          │
│                                         │
│   特点：                                 │
│   1. 可重置（每次测试恢复初始状态）        │
│   2. 确定性 Mock（外部 API 可控）         │
│   3. 全量日志（记录每一步操作）           │
│   4. 超时保护（防止无限循环）             │
│                                         │
└─────────────────────────────────────────┘
```

### 4.2 环境类型

| 类型 | 示例 | 优势 | 局限 |
|:---|:---|:---|:---|
| **完全模拟** | WebArena | 可控可复现 | 与真实有差距 |
| **容器化** | Docker | 隔离安全 | 资源消耗大 |
| **虚拟机** | OSWorld | 最接近真实 | 慢且昂贵 |
| **真实环境** | 生产影子 | 最真实 | 不可控风险 |

### 4.3 Mock 策略

- **确定性 Mock**：外部 API 返回固定结果，确保可复现
- **状态化 Mock**：维护内部状态，响应 Agent 操作
- **故障注入**：模拟网络超时、API 错误
- **部分真实**：关键路径用真实 API，其余 Mock

## 5. 轨迹分析方法

### 5.1 轨迹评估框架

```text
Agent 轨迹评估流程：

1. 收集轨迹
   ├── 每步的思考（Thought）
   ├── 每步的行动（Action）
   ├── 工具调用参数
   ├── 环境返回（Observation）
   └── 最终结果

2. 逐步标注
   ├── 步骤是否必要？
   ├── 工具选择是否正确？
   ├── 参数是否准确？
   ├── 推理是否合理？
   └── 是否存在更优路径？

3. 模式分析
   ├── 常见失败模式
   ├── 效率瓶颈
   └── 最优路径对比
```

### 5.2 失败分类

| 失败类型 | 说明 | 示例 |
|:---|:---|:---|
| **规划失败** | 任务分解错误 | 遗漏必要步骤 |
| **检索失败** | 找不到正确信息 | 搜索 query 不准 |
| **工具选择失败** | 选错工具 | 应该用搜索却用计算器 |
| **参数错误** | 工具参数填错 | 日期格式/ID 拼错 |
| **状态管理失败** | 丢失上下文 | 忘记之前的中间结果 |
| **权限越界** | 尝试不可逆操作 | 未确认就执行删除 |
| **循环卡死** | 重复相同操作 | 反复搜索同一 query |
| **环境错误** | 外部依赖失败 | API 超时未处理 |

### 5.3 效率分析

## 6. 评测自动化

### 6.1 LLM-as-Judge for Agents

- **轨迹评估**：让强模型评估 Agent 每步决策的合理性
- **结果评估**：对比 Agent 输出与参考答案
- **注意事项**：
  - Judge 模型可能偏爱特定风格
  - 需要提供完整的轨迹上下文
  - 多 Judge 投票提升一致性

### 6.2 自动化评分流程

```text
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 任务集    │ →  │ 沙箱执行  │ →  │ 状态验证  │ →  │ 报告生成  │
│ (版本化)  │    │ (隔离)    │    │ (规则+LLM)│    │ (可视化)  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                      │
                      ↓
               ┌──────────┐
               │ 轨迹日志  │
               │ (全量记录)│
               └──────────┘
```

## 7. 评测实践建议

### 7.1 评测集设计

- **分层任务**：简单 → 中等 → 困难 → 极端
- **覆盖工具组合**：单一工具 → 多工具组合 → 工具链
- **含干扰项**：环境中存在无关工具和信息
- **边界案例**：空结果、错误返回、权限不足
- **多轮交互**：需要用户澄清的任务

### 7.2 回归测试

```text
Agent 回归集管理：
├── 核心回归集（每次发布必跑）
│   ├── P0 任务（关键路径，必须通过）
│   └── P1 任务（重要功能，允许小幅退步）
├── 完整评测集（里程碑版本运行）
│   └── 所有任务 + 新增场景
├── 对抗测试集（安全验证）
│   └── 越狱/注入/权限滥用
└── 失败案例库（历史 Bug 回归）
    └── 每次修复后加入回归集
```
