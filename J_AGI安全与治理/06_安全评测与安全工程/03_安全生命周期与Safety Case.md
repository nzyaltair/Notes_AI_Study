# 安全生命周期与 Safety Case

## 一句话理解

安全生命周期把风险控制嵌入从需求到退役的全过程；Safety Case 则是一套结构化的主张、证据与论证，用于说明系统在给定用途和边界内风险已降至可接受水平。

## 安全生命周期

```text
用途界定 → 风险评估 → 安全需求 → 设计/训练 → 评测/红队 → 发布门禁
   ↑                                                              ↓
复盘改进 ← 事故响应 ← 线上监控 ← 灰度部署与变更管理
```

证据可包括数据治理记录、威胁模型、评测结果、红队发现与修复、权限设计、监控告警、人工监督和演练记录。模型、工具、策略或用途更新后均应重新评估；上线不意味着安全工作结束。

## 模型卡与系统卡

模型卡（Model Card，Mitchell et al. 2019）是随模型发布的结构化文档，标准内容包括：

- 模型描述（架构、训练数据、用途）
- 性能指标（分群体、分场景）
- 已知限制与偏见
- 伦理考量与使用限制

系统卡（System Card）在模型卡基础上补充部署上下文，覆盖工具、插件、系统提示和访问控制等。OpenAI、Anthropic 等机构在主要模型发布时均附带系统卡，作为透明度与问责的证据载体。Datasheet for Datasets（Gebru et al. 2018）是数据集侧的等价规范。

## 模型供应链安全

现代 AI 系统依赖预训练基础模型、微调框架、第三方工具和云服务，供应链各环节均可能引入风险：

| 供应链环节 | 风险 | 控制 |
|---|---|---|
| 模型权重 | 篡改、投毒、来源不明 | 哈希校验、数字签名、来源记录 |
| 训练数据 | 版权风险、PII、投毒 | SBOM式数据溯源、许可合规审查 |
| 第三方库与框架 | 依赖漏洞 | 依赖锁定、SCA扫描、漏洞响应 |
| 外部工具/插件 | 恶意能力扩展 | 工具白名单、行为审计 |
| 云服务与推理 API | 访问控制失效 | 最小权限、密钥轮换、网络隔离 |

AI 物料清单（AI-SBOM）记录模型的预训练权重来源、微调数据版本、依赖库与工具列表，支持审计和事故溯源。

## 事件分级与响应

| 级别 | 典型场景 | 响应目标 | 升级路径 |
|---|---|---|---|
| P0 | 数据大规模泄露、系统被控制、危险能力滥用 | 立即遏制 | 全团队 + 高管 + 监管通报 |
| P1 | 核心安全功能失效、严重越权行动 | 1小时内响应 | 安全核心团队 |
| P2 | 较高误伤率、性能安全回归 | 8小时内响应 | 值班团队 |
| P3 | 小范围问题、优化建议 | 下一迭代处理 | 正常工单 |

事故响应流程：遏制（隔离或下线）→ 取证（保全日志、复现环境）→ 根因分析 → 修复与验证 → 回归测试 → 改进闭环 → 必要时向监管和受影响方披露。
