# LLM 规划与长程任务

## 一句话理解

LLM 规划利用语言模型的推理能力自动生成行动计划，但 LLM 生成的计划天然不可靠——长程任务的关键不是计划写得多长，而是每一步都有前置条件、成功判据、预算、检查点和失败恢复策略。

## 概述

经典规划（[[01_STRIPS_PDDL与HTN|STRIPS/PDDL]]）需要人工定义精确的状态和动作模型，这在开放世界任务中成本过高。LLM 规划用自然语言替代了形式化建模：给定任务描述，LLM 自动生成"先做 A、再做 B、最后做 C"的计划。但这带来了新的问题：LLM 生成的计划可能忽略关键约束、假设不存在的条件、或无法处理执行中的意外。

[[00_规划与推理_综述|规划与推理]] 提到了"LLM 提供语言先验"——本笔记聚焦 LLM 规划的具体方法（CoT、ReAct、ToT、Plan-and-Execute）及其在长程任务中的工程实践，包括计划执行、监控、重规划的关键机制。

## 发展历史

| 时间 | 里程碑 | 意义 |
|:---|:---|:---|
| 2022.01 | CoT（Wei et al.） | 思维链提示，LLM 首次展示显式的多步推理能力 |
| 2022.10 | ReAct（Yao et al.） | 推理与行动交替，LLM 规划 + 工具执行 |
| 2022.12 | Plan-and-Solve（Wang et al.） | 显式分离"计划生成"和"步骤执行" |
| 2023.05 | ToT（Yao et al.） | 树状思维，在多个候选推理路径中搜索 |
| 2023.05 | Self-Refine（Madaan et al.） | 迭代生成-评估-改进计划 |
| 2023.09 | LATS（Zhou et al.） | 树搜索 + 反思，统一搜索与规划 |
| 2024 | Plan-and-Execute 范式成熟 | 全局计划 + 局部执行成为长程任务主流方案 |

## 核心概念

- **思维链（CoT）**：在 LLM 的生成中插入"让我们一步一步思考"的提示，引导模型生成显式推理步骤。CoT 不涉及外部行动，仅在语言空间内推理
- **ReAct**：CoT 的扩展，让 LLM 在"思考（Thought）"和"行动（Action）"之间交替，并将工具返回的"观察（Observation）"重新注入推理链。ReAct 是 LLM Agent 规划的基石
- **树状思维（ToT）**：在多个候选推理路径中搜索，而非仅沿一条路径前进。本质上是将搜索算法（[[02_搜索与MCTS|搜索与MCTS]]）的思想应用于 LLM 推理
- **Plan-and-Execute**：分离"全局计划生成"和"局部步骤执行"——先生成完整的高层计划，然后逐步骤执行，执行中根据反馈调整后续步骤
- **重规划（Replanning）**：当发现计划的前提条件不满足、执行失败或环境变化时，LLM 基于新信息调整或生成新计划的能力

## 技术原理

### LLM 规划方法的谱系

| 方法 | 规划方式 | 搜索范围 | 外部反馈 | 适合任务 |
|:---|:---|:---|:---|:---|
| CoT | 线性推理 | 单路径 | 无 | 数学推理、逻辑问答 |
| ReAct | 推理+行动交替 | 单路径+工具反馈 | 有（工具返回值） | 信息检索、工具使用 |
| ToT | 多候选树搜索 | 多路径 | 有（节点评估） | 规划、创意写作 |
| Plan-and-Execute | 先计划后执行 | 单计划+执行反馈 | 有（执行结果） | 多步长程任务 |
| LATS | 树搜索+反思 | 多路径+回溯 | 有（反思+工具） | 复杂长程任务 |

### 长程任务的核心挑战

**1. 计划漂移**：Agent 在执行长程任务时，随着步骤增加，可能逐渐偏离初始目标。解决方案：在每个步骤前显式回顾当前状态与目标的关系。

**2. 执行监控**：每一步执行后，需要验证结果是否与计划一致。不一致时触发重规划。

```text
目标和验收条件 → 里程碑分解 → 工具执行 → 结果验证
  → 验证通过：继续下一步
  → 验证失败：重规划（基于当前状态和失败原因）
  → 状态更新 → 计划修复（必要时回退到安全检查点）
```

**3. 错误累积**：早期步骤的错误会在后续步骤中放大。解决方案：关键步骤后设置检查点，允许回退到检查点而非从头开始。

**4. 上下文窗口限制**：长程任务的完整计划可能超出 LLM 的上下文窗口。解决方案：分层计划（高层计划在上下文，细节在外部存储）或记忆分页（[[../05_记忆与持续学习/01_Agent记忆|MemGPT 风格]]）。

### 计划的工程属性

一个生产级的长程任务计划应包含：

| 属性 | 描述 | 示例 |
|:---|:---|:---|
| 前置条件 | 计划开始前必须满足的条件 | "数据库已连接" |
| 成功判据 | 如何判断计划执行成功 | "返回结果包含 3 个以上有效来源" |
| 预算 | 时间、Token、工具调用次数限制 | "最多调用 5 次搜索 API" |
| 检查点 | 预定义的恢复点 | "每完成 2 步，保存当前状态" |
| 失败恢复策略 | 失败时的处理方式 | "重试→重规划→求助人工" |
| 风险标签 | 识别高风险步骤 | "此步骤涉及删除操作，需人工确认" |

## 优势与局限

**LLM 规划的优势**：无需人工定义动作模型，从自然语言直接生成计划；灵活适应开放式任务；LLM 的常识知识可以填补未明确说明的约束。

**LLM 规划的局限**：计划不可靠——LLM 可能生成"看似合理但实际不可行"的计划；缺乏故障保证——经典规划器可以保证"如果模型正确，计划可行"，LLM 无法给出任何保证；长程任务中容易"迷失"——随着步骤增加，目标漂移和错误累积问题突出；成本高——每次规划需要多次 LLM 调用。

## 应用场景

- **信息调研 Agent**：生成搜索计划，逐步骤搜索、阅读、验证、总结
- **代码开发 Agent**：生成代码计划，逐步骤编写、测试、修复
- **Web 操作 Agent**：生成操作计划，逐步骤点击、输入、验证结果
- **数据分析 Agent**：生成分析计划，逐步骤查询、计算、可视化

## 前沿发展

- **LLM 规划 + 符号验证**：LLM 生成计划，符号规划器验证可行性，结合两者优势
- **可学习规划策略**：通过强化学习优化 LLM 的规划策略，而非仅依赖提示工程
- **分层 LLM 规划**：高层 LLM 负责宏观计划，低层 LLM 负责具体执行和调整

## 常见问题

**Q: CoT 和 ReAct 有什么区别？**
CoT 只在语言空间内推理，不涉及外部行动；ReAct 在推理和行动之间交替，行动结果（工具返回值）重新注入推理链。CoT 适合纯推理任务（数学题），ReAct 适合需要外部信息或工具的任务。

**Q: 长程任务中，计划应该多详细？**
太粗的计划可能遗漏关键步骤，太细的计划可能因环境变化而过时。最佳实践是"粗粒度计划 + 细粒度执行"——高层计划定义里程碑，低层执行时根据当前状态决定具体操作。
