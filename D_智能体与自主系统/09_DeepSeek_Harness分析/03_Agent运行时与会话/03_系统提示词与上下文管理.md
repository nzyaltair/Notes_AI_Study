# 系统提示词与上下文管理

## 一句话理解

每个 Step 都从日志、提示词 section 和当前可见工具 Schema 组装模型请求；上下文治理的目标是保持模型可见内容可解释、可回放且在 token 预算内。

---

## 提示词组装机制

### `ctx.systemPrompt`：协作式提示词注册表

`SystemPrompt` 服务汇集插件贡献的 Section（静态区段）和 Context（动态快照区段）。每个 Step 前，`agent/pre-step` waterfall 触发协作组装。

### PromptSection：系统提示词区段

`PromptSection` 是一份只读的同进程注册约定：

| 字段 | 说明 |
|---|---|
| `name` | 唯一名称；重复注册抛错 |
| `order` | 排序键，升序拼接；约定见下表 |
| `text` | 静态字符串，或依 `AssembleContext` 动态解析的函数；可包含 `{{variable}}` 待插值 |
| `complete?` | 为 `true` 时将此 section 作为**完整**提示词；组装仍运行协作 waterfall（以解析工具、变量），然后将此 section 恢复为唯一区段 |

**order 约定**：

| Order | 用途 |
|---|---|
| `-100` | harness 身份（最早渲染） |
| `0` | 部署 persona |
| `100–199` | 工具指引 |
| 其他负值 | 在 persona 之前渲染的其他 section |

> `complete: true` 场景：一个部署或 agent preset 想完全替换提示词，同时仍让工具/变量/上下文贡献者参与组装计算。**不超过一个有效的 `complete` section**，否则组装失败。

### PromptContext：动态上下文快照区段

`PromptContext` 是与 `PromptSection` 对应的缓存安全结构，以用户角色 message 的形式注入持久化历史：

- `name`：唯一名称；重复注册抛错；
- `order`：升序拼接；
- `text`：静态或动态（`AssembleContext` 求值）；空文本不贡献内容。

**注入时机**：agent loop 仅在完整当前快照**发生变化**或被压缩移除时，才将其记录在保留的模型历史之后（通过 `agent.inject()` 以 `user/message` 事件追加）。

### AssembleContext：组装上下文

一次组装的作用域与控制信号，可合并扩展：

```ts
interface AssembleContext {
  scope?: ScopeKey   // 确定哪些 Section/Context/监听器参与；缺失时只用全局项
  signal?: AbortSignal  // 该轮次的取消信号
}
```

`assembleContextFor(agent, signal)` 是标准创建方式，自动填充 agent scope 和信号。

### ToolProviderResult：工具 Schema 注入

`ToolProviderResult.schemas` 是当前组装中对模型可见的工具 schema 集合，`knownNames` 是限制前的名称全集（区分"配置拼写错误"与"有意隐藏"）。

### 协作式整体变换约定

`system-prompt/assemble` waterfall 监听器必须：
- **保留**仍在使用的 Code Mode 贡献；
- **保留**结构化输出和工具过滤贡献；
- 不能覆盖其他插件已经写入的提示词逻辑。

## Token 计量与压力管理

### `ctx.tokenMeter`：TokenMeter

Token 计量服务持有服务级别的固定启发式估算器，并为每个 Session 维护隔离的 fold：

- **`measure(session, requestHeader?)`**：通过持久日志的当前 tail 回放，计算当前请求压力与 surface 定价；返回不可变的 `TokenMeasurement`；
- **`estimateMessage(message)`**：对单条模型消息的启发式定价（`O(1)` 快路径）。

### TokenMeasurement 快照字段

| 字段 | 说明 |
|---|---|
| `logRevision` | 生成此计量时消费的持久事件数（= 下一个未读 seq） |
| `baseline.kind` | `'usage'`：使用了最近成功请求的 provider 计量；`'estimated'`：全启发式 |
| `surfaceDeltaTokens` | 相对于 baseline 锚点的有符号增量（包含 surface 增长和缩减） |
| `totalTokens` | 当前请求+响应压力（非负） |
| `surfaceTokens` | 当前 surface 的启发式总量（= 所有节点价格之和） |
| `nodes` | 按位置顺序的 `TokenSurfaceNode[]`（每个 `{ seq, tokens }`） |

> 表层顺序具有**权威性**；替换节点的持久 `seq` 可能高于位置排在其后的节点（压缩 replace 后 seq 大但位置靠前）。

**Baseline 语义**：`kind === 'usage'` 要求最近成功请求的规范 envelope 与当前 `requestHeader` 匹配，且总量不低于其完整启发式锚点；否则服务使用固定启发式重新定价完整信封。后续成功请求会替换早先的锚点。

## 压缩协议

### 触发路径

| 触发方式 | 说明 |
|---|---|
| 自动 `pressure` | `agent/pre-step` waterfall 中检测 token 压力，压缩策略按需执行 |
| 自动 `context-overflow` | 请求返回上下文溢出错误后，由 `agent/request-error` handler 触发恢复压缩 |
| 手动 `/compact` 命令 | 用户主动调用；在轮次之间执行 |

### 压缩操作流程

```text
compaction/start (turn: N | null)
  → 生成摘要（LLM 调用）
  → compaction/summary （日志记录摘要 + shadow-price 元数据）
  → user/message { surfaceOp: { op: 'replace', start, end } }   ← 唯一的 surface 变更
  → compaction/end
```

**Shadow-price 协议**：
- `compaction/summary` 紧邻 `user/message replace` **之前**；
- 携带 `shadowedRange`（位置跨度，不是数值区间）、`shadowedSeqs`（被遮蔽节点 seq 集合，surface 顺序）、`shadowedTokenCount`（启发式 token 估价）；
- 消费方据此减去被替换内容的 token 计量，无需保留每节点定价。

**锁语义**：
- `compaction/start` 获取锁，`compaction/end` 释放；
- 两者之间不允许其他压缩；
- 中途崩溃表现为可检测的遗留锁（有 `start` 无 `end`），而非虚假已完成标志。
- 更新的 `session/end-seed` 之前的未匹配 `start` 是先前生命周期的陈旧证据，忽略。

**先剪枝再压缩**：压缩可先通过 `compaction/prune` 剪枝工具结果（不生成 LLM 摘要），再以 surface replace 替换历史片段；`compaction/prune` 也携带 shadow-price 字段，使用相同协议。

### 压缩范围验证

`compactNow()` 在没有有效范围时返回 `null` 且不写入；只有确实推进替换时才开启重试 Turn。`compactRegion(...)` 接受显式两端均包含的 surface 范围（`start`、`end` 均为 surface node seq，不是数值区间）。

---

## 设计约束

- 向模型呈现内容的唯一来源是 `deriveMessages()`：不能在请求前拼接字符串，只能通过 `user/message`（surface 事件）或 Section/Context 注册；
- 压缩后 surface 中保留的上下文（`PromptContext` 快照）会在下次步骤重新注入，与压缩无关；
- `system-prompt/assemble` waterfall 只在 `agent/pre-step` 中被调用，是唯一的提示词计算触发点。
