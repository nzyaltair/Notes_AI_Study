# 工具权限与执行边界

Agent 的风险取决于其实际可执行的动作，而不是语言表达是否安全。工具层必须把“模型建议”与“获准执行”分开。

## 设计原则

| 原则 | 实现方式 |
|---|---|
| 最小权限 | 临时、细粒度能力令牌；按任务缩小资源范围 |
| 默认拒绝 | 未被显式允许的工具、参数和环境不可调用 |
| 高影响审批 | 支付、删除、发布、外发和物理动作需独立批准 |
| 隔离执行 | 沙箱、只读副本、网络出口控制、密钥托管 |
| 可逆与幂等 | 事务、预演、回滚、去重键和补偿操作 |
| 可审计性 | 记录意图、输入来源、策略判定、参数与结果 |

## 策略执行点

```text
模型计划 → 工具调用提案 → 策略引擎 → 身份/权限校验 → 审批或沙箱 → 执行 → 审计
```

策略引擎应独立于模型，检查调用者身份、目标资源、参数范围、上下文风险、金额/频率阈值和审批状态。不要让 Agent 通过自然语言“说服自己”获得新权限。

## 常见失效

- 共享管理员密钥导致单次注入获得全局权限。
- 工具接口接受过宽参数，形成命令或路径注入。
- 只记录最终文本而没有记录真实调用链，无法追责。
- 审批只展示模型摘要而未展示关键差异、影响范围和证据。
