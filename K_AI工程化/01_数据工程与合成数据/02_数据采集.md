# 数据采集

## 一句话理解

数据采集是按任务、授权与代表性要求获取原始数据的过程，需明确目标分布、记录来源与许可、执行分层采样与隐私保护，并通过覆盖率、时效性、许可完整率等指标验收。

## 1. 概述

数据采集是数据工程的第一环，决定了后续所有处理的质量上限。AI 模型的能力受限于训练数据的覆盖面和质量，"Garbage In, Garbage Out"在 AI 时代依然成立。

采集的核心挑战：

- **代表性**：数据是否覆盖目标分布和长尾场景
- **合规性**：数据来源是否合法、是否有使用许可
- **时效性**：数据是否反映当前世界状态
- **隐私保护**：是否包含 PII 或敏感信息
- **规模与成本**：在有限预算下最大化数据价值

## 2. 数据来源

### 2.1 来源类型

| 来源类型 | 说明 | 示例 | 合规要点 |
|:---|:---|:---|:---|
| 公开语料 | 互联网公开数据 | CommonCrawl、Wikipedia、GitHub | 检查 License、robots.txt |
| 业务日志 | 产品运行产生的数据 | 用户点击、搜索、对话 | 用户同意、隐私政策 |
| 传感器数据 | 物理世界采集 | 摄像头、麦克风、GPS | 设备授权、数据最小化 |
| 合作数据 | 第三方数据采购 | 数据供应商、API | 数据使用协议、审计权 |
| 人工采集 | 定向收集/标注 | 标注平台、专家录入 | 标注协议、知识产权 |
| 合成数据 | AI/程序生成 | Self-Instruct、仿真 | 生成模型版本记录 |

### 2.2 LLM 预训练数据来源

| 数据类型 | 典型来源 | 占比（参考） |
|:---|:---|:---|
| 网页文本 | CommonCrawl | 40-60% |
| 代码 | GitHub、StackOverflow | 5-15% |
| 书籍 | Books3、Gutenberg | 5-10% |
| 学术论文 | arXiv、PubMed | 5-10% |
| 百科知识 | Wikipedia、Wikidata | 2-5% |
| 对话数据 | Reddit、论坛 | 5-10% |
| 专业领域 | 法律、医疗、金融 | 5-10% |

## 3. 采集设计

### 3.1 目标分布定义

采集前必须明确：

- **目标任务**：数据用于什么任务（预训练、SFT、评测）
- **目标分布**：期望的语言、领域、难度、长度分布
- **覆盖维度**：语言、地域、领域、难度、时间
- **许可边界**：哪些 License 的数据可用

### 3.2 分层采样

不使用简单随机采样，而是按维度分层：

```text
分层采样示例:
├── 语言: 中文 30%, 英文 50%, 其他 20%
├── 领域: 技术 25%, 科学 20%, 文学 15%, 新闻 20%, 其他 20%
├── 难度: 简单 30%, 中等 50%, 困难 20%
└── 时间: 近1年 40%, 1-3年 35%, 3年以上 25%
```

分层采样的目标：

- **避免偏差**：防止高频来源（如营销页面）淹没高质量内容
- **长尾覆盖**：确保低频但重要的领域有足够样本
- **多样性**：避免数据分布过于集中

### 3.3 增量采集

对于持续运行的数据管线：

- **变更检测**：基于 URL、hash、修改时间检测新内容
- **增量拉取**：只采集变更部分，降低带宽和存储
- **版本快照**：定期全量快照作为基准

## 4. 元数据记录

每条采集的数据必须记录：

| 字段 | 说明 |
|:---|:---|
| source_url | 数据来源 URL |
| source_type | 来源类型（web/code/book/...） |
| timestamp | 采集时间 |
| content_hash | 内容哈希（用于去重） |
| license | 数据许可证 |
| language | 检测到的语言 |
| quality_score | 初始质量评分（如可计算） |
| pii_flag | 是否检测到 PII |
| crawl_metadata | 爬取元数据（HTTP 状态、大小等） |

## 5. 隐私与合规

### 5.1 PII 识别

在采集入口执行 PII 检测：

- **类型**：姓名、邮箱、手机号、身份证号、地址、银行卡号
- **处理**：脱敏替换、删除、标记隔离
- **工具**：正则规则 + NER 模型组合

### 5.2 敏感内容隔离

- **有害内容**：暴力、色情、仇恨言论的检测与隔离
- **版权内容**：识别可能的版权材料，标记并评估
- **受限内容**：行业限制（如医疗数据需脱敏）

### 5.3 可删除性设计

- **用户数据删除**：支持按用户 ID 删除所有关联数据
- **GDPR/CCPA 合规**：Right to be Forgotten
- **数据溯源**：从训练数据到模型的可追溯链

## 6. 验收指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 覆盖率 | 目标维度的覆盖比例 | ≥ 95% |
| 时效性 | 数据最新时间距今 | ≤ 30 天 |
| 重复率 | 采集数据中的重复比例 | ≤ 5% |
| 缺失率 | 关键字段缺失比例 | ≤ 2% |
| 许可完整率 | 有明确 License 的数据比例 | 100% |
| 采集失败率 | 采集任务失败比例 | ≤ 1% |
| PII 命中率 | 含 PII 的数据比例 | ≤ 0.1%（脱敏后） |

## 7. 常见问题

- **数据偏差**：过度依赖单一来源导致分布偏差
- **许可不清**：数据 License 不明导致法律风险
- **采集风暴**：高频采集对目标站点造成压力
- **数据腐败**：传输/存储过程中数据损坏
- **冷启动**：新领域数据从零采集，周期长
