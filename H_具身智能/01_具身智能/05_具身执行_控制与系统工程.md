# 具身执行、控制与系统工程

## 一句话理解

具身系统是否有用，最终取决于它能否在真实世界以足够低的时延、足够高的稳定性和可审计的安全边界完成动作。模型再强，也必须经过动作适配、控制、监控、仿真验证和真机数据闭环，才能成为可靠系统。

## 1. 策略输出不是电机命令

策略与硬件之间必须有显式契约：动作类型、参考坐标系、单位、控制频率、限幅、延迟预算、成功/失败信号以及失联时的降级方式。

```text
任务/语言目标 → 任务规划或 VLA → 技能目标 / 短动作块
→ 可达性与碰撞检查 → IK/轨迹生成 → 伺服、阻抗或 MPC → 执行器
        ↑                    ↓                 ↓
感知/状态估计 ← 结果核验与重规划 ← 独立安全监督与日志
```

| 动作接口 | 常见场景 | 主要优点 | 风险与要求 |
|---|---|---|---|
| 关节位置/速度 | 常规机械臂伺服 | 硬件通用、易调试 | 需处理跟踪误差与关节限制 |
| 末端位姿增量 | 视觉闭环操作、VLA | 与任务语义对齐、易跨本体 | 需 IK、坐标一致性与限幅 |
| 关节力矩 | 动态腿式/高性能控制 | 控制能力强 | 风险最高，需硬实时与模型 |
| 末端力/阻抗参数 | 装配、柔性接触 | 适应位姿与接触误差 | 依赖可靠力感知、稳定性验证 |
| 技能参数 | 长程 Agent | 隔离低层风险、便于验证 | 技能库覆盖与前置条件要完整 |

## 2. 控制与实时性

### 反馈控制的作用

PID 是关节级基础：

$$u(t)=K_pe(t)+K_i\int_0^t e(\tau)d\tau+K_d\frac{de(t)}{dt}$$

它不“理解任务”，但在毫秒尺度压制扰动和跟踪误差。学习模型常在较低频（例如视觉推理频率）产生目标，而伺服控制器以更高频稳定执行；二者不要混在同一个不确定的推理循环里。

### 约束控制与 MPC

MPC 在预测窗口内求解约束优化并只执行第一个动作：

$$\min_{u_{0:H-1}}\sum_{k=0}^{H-1}\ell(x_k,u_k)+\ell_T(x_H)\quad
\text{s.t. }x_{k+1}=f(x_k,u_k),\;(x_k,u_k)\in\mathcal X\times\mathcal U$$

适合移动、四足和有动态约束的操作，但必须计算端到端时延：感知采集、同步、推理、通信、求解和执行。控制循环抖动会直接转化为轨迹误差或接触不稳定。

### 接触控制

硬接触不要只靠位置跟踪。阻抗/导纳控制、力阈值、接触检测和撤退策略共同组成接触安全层。对插拔、开门、打磨等任务，应明确何时从自由空间切换到接触模式、最大允许力/扭矩是多少、发生异常后如何撤离。

## 3. 软件架构与 ROS 2

ROS 2 可用节点、话题、服务和 Action 组织分布式系统；基于 DDS 的 QoS 可为不同数据流选择可靠性、历史深度和实时性策略。建议模块化为：

1. 硬件驱动、时钟同步与 `tf2` 坐标树；
2. 状态估计与传感器健康检查；
3. 感知、地图与对象状态；
4. 策略/规划推理与动作适配；
5. 轨迹、控制和硬件接口；
6. 独立安全监督、数据记录、回放和可视化。

工程核心是数据契约，不是节点数量：每条消息要有时间戳、frame ID、有效期、单位、置信度与异常码；模型推理应和硬实时控制隔离。MoveIt 2 可集成运动规划、运动学、3D 感知与控制，但它不是 VLA 的替代品，而是为 VLA/任务规划提供可执行性检查和轨迹层。

## 4. 仿真、数据与 sim-to-real

仿真用于大规模并行训练、回归测试、风险预筛和示教生成；真机用于暴露接触、摩擦、视觉、时延和硬件磨损等真实分布。两者不是替代关系。

| 差距来源 | 典型表现 | 缓解措施 |
|---|---|---|
| 几何/质量/摩擦误差 | 抓取滑移、接触反弹 | 系统辨识、参数随机化、真实日志校准 |
| 视觉外观差异 | 仿真策略看不懂真实物体 | 域随机化、真实图像微调、传感器建模 |
| 动作/通信时延 | 超调、抖动、错过接触时机 | 显式注入延迟、动作块重规划、时间同步 |
| 执行器非理想性 | 回差、饱和、温漂 | 硬件在环、残差控制、限幅 |
| 任务分布偏差 | 新物体/布局失败 | 主动采样、失败回放、分层技能与语义泛化 |

推荐部署阶梯：离线日志回放 → 单元仿真 → 集成仿真/硬件在环 → 限速空载 → 受限真机 → 扩大场景分布。每一步都定义可以回退的验收门槛，而非一次性把新模型接到完整功率的真机。

仿真平台的选择要匹配问题：MuJoCo 常用于接触动力学研究；ManiSkill 提供 GPU 并行仿真、视觉数据生成、演示数据与 RL/IL 基线，适合通用操作学习；高保真渲染、场景规模、可用资产与控制接口也都应纳入取舍。

## 5. 安全不是一个后处理模块

安全必须纵深防御：

| 层级 | 机制 | 目的 |
|---|---|---|
| 硬件 | 急停、限位、制动、物理隔离 | 在软件故障时仍可止损 |
| 低层控制 | 速度/力矩/功率/工作空间限制、看门狗 | 阻止危险命令直接到达硬件 |
| 规划层 | 碰撞检查、禁区、可达性和接触约束 | 在执行前排除明显不可行方案 |
| 策略层 | OOD/低置信度检测、权限与工具约束 | 避免模型在未知状态下冒进 |
| 运行层 | 人工接管、超时、审计日志、事故复盘 | 发现问题、恢复和持续改进 |

任何由学习模型输出的动作都应能被独立安全层拒绝或裁剪；“模型说它很自信”不是安全证明。

## 6. 可观测性、数据闭环与版本治理

每次运行至少记录：硬件/固件与控制器版本、策略权重与提示词版本、标定与环境版本、原始/同步观测、动作和实际执行状态、延迟、异常、安全事件、任务结果和人工干预。

建议把失败按感知、规划、控制、硬件、任务定义五类归因，并让每次修复都能回放到固定测试集。没有日志和版本治理，真机调试会退化成不可复现的演示。

## 7. 最小可行到可扩展的实践路线

1. 选一个单任务（抓放、开门或室内导航），先定义状态、动作、成功条件和安全边界。
2. 以规则/MoveIt 2/传统控制打通完整闭环，验证坐标、标定、时延和回退。
3. 在仿真与离线数据上训练 IL、RL 或 VLA 适配层，先做日志回放与对比评测。
4. 接入真机时从低速、低力、受限工作空间开始，并启用独立急停和安全监督。
5. 将成功、失败、恢复、人工干预都写入数据闭环；按新物体、新布局和扰动逐步扩大评测分布。
