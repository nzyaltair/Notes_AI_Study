# 后训练范式与推理训练

## 一句话理解

后训练在预训练先验之上塑造任务接口、偏好、拒答边界和推理策略；它是指令数据、偏好优化、可验证奖励、蒸馏与评测构成的迭代闭环。

## 范式地图

| 范式 | 信号 | 主要目标 | 风险 |
|---|---|---|---|
| 中期训练/退火 | 高质量数据+指令数据混入预末段 | 通用质量与格式先验 | 与预训练边界模糊 |
| 指令微调 | 高质量输入—输出 | 任务格式与可用性 | 覆盖不足、遗忘 |
| 偏好优化 | 成对/排序偏好 | 有用性与约束 | 偏好偏差、过度拒答 |
| 推理训练 | 可验证结果/过程奖励 | 多步求解与工具使用 | 奖励投机 |
| 蒸馏/拒绝采样 | 教师或搜索候选 | 压缩高成本能力 | 教师错误固化 |

迭代合成数据不等于开放式持续学习；长期遗忘、记忆和系统演化见 [[15_持续学习与Agent对齐接口|持续学习与 Agent 接口]] 与 D。

## 训练阶段谱系：数据配方随阶段漂移

现代训练已不是"预训练 → 后训练"两段式，而是一条配方连续漂移的流水线：

```text
预训练（网页为主，容忍低质量，靠规模）
   → 中期训练/退火（高质量数据 + 指令数据混入，低学习率）
      → SFT（指令-回复对，聚合格式与工具调用）
         → 偏好优化（RLHF/DPO，风格与安全边界）
            → 可验证奖励 RL（RLVR，推理与 agentic 能力）
```

**退火阶段（annealing / decay phase）的三个事实**：

1. **指令数据正在前移**：把 instruction tuning 数据与高质量数据混入预训练末尾已是通行做法，可大幅扩展指令数据规模并更侧重高质量数据；预训练、指令微调、高质量数据三者的界限正变得越来越模糊
2. **"基础模型"已名不副实**：如今号称 base model 的模型大多在预训练里就混入了 UltraChat 类对话数据——按"纯下一词预测互联网文本"的传统定义，很难说它们还是基础模型
3. **退火阶段是全训练最重要的部分**：它最接近部署分布且学习率最低，应把质量最高的数据（维基百科、Stack Exchange、书籍等）放在退火阶段；不把全预训练都做成高质量的原因纯粹是 token 不够（全用维基百科会很快耗尽 token）

**典型案例——MiniCPM 两阶段**：第一阶段为标准互联网数据配比；第二阶段（退火）切换为 Stack Exchange、UltraChat 等高质量对话数据，同时下调通用预训练数据占比与学习率。

**退火阶段是配比实验的主场**：中期训练比完整预训练短得多，每种候选配比能跑约 10 次消融实验；据此评估各数据源质量后，结论可反哺预训练阶段该加什么数据。数据配比（无论预训练还是后训练）虽有 DoReMi/RegMix 等算法，实践中主要仍靠试错与直觉——算法给出的解往往不够稳健。Meta 因书籍数据被起诉的法庭文件就披露了研究人员通过消融实验估算书籍语料的实际价值、再据此决定配比的真实流程（详见 [[../../K_AI工程化/01_数据工程与合成数据/11_数据配比|数据配比]]）。

## 典型流水线（2025-2026 开源案例）

- **DeepSeek-R1**：中期训练基座 → 冷启动长 CoT SFT（论文措辞谨慎，疑似蒸馏数据；合适的基座 + 长 CoT SFT 单独即可激发类 o1 能力）→ 推理 RL（GRPO + 准确性/格式奖励 + 语言一致性奖励，防 CoT 乱切语言）→ 拒绝采样 SFT → 通用 RLHF。R1-Zero 跳过全部 SFT，纯 GRPO + 规则奖励即略逊于 o1，是干净的受控实验；蒸馏出的 CoT 反哺 Qwen2.5 等小基座即大幅提升。过程奖励模型与 MCTS 均试过但未带来收益（结果奖励更好扩展）。
- **Kimi k1.5**：不依赖价值函数、过程奖励模型与 MCTS；pass@k 难度过滤 + 掌握即移出题库的课程式数据管理；长度惩罚实现 long2short。
- **Qwen3**：SFT → 推理 RL（仅约 4k 提示词即可有效）→ 通用 RLHF → 蒸馏小模型；思维/非思维模式统一于单模型（提示标签切换 + 思考预算与提前退出），通用 RLHF 后通用任务大涨、数学/代码略降，后续 Qwen3.5 因该代价回归分离式模型。
- **Qwen3-Coder-Next（2026）**：中期训练注入 agent 数据（仓库级长上下文、PR+RAG 合成、公开 agent 运行轨迹、代码中间补全）；从同一中期训练模型分支训练 4 个专家（Web/UX/QA/软件工程）再蒸馏回单一模型（branch-train-merge 式）；软件工程专家在 GitHub 自动构造的 SWE-bench 式环境中 RL（详见 [[../../D_智能体与自主系统/04_强化学习/15_Agentic_RL与大模型|Agentic RL 与大模型]]）。
