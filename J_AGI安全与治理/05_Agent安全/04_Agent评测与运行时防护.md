# Agent评测与运行时防护

## 一句话理解

Agent 评测必须覆盖完整执行轨迹与攻击场景，而非仅看最终输出；运行时防护通过独立监控、熔断和可回滚执行将实际损害限制在可接受范围内。

## 概述

Agent 评测必须测量完整轨迹：是否识别不可信内容、是否选择合适工具、是否遵守权限、是否在不确定时暂停，以及失败后能否恢复。

## 场景维度

- 工具参数注入、跨工具链攻击和权限提升。
- 恶意网页/邮件/文档造成的间接提示注入。
- 记忆投毒、租户隔离和敏感数据外泄。
- 长程任务的目标漂移、循环调用、预算耗尽与副作用。
- 多 Agent 通信伪造、委派链与冲突解决。

## 运行时防护

```text
策略监控 → 调用前检查 → 受限执行 → 结果验证 → 轨迹审计 → 异常熔断/人工接管
```

监控信号包括：异常工具序列、敏感资源访问、拒绝后反复尝试、预算/时长突增、记忆写入异常和执行结果偏离计划。熔断机制必须由独立服务触发，并提供暂停、撤销凭据、回滚事务、通知责任人和保全证据的流程。

## 指标

除任务成功率外，跟踪：越权行动率、攻击成功率、敏感数据暴露率、无效工具调用、人工接管延迟、可回滚率和安全误拒率。任何单一"安全分"都不足以代表 Agent 的运行风险。

## 行为基线与漂移检测

长期运行的 Agent 存在行为漂移风险：模型更新、记忆积累、上下文变化或对抗触发均可能导致行为偏离预期。

- **基线建立**：在受控场景下记录工具调用分布、请求频率、资源访问模式和拒绝率，作为后续对比基准
- **漂移信号**：工具调用序列异常、异常资源访问、拒绝后多次重试、预算或耗时突增、记忆写入频率异常
- **告警阈值**：基于统计控制图（如 CUSUM）或异常检测模型设定动态阈值，避免固定阈值在正常波动中产生大量误报
- **响应策略**：轻微漂移 → 记录并告警；显著漂移 → 降级为受限模式；严重异常 → 熔断并通知人工接管

行为监控系统本身需独立部署，不能依赖被监控 Agent 的配合；日志必须防篡改并具备足够的审计粒度。
