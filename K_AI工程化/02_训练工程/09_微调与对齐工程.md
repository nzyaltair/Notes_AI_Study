# 微调与对齐工程

## 一句话理解

微调与对齐工程把预训练的基础模型改造为能遵循指令、符合价值观、适应特定场景的可用模型——工程核心是管理微调数据质量、高效训练策略和对齐效果的评测与迭代。

## 概述

预训练模型拥有广泛知识但不直接"有用"——它会续写文本，但不会回答问题；会生成内容，但不会遵循格式；会产生输出，但可能有害。微调与对齐将其转化为：

1. **SFT（监督微调）**：学会遵循指令、按格式输出
2. **偏好对齐（RLHF/DPO）**：学会什么是"好的"输出，避免有害输出
3. **领域适配**：在特定领域（医疗、法律、代码）获得专业能力

## 发展历史

| 时间 | 里程碑 | 意义 |
|:---|:---|:---|
| 2019 | Fine-tuning GPT-2 | 早期 LLM 微调实践 |
| 2021 | InstructGPT | RLHF 对齐方法首次规模化验证（GPT-3 基础） |
| 2021 | Adapter Tuning | 参数高效微调（PEFT）的早期方法 |
| 2022 | LoRA | 低秩分解适配器，参数高效微调标准方法 |
| 2023 | Self-Instruct / Alpaca | 开源社区自生成 SFT 数据 |
| 2023 | QLoRA | 4-bit 量化 + LoRA，消费级 GPU 微调 70B 模型 |
| 2023 | DPO | 直接偏好优化，消除 RLHF 对奖励模型的依赖 |
| 2023 | ORPO / SimPO | DPO 的改进变体，更稳定的偏好学习 |
| 2024 | GRPO (DeepSeek) | 组相对策略优化，推理能力微调 |
| 2024 | Full Fine-tuning 回归 | 更大集群使全参数微调重新可行 |
| 2025 | 合成数据主导 SFT | 全合成 SFT 数据集验证有效性 |

## 核心概念

### SFT（监督微调）

在预训练模型基础上，用（指令，回复）对进行有监督训练：

```text
输入: [System Prompt] [User: 请翻译这段文字...] [Assistant: ]
目标: 最大化 P(response | instruction)
```

**关键工程点**：
- **数据质量 > 数量**：1K 高质量样本往往优于 100K 低质量样本
- **数据格式统一**：统一 chat template（ChatML、Llama 等格式）
- **对话轮数平衡**：单轮与多轮对话数据比例
- **领域覆盖**：避免某些能力退化（Catastrophic Forgetting）

### LoRA（低秩适配器）

LoRA 通过向权重矩阵添加低秩分解的增量，实现参数高效微调：

$$W' = W + \Delta W = W + \frac{\alpha}{r} BA$$

其中：
- $W \in \mathbb{R}^{d \times k}$：冻结的预训练权重
- $B \in \mathbb{R}^{d \times r}$，$A \in \mathbb{R}^{r \times k}$：可训练的低秩矩阵（$r \ll \min(d, k)$）
- $\alpha$：缩放因子，控制 LoRA 的影响强度

**参数节省**：秩 $r$ 时，参数量从 $d \times k$ 降至 $r(d + k)$，节省 ~99% 参数（$r = 8$，$d = k = 4096$ 时）。

**QLoRA**：4-bit 量化基础模型 + BF16 LoRA 适配器，单卡 A100 可微调 65B 模型。

### RLHF（基于人类反馈的强化学习）

标准三阶段流程：

```text
1. SFT 阶段：训练初始可用模型
2. 奖励模型（RM）训练：用偏好数据训练评分模型
3. PPO 强化学习：用 RM 作为奖励函数，用 PPO 优化策略
```

**RLHF 工程挑战**：
- PPO 实现复杂，需同时管理 Actor、Critic、Reward、Reference 四个模型
- 训练不稳定，奖励 Hacking（策略欺骗奖励模型）
- 数据和计算成本高，是 SFT 的 3-5 倍

### DPO（直接偏好优化）

绕过奖励模型，直接从偏好数据优化语言模型：

$$\mathcal{L}_{DPO} = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{ref}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{ref}(y_l \mid x)} \right) \right]$$

其中 $y_w$ 为偏好回复，$y_l$ 为拒绝回复，$\pi_{ref}$ 为参考模型（SFT 模型）。

**DPO vs RLHF**：
- DPO 工程实现简单：无需 PPO 的四模型架构
- DPO 训练更稳定，不易 Reward Hacking
- 代价：偏好数据需要对比对（而非单独标注）
- 局限：对 out-of-distribution 样本效果不如 RLHF

### GRPO（组相对策略优化）

DeepSeek-R1 使用的对齐方法，适合可验证的推理任务：

```text
对每个问题生成 G 个回复 → 计算每个回复的奖励
→ 组内归一化为优势函数 → PPO 风格优化
```

**优势**：去除 Critic 模型，计算更高效；适合代码/数学等可自动验证的任务。

## 关键方法与模型

### PEFT 方法对比

| 方法 | 参数效率 | 性能 | 适用场景 |
|:---|:---|:---|:---|
| Full Fine-tuning | 最低 | 最高 | 资源充足时 |
| LoRA | 高（~0.1-1%） | 接近全量 | 通用微调 |
| QLoRA | 最高 | 略低于 LoRA | 资源受限 |
| Prefix Tuning | 高 | 中等 | 参数共享场景 |
| Adapter | 中 | 中等 | 多任务适配 |
| Prompt Tuning | 最高 | 中等偏低 | 推理时无额外成本 |

### 偏好对齐方法对比

| 方法 | 数据需求 | 工程复杂度 | 优势 | 局限 |
|:---|:---|:---|:---|:---|
| PPO/RLHF | 偏好对 + RM 训练数据 | 最高 | 在线反馈，探索能力强 | 不稳定，成本高 |
| DPO | 偏好对 | 低 | 简单稳定 | 离线，OOD 效果弱 |
| ORPO | SFT + 偏好对 | 低 | 无需参考模型 | 较新 |
| GRPO | 可验证答案 | 中 | 适合推理任务 | 需要验证器 |

## 优势与局限

### 微调的价值

- **成本效益**：微调成本远低于预训练（通常 <1%）
- **领域专业化**：针对特定领域的专业知识注入
- **格式控制**：确保输出符合业务格式要求
- **安全对齐**：减少有害输出，增强拒答能力

### 主要挑战

- **灾难性遗忘**：微调特定任务可能导致通用能力退化
- **数据分布偏移**：微调数据不代表真实用户输入分布
- **过拟合风险**：小数据集微调容易过拟合，需要正则化
- **对齐税**：对齐后模型在某些任务的峰值性能低于基础模型

## 工程最佳实践

### 数据准备

1. 从任务评测集出发，构造训练数据（倒推数据需求）
2. 多样性 > 规模：用 DEITA/IFD 等方法选择高信息量样本
3. 保留 10-20% 通用数据防止能力退化
4. 评测集与训练集严格分离

### 超参数选择

| 超参 | 建议范围 | 说明 |
|:---|:---|:---|
| 学习率 | 1e-4 ~ 2e-4 (LoRA) | LoRA 学习率比全量高 10x |
| LoRA 秩 r | 8 ~ 64 | 更复杂任务用更高秩 |
| LoRA alpha | 16 ~ 128 | 通常 alpha = 2r |
| Batch size | 128 ~ 1024 token | 全局 batch size |
| 训练 epoch | 1 ~ 3 | SFT 一般不超过 3 epoch |
| 权重衰减 | 0 ~ 0.01 | 轻量正则化 |

### 评测与迭代

```text
微调 → 离线评测（基准 + 业务场景集）
    → 如不达标：分析失败案例 → 补充对应数据 → 重新微调
    → 达标后：在线 A/B 测试 → 全量发布
```

## 应用场景

| 场景 | 微调类型 | 数据量 |
|:---|:---|:---|
| 通用指令遵循 | SFT | 10K-1M 样本 |
| 安全对齐 | RLHF/DPO | 10K-100K 偏好对 |
| 数学/代码推理 | SFT + GRPO | 100K-1M 样本 |
| 领域专业化 | 持续预训练 + SFT | 1B-10B tokens |
| 企业私有化 | QLoRA | 1K-10K 样本 |
| 多语言适配 | SFT | 10K-100K/语言 |
